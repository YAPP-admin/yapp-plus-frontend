# 데이터와 상태 수명

## 입력과 검증

| 개체      | 필드·규칙                                                                 | 수명                      |
| --------- | ------------------------------------------------------------------------- | ------------------------- |
| 세션 대상 | sessionId, latitude, longitude, attendanceStatus                          | 기존 세션 Query           |
| 위치 표본 | 기존 LocationSample의 latitude, longitude, accuracy, timestamp, precision | 요청 함수 지역 변수       |
| 판정      | 허용·정책 차단·판정 불가와 정규화된 사유, 설정/재시도/세션 재조회 행동    | 현재 시트                 |
| 제출 대상 | 현재 계정 경계, 세션 ID·좌표, 활성 시도 식별                              | 현재 제출 시도            |
| 서버 성공 | 기존 verified·checkedInAt, context의 sessionId                            | 기존 계정별 mutation 수명 |

- 좌표는 유한한 숫자이며 위도 [-90, 90], 경도 [-180, 180]이다. 0은 누락으로 취급하지 않는다.
- accuracy는 null이 아닌 유한한 0 이상 50 이하, precision은 precise여야 한다.
- 거리 결과는 유한한 0 이상 100 이하여야 한다. 반올림·허용 오차 가산은 하지 않는다.
- 유효한 위치가 정책을 충족하지 않으면 BLOCKED, 입력 계약이나 거리 계산 문제면 UNAVAILABLE로 구분한다. 두 결과 모두 제출을 차단한다.
- native의 표본 신선도 검사를 유지한다. 웹은 반환 후 비동기 대기 없이 판정·대상 재확인·전송한다.
- 외부 입력 스키마를 화면마다 복제하지 않는다. 공용 LocationSample 검증과 기존 세션 응답 검증 후 출석 정책만 검사한다.

## 상태 전이

입력 → 위치 확인 → 출석 전송 → 서버 확인 완료.
검증·위치 실패는 입력을 유지한 실패 상태로 돌아가며 수동 제출만 새 위치 확인을 시작한다.
설정 열기는 실패 복구 동작이며 출석 전송을 실행하지 않는다.

- 활성 시도가 무효화되면 이전 응답으로 제출하거나 탐색하지 않는다. HTTP 전송 전에 무효화된 시도는 성공 mutation으로 끝내지 않는다.
- 출석 전송 이전에는 현재 계정·화면·세션·출석 가능 상태·네트워크와 조회 실패 여부를 재검사한다. 일반 토큰 갱신은 계정 변경으로 취급하지 않는다.
- 같은 세션 데이터의 무해한 재조회는 취소 사유가 아니다. ID·좌표·가능 상태 변경 또는 조회 실패를 구분한다.
- 이미 서버에 전송된 뒤에는 완료 여부를 위치 상태로 덮지 않는다. 계정별 기존 캐시 정리 경계를 유지한다.
- 원문 위치를 mutation variables/context/data/error 또는 전역 store에 넣지 않는다.
