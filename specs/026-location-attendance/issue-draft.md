# feature: 회원 코드 출석에 100m 위치 조건 적용

**생성 상태**: [GitHub #478](https://github.com/YAPP-admin/yapp-plus-frontend/issues/478) 생성 완료 · **대상**: YAPP-admin/yapp-plus-frontend
**제안 담당자**: DongjaJ · **라벨·milestone**: 추가 제안 없음
아래 본문은 저장소 feature-request 템플릿을 따르며 생성된 이슈의 기준 본문이다.
관련 열린 이슈 검색에서 같은 목적의 작업은 찾지 못했다. 기존 #462는 관리자 세션 관리로 범위가 다르다.

## 작업 배경

현재 회원은 출석 코드만 제출하며 세션 장소에 있는지 확인하지 않는다.
세션 장소에서 100m 밖이거나 위치를 확인할 수 없으면 코드 제출을 차단한다.
정확한 위치 권한과 추정 오차 50m 이하를 요구하며 반복 실패는 운영진에게 문의하도록 안내한다.

## 작업 내용

- [ ] 코드 확인 시에만 현재 위치를 확인하고 정밀 권한·오차·거리 기준을 통과하면 제출한다.
- [ ] 위치·세션 좌표를 확인할 수 없으면 전송하지 않고 원인별 재시도·설정·운영진 문의를 안내한다.
- [ ] 중복 클릭·화면 이탈·계정 및 세션 변경 뒤 지연 위치가 코드 전송으로 이어지지 않게 한다.
- [ ] 사용자 위치를 판정에만 사용하고 서버·캐시·로그·영구 저장소에 남기지 않는다.
- [ ] iOS 실기기·접근성·현장 측정을 확인하고 Android 공통 정책과 별도 적용 상태를 기록한다.

## 완료 조건

- [ ] 정확한 권한·오차 50m 이하·거리 100m 이하일 때만 기존 코드 검증 요청이 시도당 1회 전송된다.
- [ ] 거리 초과·위치 실패·좌표 누락·대상 변경 시 코드 전송이 0회이며 우회 제출이 없다.
- [ ] 실패 후 코드가 유지되고 사용자 재시도 전 자동 제출이 없다. 서버 성공으로만 완료를 표시한다.
- [ ] 경계·수명·복구 회귀 테스트, check·build, iOS 실기기 검증 결과와 미실행 항목을 구분해 보고한다.

## 참고 사항

- 명세: `specs/026-location-attendance/spec.md`, 계획: `specs/026-location-attendance/plan.md`.
- 기존 위치 브리지 #353, 코드 출석 #385의 후속이며 작업 이슈로 재사용하는 승인은 받지 않았다.
- geolib로 웹에서 계산한다. 네이티브·브리지·서버 API 변경, Android 저장소 구현은 제외한다.
- Android도 같은 차단 정책을 적용하는 방향이며 현재 구현 완료 여부와 구분한다.
- current-week의 본인 체크인 완료 조회 계약은 별도 문의다. 앱 재실행 후 완료 복원을 이 이슈에 포함하지 않는다.
- 문서 → 판정 → 제출·수명 → 안내·복구 → 통합·실기기의 다섯 단계로 리뷰한다.
- 클라이언트 사전 검사이며 변조 요청의 우회 방지를 보장하지 않는다.
