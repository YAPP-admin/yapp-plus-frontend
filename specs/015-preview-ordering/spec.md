# 기능 명세: Preview 댓글의 최신성 보존

브랜치: `fix/135-preview-publication-order`
작성: 2026-10-29. 상태: Draft. 입력: 감사 이슈 #135 수정과 Draft PR 작성.

## 사용자 시나리오와 검증

### 운영자 배포 결과 보존 (P2)

서로 다른 CI 완료 순서에서도 PR의 최신 head에 대응하는 댓글을 유지한다. 이전 실행이 늦게 끝나 최신 결과를 덮는 것을 방지한다.
독립 검증: 두 commit의 완료 순서를 뒤집은 fixture에서 오래된 결과의 공개를 거절한다.

### 예외 조건

API 조회 실패·닫힌 PR·대기 중 새 commit·승격 timeout·실행 취소를 구분한다.
외부 시스템 응답을 확인할 수 없으면 성공을 추정하지 않는다.

## 요구사항

- FR-1: 같은 PR·앱의 배포와 댓글 쓰기를 직렬화한다.
- FR-2: 댓글 쓰기 직전에 열린 PR의 현재 head와 검증 commit을 대조한다.
- FR-3: PR 정보 조회 실패 또는 오래된 commit은 최신 댓글을 갱신하지 않는다.
- FR-4: 대기 순서가 commit 순서와 달라도 오래된 실행이 최신 실행을 취소하지 않는다.

## 주요 개체

검증 commit, 대상 앱, 현재 원격 commit, 실행 결과와 공개 결과를 구분한다.

## 성공 기준

- SC-1: 순서 역전 fixture 모두에서 오래된 실행이 새로운 공개 결과를 덮지 않는다.
- SC-2: 조회 실패 시 공개 작업을 수행하지 않으며 원인을 확인할 수 있다.
- SC-3: 실제 배포 없이 검증 가능한 경계 테스트와 운영 확인 절차를 제공한다.

## 범위와 가정

GitHub Actions가 같은 저장소의 공통 잠금을 적용한다. 외부 콘솔에서 별도 배포를 실행하는
경로는 이 잠금 밖이며 별도 운영 통제가 필요하다. 이번 작업은 코드·문서·Draft PR까지이며
Production 배포·롤백은 실행하지 않는다.
