- T017~T020: 공용 web 진입점에 세 도우미와 실행 환경 판별을 공개했다. SSR·일반 웹에서는 호출하지 않고 응답 필드·오류를 검증한다. 준비 polling·구버전 fallback은 추가하지 않았다.
- T021~T022: `/dev/routes`에 개발 빌드 전용 검증 도구를 연결했다. 기존 ActionButton·SEED 토큰과 useMutation을 사용하며 좌표 대신 비민감 문자열만 캐시한다. offline에서도 실행하고 자동 재시도는 하지 않는다.
- Stackflow isActive가 false이면 도구를 unmount한다. 중복 클릭·이탈 후 늦은 응답·재진입·설정 복귀 후 재조회·키보드 focus·상태 출력·DOM/Query 캐시 좌표 미노출을 검증했다.
- 공개 도우미 테스트는 구현 전 실패, 구현 후 신규 12개 통과했다. 초기 lint의 import 위치·상태 초기화·중첩 삼항·시맨틱 output·switch·async mock 문제를 수정했다.
- 최종 check 통과: web lint 새 실행, 나머지 6개는 캐시 재사용(이 작업의 앞선 실행에서 app-bridge/mobile lint도 새로 통과). app-bridge/mobile/web typecheck 새 실행·나머지 4개 캐시. 테스트 app-bridge 54개·mobile 102개·web 225개 새 실행, ui/admin 캐시 재사용이다.
- build는 web 새 실행·admin/storybook 캐시 재사용으로 통과했다. 기존 크기 경고 외 빌드 실패는 없다. 생성된 프로덕션 JS에 위치 도구 청크와 전용 문구가 없음을 검사했다. 실서비스 출석 제출은 수정하지 않았고 기존 출석 화면 테스트 3개도 통과했다.
- expo:doctor 20/20 새 실행 통과. 이번 단계는 네이티브 설정·의존성·runtime을 변경하지 않았다.
- 브라우저 연결 도구가 timeoutMs 오류로 실패했다. native Chrome 제어로 개발 URL 진입과 페이지 제목은 확인했지만 화면 캡처가 검게 반환되고 본문 접근성 트리를 얻지 못해 시각 검증 통과로 보고하지 않는다. 작은 화면·테마·터치·스크린 리더·스크린샷 검증은 남아 있다.
- T024 미완료: iOS 새 바이너리 설치·GPS·권한 팝업·설정 복귀·런타임 분리·실기기 로그 미노출 확인은 미실행이다. 합성 입력 자동 테스트는 실기기 성공 근거가 아니다.

3단계 변경은 커밋·push·PR 생성하지 않았으며 리뷰 대기다.
최종 종속 base 대비 추가 542줄·삭제 19줄, 합계 561줄이다. 웹 호출과 개발 검증 도구를 한 리뷰 단위로 유지하며 추가 PR 분리는 필요하지 않다.

## 3단계 추가 검증 — iOS 시뮬레이터

- iPhone 15 Pro / iOS 17.5에서 Expo Location을 포함한 1.0.1 Debug 바이너리를 새로 빌드·설치했다. Expo CLI의 서명 탐색 실패 후 xcodebuild의 시뮬레이터 대상으로 빌드했다. 생성된 ios 프로젝트와 XCTest 실행 도구는 gitignored 경로에만 둔다.
- 실제 WebView 진입에서 개발 경로의 인증 차단을 발견해 개발 빌드에만 공개했다. 프로덕션 인증 정책 유지 회귀 테스트를 추가했다.
- 실제 권한 팝업 허용 직후 inactive를 background로 오인하는 실패와 Expo iOS의 소수 밀리초 timestamp가 정수 계약에서 거부되는 실패를 수정했다. 수정 전 회귀 테스트 실패, 수정 후 통과를 확인했다.
- 권한 팝업 표시·허용은 실행했다. 별도 XCTest에서 권한 거부 조회 → 위치 요청 거부 안내 → 앱 설정 이동 → 앱 복귀 → 권한 재조회를 검증했다. 화면에 좌표가 없고 작은 화면에서 버튼과 상태 출력이 보임을 확인했다.
- 정상 수신 시나리오는 아직 실패다. 합성 위치의 계약 검증은 통과하지만 요청보다 약 0.6초 앞선 측정 시각이 현재의 엄격한 신선도 조건에 걸렸다. 신선도 허용 범위는 사용자 결정 전 변경하지 않는다.
- 최종 check 통과: mobile/web lint 새 실행·5개 캐시, app-bridge/mobile/web typecheck 새 실행·4개 캐시, app-bridge 54개·mobile 103개·web 228개 테스트 새 실행·ui/admin 캐시. build는 3개 모두 캐시 재사용이며 앞선 인증 경계 수정 후 web 빌드는 새 실행으로 통과했다.
- 실기기 GPS·100m 환경의 정확도, 대략적 위치, 서비스 비활성화, 런타임 분리, 스크린 리더 검증은 남아 있다. 시뮬레이터 결과로 T024를 완료 처리하지 않는다. 임시 진단 로그는 소스에서 제거했다.

오류 주입은 실제 OS 장애를 재현한 결과가 아니다. 임시 어댑터를 원본과 바이트 단위로 대조해 복구했다. Metro·웹 서버 로그에서 좌표 필드 토큰이 없음을 확인했다.
두 시뮬레이터 모두 앱별 위치 설정·전체 위치 서비스 메뉴가 없고 설정 버튼은 설정 첫 화면을 연다. 앞선 “설정 이동 통과”는 설정 앱 실행·복귀만 의미하며 앱별 설정 목적지 검증은 실기기에 남긴다.
위치 입력 clear 후에도 OS가 성공 위치를 반환해 실제 신호 없음·OS 자체 timeout은 재현하지 못했다. VoiceOver 메뉴가 없어 음성 낭독은 미검증이다. 원격 OTA 수신 분리는 수행하지 않았다.
접근성 감사에서 기존 YAPP+ 헤더·홈 링크의 작은 터치 영역과 Expo 개발 도구의 대비·기계적 레이블이 검출됐다. 감사 도구 실행 성공을 화면 전체 접근성 통과로 간주하지 않는다.

키보드 XCTest는 미통과다. 권한 조회 후 Tab/Space로 위치 요청 실행을 기대했으나 일반 상태·전체 키보드 접근 활성화·Tab 순서 변경 모두 실행을 확인하지 못했다. 웹 단위 테스트의 키보드 통과와 별개이며, 실제 WKWebView 포커스 이동 문제인지 시뮬레이터 입력 제약인지 추가 확인이 필요하다.
이번 작업은 검증 기록만 변경했다. 실기기 GPS·100m 정확도·앱별 설정 진입·VoiceOver와 원격 OTA 적용 검증은 남아 있어 T024를 완료하지 않는다.

최종 check는 통과했으며 lint/typecheck 각 7개·test 5개 모두 Turbo 캐시 재사용이다. 제품 코드 변경이 없어 build·doctor는 재실행하지 않았다. 커밋·push는 하지 않았다.
