# 세션 페이지와 API 연결 계약

## 범위와 근거

기준은 `packages/api/src/generated`의 2026-11-16 계약이다. 생성 파일 수정·새 endpoint·SDK 전역
검증 활성화는 하지 않는다. 관리자 인증은 기존 `staffBearerAuth`, HTTP 오류는 공통 `ApiError`를 사용한다.
최신 공개 명세 재확인 실패와 실제 기수 ID 미확보는 실서버 검증의 후속 조건이다.

## API 대응

경로 기준: `/api/admin/generations/{generationId}/sessions`.

| 기능      | SDK·메서드                       | 응답·오류                                                            |
| --------- | -------------------------------- | -------------------------------------------------------------------- |
| 전체 목록 | `find1`, GET, type ALL           | 200 목록, 400 입력 오류, 401 인증, 404 기수 없음                     |
| 생성      | `create2`, POST                  | 201 sessionId, 400 입력 오류, 401 인증, 404 기수 없음, 409 날짜 충돌 |
| 수정      | `update1`, PUT `/{sessionId}`    | 204, 400 입력 오류, 401 인증, 404 대상 없음, 409 수정/날짜 충돌      |
| 삭제      | `delete1`, DELETE `/{sessionId}` | 204, 401 인증, 404 대상 없음, 409 삭제 제한                          |

생성·수정은 `CreateSessionRequest` 전체 본문을 보낸다. API 설명상 정규는 주소·좌표 필수,
팀은 모든 장소 필드 null이다. 단순 생성 Zod 객체가 이 조건까지 검증하지 않으므로 앱에서 보완한다.
`SESSION_DATE_CONFLICT`, `SESSION_UPDATE_CONFLICT`, `SESSION_DELETE_CONFLICT`를 구분한다.
검증하지 않은 오류 본문·message·요청 URL·인증 값을 사용자 안내나 로그에 그대로 출력하지 않는다.

## 공개 화면 입력

- `SessionsPage`: 설정에서 읽은 `generationId: number`, 기존 `type`·`onTypeChange`를 전달받는다.
- 라우트는 기수 설정이 없으면 안내를 렌더링한다.
- 필터는 기존 `all | offline | team` URL 계약을 유지한다. 새 기수 선택 URL은 추가하지 않는다.
- SSR에서는 요청하지 않고 기존 ClientOnly·Suspense·오류 재시도 경계를 유지한다.
- 데이터 변환과 폼 함수는 페이지 내부에 둔다. 필요 없는 공개 export와 공용 패키지를 추가하지 않는다.

## 변경 결과와 재조회

- HTTP 성공을 확인하기 전 낙관적 변경은 없다. 생성 성공은 ID 검증, 수정·삭제는 204를 확인한다.
- 성공 후 생성은 전체 필터, 수정·삭제는 현재 필터를 유지한다. 완료 UI는 재조회 완료와 분리한다.
- 이전 조회는 signal로 취소하고 무효화한다. 저장 성공 뒤 목록 실패는 별도 갱신 안내·목록 재시도로 처리한다.
- 초기 목록도 없었던 경우에는 빈 목록을 만들지 않고 최초 조회 오류와 저장 완료 안내를 각각 표시한다.
- HTTP 오류가 아닌 응답 유실·타임아웃은 결과 확인 안내와 목록 조회를 제공한다. 자동 변경 재시도는 없다.
- 인증 401은 로그인 필요 안내·기존 로그인 링크로 처리한다. 토큰 갱신·전역 인증 정책을 추가하지 않는다.
- 원래 페이지가 unmount되었으면 캐시 작업만 수행하고 해당 모달의 탐색·스낵바 콜백은 실행하지 않는다.

## 삭제 UI

- 메뉴명은 `삭제`, 제목은 `세션을 삭제할까요?`, 설명에 대상 세션명을 넣는다. 취소가 초기 포커스다.
- `STARTED`에서는 삭제를 비활성화하고 `출석이 시작된 세션은 삭제할 수 없습니다.`를 함께 표시한다.
- `NOT_STARTED`에서 확인해도 서버가 최종 판단한다. 409는 항목·오류 안내를 유지하고 상태를 재조회한다.
- 404는 대상 없음 안내 후 창을 닫고 목록을 갱신한다. 이번 요청의 삭제 완료 스낵바는 표시하지 않는다.
- 요청 중 닫기·중복 요청을 막는다. 성공 후 항목·네 개수를 갱신하고 재조회한다.
- 취소는 트리거, 성공·404로 트리거가 사라지면 목록 제목에 포커스를 옮긴다. 새 화면에는 포커스를 옮기지 않는다.
