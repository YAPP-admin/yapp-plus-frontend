# 기능 명세: 팀 세션 사진 제출 준비

후속 운영 연결과 사진 선택 즉시 업로드는 [027 명세](../027-member-team-attendance/spec.md)에서
정의한다. 아래 내용은 당시 개발 준비 범위의 기록이며 새 단계의 적용 상태는 후속 검증 기록을 따른다.

**브랜치**: `DongjaJ/team-session-auth-develop` | **작성일**: 2026-11-12 | **상태**: 1단계 명세 확정 · [#428](https://github.com/YAPP-admin/yapp-plus-frontend/issues/428)

## 사용자 시나리오와 검증

### US1 — 인증 사진 준비 (P1)

개발 검증 환경의 회원은 앨범에서 사진 한 장을 선택하거나 직접 촬영하고 제출할 사진을 확인한다.
독립 검증은 업로드 없이 사진 선택·변환·미리보기·교체·취소를 확인하는 것이다.

1. JPEG·PNG·HEIC 사진을 선택하거나 촬영하면 방향과 비율이 유지된 제출용 JPEG를 확인한다.
2. 선택을 취소하면 기존 사진은 유지된다. 권한 거부·변환 실패는 제출 성공으로 표시되지 않는다.
3. 허용 크기를 벗어나거나 읽을 수 없는 사진은 이유를 안내하고 다시 선택할 수 있다.

### US2 — 참석 팀원과 사진 제출 (P2)

회원은 사진에 나온 팀원을 선택하고 인증 사진을 제출한다.
독립 검증은 고정된 개발용 팀·세션 입력과 모의 서버로 선택부터 접수 완료까지 확인하는 것이다.

1. 본인이 기본 선택되며 해제할 수 없다. 다른 팀원은 사용자가 선택한다.
2. 제출 중 입력 변경과 연속 제출을 막는다. 서버가 접수를 확인한 경우에만 완료를 표시한다.
3. 완료 화면에 팀·참석 명단·서버 제출 시각을 표시하고 운영진 승인 후 출석 완료임을 안내한다.
4. 실패한 요청은 성공으로 표시하지 않는다. 최종 접수 여부가 불명확하면 자동 재제출하지 않는다.

### 경계 조건

- 취소·권한 거부, 손상·빈 파일, 큰 사진, 사진 회전, 최종 용량 경계.
- 오프라인, 업로드 실패, 인증 만료, 잘못된 성공 응답, 최종 제출 응답 유실.
- 입력 중·제출 중 화면 이탈, 계정 변경, 늦게 도착한 결과, 완료 URL 직접 진입.
- 실제 운영 진입 차단과 개발 화면에서 명시적 제출에 의한 서버 요청.

## 요구사항

- **FR-001**: 사진 한 장을 앨범 또는 카메라에서 받고 사용자가 선택한 경우에만 필요한 권한을 요청한다.
- **FR-002**: JPEG로 변환하고 품질 0.9, 긴 변 최대 2,560px를 적용한다. 작은 사진은 확대하지 않고 자르지 않는다. 최종 크기는 1바이트 이상 10MiB 이하다.
- **FR-003**: 본인을 포함한 제공된 팀원만 제출할 수 있다. 회원 식별자를 이름·사용자 ID로 추정하지 않는다.
- **FR-004**: 사진 업로드와 최종 접수를 구분하며 유효한 서버 접수 확인 전 완료를 표시하지 않는다.
- **FR-005**: 요청 자동 재시도·오프라인 예약 제출을 하지 않고 중복 제출을 막는다.
- **FR-006**: 사진·선택 명단·결과는 화면 흐름 수명에 한정한다. 사진·인증정보·서명 URL을 로그나 영구 저장소에 기록하지 않는다.
- **FR-007**: 취소·실패 시 필요한 입력을 유지하되 이탈·계정 변경 후 늦은 결과가 다른 화면을 바꾸거나 후속 제출을 시작하지 않게 한다.
- **FR-008**: 개발 환경에서만 전체 흐름을 제공한다. 운영 홈과 직접 URL 진입에서 팀 인증 제출을 열지 않는다.
- **FR-009**: 키보드·터치·VoiceOver로 입력·진행 상태·오류·완료를 확인할 수 있다.

### 주요 개체

- **제출 대상**: 세션 식별자, 팀 이름, 본인 소속 식별자, 선택 가능한 팀원.
- **사진 초안**: 제출용 사진과 미리보기. 교체·이탈 시 폐기한다.
- **참석 명단**: 본인을 포함한 선택 팀원. 제출 당시 값을 접수 정보와 연결한다.
- **접수 확인**: 서버 사진 식별자·제출 시각·검토 대기 상태. 출석 승인과 다르다.

## 성공 기준

- **SC-001**: 앨범·촬영·HEIC 입력과 취소·권한 거부 사례가 기대 결과와 일치한다.
- **SC-002**: 대표 단체 사진에서 팀원 얼굴이 구분되고 최종 파일 제한을 만족한다.
- **SC-003**: 모의 서버의 정상·실패·응답 유실에서 잘못된 완료 표시와 자동 재제출이 없다.
- **SC-004**: 운영 진입은 차단하고, 개발 화면의 명시적 제출은 기존 서버 API를 사용한다.
- **SC-005**: 자동 검증·실기기·접근성의 실행 및 미실행 결과를 구분해 기록한다.

## 가정과 제외

- 실제 회원용 조회와 운영 연결은 후속 작업이다. 현재는 명시적 개발 입력만 사용한다.
- 검토 결과·사진 열람·반려 후 재제출·관리자·Android·서버 변경·배포는 제외한다.
- 이전 브리지 버전 호환과 업데이트 안내는 만들지 않는다.
- JPEG를 채택한다. WebP 서버 지원 확대와 일반 브라우저의 실제 로그인은 제외한다.

## 4단계 리뷰의 범위 변경

사용자는 별도 모의 base URL을 제거하고 개발 화면에서도 실제 서버에 사진 제출 요청을 보내도록 승인했다. 업로드된 이미지 정리는 사용자가 서버 담당자에게 요청한다. 자동 테스트는 MSW를 유지하며 에이전트가 실제 사진 제출·삭제를 검증 목적으로 실행하지 않는다. 회원용 대상 조회와 운영 노출은 여전히 제외한다.
