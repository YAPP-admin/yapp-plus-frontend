# 기능 명세: 불리언 상태와 조건부 명령 명명 정리

작성일: 2026-11-20 · 상태: 초안 · 이슈: #504

## 사용자 시나리오와 검증

### US1 — 상태와 질의의 의도 파악 (P1)

개발자는 boolean 값과 순수 질의를 읽을 때 이름만으로 참·거짓의 의미를 파악한다.

독립 검증: 변경된 변수와 순수 함수가 `is`·`has`·`can`·`should`로 시작하고 기존 동작 테스트가 통과한다.

### US2 — 조건부 명령의 결과 파악 (P2)

개발자는 부수효과를 내는 함수가 성공 여부를 반환할 때, 이름에서 조건부 결과임을 파악한다.

독립 검증: 반환값이 다음 제어 흐름에 사용되는 명령은 `try…` 또는 `…IfNew` 의미를 가지며 호출부와 테스트가 함께 갱신된다.

## 요구사항

- **FR-001**: 내부 boolean 상태 변수는 대상과 상태를 드러내는 술어형 이름을 사용한다.
- **FR-002**: 순수 boolean 질의 함수는 술어형 이름을 사용한다.
- **FR-003**: 조건부 명령은 부수효과와 반환값의 의미를 함께 드러낸다.
- **FR-004**: React hook, 생성 코드, API 상태 리터럴, 외부 공개 계약은 별도 영향 검토 없이 변경하지 않는다.
- **FR-005**: 제품 코드와 테스트 코드는 독립 검토 가능한 단위로 나누고 각 단위에 가까운 회귀 검증을 실행한다.

## 성공 기준

- **SC-001**: 승인된 내부 후보가 전수 감사 기준에 따라 분류되고 변경 근거를 남긴다.
- **SC-002**: 변경된 앱·패키지의 lint, typecheck, 테스트가 통과한다.
- **SC-003**: 생성 코드·상태 리터럴·외부 계약의 동작 변경이 없다.

## 가정

- 감사 보고서의 86개 후보 중 공개 계약·프레임워크 명명·테스트 전용 후보는 별도 변경 단위로 다룬다.
- 부수효과 명령을 단순히 `is…`로 바꾸지 않고, 실제 반환값 사용 여부를 먼저 확인한다.
