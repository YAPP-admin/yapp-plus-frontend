# 팀 세션 결과 조회·표시 계약

## 기존 API

| 생성 옵션            | 경로                                                 | 사용 목적                          |
| -------------------- | ---------------------------------------------------- | ---------------------------------- |
| find7Options         | GET /api/generations/current/sessions                | 현재 기수 ID와 세션 유형·날짜·시간 |
| find8InfiniteOptions | GET /api/attendance-history                          | 본인 출결·심사 상태와 다음 페이지  |
| find1Options         | GET /api/sessions/{sessionId}/team-attendance-photos | 최신 사진 ID·심사 상태·반려 사유   |
| find6Options         | GET /api/sessions/current-week                       | 기존 홈 조회와 재업로드 가능 여부  |

실제 경로·타입의 기준은 생성 SDK다. 새 HTTP 경로·확인 Mutation·resultId는 추가하지 않는다.
생성 Query key와 옵션을 재사용하고 화면 정책이 필요한 부분만 홈 전용 훅이 조합한다.

## 결과 판정

일정 type이 TEAM이고 시작된 세션의 본인 내역이 있을 때만 후보로 삼는다. 시작 전에 심사됐어도
세션 시작 이후 홈 진입·복귀부터 안내하며, 시작 시각용 타이머는 추가하지 않는다. 아래 순서로 판정한다.

| 본인 attendanceStatus                            | 추가 조건                                                    | 결과          |
| ------------------------------------------------ | ------------------------------------------------------------ | ------------- |
| ABSENT                                           | 없음                                                         | ABSENT        |
| PRESENT, LATE, EARLY_LEAVE, LATE_AND_EARLY_LEAVE | 없음                                                         | COMPLETED     |
| UNDECIDED                                        | 본인 staffDecisionStatus와 최신 photo.status가 모두 REJECTED | REJECTED      |
| 그 외                                            | 없음                                                         | 표시하지 않음 |

확정된 본인 출결은 팀 심사 상태와 달라도 우선한다. 미확정 반려에서 사진·본인 심사 상태가
불일치하면 안내를 보류한다. NOT_SELECTED를 사진 승인·반려와 동일하게 처리하지 않는다.
photo:null은 반려 근거가 될 수 없지만 본인 확정 출결에는 null 식별자로 사용할 수 있다.
imageUrl:null은 기존 photoId를 유지한다. 사진 조회 실패·403·404는 photo:null로 변환하지 않는다.

## 후보 탐색과 갱신

- find7의 현재 기수와 인증된 userId로 표시 이력 범위를 정한다. find8의 본인 내역과 sessionId로
  결합하고 커서를 따라간다. 일정 목록만으로 회원 자격·본인 결과를 추정하지 않는다.
- 본인 결과가 있는 팀 세션의 사진만 조회한다. 재업로드 가능한 반려를 우선하고 나머지는
  세션 날짜·시작 시각 내림차순, 같으면 sessionId 내림차순으로 선택한다.
- 먼저 현재 find6 세션의 반려 후보를 확인한 뒤 나머지 과거 결과를 탐색한다. 이 순서로
  재업로드 우선순위를 지키며, 현재 세션도 본인 내역이 제공되는 시작 이후에만 판단한다.
- 이미 표시한 결과를 건너뛰어 한 건을 찾으면 다음 페이지·사진 탐색을 멈춘다. 후보 조회 실패는
  이번 진입의 자동 표시를 보류하고 저장하지 않는다. 새 홈 진입·복귀에서 다시 시도한다.
- 활성 홈 최초 진입·복귀에서 관련 내역·사진도 갱신한다. 이전 캐시만으로 새 모달을 열지 않는다.
  계정 변경·홈 비활성화 후 늦게 도착한 응답은 시트를 열거나 표시 이력을 기록하지 않는다.
- 재제출 성공 시 기존 주간·사진 key와 본인 내역의 Infinite Query key를 무효화한다. Query 옵션·
  키를 새로 발명하거나 Mutation 완료를 후속 조회 성공과 묶지 않는다. polling은 추가하지 않는다.

## 시트와 후속 행동

- 홈의 useScreenActiveContext·useRefetchOnScreenReturn 계약을 따른다. 한 진입에서 표시 후 닫아도
  다음 결과를 이어서 열지 않는다. 홈이 다시 활성화되거나 앱 복귀한 때 새 진입으로 처리한다.
- BottomSheet는 Activity 안에서 렌더링하며 layerIndex·기존 닫기·기본 포커스 이동과 복귀를
  재사용한다. 별도 Portal이나 수동 포커스 effect를 추가하지 않고 제목과 설명을 연결한다.
- 반려: 제목은 '팀 세션 인증이 반려됐어요'. 같은 sessionId의 최신 find6.AVAILABLE일 때
  TeamAttendanceGuide로 이동한다. 안내 기한은 세션 endTime을 한국 시간으로 표시한다.
- 기한 경과: '재업로드 기한이 지났어요'와 확인 버튼. 기한 전이어도 제출 불가로 응답되면
  '현재 다시 업로드할 수 없어요'와 확인을 표시한다. 마감·최종 접수 허용은 서버가 판단한다.
- 결석: '결석으로 처리됐어요'와 '확인이 필요하면 운영진에게 문의해 주세요'. 사유는 제공되지
  않으므로 생략한다. 문의는 기존 https://pf.kakao.com/_aGxofd 링크와 WebView 외부 이동 규칙을 따른다.
- 완료: '팀 세션 출석이 완료됐어요!'와 '운영진이 출석을 승인했어요', 기존 완료 일러스트·확인 버튼.
- 반려 사유는 find1Options 사진 조회 응답의 photo.rejectionReason을 표시 모델의 reason으로 전달한다.
  결석 사유는 현재 API에 없으므로 사진 반려 사유를 결석 사유로 대신 사용하지 않는다.
  개발 미리보기 사유는 fixture이며 실제 API 공급은 5단계 홈 연결에서 적용한다.
- 과거 세션은 이름·날짜를 함께 표시한다. 반려 사유가 null이면 사유 영역을 생략하고 긴 사유는
  줄바꿈한다. 화면보다 긴 내용은 시트 안에서 스크롤하며 버튼에 접근할 수 있게 한다.
- 확인은 닫기, 재업로드·문의는 닫은 후 해당 흐름으로 이동한다. 재업로드 후 사진 선택을
  취소해도 기존 반려 모달을 다시 보여주기 위해 표시 이력을 삭제하지 않는다.
