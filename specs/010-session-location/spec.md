# 기능 명세: 세션 장소 검색과 위치 설정

**브랜치**: `DongjaJ/3gx63`
**작성일**: 2026-10-23
**상태**: 1-4 리뷰 대기
**이슈**: [#88](https://github.com/YAPP-admin/yapp-plus-frontend/issues/88)
**입력**: 운영진이 세션 생성·수정 시 유형에 맞는 장소를 입력하고 오프라인 기준 위치를 확인·조정한다.

## 사용자 시나리오와 검증

### US1 — 장소를 지정한 세션 생성 (P1)

운영진이 오프라인 또는 팀 세션의 장소를 입력해 일정을 추가한다. 새로운 일정 등록의 최소 기능이므로 우선한다.
독립 검증: 빈 목록에서 두 유형을 각각 생성하고 목록에 장소가 표시되는지 확인한다.

1. 오프라인을 선택하고 주소를 검색하면 10개씩 결과와 페이지 이동을 제공한다. 새 검색은 첫 페이지부터 시작한다.
2. 주소 선택 후 기준 위치를 확인하고 마커 드래그로 조정한다. 위도·경도는 읽기 전용으로 표시하고 초기 위치 복귀를 제공한다. 상세주소 없이도 저장 가능하다.
3. 팀 세션은 안내 문구만 선택 입력한다. 비워 저장하면 목록에는 `팀별 자율 장소`가 표시된다.
4. 저장 성공 시 전체 필터로 전환하고 새 세션·개수를 반영한다. 실패하면 입력을 유지하고 재시도를 제공한다.
5. 조회 중·빈 결과·오류를 구분하고, 이전 검색이나 주소의 늦은 결과가 현재 입력을 덮어쓰지 않는다.

### US2 — 저장한 세션 장소 수정 (P2)

운영진이 저장한 주소와 조정 위치를 다시 확인하고 수정한다. 기존 일정의 정확성을 유지한다.
독립 검증: 생성 기능을 실행하지 않고 예시 세션의 세션 정보 메뉴에서 수정·저장·취소한다.

1. 저장된 유형·주소·상세주소·최종 좌표 또는 팀 안내를 복원한다. 재조회로 저장 위치를 바꾸지 않는다.
2. 다른 주소를 선택하면 이전 상세주소·좌표를 초기화한다. 같은 주소 재클릭은 입력을 지우지 않는다.
3. 유형 왕복 전환 시 같은 폼의 초안을 보존하되 현재 유형의 정보만 저장한다.
4. 수정 성공 시 식별자·출석 집계를 보존하고 현재 필터·정렬·개수를 갱신한다.
5. 취소 후 다시 열면 마지막 저장값을 표시한다. 없는 수정 대상은 오류로 안내한다.

### 경계 조건

[입력 정책](location-policy.md)의 LP-01~~11과 [상태 정책](state-policy.md)의 ST-01~~15를 수용 기준으로 포함한다.
지도 실패와 좌표 조회 실패를 구분한다. 유효한 저장 좌표가 있으면 지도 없이도 수정 저장할 수 있지만,
새 주소의 좌표 조회가 실패하면 저장하지 않는다.
좁은 화면, 긴 장소, 검색 중 폼 닫기, 유형 변경, 중복 제출과 수정 후 카드가 필터에서 사라지는 경우를 검증한다.

## 요구사항

### 기능 요구사항

- **FR-001**: US1의 주소 검색·10개 단위 페이지 이동·선택과 상세주소 입력을 제공한다.
- **FR-002**: 오프라인은 도로명주소와 유효 기준 좌표를 필수로 받으며, 조회 완료 뒤 위치 조정과 초기 위치 복귀를 제공한다.
- **FR-003**: 팀 안내는 선택 입력이고 미입력 대체 문구는 저장값과 구분한다.
- **FR-004**: US2의 저장값 복원·주소 변경·유형 전환·취소 정책을 따른다.
- **FR-005**: 검색·좌표·지도·저장의 진행·실패·재시도를 구분하고 늦은 응답과 중복 저장을 차단한다.
- **FR-006**: 기존 세션명·한국 시간의 같은 날 일정·종료가 시작보다 늦어야 하는 검증과 생성·수정 후 목록 정책을 유지한다.
- **FR-007**: 키보드·보조 기술·터치로 생성·수정할 수 있고 오류 안내 및 모달 포커스 복귀를 제공한다.
- **FR-008**: 개발용 저장 결과는 화면 이동 후 유지하고 새로고침하면 초기화한다. 운영 환경에서 모의 편집을 제공하지 않는다.
- **FR-009**: 목록의 로딩·오류·재시도·전체 빈 상태·필터 빈 상태를 구분한다.

### 주요 개념

- **세션**: 식별자·유형·이름·일정·유형별 장소·출석 집계를 가진다.
- **오프라인 장소**: 선택 주소·선택 상세주소·최종 기준 위치를 가진다.
- **팀 장소 안내**: 선택 문구이며 주소나 좌표가 아니다.
- **편집 초안**: 열린 폼에만 존재하고 취소하면 폐기하는 입력이다.

## 성공 기준

- **SC-001**: 두 유형 모두 생성과 수정 후 장소가 목록·재진입 폼에 일치한다.
- **SC-002**: LP-01~~11 및 ST-01~~15의 모든 시나리오에서 기대 결과를 충족한다.
- **SC-003**: 실패·취소·지연 응답으로 잘못된 주소·좌표 조합이 저장되는 사례가 없다.
- **SC-004**: 키보드와 터치 각각으로 두 유형의 생성·수정을 완료하고 오류·진행 안내를 보조 기술로 확인한다.

## 가정과 범위

- 대상은 관리자 운영진이며 실제 주소 조회·지도 확인과 개발용 세션 저장까지 제공한다.
- 주소 서비스·지도 사용을 위한 키와 도메인 설정은 후속 2단계에서 준비한다. 발급 완료를 가정하지 않는다.
- 삭제 UI, 실제 세션 서버 저장, 인증·권한·배포 변경, 출석 반경·GPS 판정, 회원 앱 지도 연결은 제외한다.
- 기존 008의 승계 관계는 [연결 문서](predecessor.md)를 따른다. 기존 삭제 작업까지 완료했다고 처리하지 않는다.
- 각 세부 단계 종료 시 보고하고 사용자 리뷰와 다음 진행 지시를 기다린다.
