# 데이터 모델과 수명

## 주간 세션 — 서버 소유 (US1·US2·US3)

기존 생성 DTO와 `pages/home/model/current-week-schema.ts` 검증을 사용한다.
세션은 `null`일 수 있고, 존재하면 `id`, `name`, `date`, `startTime`, nullable `location`, `attendanceStatus`를 갖는다.
주소·좌표 등 기존 정규 출석 필드는 유지한다. 새로운 상태는 생성 enum에 이미 포함돼 있다.
`type`·`endTime`은 현재 주간 DTO에 없는 미래 계약이며 임의 타입 확장으로 넣지 않는다.

## 홈 표시 정책 — 응답에서 파생 (US1)

입력은 세션, 조회 상태, 팀 운영 연결 가능 여부다. 세션이 있으면 `location === null`로 임시 유형을 구한다.
출력은 상태 문구·행동·비활성화 이유다. 별도 저장하지 않고 [상태 표](contracts/attendance-flow.md)로 계산한다.
조회 중·실패·paused는 행동을 차단한다. 주차·계정 변경 시 다른 세션의 성공 이력을 섞지 않는다.

## 회원 제출 대상 — 조회 경계에서 검증 (US3)

현재 내부 요구 형태는 다음과 같다. 이는 서버의 신규 응답 형태를 확정한 것이 아니다.

| 필드                         | 의미·검증                                                 |
| ---------------------------- | --------------------------------------------------------- |
| `sessionId`                  | 현재 선택한 주간 세션과 일치하는 양의 ID                  |
| `teamName`                   | 표시 가능한 팀 이름                                       |
| `selfMembershipId`           | 현재 기수 본인의 멤버십 ID, 팀원 목록에 정확히 한 번 존재 |
| `members`                    | 비어 있지 않고 `membershipId`가 중복되지 않는 목록        |
| 팀원 `membershipId`          | 제출에 사용할 멤버십 ID. 사용자 ID로 대체 금지            |
| 팀원 `name`, `positionLabel` | 현재 제출 대상 스키마가 요구하는 표시 정보                |

API의 직군 필드가 nullable 등 다른 형태면 변환 정책을 계약 확인 단계에서 결정한다.
조회 결과의 계정·세션이 바뀌면 기존 선택 상태를 재사용하지 않는다.

## 사진 임시 상태 — 한 흐름 소유 (US3)

선택 소스, JPEG Blob·미리보기 URL, 선택한 멤버십 ID, 선택·업로드·제출 진행 상태를 메모리에 둔다.
본인은 기본 선택·해제 불가다. 최초 선택 취소는 안내, 교체 취소·실패는 기존 사진·참석자 유지다.
사진 교체 시 이전 URL, 흐름 종료 시 전체 URL과 진행 요청을 정리한다. 늦은 네이티브 응답은 종료된 흐름에 반영하지 않는다.

## 접수 결과 — 제출 성공부터 흐름 종료까지 (US3)

기존 접수 모델의 `photoId`, `submittedAt`, `PENDING_APPROVAL`, 팀·참석자 정보를 사용한다.
접수 완료 화면은 이 결과로 열며 새로고침·직접 URL 진입으로 접수 결과를 복원하지 않는다.
이 결과가 홈의 출석 상태를 덮어쓰지 않는다. 운영진 승인 후의 `CHECKED_IN`은 다음 주간 조회로 확인한다.

## 전이

- 정규: 서버 `AVAILABLE` → 코드 성공 → 로컬 완료 화면 → 주간 재조회 상태 표시.
- 팀: 서버 `AVAILABLE` + 계약 준비 → 안내 → 사진·참석자 → 업로드·제출 → 접수 완료 → 주간 재조회.
- 서버가 `PENDING_APPROVAL` 또는 `CHECKED_IN`을 반환하면 신규 진입을 막는다.
- 서버가 다시 `AVAILABLE`이면 일반 진입을 허용한다. 반려·승인 이벤트를 클라이언트에서 합성하지 않는다.
