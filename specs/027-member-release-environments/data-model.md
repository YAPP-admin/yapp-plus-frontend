# 배포 개념과 상태

업무 데이터 스키마·DB는 추가하지 않는다. 이 문서는 [배포 계약](contracts/delivery.md)의 실행 정보를 정의한다.

## 환경

배포 대상 환경은 `development | production`이다. 로컬 Metro의 실행 모드와 별개다.
각 환경은 웹 URL, API URL, OAuth 공개 식별자, Firebase 프로젝트, EAS 환경·채널의 조합이다.
이 값들은 검증된 공급 경로로 읽으며 비밀을 배포 기록에 복사하지 않는다.

## 릴리스 후보

- 필드: 실행 종류(main/tag/manual), 소스 SHA, 환경, 선택한 태그(운영), CI 실행 ID.
- 운영 태그는 main에 포함된 정확한 commit으로 해석하고 성공한 push CI와 연결한다.
- 태그의 버전, 앱 표시 버전, IPA build number, OTA runtime은 서로 다른 식별자다.
- 입력 → 출처 검증 → 영향 판정 → 실행/생략 → 대상별 결과 기록 순서로 처리한다.

## 대상별 성공 기록

키는 대상(web/mobile)과 환경이다. 웹은 GitHub Deployment 성공 상태·ref/SHA·Vercel ID/URL을
조회하고 모바일은 선택한 EAS 채널의 실제 branch에서 마지막 iOS 게시 SHA·group·runtime을 조회한다.
GitHub 모바일 결과는 요약이며 EAS 원본을 대체하는 두 번째 활성화 기준으로 사용하지 않는다.

- `기록 없음`: 최초 게시로 전체 대상 실행.
- `조회 오류`: 환경별 오류 계약 적용. 성공 기록이 없다고 추정하지 않는다.
- `정상 기록`: source SHA부터 후보까지 비교. 실패·생략은 성공 기준을 이동시키지 않는다.
- `실행 성공`: 외부 결과 확인 후 성공 기준 갱신. 웹은 개발 alias 연결도 성공해야 한다.
- `기록 실패`: 외부 결과를 수동 대조한 후 재실행/복구한다. 자동 멱등성 저장소는 추가하지 않는다.
- `복구`: 정상 산출물의 원래 source SHA를 기록한다. 복구 이후 자동 배포는 명시적으로 재개한다.

## IPA 출처

기존 artifact에 환경·프로필·SHA·앱 버전·runtime·build number·run ID·attempt·checksum을 연결한다.
제출은 선택한 artifact의 성공 빌드 출처와 환경·checksum을 검증하며 `--latest`로 추정하지 않는다.
생성 → 업로드 → TestFlight 사용 가능 → 실기기 검증 → 정식 출시는 별도 확인 단계다.

## 세션과 알림

세션 저장 키는 환경별로 분리하고 기존 세션 데이터 형식은 유지한다. 환경 없는 구형 키는 삭제하며
새 환경 키로 복제하지 않는다. 같은 환경으로 돌아오면 그 환경의 저장된 세션만 복원한다.
알림 수신 선택은 기존 Firebase project ID와 FID 조합을 유지한다. OS 알림 권한은 앱 설치에
속하므로 환경별 서버 등록·사용자 선택과 구분하고 실제 push 수신으로 환경 일치를 검증한다.
