# 기능 명세: 회원 코드 출석과 사전 출결 보고

**브랜치**: `DongjaJ/7al70` | **작성일**: 2026-11-08 | **상태**: 1단계 코드 출석 구조 수정 완료 · 리뷰 대기 · [#385](https://github.com/YAPP-admin/yapp-plus-frontend/issues/385)
**입력**: Android develop의 오늘 커밋을 제외한 구현 범위로 코드 출석과 사전 출결 보고를 연결한다.

## 사용자 시나리오와 검증

### US1 — 세션 출석하기 (P1)

회원은 출석 가능 상태인 세션에 4자리 코드를 제출하고 실제 검증 결과를 확인한다.
핵심 사용 목적이므로 먼저 구현한다. 독립 검증은 홈에서 코드 입력·성공·오류·복귀까지다.

1. 출석 대상과 가능 여부에 맞는 버튼·안내를 표시한다. 불가능한 상태에서는 제출할 수 없다.
2. 숫자 4자리를 입력하거나 붙여넣고 제출한다. 앞자리 0을 포함한 코드를 입력할 수 있다.
3. 서버가 출석을 확인한 경우에만 완료 화면을 표시하고 홈으로 돌아와 해당 세션의 완료 상태를 본다.
4. 잘못된 코드나 일시적 실패는 완료로 바뀌지 않으며 입력을 수정하거나 다시 시도할 수 있다.

### US2 — 사전 출결 보고하기 (P2)

회원은 지각·조퇴·결석을 선택하고 선택적 사유를 제출한다.
독립 검증은 출석하지 않은 상태에서 세 종류 보고의 성공·실패를 각각 확인하는 것이다.

1. 유형을 선택한 뒤 최대 30자의 사유를 입력한다. 사유를 비워도 제출할 수 있다.
2. 서버가 제출을 확인하면 입력창을 닫고 보고 완료 안내를 표시한다.
3. 자격 없음·대상 없음·보고 불가·대상 변경은 구분해 안내한다. 대상이 바뀌면 최신 내용을 확인하고 수동으로 다시 제출한다.

### 경계 조건

- 연속 클릭, 붙여넣기·백스페이스, 30자 경계와 이모지, 통신 단절·응답 유실.
- 출석 가능 상태 변경, 주간 경계, 직접 URL 진입, 입력 중 뒤로가기, 숨겨진 화면으로 늦게 도착한 결과.
- 인증 만료, 로그아웃·다른 계정 로그인, 제출 성공 뒤 조회 갱신 실패.

## 요구사항

- **FR-001**: 실제 로그인한 회원이 출석·보고를 제출한다. 일반 브라우저에서 실제 인증을 새로 제공하지 않는다.
- **FR-002**: 출석 가능 여부는 서버가 정하며, 클라이언트가 출석 시간·점수를 계산하지 않는다.
- **FR-003**: 코드 네 자리와 보고 유형·선택적 사유를 검증하고, 유효한 서버 성공 확인 전 완료를 표시하지 않는다.
- **FR-004**: 제출 중 중복과 시트 닫기를 막고 진행 상태를 안내한다. 연결 복귀나 인증 복구만으로 제출을 자동 재실행하지 않는다.
- **FR-005**: 완료 상태는 제출한 계정에 한정하고 오류·입력·화면 이동은 현재 화면에 한정한다. 입력값을 URL·영구 저장소·로그에 남기지 않는다.
- **FR-006**: 홈의 출석 완료 표시는 현재 앱 화면 수명의 확인 결과이며 재시작 후 영구 복원을 보장하지 않는다.
- **FR-007**: 보고 가능 시각·대상 선택·최종 출석 결과·점수는 서버 결과를 따른다. 보고 취소·이력 UI를 추가하지 않는다.
- **FR-008**: 키보드·스크린 리더·터치로 입력·오류 수정·완료·복귀가 가능해야 한다.

### 주요 개체

- 출석 대상: 세션 식별자, 일정, 출석 가능 상태.
- 출석 확인: 해당 계정과 세션에 대한 성공 확인 및 확인 시각.
- 출결 보고: 지각·조퇴·결석 유형, 선택적 사유, 서버가 선택한 세션과 제출 시각.

## 성공 기준

- **SC-001**: 가능한 상태에서만 코드 제출에 진입하고 정상·잘못된 코드·서버 실패 사례가 모두 기대 결과와 일치한다.
- **SC-002**: 세 보고 유형 모두 빈 사유·길이 경계·서버 실패를 구분하며 실패를 성공으로 안내하지 않는다.
- **SC-003**: 연속 클릭·통신 복귀에 의한 의도치 않은 중복 제출과 다른 계정에 반영되는 늦은 결과가 없다.
- **SC-004**: 두 사용자 흐름의 자동 검증·접근성 확인·실기기 확인 결과와 미실행 항목을 별도로 기록한다.

## 가정과 제외 범위

- 비교 기준은 Android `2b837e3c`다. 11월 8일 한국 시간의 팀 사진 UI 두 커밋은 제외한다. 이 커밋이 심사 바이너리와 동일하다고 주장하지 않는다.
- 기존 화면·인증을 재사용한다. 공지 작업 세션, 팀 사진·푸시·알림·프로필·관리자 기능은 제외한다.
- 출석 완료의 수명은 Android와 같이 비영구 상태다. 새 조회 계약을 만들지 않는다.
- 이슈 생성 및 단계별 리뷰 후 순차 구현한다. 사전 출결 보고는 아직 구현하지 않았다.
