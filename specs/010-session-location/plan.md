# 구현 계획: 세션 장소 검색과 위치 설정

**브랜치**: `DongjaJ/3gx63` | **작성일**: 2026-10-23 | **명세**: [spec.md](spec.md)
**상태**: 구현 후 승인된 리뷰 결정 반영. 단계별 실행·미검증 기록은 [quickstart.md](quickstart.md)를 따른다.

## 요약

행안부 주소 검색과 좌표 조회를 브라우저에서 수행하고 `proj4`로 변환한 좌표를 카카오 지도에서 조정한다.
생성·수정 공통 폼과 브라우저 메모리 저장소를 연결한다. 기존 문자열 장소는 유형별 구조로 함께 전환한다.

## 기술 맥락

- TypeScript·React 19, TanStack Start/Router/Query/Form, Zod, SEED, vanilla-extract를 기존 구성대로 사용한다.
- Node.js 24.20.0·pnpm 12.3.4. 새 외부 의존성은 `proj4`, `react-kakao-maps-sdk`이며 설치 단계에서 정확한 버전·타입 의존성과 공급망 정책을 확인하고 catalog에 고정한다.
- 사용자 승인에 따라 개발·배포 모두 예시 데이터를 사용하며 저장은 각 브라우저 메모리뿐이다. SSR에서는 저장소에 접근하지 않는다. 실제 세션 API·공용 패키지·브리지는 변경하지 않는다.
- Vitest·Testing Library로 경계와 상태를 검증하고 실제 키와 브라우저로 외부 연동을 검증한다.
- 성능 범위: 입력 300ms 중지 후 자동 검색·페이지 이동 즉시 조회, 페이지당 10개, 중복 요청 차단, 자동 무한 재시도 없음. 검증되지 않은 응답 시간 목표를 제시하지 않는다.
- JSON 조회는 요청당 10초 후 실패로 처리한다. 이 값은 서비스 보장이 아닌 클라이언트 초기 설정이다.

## 구조

문서는 이 디렉터리의 spec/plan/research/data-model/quickstart/tasks와 contracts에 둔다.
앱 파일은 `apps/admin/src/pages/sessions/` 아래에 둔다.

- `model/session.ts`, `sessions.mock.ts`, `sessions.ts`, `session-queries.ts`: 스키마·저장·조회/Mutation.
- `model/location/`: 환경 변수, JSON 전송, Juso DTO 검증·ViewModel 매핑, 좌표 변환과 요청 수명. 단일 소비자이므로 공용 패키지로 옮기지 않는다.
- `ui/session-form.tsx`: 생성·수정 공통 폼, 유형별 임시 입력·최종 좌표의 소유자.
- `ui/address-search.tsx`, `ui/session-location-map.tsx`: 검색과 지도 입력. 좌표는 props로 받아 변경을 상위 폼에 전달한다.
- 기존 `sessions-page.tsx`, `session-card.tsx`, `session-list.tsx`: 진입점·목록 상태·표시.
- 테스트는 해당 파일 옆에 둔다. 재사용 UI를 변경하면 해당 Storybook 사례도 함께 추가한다.

## 복구와 미검증 사항

주소 검색·좌표 조회·지도 표시의 기존 실제 환경 검증은 quickstart에 기록한다. 이 문서 정리는 신규 외부 검증이 아니다.
지도 실패는 SDK 상태를 따르며 새로고침을 안내한다. 미저장 입력 유실 가능성을 안내하고 별도 로더·재시도 정책을 추가하지 않는다.
2-5와 3단계에서 실패하면 해당 단계에서 멈추고 근거를 기록한다. 다른 공급자나 서버 프록시로 임의 전환하지 않는다.
저장 오류를 성공처럼 반영하지 않고 모의 저장소 변경은 검증 후 원자적으로 적용한다.

## 리뷰 반영: Overlay Kit 도입

어드민의 명령형 모달 진입점은 `overlay.open`과 완료·취소 콜백으로 통일한다.
화면은 SEED를 유지하고, TanStack Form·Mutation의 입력·저장 상태는 모달 내부에서 관리한다.
`openAsync`, 별도 포커스 관리, 종료 애니메이션 타이머, 범용 모달 레지스트리는 추가하지 않는다.
닫기는 `unmount`로 즉시 제거하여 현재 조건부 렌더링과 같은 초안 폐기 동작을 유지한다.
Provider는 Query·Router 아래 대시보드 콘텐츠에 두며 pathname 변경 시 재생성한다.
검색 조건 변경은 같은 페이지로 취급하여 Provider를 유지한다.

1. **O1 기반**: catalog 의존성·Provider, SEED 연동과 컨텍스트·닫기·페이지 이동 검증.
2. **O2 세션 모달**: 생성·수정 상태와 조건부 JSX를 open 호출로 전환. Snackbar를 모달에서도 사용할 수 있는 위치로 이동.
3. **O3 일정 선택창**: 선택 초안을 모달에 두고 확인 콜백으로 값 전달. 중첩 모달·취소·재진입 검증.

각 단계는 사용자 리뷰 후 다음 단계로 진행한다. 첫 소비자는 admin이므로 공용 패키지로 추출하지 않는다.
문제가 생기면 Provider 연결·의존성을 제거하고 기존 모달 호출을 유지한다. 데이터 계약 변경은 없다.
