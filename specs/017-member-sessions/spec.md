# 기능 명세: 회원용 세션 확인

**브랜치**: `DongjaJ/nsu85` · **작성일**: 2026-11-05 · **상태**: 범위 축소 리뷰 대기

**입력**: 회원용 홈·일정 조회 API 연결 및 로그아웃·계정 전환 시 전체 캐시 초기화.
작업 이슈: [#328](https://github.com/YAPP-admin/yapp-plus-frontend/issues/328).

## 구현 범위 조정 — 2026-11-06

사용자 리뷰에 따라 이 작업은 홈·일정 조회와 화면 상태에 집중한다.
인증 provider·mutation·Stackflow 전환 구조는 기존 구현을 사용한다.
인증 전환, 늦은 인증 응답 차단, 화면 수명과 앱 복귀 세션 복구는 인증 작업 #329와의 연동 대상으로 분리한다.
main의 #329 통합 기준으로 로그아웃·탈퇴·계정 변경 시 모든 업무 query·mutation을 제거한다.
인증 제어 query와 진행 중 인증 mutation은 수명 관리를 위해 유지한다. 이를 queryClient.clear()로
전체 항목을 제거한 것으로 표현하지 않는다. 계정 전환·늦은 갱신 폐기는 자동 통합 검증을 마쳤으며
실제 WebView 검증은 별도로 남아 있다.
같은 로그인 세션의 토큰 갱신에서는 데이터를 유지한다. 출시 전 계정 격리 검증은 필수다.
이 절이 아래의 이전 인증 구현 제안보다 우선하며, 전환 세대·상태 소유 방식은 여기서 새로 설계하지 않는다.

## 사용자 시나리오와 검증

### US1 — 계정 전환 후 내 정보만 확인한다 (P1)

회원은 로그아웃하거나 다른 계정으로 로그인했을 때 이전 사용자의 화면과 임시 데이터가 남지 않기를 기대한다.
인증 작업에서 구현하고 출시 전에 통합 검증해야 하는 경계다. 독립 검증은 임의의 캐시와 지연 요청을 주입한 계정 전환이다.

1. A 계정의 화면을 열고 로그아웃을 완료하면 이전 데이터와 입력 상태가 제거되고 로그인 화면으로 이동한다.
2. B 계정으로 전환하거나 같은 계정으로 새 로그인 세션을 만들면 이전 로그인에서 보관한 데이터를 재사용하지 않는다.
3. 전환 전 요청이 나중에 끝나도 이전 결과·성공 안내·화면 이동을 새 로그인에 반영하지 않는다.
4. 로그인 취소 또는 실패한 로그아웃만으로 현재 사용자의 데이터를 지우지 않는다. 탈퇴 완료는 로그아웃처럼 정리한다.

### US2 — 인증이 갱신되어도 조회를 계속한다 (P1)

회원은 같은 로그인 상태의 인증 자격 갱신 때문에 모든 화면 데이터를 다시 불러오지 않는다.
독립 검증은 만료된 인증으로 조회를 시작하고 네이티브 갱신 결과를 주입하는 시나리오다.

1. 인증 만료 조회는 네이티브에 갱신을 요청하고 같은 로그인에 한해 한 번 다시 조회한다.
2. 갱신 중 로그아웃·계정 전환이 일어나면 이전 요청을 새 계정으로 재전송하지 않는다.
3. 같은 로그인 세션의 인증 자격만 갱신되면 다른 화면의 데이터는 유지한다.
4. 갱신 실패나 접근 권한 부족을 빈 일정으로 안내하지 않고 복구 가능한 오류로 표시한다.

### US3 — 현재 활동 기수 전체 일정을 확인한다 (P1)

회원은 일정 탭에서 세션명·장소·일시를 확인해 활동을 준비한다. 독립 검증은 일정 탭 직접 진입이다.

1. 현재 활동 기수의 일정을 서버가 제공한 순서로 표시하며 로그인 회원의 소속 기수로 다시 필터링하지 않는다.
2. 정규 세션에 종류 칩을 표시하고, 장소가 없으면 `-`를 표시한다.
3. 조회 성공 시각을 한국 시간 기준 종료 시각과 비교해 지난 일정으로 흐리게 표시한다. 시간 경과만으로 화면을 갱신하는 타이머는 두지 않는다.
4. 빈 목록은 `등록된 세션 일정이 없어요`로 안내한다. 조회 실패에는 다시 시도를 제공한다.
5. 재조회에 실패해도 이미 확인한 목록은 유지하고 갱신 실패를 별도로 안내한다.

### US4 — 홈에서 이번 주 세션을 확인한다 (P1)

회원은 홈에서 이번 주 세션과 주간 달력을 확인하고 전체 일정으로 이동한다. 독립 검증은 홈 직접 진입이다.

1. 이번 주 조회 결과의 세션명·장소·주간 범위·세션 날짜를 표시한다.
2. 당일에는 `오늘은 …`, 그 외에는 `이번 주는 …`로 안내하고, 장소가 없으면 `이번 주 세션`을 표시한다.
3. 세션이 없으면 `이번 주 예정된 세션이 없어요`로 안내한다. 카드 오류가 다른 홈 영역을 가리지 않는다.
4. 전체 세션 바로가기로 일정 탭에 이동한다. 홈은 세션 종류나 출석 완료를 추측하지 않는다.
5. 실서비스에서 미연동 출석·팀 인증·사전 출결보고를 실행해 성공 화면으로 이동할 수 없다.

### 경계 사례

- 자정·월말·연말, 해외 기기의 시간대, 종료 시각 직전·정각·직후, 분이 포함된 일정.
- 빈 응답과 잘못된 응답의 구분, 오프라인과 재연결, 기존 데이터가 있는 재조회 실패.
- 두 화면의 동시 인증 만료, 늦은 인증 갱신 결과, 로그아웃 도중 끝나는 조회·작업.
- 숨겨진 탭 복귀, 앱 복귀 중 계정 변경, 주소 직접 진입과 이전 화면 복원.

### 주요 개체

- 이번 주 일정: 주간 시작·종료 날짜와 선택적인 세션, 출석 가능 상태.
- 기수 일정: 현재 활동 기수 식별 정보와 순서가 있는 세션 목록.
- 로그인 세션: 사용자·로그인 식별자와 갱신 가능한 인증 자격. 활동 세션과 구분한다.
- 화면 조회 상태: 준비·조회 중·내용·빈 결과·오류 및 기존 내용의 갱신 상태.

## 성공 기준

- SC-01: 정상·빈 결과·실패·복구의 모든 홈·일정 수용 시나리오가 통과한다.
- SC-02: 계정 전환·로그아웃 후 이전 계정의 데이터·입력·성공 안내가 노출되는 검증 사례가 0건이다.
- SC-03: 같은 로그인 세션의 인증 갱신으로 다른 화면 데이터가 초기화되는 사례가 0건이다.
- SC-04: 한국 시간 경계와 분 단위 표기 시나리오가 기기 시간대에 관계없이 동일한 결과를 낸다.
- SC-05: 실서비스에서 모의 출석·보고 완료로 진입하는 검증 사례가 0건이다.

## 전제와 제외 범위

- 실제 대상은 로그인된 WebView이며 일반 브라우저의 로그인 연결은 제외한다.
- 현재 디자인과 Android 조회 구조를 따르되 기기 시간대 사용과 분 생략은 따르지 않는다.
- 출석·팀 인증·사전 출결보고 제출, 공지 연결, 월간 목록·D-day·지도·세션 상세는 제외한다.
- 네이티브 인증·갱신 기능과 서버의 기존 조회 계약을 사용한다. 실제 앱·서버 검증은 별도 증거가 필요하다.
- 자동 회귀 테스트와 실제 화면 검증을 요구하며 완료 여부는 [검증 기록](validation.md)에서 구분한다.
