# 기능 명세: 어드민 출석 관리

**브랜치**: `tallinn/xoaj3` · **작성일**: 2026-10-29 · **상태**: 0단계 리뷰 후 1단계 진행 승인

**이슈**: [#180](https://github.com/YAPP-admin/yapp-plus-frontend/issues/180)

[제품 맥락](../../docs/mission.md)과 사용자 합의를 기준으로 운영진의 출석 관리 흐름을 정의한다.
이번 구현은 상태가 유지되는 모의 데이터로 화면과 동작을 완성한다. 실제 서버 연결은 후속 범위다.
0단계 산출물은 문서이며, 아래 기능의 구현 완료를 의미하지 않는다.

## 사용자 시나리오와 수용 조건

### 1. 세션 출결 조회와 수정 (P1)

운영진은 세션별 명단, 사전 보고, 실제 출결과 명찰 확인 여부를 각각 파악한다.
독립 검증: 일반 세션에서 조회·필터·수정·이탈 경고를 확인한다.

1. 세션이 생성되면 대상 회원의 출석이 자동 준비되고, 출석 코드 발급 전에도 명단을 조회한다.
2. 사전 보고가 지각이어도 실제 출결은 출석일 수 있다. 보고 유형을 바꿔 실제 출결을 수정하지 않는다.
3. 미정·출석·지각·조퇴·결석 중 하나를 선택하고, 필요한 시간 구간과 일반/무단 구분을 수정한다.
4. 명찰 확인만 변경하면 출결과 점수가 바뀌지 않는다.
5. 미반영 변경을 가진 채 화면을 나가려 하면 계속 편집하거나 변경을 버리고 이동할 수 있다.

### 2. 출석 마감과 취소 (P1)

운영진은 변경 내용을 확인하고 한 번의 출석 마감으로 세션 결과를 확정한다.
독립 검증: 필터에 숨겨진 회원을 포함한 명단으로 마감과 취소를 수행한다.

1. ‘출석 마감’을 누르면 변경 반영과 마감을 수행한다. 별도의 ‘저장’이나 2차 최종 마감은 없다.
2. 남은 미정은 전체 명단에서 결석으로 바뀐다. 적격 사전 결석 보고는 일반 결석, 나머지는 무단 결석이다.
3. 운영진이 명시적으로 지정한 출결은 유지한다. 완료 후 편집을 잠근다.
4. ‘마감 취소’는 모의 구현에서 결과·점수를 유지한 채 편집을 다시 허용한다.
5. 일부 변경 반영 후 마감이 실패하면 반영된 변경과 마감 실패를 구분해 알리고 재시도할 수 있다.

### 3. 팀 사진 검수 (P1)

운영진은 미제출과 검수 대기를 구분하고 사진을 연속으로 검수한다.
독립 검증: 미제출·검수 대기·승인·반려 팀을 포함한 세션으로 판단과 마감을 확인한다.

1. 제출된 사진은 검수 대기로 표시하며 승인 또는 반려할 수 있다.
2. 사진을 볼 수 없어도 제출 사실은 유지한다. 검수 대기를 미제출로 바꾸지 않는다.
3. 팀 승인으로 회원의 명시적인 개별 지각·결석 결정을 덮어쓰지 않는다.
4. 모의 구현은 검수 대기가 남으면 마감을 막는다. 판단 초안은 마감 전에 반영한다.
5. 마감 도중 새로운 검수 대기가 발견되면 목록을 갱신하고 재검수를 안내한다.

### 4. 출결 근거와 누적 점수 조회 (P2)

운영진은 보고·변경 이력과 회원별 누적 점수의 근거를 확인한다.
독립 검증: 보고 이력, 회원 상세, 누적 점수를 고정된 시나리오와 비교한다.

1. 보고 유형은 지각·조퇴·결석만 제공하며, 실제 출결 이력과 분리해서 보여준다.
2. 초기 100점에서 출결과 기타 조정 내역이 반영된 합계를 확인한다.
3. 40점 미만만 경고한다. 결석 횟수 10회 기준은 추가하지 않는다.
4. 공결 상세 정책과 편집, 회비·면제 관리 화면은 이번 범위에서 제외한다.

## 경계 상황

- 빈 명단, 검색 결과 없음, 로딩, 조회 실패, 알 수 없는 세션을 구분한다.
- 부분 조회된 명단만으로 전체 인원·점수를 확정하거나 마감하지 않는다.
- 마감 중 중복 클릭을 막고, 실패한 작업만 재시도할 수 있도록 초안을 보존한다.
- 출석 코드 없음·만료·재발급을 구분한다. 목록 조회나 세션 생성으로 코드를 자동 발급하지 않는다.
- 사진 접근 실패·만료와 미제출을 구분하고, 재조회 실패가 승인으로 처리되지 않게 한다.
- 보고 시점이나 점수 근거가 없으면 임의로 일반/무단 여부를 추론하지 않는다.

## 기능 요구사항

| 식별자 | 요구사항                                               | 수용 근거    |
| ------ | ------------------------------------------------------ | ------------ |
| FR-01  | 세션 목록과 일반/팀 세션 출석 상세를 제공한다.         | 시나리오 1·3 |
| FR-02  | 사전 보고, 출결 상태, 명찰 여부를 독립적으로 표시한다. | 시나리오 1·4 |
| FR-03  | 출결 수정 초안과 이탈 확인을 제공한다.                 | 시나리오 1   |
| FR-04  | 마감 시 전체 명단의 미정을 결석으로 전환한다.          | 시나리오 2   |
| FR-05  | 마감 후 잠금, 취소 후 편집 재개를 제공한다.            | 시나리오 2   |
| FR-06  | 사진 검수와 미제출/검수 대기를 구분한다.               | 시나리오 3   |
| FR-07  | 누적 점수와 근거를 조회하고 40점 미만을 경고한다.      | 시나리오 4   |
| FR-08  | 명시적인 동작으로 출석 코드를 발급·재발급한다.         | 경계 상황    |
| FR-09  | 부분 실패를 구분하고 중복 반영 없이 재시도한다.        | 시나리오 2·3 |

### 점수 기준

| 출결                            | 일반 | 무단      |
| ------------------------------- | ---- | --------- |
| 출석                            | 0    | 해당 없음 |
| 지각·조퇴 1시간 이내            | -4   | -10       |
| 지각·조퇴 1시간 초과 3시간 이내 | -8   | -14       |
| 결석                            | -12  | -20       |

초기 점수는 100점이며 회비 지연은 일당 -5점의 읽기 전용 조정 내역으로 다룬다.
사전 보고와 실제 결과가 달랐다는 이유로 추가 감점하지 않는다.
지각과 조퇴의 동시 편집은 이번 단계에 넣지 않는다. 공결을 일반 결석으로 치환하지 않는다.

### 핵심 개체

- 세션: 기수, 일정, 일반/팀 구분, 마감 여부, 전체 출결 요약.
- 출석: 회원, 실제 출결, 감점 근거, 명찰 확인, 운영진 수정 여부.
- 사전 보고: 회원, 유형, 사유, 보고 시각과 정책상 적격 여부.
- 팀 사진: 제출 사실, 검수 상태, 사진 접근 가능 여부, 대상 회원과 검수 판단.
- 점수 내역: 회원별 출결 기여와 기타 조정, 합계 및 경고 여부.

## 성공 기준

- SC-01: 위 4개 시나리오의 모든 수용 조건을 모의 데이터로 재현할 수 있다.
- SC-02: 마감 후 전체 대상 회원의 미정 인원이 0명이다.
- SC-03: 명찰 확인 전후 출결 및 점수 차이가 0이다.
- SC-04: 검수 대기가 남은 세션의 마감 성공 건수가 0이다.
- SC-05: 합계가 39점이면 경고하고 40점이면 경고하지 않는다.

## 전제와 범위

세션 생성 시 출석 자동 생성은 사용자 전제로 채택한다. 실제 서버의 생성 시점은 별도로 확인한다.
보고 적격성의 정확한 시각 경계는 모의 데이터의 적격 여부로 제공하며 임의로 48시간으로 확정하지 않는다.
마감 취소의 결과 보존과 사진 마감 차단은 [계약 초안](contracts/attendance-api.md)의 적용 상태를 따른다.
서버 연결·인증 변경·회원 앱 변경·공결 정책 확정·관리자 사진 업로드는 제외한다.
다음 단계는 매 단계 리뷰 및 진행 확인 후에만 시작한다.
