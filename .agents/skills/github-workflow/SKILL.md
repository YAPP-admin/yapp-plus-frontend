# GitHub 작업 흐름

이 스킬은 저장소 변경과 GitHub 작업을 이슈에 연결하고, 외부 상태 변경을 사용자가 승인한 범위로
제한합니다.

## 공통 승인 경계

- `git status`, `git diff`, `git log`, `git fetch`, 이슈·PR·CI 조회와 초안 작성은 승인 없이 수행할
  수 있습니다. `git fetch`는 원격 저장소의 상태를 변경하지 않기 때문에 동기화 판단에 사용합니다.
- 파일 수정 요청이나 `진행해`라는 지시는 issue 생성, 브랜치 생성·전환·이름 변경, `git pull`,
  commit, push, PR 변경, CI 재실행, merge, 브랜치 삭제를 승인하지 않습니다.
- issue 생성, 브랜치와 로컬 이력을 바꾸는 작업, commit, push, PR 생성·수정·종료, CI 재실행,
  merge와 브랜치 삭제는 각각 사용자가 명시적으로 승인한 경우에만 수행합니다.
- `커밋하고 푸시해서 PR 작성해`처럼 여러 작업을 명시하면 해당 작업만 묶어서 승인한 것으로
  처리합니다. 빠진 작업이나 후속 작업으로 승인을 확장하지 않습니다.
- `CI가 통과하면 merge해` 같은 조건부 승인은 조건과 대상이 명확할 때만 유효합니다. 조건이
  충족되지 않으면 실행하지 않고 현재 상태를 보고합니다.
- 승인은 한 번만 사용합니다. 실패한 명령의 재시도나 다른 issue·PR·브랜치에는 다시 승인을
  확인합니다.
- 외부 변경 직전에는 대상과 실행할 작업을 짧게 알리고, 완료 후 URL, commit SHA와 결과를
  보고합니다.

## Git 안전 규칙

- 저장소 또는 전역 `git config`를 변경하지 않습니다. 사용자 환경에 지속되는 설정 변경이 필요하면
  이유와 범위를 설명하고 사용자가 직접 결정하도록 합니다.
- `--no-verify` 등으로 Git hook을 우회하지 않습니다. hook 실패 원인을 해결할 수 없다면 변경하지
  않고 보고합니다.
- 대화형 rebase와 대화형 Git 명령은 사용자가 명시적으로 요청하지 않으면 실행하지 않습니다.
- `git reset --hard`, `git clean`, commit 삭제처럼 작업을 복구하기 어려운 명령은 정확한 대상과 손실
  범위를 사용자가 승인한 경우에만 실행합니다.
- `main` 직접 push와 `main` force push는 수행하지 않습니다. 다른 브랜치의 force push도 대상과
  이유를 사용자가 별도로 승인해야 합니다.

## 저장소 변경 시작

애플리케이션, 문서, 설정 또는 자동화를 수정하기 전에 다음 순서를 지킵니다.

1. `git fetch origin` 후 `origin/main`, 현재 브랜치와 작업 트리 상태를 확인합니다.
2. Conductor workspace에서 자동 생성된 브랜치는 사용자가 명시적으로 요청하지 않으면 생성, 전환,
   이름 변경 또는 삭제하지 않습니다.
3. 관련된 열린 issue가 있는지 검색합니다.
4. 기존 issue가 있으면 사용자에게 확인한 뒤 그 issue를 작업 기준으로 사용합니다.
5. 기존 issue가 없으면 [issue 지침](references/issue.md)에 따라 초안을 작성하고 생성을 승인받습니다.
6. issue가 생성되고 번호가 확인된 뒤 구현을 시작합니다.

사용자가 명시적으로 issue 없이 진행하라고 지시한 경우에만 3~6단계를 생략하고 그 사실을 최종
응답에 남깁니다.

## 작업별 지침

- issue를 검색·작성·수정·종료할 때는 [issue 지침](references/issue.md)을 읽습니다.
- commit을 준비하거나 수행할 때는 [commit 지침](references/commit.md)을 읽습니다.
- push 또는 PR을 준비하거나 수행할 때는 [PR 지침](references/pull-request.md)을 읽습니다.
- PR을 ready 상태로 전환하거나 merge할 때는 [merge 지침](references/merge.md)을 읽습니다.

현재 작업에 필요한 reference만 읽습니다. 단순 조회에는 관련 reference를 읽지 않아도 됩니다.

## 중단 조건

다음 상황에서는 외부 상태를 변경하지 않고 사용자에게 보고합니다.

- 대상 issue, 브랜치 또는 PR이 불명확합니다.
- 요청한 작업에 필요한 별도 승인이 없습니다.
- 작업 트리에 사용자 변경과 충돌할 가능성이 있습니다.
- CI 실패, merge conflict 또는 미해결 리뷰가 있습니다.
- PR 템플릿의 필수 항목을 근거 없이 작성하거나 체크해야 합니다.
