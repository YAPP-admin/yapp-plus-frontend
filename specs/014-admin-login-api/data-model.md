# 데이터 모델: 관리자 로그인 API와 세션 연동

## 로그인 입력

| 필드       | 형식   | 규칙                                      |
| ---------- | ------ | ----------------------------------------- |
| `username` | 문자열 | 제출 직전 앞뒤 공백 제거, 빈 결과는 거부  |
| `password` | 문자열 | 빈 문자열은 거부, 공백을 포함한 원문 전달 |

폼 수명 동안만 유지하며 영구 저장하거나 로그에 기록하지 않는다. API 요청에서는 `username`을
`loginId`로 변환한다.

## Staff 로그인 응답

| 필드          | 형식       | 사용                                             |
| ------------- | ---------- | ------------------------------------------------ |
| `staff`       | Staff 요약 | 계약 검증만 수행하고 이번 범위에서 저장하지 않음 |
| `accessToken` | 문자열     | non-empty 검증 뒤 관리자 세션으로 저장           |

생성 스키마로 전체 응답을 검증한다. 필수 필드가 없거나 형식이 다르면 서비스 실패다.

## 관리자 세션

| 속성      | 값                                           |
| --------- | -------------------------------------------- |
| 저장 key  | `yapp-plus-admin.access-token.v1`            |
| 저장 값   | Staff access token 문자열                    |
| 지속 범위 | 같은 origin의 브라우저 재시작 이후까지       |
| 사용 범위 | 생성 client의 `staffBearerAuth` 요청         |
| 제외 범위 | SSR, `userBearerAuth`, 문서·로그·검증 이미지 |

### 상태 전이

```text
없음 ── 로그인 성공+저장 성공 ──> 저장됨
저장됨 ── 새 로그인 성공+저장 성공 ──> 새 token으로 교체
없음/저장됨 ── 입력·서비스·검증·저장 실패 ──> 기존 상태 유지
```

token 만료·폐기 확인과 제거는 이번 기능에 포함하지 않는다.

## 로그인 결과

| 상태                  | 조건                                 | 화면 결과              |
| --------------------- | ------------------------------------ | ---------------------- |
| `success`             | 응답 검증과 token 저장 모두 성공     | 현재 화면이면 `/` 이동 |
| `invalid-credentials` | HTTP 401                             | 자격 증명 오류 안내    |
| `unavailable`         | 그 밖의 HTTP·네트워크·검증·저장 실패 | 서비스 오류 안내       |

화면이 사라진 뒤 `success`가 도착하면 token 상태 전이는 유지하지만 화면 이동은 실행하지 않는다.
