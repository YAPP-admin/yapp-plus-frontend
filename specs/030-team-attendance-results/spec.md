# 기능 명세: 팀 세션 출석 결과 안내

**브랜치**: `DongjaJ/t90s9` · **작성일**: 2026-11-26 · **상태**: 1단계 리뷰 대기
**기준 이슈**: [#622](https://github.com/YAPP-admin/yapp-plus-frontend/issues/622)
**입력**: 팀 세션 인증 반려·결석·출석 완료 모달과 기기별 표시 이력을 구현한다.

## 사용자 시나리오와 검증

### US1 — 본인 출석 결과 확인 (P1)

회원은 홈에 들어오거나 돌아올 때 자신의 팀 세션 출석 결과를 확인한다.
우선순위 이유: 팀 사진 심사와 개인 출결을 구분해 잘못된 완료 안내를 막는 핵심 경험이다.
독립 검증: 결과별 입력을 제공해 해당 시트의 제목·설명·행동을 확인한다.

1. 본인이 결석으로 확정되었으면 결석 안내를 표시한다.
2. 본인 출석이 확정되었으면 출석 완료를 안내한다. 팀 사진이 승인돼도 본인 미선택만으로
   출석 완료를 표시하지 않는다.
3. 본인 인증이 반려되었고 확정 출결이 없으면 반려 사유를 표시한다.
4. 검토 중·미제출·미선택·공결만으로 세 결과 중 하나를 추정하지 않는다.

### US2 — 새 결과만 한 번 확인 (P1)

회원은 같은 기기에서 이미 본 결과를 반복해서 보지 않으면서 재제출 후의 새 결과는 확인한다.
우선순위 이유: 다른 팀원이 제출을 담당해도 결과 안내를 놓치지 않아야 한다.
독립 검증: 서로 독립된 두 회원의 표시 이력을 사용해 같은 제출자의 재제출을 재현한다.

1. 시트를 실제로 본 뒤 닫거나 홈을 다시 열어도 같은 사진·본인 결과는 다시 표시하지 않는다.
2. A가 사진을 다시 제출하면 B도 다음 홈 진입에서 새 사진의 반려·출석 결과를 확인한다.
3. B가 재제출 중간 과정을 보지 못했더라도 새 결과를 표시한다.
4. 숨겨진 홈이나 조회만 완료된 화면은 결과를 본 것으로 기록하지 않는다.

### US3 — 결과에 맞는 후속 행동 (P2)

회원은 반려 후 사진을 다시 제출하거나 결석 결과를 문의할 수 있다.
우선순위 이유: 결과 안내에서 기존 제출·문의 흐름으로 이어져야 한다.
독립 검증: 제출 가능·기한 종료·문의·확인 입력으로 버튼과 목적지를 검증한다.

1. 재업로드 가능한 반려의 버튼은 해당 세션의 기존 사진 안내로 이동한다.
2. 기한이 지난 반려는 사유와 기한 종료를 안내하고 확인 버튼을 제공한다.
3. 결석의 문의 버튼은 기존 이용문의 채널을 열며 확인 버튼은 시트를 닫는다.

### 경계 사례

- 여러 미표시 결과는 홈 진입당 한 건만 보여준다. 재업로드 가능한 반려를 먼저 선택하고,
  나머지는 세션 최신순으로 표시한다. 현재 활동 기수의 지난 세션도 포함한다.
- 조회 실패나 결과 간 불일치는 이번 진입의 자동 안내를 보류하며 홈 사용을 막지 않는다.
- 계정 전환 시 열린 시트를 폐기하고 새 계정의 기록을 사용한다. 같은 계정 재로그인은
  해당 기기의 기존 표시 이력을 유지한다.
- 저장 기능을 사용할 수 없으면 현재 실행 중에는 중복을 막는다. 기기·브라우저 변경이나
  저장소 삭제 후에는 이미 본 결과가 다시 표시될 수 있다.

## 요구사항

### 기능 요구사항

- **FR-001**: 세션 시작 이후 활성 홈 최초 진입·홈 복귀·앱 복귀에서 최신 결과를 확인한다.
- **FR-002**: 팀 사진 심사보다 본인의 확정 출결을 우선해 반려·결석·완료를 구분한다.
- **FR-003**: 현재 활동 기수의 지난 팀 세션을 포함하고 한 번의 진입에서 한 건만 표시한다.
- **FR-004**: 실제 시트 표시 시점에 기기별 이력을 남긴다. 버튼 클릭을 기록 조건으로 삼지 않는다.
- **FR-005**: 같은 사진·본인 결과를 다시 표시하지 않으며 새 사진의 결과는 다시 안내한다.
- **FR-006**: 재제출 시 다른 회원의 저장 기록을 지우는 동작에 의존하지 않는다.
- **FR-007**: 재업로드·문의·확인을 기존 흐름과 연결한다. 사용할 수 없는 재업로드는 안내한다.
- **FR-008**: 반려 사유와 기한을 실제 값으로 표시하고 제공되지 않은 결석 사유는 생략한다.
- **FR-009**: 지난 세션 결과에 세션 이름·날짜를 표시해 현재 홈의 세션과 구분한다.
- **FR-010**: 조회·저장 실패로 홈을 차단하지 않으며 계정 간 안내와 표시 이력을 섞지 않는다.
- **FR-011**: 키보드·스크린 리더·터치와 작은 화면에서 모든 후속 행동을 사용할 수 있다.

### 주요 개체

- **세션**: 기수, 날짜, 유형과 제출 가능 시간을 가진 활동 단위다.
- **사진 제출**: 같은 사람이 재제출해도 이전 사진과 구분되는 팀의 제출 단위다.
- **본인 결과**: 사진 심사와 개인 출결을 종합해 해당 회원에게 안내할 결과다.
- **표시 이력**: 회원·기수·세션별로 해당 기기에서 마지막으로 본 사진과 결과다.

## 성공 기준

- **SC-001**: 세 결과와 검토 중·미선택·공결 사례에서 잘못된 결과 시트가 0건이다.
- **SC-002**: 같은 결과의 재진입·재시작에서는 중복 0건이며 새 사진의 결과는 회원마다 한 번 표시한다.
- **SC-003**: 과거 결과가 여러 건이어도 한 번의 홈 진입에 최대 한 건만 표시한다.
- **SC-004**: 재업로드·기한 종료·문의·확인의 대표 흐름을 키보드와 터치로 완료할 수 있다.

## 가정과 범위

- 현재 활동 기수만 대상으로 하며 이전 기수의 이력 안내와 기기 간 동기화는 제외한다.
- 시작 전 제출·심사가 끝나도 세션 시작 이후 홈 진입·복귀부터 안내한다. 사용자 확인으로 정한
  범위이며 시작 시각에 자동으로 화면을 갱신하는 별도 타이머는 두지 않는다.
- 출석 완료는 정상 출석·지각·조퇴·지각과 조퇴의 본인 확정 상태를 포함하며 공결은 제외한다.
- 같은 사진과 같은 최종 결과로 되돌아온 중간 정정을 관찰하지 못한 경우까지 알리지 않는다.
  새 결과마다 서버 식별자를 만드는 별도 정책은 도입하지 않는다.
- 새로운 푸시·알림함 기능, 관리자 출결 정책, 배포 실행은 범위에 포함하지 않는다.
