# 기능 명세: 로그인 응답 기반 가입 승인 처리

**브랜치**: `DongjaJ/yapp-approval-screen` · **작성일**: 2026-11-26
**상태**: 1단계 진행 중 · **이슈**: [#599](https://github.com/YAPP-admin/yapp-plus-frontend/issues/599)
**입력**: 로그인·가입 결과로 승인 상태를 판단하고 기존 대기·완료·에러 화면을 연결한다.

## 사용자 시나리오와 검증

### US1 — 승인 상태에 맞는 화면 진입 (P1)

회원은 로그인하거나 가입한 뒤 자신의 승인 상태에 맞는 화면을 본다.
우선순위 이유: 승인 전 사용자가 회원 서비스를 사용하는 경로를 막는 핵심 동작이다.
독립 검증: 상태별 로그인·가입 결과를 제공해 화면 이동과 보호 내용의 비노출을 확인한다.

1. 승인 대기 회원이 로그인하거나 가입하면 기존 대기 화면만 본다.
2. 승인된 기존 회원이 로그인하면 홈으로, 신규 가입 직후 승인된 회원은 가입 완료 화면으로 이동한다.
3. 거절·상태 확인 불가 회원은 기존 에러 화면과 운영진 문의 경로를 본다.
4. 제한 상태에서 보호 화면으로 직접 진입하거나 뒤로 돌아가도 회원 내용이 표시되지 않는다.

### US2 — 대기 화면에서 로그인으로 복귀 (P1)

회원은 대기 화면의 기존 뒤로가기로 로그인 화면에 돌아가 승인 결과를 다시 확인한다.
우선순위 이유: 앱을 강제로 종료하지 않고도 재로그인할 수 있는 유일한 화면 내 경로다.
독립 검증: 뒤로가기 확인·취소와 같은 계정·다른 계정 재로그인을 각각 확인한다.

1. 뒤로가기를 누르면 로그인 화면으로 돌아갈지 묻는다. 취소하면 대기 상태를 유지한다.
2. 확인하면 로그인 화면으로 이동하고, 다시 로그인을 완료했을 때만 최신 승인 결과를 반영한다.
3. 같은 앱 실행 중 대기했던 같은 계정이 승인되면 가입 완료 화면을 한 번 보여준다.
4. 다른 승인 계정으로 로그인하면 홈으로 이동한다. 이전 계정의 대기 이력을 적용하지 않는다.
5. 에러 화면의 뒤로가기는 로그인으로 이동한다. 가입 입력이나 보호 화면을 복원하지 않는다.

### US3 — 앱 수명과 기존 사용자 호환 (P2)

대기 사용자는 완전 재실행 시 로그인하고, 기존 자동 로그인 사용자는 기존 경험을 유지한다.
우선순위 이유: 새 승인 처리의 저장 정책과 기존 설치본 호환성을 구분해야 한다.
독립 검증: 대기 상태의 백그라운드 복귀·완전 재실행과 이전 저장 세션 복원을 비교한다.

1. 대기 중 백그라운드 복귀는 대기 화면을 유지하며 승인 상태를 자동 조회하지 않는다.
2. 대기 중 앱을 완전히 종료했다가 열면 로그인 화면을 본다. 재로그인 결과가 승인이라면 홈으로 이동한다.
3. 이미 저장된 세션은 일괄 로그아웃 없이 자동 로그인한다.
4. 구버전 앱의 전환 필드 없는 응답은 거부한다. OTA 적용 전 로그인 실패를 허용하고 강제 업데이트 흐름은 추가하지 않는다.

### 경계 사례

- 로그인·가입 취소, 네트워크 실패, 잘못된 응답을 승인으로 취급하지 않는다.
- 계정 전환이나 로그아웃 이후 도착한 이전 응답은 새 화면·계정을 덮지 않는다.
- 로그인 복귀 중 중복 클릭을 막고 정리 실패 시 대기 화면에서 다시 시도할 수 있게 한다.
- 같은 실행 중의 대기 이력은 앱 완전 종료 이후 복원하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001 (US1)**: 새 로그인·가입 결과의 승인 상태에 따라 대기·서비스·에러 화면을 구분한다.
- **FR-002 (US1)**: 새 로그인에서 대기·거절·확인 불가인 계정은 정상 로그인으로 확정하지 않는다.
- **FR-003 (US1)**: 보호 화면 직접 진입·뒤로가기·딥링크에서도 제한 상태의 내용 노출을 막는다.
- **FR-004 (US1)**: 신규 가입 직후 승인된 회원은 기존 가입 완료 화면과 시작하기를 유지한다.
- **FR-005 (US2)**: 대기 화면 디자인을 유지하며 별도 하단 버튼을 추가하지 않는다.
- **FR-006 (US2)**: 기존 뒤로가기로 확인·취소를 거쳐 로그인 화면에 복귀할 수 있다.
- **FR-007 (US2)**: 같은 앱 실행 중 같은 대기 계정이 승인되면 가입 완료 화면을 한 번 표시한다.
- **FR-008 (US2)**: 다른 계정의 대기 이력이나 늦은 인증 결과를 현재 계정에 적용하지 않는다.
- **FR-009 (US3)**: 새로 대기·거절·확인 불가로 판정한 계정의 자동 로그인 정보를 저장하지 않는다.
- **FR-010 (US3)**: 백그라운드 복귀는 상태를 유지하고 완전 재실행은 대기 이력을 잊고 로그인한다.
- **FR-011 (US3)**: 새 앱의 기존 저장 세션 복원은 유지한다. 구버전 응답의 필수 필드 누락은 INVALID_RESPONSE로 거부하며 OTA 적용 전 로그인 실패를 허용한다.
- **FR-012 (US1–US3)**: 취소·실패·저장소 오류와 조회 불가를 승인이나 실제 로그아웃 성공으로 오인하지 않는다.

### 주요 개념

- 승인 상태: 승인 대기, 승인, 거절 또는 확인 불가라는 회원 심사 결과.
- 제한 상태: 회원 서비스로 진입하지 못하고 대기 또는 에러 안내를 보는 상태.
- 실행 중 대기 이력: 같은 계정의 승인 전환을 판단하며 앱 완전 종료 시 사라지는 기록.
- 기존 저장 세션: 이번 변경 전에 저장되어 승인 확인 없이 복원될 수 있는 호환 대상.

## 성공 기준

- **SC-001**: 새 로그인·가입의 모든 상태별 시나리오에서 기대 화면이 한 번만 표시된다.
- **SC-002**: 제한 상태의 직접 진입·뒤로가기 시나리오에서 보호 내용 노출이 0건이다.
- **SC-003**: 같은 계정 승인 전환과 다른 계정 로그인·앱 재실행을 구별해 환영 화면 오표시가 없다.
- **SC-004**: 대기 화면에 새 하단 버튼이 없고 기존 뒤로가기만으로 로그인에 복귀할 수 있다.
- **SC-005**: 새 앱의 기존 자동 로그인과 구버전 응답 거부를 검증하며 미검증 범위를 명시한다.

## 확정 정책과 범위

- 2026-11-26 사용자 선택: 기존 세션 유지, 같은 실행 중에만 가입 완료, 기존 뒤로가기만 사용,
  확인 불가도 기존 에러 화면. 구버전 호환은 후속 사용자 결정으로 제거했다. 내 정보 조회 기반의 이전 계획을 대체한다.
- 대상은 현재 회원 iOS 앱의 Google·Apple 로그인이다. Kakao 추가와 별도 Android 앱은 제외한다.
- 내 정보 조회 변경, 자동 재조회, 주기적 확인, 재신청, 새 승인 확인 버튼은 제외한다.
- 새 앱이 복원하는 기존 저장 세션은 다음 직접 로그인 전까지 승인 검사를 보장하지 않는다.
- 승인 이후 서버 상태가 바뀌어도 자동 반영하지 않는다. 서버의 업무 접근 권한 검사를 대체하지 않는다.
- 명세·계획·회귀 테스트·실기기 검증을 단계별 리뷰하며 배포는 별도 승인 범위다.
