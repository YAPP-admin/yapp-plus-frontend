# 조사와 결정

기준: 2026-11-20, `origin/main`의 `cc90b35e`. 아래는 현재 코드 조사와 대화에서 확정한 정책이다.

## 1. 상태와 유형

- 결정: 주간 API를 홈 상태의 단일 기준으로 사용하고 유형은 일시적으로 장소의 `null` 여부로 판별한다.
- 근거: `packages/api/src/generated/types.gen.ts`에 `CHECKED_IN`·`PENDING_APPROVAL`은 이미 존재하지만 주간 세션의 `type`·`endTime`은 없다. 목록 API에는 두 필드가 있다.
- 대안: 목록 추가 조회·시간/역할 추론은 채택하지 않는다. 사용자 요청대로 백엔드 필드 추가 전에는 최소 임시 판별을 사용한다.
- 주의: 체크인은 최종 출결 등급이 아니다. 인증 대기는 본인이 인증 대상일 때의 상태이며 팀 전체 상태로 확장하지 않는다.

## 2. 과거 성공 기록과 복귀

- 결정: 홈·코드 진입의 과거 mutation 성공 우선 표시를 제거하고 현재 제출의 완료 화면 방어는 유지한다.
- 근거: `pages/home/model/code-attendance.ts`의 `useAttendanceConfirmation`은 성공 기록을 보존하며 홈과 완료 화면 모두에서 사용한다. 전체 제거는 완료 화면 직접 진입 방어를 깨뜨린다.
- 결정: 홈 복귀는 신선한 캐시도 재조회한다. 다른 화면의 기존 stale 기준 동작은 유지한다.
- 근거: `shared/lib/screen-activity.ts`는 stale일 때만 재조회한다. `providers.tsx`의 기본 stale 시간은 30초다.
- 제한: 네이티브 AppState에서 웹 Query focus로 연결하는 경로를 확인하지 못했다. iOS·Android WebView 포그라운드 확인이 필요하다. 필요해진 브리지 변경은 별도 리뷰 대상이다.

## 3. 사진 흐름 수명

- 결정: 안내·업로드·접수 완료가 같은 사진 상태 소유자를 사용한다. 사진·접수 정보는 메모리에만 둔다.
- 근거: 현재 `home-sheets.tsx` 안내는 별도 Activity이며 업로드로 replace한다. `use-attendance-photo.ts`는 unmount 시 URL을 해제하므로 안내에서 선택한 사진을 기존 구조 그대로 넘기면 수명이 끊긴다.
- 대안: 전역 저장소·영구 저장은 불필요하다. 기존 업로드/완료 흐름에 안내 단계를 통합하고 URL 호환성을 유지한다.
- 유지: `use-photo-submission.ts`의 presign→업로드→제출, 불확실한 최종 제출 자동 재시도 금지, 브리지 이미지 제한.

## 4. 팀 조회 선행 조건

- 결정: 회원이 사용할 수 있는 세션별 팀·팀원 조회 계약을 확인한 뒤 운영 연결한다.
- 근거: 기존 제출 대상은 `sessionId`, `teamName`, `selfMembershipId`, 팀원의 `membershipId`·`name`·`positionLabel`을 요구한다. 현재 프로필만으로 구성할 수 없고 관리자 조회를 대체 사용하면 권한 경계를 위반한다.
- 대안: 개발용 고정 대상·userId 대입·새 API 경로 추측은 사용하지 않는다.
- 확인 시점: 3단계 시작 전 실제 응답의 본인 포함·ID 중복·소속 변경·필드 누락 정책을 확인한다. 준비 전 홈 팀 진입은 비활성화한다.

## 5. 디자인과 Android 비교

- 디자인 기준: [홈 흐름](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=222-40284), [확인 중](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=1091-4728).
- 확인한 구분: 정규는 코드 출석, 팀은 안내→사진 선택·팀원 선택→접수 완료다. 승인 완료와 접수 완료는 다른 사건이다.
- Android 조사 기준: `develop`의 `7fa39e5ab7c03f0805cd4538a1cffdd514a66733`. 확인 중·승인 UI는 있으나 조사한 연결은 디버그 정적 상태이며 사진 조회 콜백도 비어 있었다. 이를 운영 완료 근거로 삼지 않는다.
- 결정: 제출 후 사진 조회·승인 바텀시트·FCM은 사용자와 합의하여 제외한다. 제출 전 미리보기는 유지한다.

## 6. 시간 안내와 출시 순서

- 결정: 종료 시간 없이 고정 14~18시를 표시하지 않는다. 일반 시간 안내 후 주간 API에 종료 시간을 요청한다.
- 근거: 사용자 결정이며 목록 조회 추가 없이 홈·정규 기능을 먼저 완성할 수 있다.
- 외부 의존성: 실제 `type`·`endTime` 응답 및 회원용 조회 계약 수신은 아직 완료되지 않았다. 문서는 요청 내용만 정리하며 외부에 전달 완료했다고 간주하지 않는다.
