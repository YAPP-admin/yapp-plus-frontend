# 구현 계획: 회원 웹 계층형 오류 경계

**브랜치**: `DongjaJ/sgbp0` | **작성일**: 2026-11-25 | **명세**: [spec.md](spec.md)

## 요약

별도 ApiErrorBoundary 없이 LocalErrorBoundary·AuthErrorBoundary·AppErrorBoundary로 책임을 나눈다.
ErrorState는 표시만, 공통 조회 판정은 완료된 오류 전달만 담당한다. 생성 Query 옵션과 기존 인증
cache·작업 세대를 사용한다. 이슈 #581과 공식 명세를 기준으로 단계별로 구현한다.

## 기술 맥락

- React 19.3.0, TypeScript 6.0.3, TanStack Query 5.102.8, react-error-boundary 6.1.6.
- 기존 Stackflow·SEED·vanilla-extract·Vitest 5.0.0·Testing Library·MSW 사용. 새 의존성 없음.
- 상태 저장은 기존 Query cache와 화면 수명이다. 새 영구 저장·서버 schema 변경 없음.
- 웹·WebView 지원은 기존 `.mwgrc`의 widely 기준을 유지한다.
- 성능 제약: timer·추가 인증 polling·화면 복귀 중복 요청·실패 자동 재시도 루프를 추가하지 않는다.

## 구현 원칙

1. Local은 일반 오류를 ErrorState로 바꾸고 인증 오류는 fallback에서 다시 throw한다.
2. Auth는 인증 오류만 처리하고 다른 오류는 최종 App 경계로 전파한다. 모든 보호 Activity에 같은 정책을 적용한다.
3. App은 Provider 바깥 최종 경계이며 Query·라우터 없이 새로고침과 `/` 링크를 제공한다.
4. 캐시가 있는 Suspense Query의 완료된 오류를 명시적으로 전달한다. 생성 옵션·query key를 다시 만들지 않는다.
5. 로딩 fallback과 reset을 결합해 캐시가 있는 실패의 reset 직후 재throw·기존 콘텐츠 반짝임을 방지한다.
6. GET은 기존 갱신·한 번의 재전송을 유지하고, Mutation은 인증 오류만 throw한다. 입력 검증·일반 제출 오류는 로컬 처리한다.
7. 재인증 필요는 기존 인증 cache의 `ERROR / AUTH_REQUIRED`로 표현한다. 네이티브 로그아웃·토큰 삭제를 호출하지 않는다.
8. 갱신 뒤에도 남은 최종 인증 오류만 재인증으로 반영한다. 기존 인증 작업 세대 정책은 유지한다.
9. 보호 콘텐츠 차단·가드 반영 뒤 업무 조회 취소·캐시 정리를 연결한다. 전환 중 무인증 재요청을 시작하지 않아야 한다.
10. 진행 중 서버 Mutation은 캐시 삭제로 취소됐다고 간주하지 않는다. Mutation별 수명 정책은 이후 적용 단계에서 유지한다.
11. 일반 조회 실패 때 경계 내부 폼 입력만 초기화한다. 기존 경계 밖 사진 보관·Activity 수명을 임의로 확대·변경하지 않는다.
12. 제출 Mutation의 진행·성공 처리 소유자는 Query fallback으로 제거하지 않는다. 서버 성공은 후속 조회 실패와 별도로 완료시킨다.

## 검증과 복구

[quickstart.md](quickstart.md)의 회귀 시나리오를 가까운 계층에서 검증한다. 제품 코드 변경 단계마다
`node --run check`와 `node --run build`를 실행한다. 모바일 설정·의존성 변경이 없어 expo:doctor는 대상이 아니다.
재현 가능한 버그는 수정 전 실패를 확인한다. UI 화면 증거는 `.context/`에 보관한다.
새 데이터 형식·배포 설정 변경 없이 적용하고 문제 발생 시 소비자 적용부터 역순 revert한다.
