# 기능 명세: 관리자 세션 관리 화면과 모의 동작

**브랜치**: `DongjaJ/gihc4`
**작성일**: 2026-10-15
**상태**: 확정 — 2026-10-15 사용자 다음 단계 진행 지시로 승인
**이슈**: [#68](https://github.com/YAPP-admin/yapp-plus-frontend/issues/68)
**입력**: 최신 Figma와 기획 대화를 기준으로 세션 관리를 구현하고, 세부 단계마다 리뷰받는다.

## 사용자 시나리오와 검증

### US1 — 세션 목록 조회와 유형 필터 (P1)

운영진이 세션 일정과 출석 현황을 확인하고 원하는 유형의 세션을 찾는다.
우선순위 근거: 세션 확인과 후속 관리의 출발점이다.
독립 검증: 두 유형의 예시 세션이 있는 목록에서 필터를 전환한다.

1. 목록에 세션명, 유형, 날짜·시간, 장소와 출석 집계가 표시된다.
2. `전체 / 오프라인 / 팀 세션` 중 하나를 선택하면 해당 세션과 결과 개수가 표시된다.
3. 번호 페이지 이동 없이 한 페이지를 스크롤하여 선택한 유형의 모든 예시 세션을 확인한다.
4. 필터를 바꾸고 브라우저 뒤로 가기·앞으로 가기를 실행하면 해당 필터 상태로 돌아간다.
5. 세션 관리 목록은 화면 너비와 관계없이 1열로 표시한다. 카드 본문은 정보 표시용으로, 눌러도 이동하거나 폼을 열지 않는다. 케밥 메뉴의 세션 정보·삭제 항목으로 수정 폼·삭제 확인을 연다. 출석부 이동은 기존 출석 관리 화면에서 제공한다.
6. 전체 세션이 없는 경우와 선택한 유형의 결과가 없는 경우를 구분해 안내한다.
7. 조회 중에는 로딩 상태를, 조회 실패 시에는 오류와 재시도를 제공한다.

### US2 — 세션 생성 (P1)

운영진이 일정과 장소를 입력해 세션을 추가한다.
우선순위 근거: 실제 세션 관리 흐름을 검증하기 위해 목록과 함께 필요하다.
독립 검증: 목록 또는 전체 빈 상태에서 생성 창을 열어 성공·실패를 각각 확인한다.

1. 생성 창에는 세션명·장소·날짜·시작 시간·종료 시간·유형의 여섯 입력 항목이 있다.
2. 필수 입력이 비었거나 날짜·시간 형식이 유효하지 않으면 저장하지 않고 해당 입력의 오류를 안내한다.
3. 제출 중에는 진행 상태를 표시하고 중복 생성을 막는다.
4. 생성에 실패하면 입력을 유지하고 오류를 안내하며 재시도할 수 있다.
5. 생성에 성공하면 창을 닫고 새 세션과 목록 개수를 반영한다. 성공 후 필터는 D2에 따라 전체로 전환한다.
6. 취소하면 세션이 생성되지 않는다. 창을 다시 열면 D5에 따라 입력이 초기화되어 있다.

### US3 — 세션 정보 수정과 삭제 (P2)

운영진이 세션 정보를 확인·수정하고 불필요한 세션을 삭제한다.
우선순위 근거: 목록·생성 이후의 관리 동작이며 각각 기존 예시 데이터로 검증할 수 있다.
독립 검증: 예시 세션의 메뉴에서 정보 수정과 삭제를 각각 실행한다.

1. `세션 정보`를 선택하면 저장된 여섯 항목이 채워진 수정 폼이 열린다. 생성과 같은 필수 입력·날짜·시간 검증을 적용한다.
2. 수정 저장 중에는 중복 제출과 닫기를 막는다. 성공하면 같은 세션의 정보를 갱신하고 창을 닫는다. 식별자와 출석 집계는 유지한다.
3. 수정 실패 시 편집한 입력을 유지하고 오류와 재시도를 제공한다. 취소·닫기·Esc는 미저장 변경을 버리고 다시 열면 마지막 저장값을 표시한다.
4. 수정 성공 후 현재 유형 필터를 유지하고 정렬·개수를 다시 계산한다. 유형 변경으로 필터에서 제외되면 카드가 사라지고 완료 안내를 제공한다.
5. `삭제하기`를 선택하면 세션명을 포함한 확인 창을 표시한다.
6. 삭제를 취소하면 목록을 유지한다. 확인 후 성공하면 해당 항목과 개수를 갱신하고 현재 필터를 유지한다.
7. 삭제 중에는 중복 요청을 막고, 실패하면 항목을 유지하면서 오류와 재시도를 제공한다.
8. 마지막 항목을 삭제하면 현재 조건에 맞는 빈 상태를 표시한다.

### US4 — 공통 관리자 화면과 접근성 (P1)

운영진이 데스크톱과 좁은 화면에서 메뉴와 세션 관리 기능을 이용한다.
우선순위 근거: 모든 세션 관리 동작에 접근할 수 있어야 한다.
독립 검증: 기존 관리자 메뉴를 이동하고 키보드·스크린 리더·터치로 주요 동작을 확인한다.

1. Figma의 사이드바·헤더·본문 배치를 참고하고 기존 관리자 메뉴와 현재 위치 표시를 유지한다.
2. 좁은 화면에서도 메뉴, 카드, 생성·수정·삭제 창의 내용과 주요 버튼에 접근할 수 있다.
3. 입력에는 식별 가능한 레이블이 있고 키보드 포커스와 오류·진행 상태를 인지할 수 있다.
4. 모달 안에서 키보드 포커스가 유지되고 닫으면 실행한 컨트롤로 돌아간다.
5. 삭제로 실행한 컨트롤이 사라지면 남은 목록 항목이나 목록 제목으로 포커스를 옮긴다.

### 경계 조건

- 유효하지 않거나 이전 직군 필터가 담긴 목록 주소는 전체 유형으로 표시한다.
- 긴 세션명과 장소, 낮은 화면 높이에서도 내용을 확인하고 모달을 닫을 수 있다.
- 모달 취소·닫기와 요청 중 닫기 처리는 확정한 D5를 따른다.
- 모의 생성·수정·삭제 결과는 화면 이동 후 유지하고 브라우저 새로고침 시 초기 상태로 돌아간다.
- 실제 출석 기록 삭제·점수 재계산은 모의 목록 삭제로 검증했다고 간주하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: US1에 따라 세션 목록·유형 필터·결과 개수·스크롤·상태 안내를 제공한다.
- **FR-002**: US2에 따라 여섯 항목을 입력받고 생성 성공·실패·재시도·취소를 처리한다.
- **FR-003**: US3에 따라 수정 폼·저장·취소와 삭제 확인·성공·실패 처리를 제공한다.
- **FR-004**: US4에 따라 공통 관리자 레이아웃과 좁은 화면·접근성 동작을 제공한다.
- **FR-005**: 대상 직군과 출석받기 on/off는 입력, 표시, 필터 및 보이지 않는 저장 기본값에 포함하지 않는다.
- **FR-006**: 장소는 텍스트로 입력하고 표시한다. 지도 검색이나 지도 앱 이동은 제공하지 않는다.
- **FR-007**: 개발 환경의 모의 데이터로 동작을 검증한다. 실제 운영 데이터와 연결하지 않으며 프로덕션에서 모의 생성·수정·삭제가 동작하지 않는다.
- **FR-008**: 모의 변경의 유지·초기화와 오류·경계 상황은 위 시나리오 및 경계 조건을 따른다.

### 주요 개념

- **세션 유형**: 오프라인 또는 팀 세션이다. `전체`는 조회 조건이며 세션의 유형이 아니다.
- **세션**: 식별 정보, 세션명, 장소, 날짜, 시작·종료 시간, 유형과 출석 집계를 가진다.
- **생성·수정 입력**: 운영진이 입력하는 여섯 항목이다. 식별 정보와 출석 집계는 직접 입력하지 않는다.
- **출석 집계**: 카드에 표시하는 세션별 출결 현황이다. 출석 판정이나 점수 계산 정책은 변경하지 않는다.

## 성공 기준

- **SC-001**: US1의 세 필터, 전체·필터 빈 상태, 로딩, 오류·재시도와 주소 탐색 시나리오를 모두 확인한다.
- **SC-002**: US2의 필수 입력 검증, 중복 제출 방지, 성공 반영, 실패 시 입력 보존 및 취소를 모두 확인한다.
- **SC-003**: US3의 수정 초기값·검증·저장 성공·실패·취소·필터 반영, 삭제 취소·성공·실패 및 마지막 항목 삭제를 모두 확인한다.
- **SC-004**: US4의 데스크톱·좁은 화면에서 와이어프레임의 정보 구조, 시각적 일관성·가독성을 확인하고 키보드·스크린 리더·터치에서 주요 동작에 접근할 수 있음을 확인한다.
- **SC-005**: 삭제된 두 항목이 노출되거나 저장되지 않고 모의 데이터의 화면 이동 유지·새로고침 초기화 및 프로덕션 비활성화를 확인한다.

## 가정과 범위

### 확정된 범위

- 추가 지시: `세션 정보`는 기존 값이 채워진 수정 폼을 연다. 여섯 항목의 수정·저장·취소를 이번 범위에 포함한다.

- 2026-10-15 추가 지시: 와이어프레임은 정보 구조와 레이아웃의 참고 자료다. 픽셀 단위 일치를 요구하지 않으며, 시각적 완성도와 사용성을 높이기 위해 당근 SEED 컴포넌트를 적극 활용할 수 있다.

- 관리자 공통 레이아웃, 세션 목록, 유형 필터, 생성, 정보 수정, 삭제와 좁은 화면 대응을 포함한다.
- 현재 범위는 모든 예시 데이터를 한 페이지에서 스크롤하는 방식이다. 서버 기반 추가 로딩은 실제 연동 시 별도로 정한다.
- 알림 기획은 세션 맥락의 참고 자료다. 알림 발송·예약·수신 대상 설정은 구현하지 않는다.
- 실제 API 연결, 인증·권한·로그아웃, 지도 연동, 출석 판정·점수 재계산은 제외한다.
- 여섯 입력의 필수 여부를 검증하며, 근거 없는 글자 수 제한이나 과거 날짜 금지 정책은 추가하지 않는다.

## 빈 상태 CTA 정책 (8단계 리뷰 반영)

- 전체 필터의 빈 목록은 중앙 패널에 제목·설명·`세션 만들기` CTA를 표시한다.
- 생성 CTA는 8단계에서 비활성으로 표시하고 준비 중임을 안내한다. 9~11단계에서 생성 폼과 연결한다.
- 필터 선택 중 빈 목록은 전체 데이터 유무에 관계없이 `필터 초기화` CTA를 제공한다. 기존 URL 필터 변경 경로로 전체 목록을 표시하고 뒤로 가기 이력을 유지한다.
