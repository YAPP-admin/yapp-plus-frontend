# 세션 장소 입력: 기존 작업과 연결 관계

**단계**: 1-1 — 승인; 1-4에서 저장소 문서로 편입
**기준**: `origin/main`의 `dc5c957`, 현재 브랜치 `DongjaJ/3gx63`
**문서 성격**: 저장소 반영 전 검토 초안. 애플리케이션과 기존 명세는 변경하지 않았다.

## 현재 상태와 작업 기준

- 현재 브랜치는 최신 `origin/main`과 같으며 작업 시작 시 사용자 변경은 없었다.
- [기존 명세](../008-admin-sessions/spec.md)와 [작업 목록](../008-admin-sessions/tasks.md)은 목록·필터·카드까지 구현된 상태를 기록하고 있다.
- 실제 코드에도 생성·수정 폼과 수정 서비스가 없다. 장소는 필수 문자열이며 list/create/delete 모의 서비스만 있다.
- [기존 이슈 #68](https://github.com/YAPP-admin/yapp-plus-frontend/issues/68)은 종료되었다. 종료 상태를 미완료 폼까지 구현되었다는 근거로 사용하지 않는다.
- 열린 이슈 전체를 확인했으나 같은 세션 장소 범위의 이슈는 없었다. 종료된 #68은 선행 작업으로 참조하고 후속 이슈를 별도로 생성할 것을 제안한다.
- [공지 작업 #87](https://github.com/YAPP-admin/yapp-plus-frontend/issues/87)이 `specs/009-admin-notices/`를 참조하고 있어, 앞선 계획의 `009-session-location` 대신 `010-session-location`을 후속 명세 경로로 제안한다. 기존 명세나 브랜치 이름은 바꾸지 않는다.

## 기존 요구사항과의 관계

| 기존 항목                                 | 처리                          | 후속 작업에서 적용할 내용                                                                                    |
| ----------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------ |
| FR-001: 세션 목록·필터·상태               | 유지·일부 승계                | 기존 목록·URL 필터·정렬을 유지하고 미완료 로딩·오류·빈 상태를 4-1에서 보완한다.                              |
| FR-002, US2: 생성                         | 승계·장소 입력 변경           | 기존 생성 성공·실패·취소 정책을 유지하며 유형별 장소 입력과 검색·지도를 포함한다.                            |
| FR-003, US3의 수정 항목                   | 승계·장소 입력 변경           | 기존 값 복원·저장·실패·취소·집계 보존을 구현한다.                                                            |
| FR-003, US3의 삭제 항목                   | 기존 작업에 유지              | 삭제 UI·Mutation은 이번 기능에서 구현하지 않는다. 기존 delete 서비스도 기능을 확장하지 않는다.               |
| FR-004: 관리자 화면·접근성                | 기존 기반 재사용              | 새 폼·검색·지도 입력의 접근성을 검증한다. 기존 관리자 셸을 다시 설계하지 않는다.                             |
| FR-005: 직군·출석받기 제외                | 유지                          | 새 입력이나 숨은 저장 기본값으로 추가하지 않는다.                                                            |
| FR-006: 장소 텍스트·지도 제외             | 대체                          | 오프라인은 주소·좌표 필수, 상세주소 선택. 팀은 선택 안내 문구만 받는다. 지도 확인·위치 조정을 포함한다.      |
| FR-007: 모의 데이터·실제 운영 데이터 제외 | 저장 경계 유지·외부 조회 추가 | 세션 저장은 DEV 브라우저 메모리에 유지하고 주소·좌표 조회와 지도 표시는 실제 외부 서비스를 사용한다.         |
| FR-008: 모의 변경 유지·초기화             | 유지                          | 화면 이동 후 유지, 새로고침 초기화, SSR·프로덕션의 모의 기능 차단을 유지한다.                                |
| D1~D5                                     | 유지                          | 한국 시간·같은 날 일정, 종료 > 시작, 생성 후 전체 필터, 최신순 정렬, 신규 집계 0, 취소·닫기 정책을 유지한다. |
| D6: 문자열 공백 처리·장소 필수            | 일부 대체                     | 세션명 필수와 문자열 trim은 유지한다. 장소 필수 여부는 오프라인·팀 정책에 맞춰 변경한다.                     |

기존의 "실제 API 제외"는 세션 저장·인증 연동 제외로 구분한다. 실제 주소 API를 사용한다는 이유로 프로덕션 모의 편집 기능을 활성화하지 않는다. 주소 검색 결과의 페이징은 세션 목록의 페이징과 별개다.

## 기존 작업 목록과 후속 단계 대응

| --------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| T001~~T009, T011~~T020      | 기반 재사용                | 기존 완료 이력을 유지한다. 장소 모델·fixture·카드 변경에 필요한 부분만 3-1에서 갱신한다.                       |
| T010, T021의 남은 시각 검증 | 기존 기록 유지             | 미완료를 그대로 남긴다. 후속 5-3의 검증이 실제로 같은 조건을 충족한 경우에만 근거를 연결한다.                  |
| T022~T024: 목록 상태        | 4-1, 5-3~5-4               | 로딩·실패와 재시도·전체/필터 빈 상태·프로덕션 안내를 승계한다. 생성 버튼은 4-2까지 노출하지 않는다.            |

| T030~T033: 생성 연결        | 4-2, 5-3~5-4               | 생성 Mutation·캐시·전체 필터 전환·완료 안내·실제 화면 검증을 승계한다.                                         |
| T034~T036: 수정 폼          | 3-7, 4-4                   | 공통 폼의 초기값·취소·대상 전환을 검증하고 실제 수정 진입점을 연결한다.                                        |
| T037: 수정 서비스           | 4-3                        | updateSession, 입력 검증, ID·집계 보존, 없는 ID 오류와 저장소 격리를 구현한다.                                 |
| T038~T040: 수정 연결        | 4-4                        | 수정 Mutation·캐시 교체·현재 필터 유지·정렬·포커스 복귀를 구현한다.                                            |
| T041~T044: 삭제             | 이번 범위 밖               | 기존 미완료 항목으로 남긴다. 세션 정보 메뉴에 미구현 삭제 동작을 노출하지 않는다.                              |
| T045~T047: 전체 검증        | 이번 범위만 5-1~5-4에 포함 | 장소·생성·수정 검증을 수행한다. 삭제 등 기존 전체 범위까지 완료한 것으로 처리하지 않는다.                      |

승계는 기존 작업을 구현 완료로 체크한다는 뜻이 아니다. 후속 명세 작성 단계에서 원본에는 승계 경로를 남기고, 실제 구현·검증 상태는 후속 작업 목록에서 추적한다. 기존 리뷰 대기·미검증 기록은 삭제하거나 승인된 것으로 바꾸지 않는다.

## 후속 문서에 남길 합의

- 행안부 주소·건물명 검색 및 좌표 조회 → 브라우저 좌표 변환 → 카카오 지도에서 확인·조정 → 모의 세션 저장 순서로 구현한다.
- 장소명 전용 입력은 추가하지 않는다. 상세주소에 장소명·층·호수를 직접 입력한다.
- `proj4`의 선택 이유, 표준 브라우저 API와 Geolocation의 한계, EPSG:5179 → EPSG:4326 변환과 `[경도, 위도]` 순서는 1-4의 조사·설계 문서에 기록한다.
- `react-kakao-maps-sdk`로 지도·마커·SDK 로딩을 연결하고 admin의 작은 장소 입력 컴포넌트에서 폼 상태와 연결한다. 범용 지도 래퍼는 직접 만들지 않는다.
- API 키 발급과 브라우저 직접 호출 설정은 2단계다. 이번 단계에서는 키 신청·설정·패키지 설치를 하지 않는다.

## 제외 범위와 보존할 작업

- 실제 세션 백엔드 연결·DB 마이그레이션, 출석 반경·GPS 판정, 회원 앱 지도 연결은 제외한다.
- 인증·권한·배포 방식 변경, 관리자 셸 개선, 삭제 UI, 알림·출석 재계산은 제외한다.
- 공통 패키지와 앱 브리지를 확장하지 않는다. 변경은 관리자 세션 기능에 집중한다.
- 현재 브랜치를 유지한다. commit·push·PR·GitHub 이슈 변경은 수행하지 않았다.
