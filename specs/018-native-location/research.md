# 조사와 결정

조사일: 2026-11-07. 저장소 기준 commit은 [plan.md](plan.md)에 기록했다.
앞선 계획 대화의 읽기 전용 조사 결과를 사용하며 API 동작은 아래 공식 문서에 근거한다.

| 결정                        | 이유                                                                      | 검토한 대안                                                           |
| --------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Expo Location 사용          | Expo SDK 58 앱에서 OS 위치·권한 접근이 필요하고 현재 의존성에 기능이 없음 | WebView Geolocation은 선택한 네이티브 권한 소유 방식과 다름           |
| 단발 API 사용               | 사용자 리뷰에 따라 getCurrentPositionAsync와 15초 응답 대기로 단순화      | 구독 취소 대신 timeout 뒤 늦은 결과를 무시하며 OS 측정은 남을 수 있음 |
| 정확도·권한 수준 함께 반환  | 대략 위치도 전달한다는 사용자 결정, 출석 판정은 후속 작업                 | 정밀 위치만 허용하거나 임의 반경으로 차단하지 않음                    |
| RPC 결과로만 전달           | 일회성 사용이며 지속 상태 공유·영구 저장이 필요 없음                      | 공유 store·위치 구독 공개 API는 현재 범위 밖                          |
| 설정 이동 후 수동 재요청    | 사용자 동작으로 수집한다는 합의와 일치                                    | 앱 복귀 자동 측정은 제외                                              |
| 앱 버전 1.0.1로 런타임 분리 | 기존 appVersion 정책에서 새 네이티브 모듈이 없는 바이너리와 구분 필요     | build 번호만 증가하거나 기존 런타임 OTA 배포는 호환성을 보장하지 못함 |

## 확인한 현재 상태

- 브리지는 인증과 safe-area만 제공한다. 네이티브 RPC timeout과 웹 연결 timeout은 180초다.
- 모바일 앱에 expo-location은 없다. 공식 SDK 58 권장 버전은 ~58.0.20이며 설치 때 호환성을 재검증한다.
- 실서비스 홈의 출석은 준비 중 상태다. 이전 회원 세션 명세도 제출을 제외한다.
- 앱은 서비스 origin 밖 탐색을 외부 브라우저로 넘긴다. 기존 신뢰 경계의 전면 개편은 별도 작업이다.
- 열린 이슈의 위치 검색 결과는 0건이었다. 출석 내역 연동 #352는 이번 위치 기반과 목적이 다르다.
- 제품 원문 스프레드시트는 도구에서 접근 실패했다. 상세 출석 정책을 인용하거나 새로 확정하지 않는다.

## 공식 근거

- 후속 사용자 합의: 출석 허용 반경 100m를 예정 기준으로 기록한다. accuracy는 측정 품질 정보로 전달하고 허용 반경에 더하지 않는다. 큰 오차·미확인 오차의 재측정 기준은 후속 API에서 확정한다.
- [Expo Location](https://docs.expo.dev/versions/latest/sdk/location/): foreground 권한, 정밀 권한 메타데이터, 구독·해제, 플러그인 설정과 새 바이너리 필요 조건.
- [Expo runtime versions](https://docs.expo.dev/eas-update/runtime-versions/): 네이티브 모듈 변경 시 바이너리·런타임 호환성 분리와 appVersion 정책.

측정 응답 대기 15초, BUSY 반환은 이 작업의 구현 기본값이며 출석 허용 정책이 아니다.
정책·계약 미결정 항목은 없다. 이슈 생성 승인·단계 리뷰·실기기 접근 여부는 작업 진행 조건이다.
