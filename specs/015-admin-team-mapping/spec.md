# 기능 명세: 관리자 팀 매핑 화면

**브랜치**: `DongjaJ/team-mapping-plan` | **작성일**: 2026-11-02 | **상태**: 1단계 사용자 리뷰 대기
**입력**: Figma 12개 화면과 인터뷰에서 확정한 팀 매핑 화면·입력 구현 계획.
**맥락**: [제품 목적](../../docs/mission.md), [설계 근거와 Figma 대응](research.md).

## 사용자 시나리오와 인수 기준

### US1 — 팀 구성 조회와 탐색 (P1)

운영진은 팀 빌딩 전·배정 중·확정됨 화면에서 팀 구성과 미배정 현황을 확인한다.
우선 이유는 모든 입력 작업의 진입점이기 때문이다. 고정 예시 입력만으로 독립 검증한다.

1. 개발·운영에서 같은 화면 상태로 진입하면 같은 예시 데이터와 조작을 제공한다.
2. 팀이 없으면 빌딩 전 안내와 생성 진입점을 표시한다. 운영도 준비 중 화면으로 대체하지 않는다.
3. 전체·구성 완료·확인 필요·미배정 선택에 맞는 목록과 개수가 표시되고 뒤로가기로 복원된다.
4. PM 또는 Design이 없으면 누락 직군을 경고한다. 다른 직군 누락은 경고 조건이 아니다.
5. 팀명·서비스명·인원·직군별 수·팀원·팀장을 보고 상세 패널을 열 수 있다.

### US2 — 새 팀 입력 검토 (P2)

운영진은 팀명과 팀원을 입력해 생성 예정 구성을 검토한다.
조회 다음으로 팀 구성 입력을 검토할 수 있다. 원본 목록이 유지되는지 독립 검증한다.

1. 팀명은 공백 정리 후 필수, 서비스명은 선택, 팀원은 1명 이상 필수다.
2. 이름·직군으로 검색하고 회원을 추가·제거하면 선택 인원과 직군별 구성이 갱신된다.
3. 다른 팀 소속 후보는 현재 소속과 이동 예정임을 알린다. 동명이인은 식별자로 구분한다.
4. 기존 팀을 0명으로 만드는 후보 선택을 차단한다. 만들기와 Enter 제출은 실제 반영하지 않는다.

### US3 — 상세 패널에서 팀원 변경 예정 검토 (P2)

운영진은 현재 팀의 회원 추가·다른 팀 이동·제외를 선택한다.
팀 간 배정 검토를 완성한다. 원본과 변경 예정의 구분을 독립 검증한다.

1. 상세 패널 안에서 후보를 검색하고 이동 대상 또는 제외를 선택할 수 있다.
2. 원본 팀원 목록·배경 카드·전체 통계를 유지하고 변경 예정만 별도 표시한다.
3. 회원별 예정은 하나이며 최신 선택으로 교체한다. 예정 취소와 전체 취소를 제공한다.
4. 현재 작업의 모든 예정을 합산해 영향받는 기존 팀이 최소 1명을 유지하게 한다.
5. 팀명·서비스명 수정과 팀 삭제는 비활성이며, 팀원 최종 반영도 비활성이다.

### US4 — 미배정 회원의 개별·일괄 대상 선택 (P2)

운영진은 미배정 회원을 고르고 배정 예정 팀을 지정한다.
남은 인원의 배정을 검토한다. 선택 체크와 배정 예정의 분리를 독립 검증한다.

1. 이름·직군·과거 기수 이력과 개별 팀 선택을 제공한다.
2. 일괄 대상 선택은 체크된 회원의 기존 대상을 덮어쓴다. 이후 개별 재지정이 가능하다.
3. 체크 해제는 일괄 대상에서만 제외한다. 기존 예정은 별도 취소로 지운다.
4. 원본 미배정 수·팀 인원은 유지하고 실제 배정 반영은 비활성이다.

### US5 — 초안 보호와 확정 화면 검토 (P2)

운영진은 미반영 초안을 잃기 전에 확인받고, 확정 이력과 편집 모드를 구분한다.
입력 수명과 최종 상태를 검토한다. 생성·패널·미배정 각 작업에서 독립 검증한다.

1. 생성 폼 변경 또는 배정 예정이 있으면 닫기·다른 팀·필터·화면 상태·페이지 이동 전에 확인한다.
2. 검색·체크만 있으면 확인하지 않는다. 초기값으로 되돌린 입력도 확인하지 않는다.
3. 계속 편집은 입력과 현재 화면을 보존하고, 변경 버리기는 초안을 제거한 뒤 요청한 이동을 실행한다.
4. 확정 모달은 원본 기준의 팀 수·배정·미배정·확인 필요 수와 미배정 경고를 표시한다.
5. 확정됨 조회에서 수정하기를 누르면 확정 이력을 유지하며 팀원 배정 편집만 허용한다.
6. 편집 종료 시 변경이 있으면 확인한다. 최종 확정과 실제 성공 처리는 발생하지 않는다.

### 경계 사례

후보·팀·검색·필터 결과 없음, 긴 이름, 동명이인, 마지막 팀원 이동·제외, 예정을 취소해도
다른 예정 때문에 0명이 되는 경우, 입력 원복, 새로고침·탭 닫기, 모바일 패널·확인창 포커스를 검증한다.

## 요구사항

- **FR-001**: 개발·운영에 동일한 읽기 전용 예시 데이터와 화면·입력을 제공한다. 새로고침 시 원본으로 복원한다.
- **FR-002**: 기존 관리자 셸을 유지하고 회원 관리 하위 메뉴·회원 목록 안내에서 팀 매핑에 진입한다.
- **FR-003**: 목록·분류·개수·상세·팀장·과거 기수 표시를 제공하고 필터 탐색을 복원한다.
- **FR-004**: 새 팀 입력과 후보 검색·선택·제거를 제공한다. 팀명과 팀원 1명 이상을 요구한다.
- **FR-005**: PM 또는 Design 누락만 확인 필요로 분류한다. 인원수·다른 직군 누락은 분류 조건이 아니다.
- **FR-006**: 회원별 변경 예정과 취소를 제공하되 원본 목록과 통계는 바꾸지 않는다.
- **FR-007**: 변경 예정 합산 결과 기존 팀을 최소 1명으로 유지한다. 전체 예정 취소는 항상 가능하다.
- **FR-008**: 미배정 회원의 체크·개별 지정·일괄 덮어쓰기를 구분한다.
- **FR-009**: 초안은 현재 작업에만 유지하고 이탈 확인 후 버린다. 다른 팀에 걸쳐 초안을 보관하지 않는다.
- **FR-010**: 확정 요약·이력과 팀원 전용 편집 모드를 제공한다. 확정 상태 자체는 변경하지 않는다.
- **FR-011**: 만들기·배정 반영·삭제·팀 확정·팀 정보 수정의 실제 실행은 비활성이다. 성공 알림은 시각 사례로만 검토한다.
- **FR-012**: 데스크톱·375px과 키보드·스크린 리더·터치 조작을 지원한다. 단계별 검증 결과를 리뷰받는다.

### 핵심 개체

기수별 화면 상태, 후보 회원의 활동, 팀과 소속, 선택적인 확정 이력, 생성 초안, 회원별 변경 예정이다.
원본과 초안은 별도이며 서버 저장 결과를 표현하지 않는다. 기술 표현은 [데이터 모델](data-model.md)에 정의한다.

## 성공 기준

- **SC-001**: 제공된 Figma 12개 상태의 비교 근거와 합의된 차이를 모두 기록한다.
- **SC-002**: 개발·운영에서 3개 화면 상태 및 US1~US5 인수 흐름을 같은 입력으로 재현한다.
- **SC-003**: 모든 최종 실행 경로에서 실제 저장·배정·확정·가짜 성공·원본 변경이 발생하지 않는다.
- **SC-004**: 변경 폐기 경로와 최소 인원 보호 사례가 검증되며 375px에서도 주요 조작을 완료할 수 있다.

## 확정 범위와 가정

화면 표기는 ‘팀 매핑’으로 통일한다. 팀장 지정·해제, 기수 전환, 기존 회원 화면의 데이터 공급 변경,
회원 웹·모바일 반영은 제외한다. 실제 API 연동과 운영 데이터 조회는 후속이다.
팀명 최대 길이·대소문자 중복 규칙·팀별 인원 상한·팀장 필수 정책을 새로 만들지 않는다.
외부 기능명세서·용어 원문은 계획 조사 때 접근되지 않아 사용자 인터뷰와 Figma를 기준으로 한다.
