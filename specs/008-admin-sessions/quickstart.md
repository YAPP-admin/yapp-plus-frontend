# 실행과 검증 가이드

이 문서는 후속 구현 단계에서 사용할 절차다. 현재 구현 완료를 의미하지 않는다.

## 준비

1. `mise.toml`의 Node 24.20.0, package.json의 pnpm 12.3.4를 사용한다.
2. 로컬 mise 설정이 신뢰되지 않았다는 오류가 나오면 이 저장소의 설정을 검토하고 신뢰한 뒤 실행한다.
3. 의존성이 없는 경우 `pnpm install --frozen-lockfile`로 설치한다. lockfile 변경이 생기면 이유를 확인한다.
4. `pnpm --filter @yapp-plus/admin dev`로 실행하고 `http://localhost:3001/sessions`를 연다.

## 단계별 자동 확인

```sh
pnpm --filter @yapp-plus/admin test
node --run check
node --run build
```

각 리뷰 단계에서는 변경 동작의 테스트를 먼저 실행한다. PR 완료 시 전체 check와 앱 build를 수행한다.
테스트는 필터·날짜 검증·모의 저장소, 페이지 상호작용, 실제 라우트 탐색 순으로 가까운 계층에 둔다.

## 브라우저 확인

- 1577px 데스크톱, 1024px, 390px 너비에서 목록과 모달의 정보 위계·가독성·SEED 스타일 일관성을 확인한다. 와이어프레임은 레이아웃 참고로 사용하고 픽셀 일치를 합격 기준으로 삼지 않는다. 390×568에서는 하단 버튼 접근도 확인한다.
- 명세 US1~US4를 따라 전체·유형 조회, 생성 성공·검증 오류, 수정 초기값·저장·취소·실패 재시도, 삭제 취소·성공을 확인한다.
- 긴 이름·장소와 많은 예시 세션에서도 내용과 모든 항목에 접근할 수 있는지 확인한다.
- 수정 후 같은 id·출석 집계가 유지되고 유형·일시 변경이 현재 필터·정렬·개수에 반영되는지 확인한다.
- 필터 뒤로 가기·앞으로 가기, 카드와 메뉴의 독립 동작, 화면 이동 후 데이터 유지, 새로고침 초기화를 확인한다.
- 키보드만으로 열기·입력·오류 수정·Esc·닫기를 실행하고 스크린 리더의 이름·상태 안내를 확인한다.
- 실제 터치 환경과 스크린 리더를 실행하지 못하면 해당 검증을 완료로 기록하지 않는다.
- 지연·실패·재시도는 테스트 대역으로 재현한다. 프로덕션에서는 준비 중 안내와 편집 불가 상태를 확인한다.
- 프로덕션 산출물에서 모의 fixture의 고유 문구와 저장소 구현이 제외되었는지 확인한다.

## 증거와 현재 제한

스크린샷은 `.context/`에 단계별로 저장하고 리뷰 응답에 첨부한다.
최종 실행 명령·성공 여부·미검증 항목은 이 디렉터리의 `validation.md`에 기록한다.
2단계 작성 시점에는 의존성이 설치되지 않아 check가 oxfmt 실행 전에 중단되었다.
앱 코드를 변경하지 않았으므로 이 단계에서 build와 UI 검증은 수행하지 않는다.
