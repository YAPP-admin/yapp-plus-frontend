# 단계별 검증 가이드

## 준비

`mise.toml`·`mise.lock`의 Node.js 24.20.0, `package.json`의 pnpm 12.3.4를 사용한다.
필요한 의존성은 `pnpm install --frozen-lockfile`로 설치한다. 루트 script는 `node --run`으로 실행한다.
제품 코드 작성 전 `docs/frontend-development.md`, `apps/web/AGENTS.md`와 해당 경로 지침을 읽는다.
Modern Web Guidance는 `.agents/skills/modern-web-guidance/SKILL.md` 절차와 저장소 고정 버전 1.0.0을 따른다.

## 1단계 문서

명세 FR과 작업 ID 대응, 링크, 미확정 계약의 진입 차단, 제외 범위, 변경량을 검사한다.
`node --run check`를 실행하고 의존성·환경 문제로 중단되면 실제 실패 지점과 후속 미실행을 기록한다.
제품 코드가 없으므로 빌드·모바일 doctor·실기기 검증은 이번 단계 대상이 아니다.

## 2단계 홈·정규

`node --run dev:web`으로 개발 화면을 열고 기존 MSW를 사용한다. 실제 회원의 출석을 테스트 데이터로 쓰지 않는다.
상태 정책은 단위 테스트, 카드·내비게이션은 기존 화면 테스트에서 확인해 중복 검증을 줄인다.

| 사례                                  | 기대 결과                                |
| ------------------------------------- | ---------------------------------------- |
| 세션 없음, 장소 null/빈 문자열/문자열 | 빈 화면 / 팀 / 정규 / 정규               |
| 다섯 상태 × 두 유형                   | 계약 표 문구·행동 일치, 팀 준비 중 안내  |
| 응답 지연·재조회 실패·오프라인 대기   | 진입 잠금, 이전 데이터 유지와 복구 안내  |
| 정규 코드 성공과 느린 재조회          | 완료 화면 즉시 표시, 홈은 서버 상태 표시 |
| 이전 세션 성공·계정/주차 변경         | 현재 응답을 이전 성공이 덮어쓰지 않음    |
| 신선한 캐시에서 홈 재진입·앱 복귀     | 재조회 발생, 홈에 머무르면 폴링 없음     |
| 네이티브 앱 백그라운드→포그라운드     | 실제 WebView에서 최신 상태 반영          |

공용 훅의 다른 소비자 동작, 완료 직접 진입, 코드·위치 회귀를 확인한다.
상태/오류가 스크린 리더로 전달되는지, 버튼의 비활성화 사유·터치·키보드 포커스를 확인한다.
`node --run check`, `node --run build`와 관련 Storybook 사례를 검증한다.

## 3단계 팀

[회원용 조회 계약 확인표](contracts/attendance-flow.md)를 먼저 충족하고 테스트용 계정·세션을 사용한다.
안내에서 카메라와 보관함을 각각 실행하고 최초 취소, 사진 교체 취소·실패, 본인 해제 방지,
성공 접수, 업로드 실패, 최종 제출 응답 유실, 뒤로가기·새로고침을 확인한다.
사진은 흐름 종료 시 해제되고, 접수 성공이 홈의 체크인 확정으로 오인되지 않아야 한다.
운영 연결 이후에도 서버 `AVAILABLE` 재반환은 일반 제출 흐름으로 처리한다.

## 4단계 통합

이전 단계 이후 변경된 부분과 새 연결 위험만 추가 확인한다. 승인 대기→체크인 상태는 서버 응답 변화로 모의한다.
FCM·승인 팝업·제출 사진 조회는 검증 대상에 포함하지 않는다.
실행 결과는 명령·성공/실패·Turbo 캐시/신규 실행·실기기 여부를 구분해 `validation.md`에 남긴다.
모바일 설정·의존성을 실제 변경한 경우에만 `node --run expo:doctor`를 추가한다.
