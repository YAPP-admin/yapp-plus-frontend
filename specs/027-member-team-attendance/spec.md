# 기능 명세: 최신 API와 회원 팀 출석 운영 연결

**브랜치**: DongjaJ/api-v4 | **작성일**: 2026-11-23 | **상태**: 0단계 문서 리뷰 대기
**기준 이슈**: [#501](https://github.com/YAPP-admin/yapp-plus-frontend/issues/501)
**입력**: 최신 백엔드 반영, 회원 앱 우선, 단계별 리뷰. 사진은 선택 직후 업로드한다.

## 사용자 시나리오와 검증

### US1 — 실제 팀과 제출 가능 여부 확인 (P1)

회원은 자신의 팀원과 기존 사진 제출 여부를 확인하고 올바른 대상으로 인증을 시작한다.
명단 오류나 다른 팀을 대상으로 제출하는 일을 막기 위한 선행 경험이다.
독립 검증은 정상·누락 명단과 기존 사진·조회 실패를 공급해 진입 가능 여부를 확인하는 것이다.

1. 본인 팀을 확인하면 본인이 기본 선택되고 다른 팀원을 선택할 수 있다. 본인은 해제할 수 없다.
2. 기존 사진을 확인하면 심사 중·승인·반려와 관계없이 추가 제출을 막고 운영진 문의를 안내한다.
3. 사진 조회가 실패하면 미제출로 취급해 진행한다. 세션·팀원 조회 실패는 진행을 막는다.
4. 직군이 없는 팀원도 명단에 표시되며 직군은 ‘—’로 표시한다.

### US2 — 선택 즉시 사진 업로드 (P1)

회원은 앨범 또는 카메라로 사진 한 장을 준비하고 참석자를 고르는 동안 업로드를 마친다.
최종 제출 시 사진 전송을 다시 기다리지 않도록 한다.
독립 검증은 최종 접수 없이 선택·교체·취소·업로드 실패와 재시도를 확인하는 것이다.

1. 안내에서 고른 앨범·카메라는 진입 조건 확인 후 한 번 열리고, 취소하면 업로드 화면에 남는다.
2. 사진 준비 성공 직후 업로드를 시작한다. 업로드 중 사진 변경·최종 제출은 막고 참석자 선택은 허용한다.
3. 사진 선택 취소·준비 실패는 기존 사진을 유지한다. 새 사진 준비 성공 후에는 이전 사진을 제출하지 않는다.
4. 업로드 실패 시 현재 사진을 유지하고 다시 업로드할 수 있다. 새 사진의 업로드 성공 전 제출은 불가능하다.

### US3 — 업로드한 사진과 참석자 접수 (P1)

회원은 최신 팀원 명단과 선택한 사진으로 인증을 접수하고 서버가 확인한 결과만 본다.
독립 검증은 업로드 완료 입력으로 명단 변경·최종 접수·응답 유실을 확인하는 것이다.

1. 제출 직전 확인에서 같은 팀의 명단이 바뀌면 사진은 유지하고 본인만 다시 선택한다. 자동 제출하지 않는다.
2. 다른 팀 또는 다른 출석 세션으로 바뀌거나 계정이 바뀌면 사진을 포함한 초안을 모두 폐기한다.
3. 최종 제출은 이미 업로드한 사진을 사용한다. 서버 접수 성공 후 팀·참석자·제출 시각과 심사 대기를 표시한다.
4. 접수 후 조회 실패는 접수 성공을 취소하지 않는다. 접수 여부가 불명확하면 재제출을 막고 홈 복귀를 안내한다.

### US4 — 유형별 홈 출석과 최신 상태 (P1)

회원은 정규 세션에서는 코드·위치 기반 출석을, 팀 세션에서는 사진 인증을 사용한다.
유형에 맞지 않는 출석 요청을 막고 서버의 승인·정정 결과를 확인한다.
독립 검증은 세션 유형과 모든 출석 상태의 조합, 홈·앱 복귀를 확인하는 것이다.

1. 정규 세션의 출석 가능 상태는 코드 출석, 팀 세션의 출석 가능 상태는 팀 인증 안내로 연결한다.
2. 출석 완료·심사 중·대상 아님·시작 전·세션 없음 상태에서는 새로운 출석을 시작하지 않는다.
3. 본인이 출석 가능해도 기존 팀 사진이 확인되면 홈에서 제출됨을 표시하고 버튼을 비활성화한다.
4. 제출 직후와 홈·앱 복귀 시 상태를 갱신한다. 과거 성공 기억이 최신 서버 정정을 덮어쓰지 않는다.

### 경계 조건

사진 조회 오류와 화면 이탈에 따른 취소를 구분한다. 취소한 행동은 후속 전송을 시작하지 않는다.
직접 URL 진입, 완료 정보 없는 진입, 사진 도구 취소·권한 거부, 업로드 중 이탈, 늦은 응답,
명단 순서만 변경된 응답, 접수 응답 유실, 조회 실패 뒤 재시도를 검증한다.

## 요구사항

- **FR-001**: 확인된 세션 유형으로 출석 경로를 구분하며 팀 세션에서 코드·위치 출석을 시작하지 않는다. (US4)
- **FR-002**: 현재 본인과 선택 가능한 팀원만 표시·제출하고 사용자 ID나 이름으로 소속 ID를 추정하지 않는다. (US1)
- **FR-003**: 기존 사진을 확인한 경우만 추가 제출을 차단하며 사진 조회 실패는 미제출로 취급한다. (US1)
- **FR-004**: 사진 조회 실패 허용은 세션·팀원·업로드·최종 접수의 실패에 확대하지 않는다. (US1·US3)
- **FR-005**: 안내의 사진 도구 선택은 한 번만 실행하고 세션 시작·종료 시간을 실제 값으로 표시한다. (US2)
- **FR-006**: 준비한 사진은 즉시 업로드하고 최종 접수에서 같은 사진을 다시 업로드하지 않는다. (US2·US3)
- **FR-007**: 새 사진 준비 성공 시 이전 업로드 결과를 폐기하고 실패한 새 사진 대신 이전 사진을 제출하지 않는다. (US2)
- **FR-008**: 업로드 실패의 명시적 재시도를 제공하며 업로드 중·최종 접수 중 중복 행동을 막는다. (US2·US3)
- **FR-009**: 같은 팀의 실질적인 명단 변경은 사진 유지·본인 재선택, 팀·세션·계정 변경은 전체 폐기를 적용한다. (US3)
- **FR-010**: 유효한 접수 성공만 완료로 표시하고 결과 불명에서는 자동·수동 재제출을 막는다. (US3)
- **FR-011**: 완료 직접 진입에서 접수 정보를 만들지 않고 홈 복귀를 제공한다. (US3)
- **FR-012**: 홈·앱 복귀와 접수 성공 직후 최신 상태를 조회하며 주기적 조회는 추가하지 않는다. (US4)
- **FR-013**: 사진·인증정보·서명 URL을 로그·영구 저장소에 남기지 않고 초안은 화면 흐름 수명에 한정한다. (US2·US3)
- **FR-014**: 키보드·터치·VoiceOver로 선택·진행·실패·완료를 확인할 수 있어야 한다. (US1~US4)

### 주요 개체

- 제출 대상: 출석 세션, 본인 팀, 본인 소속 식별자, 선택 가능한 팀원.
- 사진 초안: 현재 사진·미리보기·업로드 상태. 최신 사진의 성공한 업로드만 접수할 수 있다.
- 참석 명단: 본인을 포함한 현재 선택. 명단 변경 시 재확인이 필요하다.
- 접수 확인: 제출 식별자·시각·참석자·심사 대기. 출석 승인과 구분한다.

## 성공 기준

- **SC-001**: 정규·팀 유형과 모든 출석 상태의 수용 사례에서 잘못된 출석 경로 진입이 0건이다.
- **SC-002**: 사진 준비 성공 후 최종 버튼을 누르기 전에 업로드가 시작되고, 최종 접수에서 재업로드가 0건이다.
- **SC-003**: 기존 사진 확인 시 추가 제출이 0건이며, 사진 조회 실패만으로 진입을 차단하지 않는다.
- **SC-004**: 교체·팀 이동·계정 변경·응답 유실 사례에서 이전 사진 제출·거짓 완료·자동 재제출이 0건이다.
- **SC-005**: 홈·앱 복귀 후 서버 승인·정정 결과를 확인하며 자동 검증과 사용자 실기기 확인을 구분해 기록한다.

## 전제와 제외 범위

- 기존 iOS 사진 입력·인증·위치 확인을 재사용한다. 일반 브라우저는 개발 화면 검증만 한다.
- 사진 열람 화면·반려 후 재제출·승인 팝업·FCM·회식·관리자 기능 전환·배포는 제외한다.
- 교체·미접수 사진의 서버 정리는 백엔드 정책에 맡긴다. 별도 동시 제출 잠금·서버 변경은 하지 않는다.
- 실제 사진 제출은 자동 검증 후 사용자가 지정한 테스트 세션에서 직접 확인한다.
- 이전 [사진 제출 명세](../023-team-attendance-submit/spec.md)의 개발 전용·최종 버튼 업로드 제약은
  이번 승인된 범위에서 대체한다. 운영 진입은 6단계 전까지 차단한다.
- #501의 장소 기반 임시 판별과 사진 조회 제외는 이번 대화의 유형 필드 사용·기존 제출 확인용 조회로 대체한다.
