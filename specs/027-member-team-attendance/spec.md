# 기능 명세: 회원 팀 출석 운영 연결

기준 이슈: #501. 2026-11-24 사용자 리뷰에서 확정한 범위다.
초기 조사와 단계별 변경 이력은 [검증 기록](validation.md)에 보존한다.

## 사용자 흐름

1. 홈은 주간 조회의 세션 type과 본인 attendanceStatus로 출석 경로를 결정한다.
2. REGULAR + AVAILABLE은 코드·위치 출석, TEAM + AVAILABLE은 사진 안내로 연결한다.
3. 안내에서 앨범·카메라를 누르면 브리지를 호출한다. 취소하면 안내에 남고 성공하면 업로드 화면으로 이동한다.
4. 선택 사진은 Context의 File·미리보기 URL로 보관하며 실제 팀원을 조회한다. 본인은 기본 선택·해제 불가다.
5. 최종 제출 버튼에서 체크섬 생성 → presign → PUT → 사진 키·참석 명단 접수를 순서대로 실행한다.
6. 유효한 201 접수 결과가 있어야 완료 화면을 표시한다. 접수는 운영진 승인과 구분한다.
7. 홈으로 돌아오면 최신 서버 상태를 표시한다. 과거 코드 출석 성공 기록으로 서버 정정을 덮어쓰지 않는다.

## 조회·오류 정책

- TEAM의 PENDING_APPROVAL에서만 사진 상세를 조회한다. 사진은 팀 기준, 출석 상태는 본인 기준이다.
- 사진 없음·첫 조회 실패에도 검토 중 상태를 유지한다. 사진 존재 여부로 제출 가능 여부를 추정하지 않는다.
- 주간·사진 재조회 실패는 기존 데이터를 유지한다. 별도의 오류 안내·버튼 차단을 추가하지 않는다.
- 첫 주간 조회 실패는 오류 안내·재시도, 팀원 조회 실패는 안내 문구만 제공한다.
- 사진 선택·업로드·접수 진행은 Mutation이 소유한다. 제출 중 입력·중복 제출을 막는다.
- 결과 불명은 완료로 표시하지 않고 재제출을 막으며 홈 복귀를 안내한다.
- 홈·앱 복귀 시 주간 상태를 강제 갱신한다. 다른 화면의 stale 정책은 유지하고 polling은 하지 않는다.
- 제출 함수에서 세션 유형·가능 여부를 다시 검사하거나 팀원·사진을 명령형 재조회하지 않는다.
  서버가 최종 접수 가능 여부를 판정한다.

## 수명과 진입

- Activity에는 sessionId만 전달하고 사진·File·서명 URL을 경로에 넣지 않는다.
- 안내·업로드는 sessionId가 필요하며 로그인 또는 개발 모킹 환경에서만 허용한다. 정적 모드는 차단한다.
- 선택 사진 없는 입력 화면, 접수 정보 없는 완료 단계는 성공 정보를 만들지 않는다.
- 완료·이탈·계정 변경 시 사진 초안을 폐기하고 object URL을 해제한다. 늦은 결과가 이전 흐름을 이어가지 않게 한다.

## 제외·보류

즉시 업로드, initialPhotoSource Effect 실행, 별도 Query 래퍼, 사진 존재 기반 제출 차단,
제출 직전 명단 비교·팀 이동 자동 초기화, 모의 업로드 서비스는 이번 범위에서 제외한다.
조회·제출 계약과 기존 브리지·생성 API를 재사용하고 새 의존성은 추가하지 않는다.
실제 iPhone 카메라·앨범·접수·승인 후 복귀·VoiceOver는 사용자 요청으로 보류한다.
자동 검증 완료를 실기기 검증 완료로 간주하지 않는다.
