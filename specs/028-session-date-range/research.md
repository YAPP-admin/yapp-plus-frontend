# Research: 세션 시작일·종료일 분리

## Decision

관리자 세션 계약의 날짜 필드를 `date`에서 `startDate`·`endDate`로 변경하고, 시작 날짜와 종료 날짜가 같은 경우에만 시간 순서를 비교한다. 서로 다른 날짜라면 종료 시간이 더 이르더라도 전체 종료 일시가 늦으면 유효하다.

## Rationale

- 사용자가 요청한 날짜 범위를 데이터 손실 없이 저장하려면 생성·수정 요청과 목록 응답 모두에 두 값이 필요하다.
- `YYYY-MM-DD`와 `HH:mm`은 고정 폭 ISO 형식이므로 문자열로 합친 값의 사전식 비교가 일정 순서를 보존한다.
- 날짜는 한국 시간의 달력 값이므로 `Date` 객체로 변환하면 브라우저 시간대에 따라 날짜가 바뀔 수 있다.

## Alternatives Considered

- `date` 하나를 유지하고 종료일을 화면 상태로만 두는 방식은 서버 저장 시 종료일이 유실되므로 제외했다.
- 시작·종료를 단일 ISO datetime으로 바꾸는 방식은 기존 API의 날짜·시간 입력과 초 단위 보존 정책을 불필요하게 바꾸므로 제외했다.
- `Temporal`을 도입하는 방식은 런타임 지원·polyfill 범위를 늘리며, 이 변경에는 날짜 산술이 없어 현재의 검증된 ISO 문자열 경계를 유지한다.

## Contract Dependency

백엔드 OpenAPI 원본은 이 저장소에 없으므로, 이 프론트 변경을 실서버에 적용하기 전에 원본 명세와 백엔드 DTO·저장 모델이 `startDate`·`endDate`를 지원해야 한다. 현재 작업은 그 계약을 소비하는 프론트와 개발 mock을 일관되게 갱신한다.
