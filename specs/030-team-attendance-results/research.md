# 조사: 팀 세션 출석 결과 안내

## 확인 근거

- 프론트엔드 조사 기준 HEAD: `affe8668736d03eddc3ba97edea37ab1160e3f15`.
  최신 origin/main `aa301502c2b2473b1741bb94363094700c684dae`까지 8개 커밋의 차이가 있으며,
  입력·목록의 오류 경계와 인증 오류 전파·사진 제출 테스트가 변경됐다.
- 기존 #501은 승인 팝업·반려 상세를 제외한다. 이번 작업은 #622로 구분한다.
- 생성 SDK·타입과 기존 홈·사진 제출·출석 내역 코드를 확인했다. backend/dev의
  TeamAttendancePhoto·AttendanceHistory 구현도 읽었지만 실제 배포 SHA와 동일하다고 간주하지 않는다.
- 제공된 Figma 세 노드의 스크린샷과 디자인 컨텍스트를 확인했다.

## 조회의 구분

- find7: 현재 기수 전체 세션과 generationId. 본인 내역과 sessionId 교집합을 사용한다.
- find8: 본인 attendanceStatus·staffDecisionStatus. 시작된 세션만 최신순으로 반환하며 커서가 있다.
- find1: 팀의 최신 photoId·status·rejectionReason. 정상 photo:null과 실패를 구분한다.
  imageUrl:null은 사진 삭제·만료일 수 있으며 photoId를 없애지 않는다.
- find6: 현재 홈 세션의 제출 가능 상태. 같은 sessionId의 AVAILABLE만 재업로드 진입 근거로 쓴다.
- 최종 제출 성공은 현재 find6·find1만 무효화하므로 find8의 실제 소비 Query key도 추가해야 한다.

## 시작 전 결과의 계약 공백

제출은 세션 시작 20분 전부터 가능하지만 find8은 시작된 세션만 제공한다. find1에는 본인 선택
여부가 없고 find6.AVAILABLE은 미제출·반려를 구분하지 못한다. 사용자는 기존 API를 유지하고
세션 시작 이후 홈 진입·복귀부터 안내하기로 선택했다. 시작 전 결과를 추정하거나 별도 API를
추가하지 않으며, 시작 시각 자동 갱신을 위한 타이머도 두지 않는다.

## Modern Web Guidance

modern-web-guidance@1.0.0의 dialog·accessibility를 조회했다. 포커스 이동·복귀와 제목 연결을
검증하되 프로젝트의 SEED·Stackflow 계약이 우선한다. native dialog용 속성·수동 포커스 트랩을
기존 BottomSheet 위에 중복 추가하지 않는다. 구현 단계에서 해당 가이드 준수와 실제 WebView를 확인한다.
