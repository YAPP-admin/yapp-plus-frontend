# 구현 계획: 회원 앱 PostHog 도입

**브랜치**: `DongjaJ/posthog` | **작성일**: 2026-11-28 | **명세**: [spec.md](spec.md)

## 요약

웹은 행동 이벤트 24개·자동 클릭·페이지뷰·마스킹된 녹화, iOS는 별도 단계에서 오류·크래시만 담당한다.
원문 40개를 계약으로 보존하며 미구현·서버 이벤트 16개는 보류한다.
관련 이슈는 [#669](https://github.com/YAPP-admin/yapp-plus-frontend/issues/669)이며 정식 명세 경로는 `specs/031-member-posthog/`다.

## 기술 맥락

- 언어·도구: TypeScript, React 19, Vite·Stackflow, Expo 58.1·React Native 0.88.1, Node 24.20.0·pnpm 12.3.4.
- 의존성: 웹 `posthog-js`·`@posthog/react`; iOS `posthog-react-native`·`@posthog/react-native-plugin` 및 필요한 Expo 모듈. catalog·lockfile에 호환 버전을 고정한다.
- 저장: PostHog SDK의 식별·전송·녹화 기능을 사용한다. 별도 분석 DB·전송 큐·공용 분석 패키지는 만들지 않는다.
- 검증: Vitest·Testing Library로 데이터 변환·동작을 검증하고, 실제 프로젝트·iOS 릴리스에서 수신·마스킹·심볼 해석을 확인한다.
- 성능: 기존 사용자 작업을 분석 전송 때문에 기다리게 하지 않으며 숨겨진 화면의 timer·observer를 중단한다.
- 제약: SDK 전송 실패를 제품 오류로 전파하지 않는다. 비밀 업로드 키는 클라이언트 산출물에 포함하지 않는다.

## 구조와 책임

- 웹 `src/app`: SDK 단일 초기화와 `PostHogProvider`, 인증 식별·초기화 조합.
- 웹 `src/shared`: 도메인 비의존 설정·전송·활성 시간 측정. 도메인 이벤트 타입·변환은 기존 `pages`/`features` 소유 슬라이스에 둔다.
- React 외부 인증 처리에는 초기화된 분석 콜백을 주입한다. 기능 슬라이스끼리 직접 import하거나 화면마다 SDK를 초기화하지 않는다.
- `packages/app-bridge`: 선택적 앱 생명주기 계약. 웹의 Stackflow 활성 화면·탭과 함께 노출을 판정한다.
- 모바일: 기존 인증·알림 런타임 옆에 iOS 오류 수집을 초기화하고 기존 Expo 설정·배포 경로를 확장한다.
- 산출물: `spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`, `checklists/requirements.md`. 1단계 리뷰 후 작성한 세부 작업 목록은 `tasks.md`를 따른다.

## 연결 방식

1. 웹은 Provider와 `usePostHog`을 사용한다. 사용자 동작은 handler·mutation 결과에서, 화면 노출은 활성 상태 변화에서 수집한다.
2. 내부 userId를 문자열로 identify한다. 신규 등록 토큰만 있으면 익명 유지하고, userId 확보 후 식별한다. 토큰 갱신·sessionId 변경만으로 reset하지 않는다.
3. 실제 로그아웃·계정 변경·탈퇴 시 식별과 녹화를 분리한다. 탈퇴 성공 기록은 reset 전에, 로그아웃 확인 클릭 기록은 클릭 시 전송한다. 늦은 계정별 요청 결과는 기존 인증 작업 유효성 검사에 맞춘다.
4. `appLifecycleState`와 document visibility를 합성하고 활성 상태가 실제로 바뀔 때만 화면 노출을 기록한다. 홈은 전면 복귀도 포함한다. 읽기 시간은 단조 증가 시계로 활성 구간만 누적한다.
5. 자동 페이지뷰는 SDK history 감지를 이용하고 동일 경로 정규화 알림은 중복 제거한다. 명시적 화면 이벤트와 페이지뷰를 합산해 동일 지표로 쓰지 않는다.
6. 명시적 속성은 허용 목록으로 구성한다. 자동 이벤트·녹화에 별도 마스킹을 적용하고 입력·동적 속성·사용자 이미지를 검사한다. 콘솔·네트워크 본문/헤더·캔버스·웹 오류 자동 수집은 끈다.
7. 푸시는 기존 소비자의 처리 요청 단위로 중복 제거한다. acknowledge 재시도와 이미 목적지인 경우를 처리하고 eventId를 영구 키로 저장하지 않는다.

## iOS 오류·배포

- 처리되지 않은 JS 예외·Promise 거부와 native crash를 켠다. 행동·화면·앱 생명주기 자동 이벤트·네이티브 녹화·콘솔 오류 수집은 끈다. Android 수집은 비활성화한다.
- Expo용 Metro 설정과 `posthog-react-native/expo` 설정 플러그인으로 JS 소스맵·iOS dSYM 업로드를 연결한다. 필요한 native plugin을 설치하며 생성 ios/android 파일을 직접 수정하지 않는다.
- EAS native build 업로드와 OTA 업로드를 구분한다. OTA는 실제 배포할 export 산출물의 소스맵을 업로드하고 같은 산출물을 배포한다. 재export한 다른 번들의 맵을 사용하지 않는다.
- 업로드 실패는 배포를 중단한다. 고정된 PostHog CLI와 최소 권한 업로드 키를 CI/EAS에만 제공한다. 오류에 앱 버전·빌드·runtime·OTA update ID·배포 SHA를 연결한다.
- 앱 버전은 현재 1.0.9에서 1.0.10으로 올리고 appVersion runtime 정책을 유지한다. 반영 전 다른 작업이 버전을 올렸다면 충돌 없이 다음 미사용 버전으로 조정한다. 새 native 모듈용 OTA가 이전 runtime에 전달되지 않게 한다.
- 기존 main 검증·iOS TestFlight build/submit 분리를 유지한다. 새 바이너리는 별도 배포 절차를 거치며 Android 배포 파이프라인은 추가하지 않는다.

## 복구

- 웹: 녹화는 프로젝트 설정에서 중단, 전체 수집은 환경 변수로 비활성화 후 검증된 main 커밋으로 배포한다.
- 브리지: 필드는 선택적이므로 이전 native에서 visibility fallback을 유지한다.
- iOS: 수집을 끈 호환 runtime OTA 또는 이전의 정상 호환 OTA로 복구한다. native 시작 크래시는 OTA가 적용되기 전에 발생할 수 있으므로 수정 바이너리 배포 경로도 유지한다.
- 데이터: API·DB 마이그레이션은 없다. 잘못 수집된 이벤트의 분석 제외·삭제는 별도 영향 확인과 승인 후 수행한다.
