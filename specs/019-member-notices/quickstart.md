# 검증 가이드

## 준비와 명령

고정 mise 도구와 lockfile을 사용한다. 현재 단계는 문서만이며 제품 검증은 각 구현 단계에서 실행한다.
개발 브라우저는 apps/web/README.md의 VITE_API_MOCKING 설정을 사용한다. 인증·개인 데이터는 fixture나 로그에 기록하지 않는다.

```sh
mise exec -- pnpm install --frozen-lockfile
mise exec -- pnpm --filter @yapp-plus/web test
mise exec -- node --run check
mise exec -- node --run build
mise exec -- node --run dev:web
```

변경한 인접 테스트부터 실행한 뒤 check/build를 수행한다. 동일 결과를 불필요하게 반복 검증하지 않는다.

## 화면과 실환경

- 좁은 화면·확대·라이트/다크·safe-area에서 로딩·오류·긴 본문·이미지 실패를 확인한다.
- 필터 키보드 이동·선택·포커스, 링크/읽음 버튼 접근성 이름·비활성·오류 안내를 확인한다.
- 실제 WebView에서 로그인 → 홈 → 상세 → 읽음 → 게시판 → 상세 재진입을 확인한다.
- Native 뒤로가기·백그라운드 복귀·네트워크 단절/복구·계정 전환·VoiceOver/TalkBack·터치는 별도 기록한다.
- mock·실제 인증·S3·실기기 성공을 구분한다. 실서버 읽음은 승인된 테스트 회원·공지에서 수행한다.

## 결과 기록

validation.md에 명령·성공/실패·새 실행/캐시·미실행 이유·남은 위험을 기록한다.
스크린샷은 .context/에 저장한다. 브라우저 캡처를 실기기 음성 조작의 근거로 대체하지 않는다.
문서·코드·테스트·lockfile·untracked를 포함한 실제 base 대비 추가·삭제 합계를 단계 리뷰에 제출한다.
