# 상태와 수명

| 개념                         | 소유자·수명                            | 저장 여부                       |
| ---------------------------- | -------------------------------------- | ------------------------------- |
| 승인된 세션                  | 기존 SessionManager, 기존 자동 복원    | 기존 SecureStore 형식 유지      |
| 현재 제한 결과               | AuthActions, native 프로세스           | 저장하지 않음                   |
| 마지막 대기 계정 ID          | AuthActions, native 프로세스           | 저장하지 않음                   |
| 웹 인증 결과                 | 기존 QueryClient 인증 캐시             | 브라우저 저장소에 추가하지 않음 |
| 로그인 복귀 Dialog·진행 상태 | 해당 Activity와 기존 로그아웃 mutation | 로컬 상태만                     |

## 전이

- PENDING 수신: 사용자·상태 검증 → 이전 세션 정리 → 현재 제한 결과와 대기 ID 기록 → 대기 화면.
- REJECTED/null 수신: 이전 세션 정리 → 현재 제한 결과 기록 → 에러 화면. 대기 이력은 정리한다.
- 잘못된 응답: INVALID_RESPONSE → 로그인·가입의 기존 오류 안내를 유지한다. 정상 세션으로 확정하지 않는다.
- 대기 뒤로가기 취소: 변화 없음. 확인: 현재 제한 결과 정리 → SIGNED_OUT → Login.
- 제한 화면에서의 로그아웃만 대기 ID를 보존한다. 정상 로그인 뒤의 일반 로그아웃은 이력을 보존하지 않는다.
- APPROVED 수신: 같은 대기 ID이면 PENDING_TO_APPROVED와 함께 정상 세션 확정, 다르면 NONE을 포함한 일반 정상 로그인.
- 승인 세션 확정 성공 시 대기 ID를 소비한다. 저장 실패·인증 취소·일시 네트워크 실패는 성공으로 소비하지 않는다.
- 다른 계정의 PENDING은 대기 ID를 교체한다. 다른 계정의 승인·거절·신규 가입 필요 결과는 이전 이력을 정리한다.
- 완전 종료: 메모리 제한 결과·대기 ID 소멸. 새 대기 계정의 저장 세션이 없으므로 재실행은 Login.
- 백그라운드 복귀·WebView 재연결: native 프로세스가 살아 있으면 getSession으로 제한 결과 유지.

## 경합·실패 불변식

현재 인증 세대에 해당하는 결과만 반영한다. 제한 상태 확정도 웹의 인증 의도 확정으로 다뤄
이전 readAuthSession 결과·업무 캐시가 정상 로그인을 복원하지 못하게 한다.
세션 정리는 기존 직렬화·세대 검사 경계를 사용한다. 삭제 실패 시 메모리 인증을 차단하고
기존 STORAGE 복구 경로를 유지하며 제한 결과 확정이나 로그인 복귀 성공으로 보고하지 않는다.
제한 계정에 반환된 access/refresh token은 저장·웹 전달·진단 로그에 사용하지 않는다.
서버가 발급한 미사용 토큰의 서버측 수명은 기존 서버 정책을 따른다. 새 revoke 정책은 추가하지 않는다.

## 호환 예외

기존 저장 세션은 승인 상태 없이도 기존 refresh 경로로 복원한다. 이를 APPROVED를 확인한 결과로
표현하지 않는다. 복원 결과의 reviewTransition은 NONE이다. 기존 가입 완료·홈 동작은 새 응답을
판정하는 경로와 구분해서 테스트한다.
