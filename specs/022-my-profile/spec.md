## 사용자 시나리오와 검증

### US1 — 서버에 등록된 내 프로필을 확인한다 (P1)

회원은 마이페이지에서 자신의 이름·회원 상태·기수·직군을 확인한다.
이 화면의 핵심 목적이며, 정상 프로필과 소속 없는 프로필을 공급해 독립적으로 확인할 수 있다.

1. 로그인 때 받은 이름과 최신 프로필 이름이 다르면 최신 프로필 이름만 표시한다.
2. 프로필을 아직 받지 않았다면 이름을 포함한 네 항목을 `—`로 표시한다.
3. 소속 없는 회원은 이름만 표시하고 나머지 항목은 `—`로 표시한다.
4. 직군만 없는 회원은 이름·회원 상태·기수를 표시하고 직군만 `—`로 표시한다.
5. 기수는 서버가 선택한 소속의 표시 번호에 `기`를 붙인다. 다른 소속을 임의로 선택하지 않는다.

### US2 — 프로필 조회가 실패해도 마이페이지를 이용하고 복구한다 (P1)

회원은 프로필 처리 상태를 이해하고 재시도하면서 출석 현황과 메뉴를 계속 이용한다.
프로필만 지연·실패시키고 출석 조회는 성공시키는 조건으로 독립적으로 검증한다.

1. 최초 조회 중에는 `—`와 로딩 안내를 표시하며 출석 현황·출석 내역·출석 규칙은 사용 가능하다.
2. 최초 조회 실패에는 `—`와 오류·재시도를 표시한다. 다시 시도하여 성공하면 프로필이 표시된다.
3. 이전 조회 성공 후 재조회가 실패하면 마지막 성공 프로필을 유지하고, 다음 화면 복귀에서 다시 조회한다.
4. 프로필 재시도는 최초 실패 상태에서만 제공하며 출석 현황을 재시도하거나 초기화하지 않는다.
5. 출석 현황이 실패해도 프로필 조회와 표시는 유지한다.

### US3 — 현재 로그인한 계정의 정보만 확인한다 (P1)

회원은 화면 복귀 시 기존 갱신 정책에 따라 프로필을 확인하고 다른 계정의 정보를 보지 않는다.
미로그인·로그아웃·계정 전환과 화면 복귀를 각각 재현해 독립적으로 검증한다.

1. 인증 없는 일반 브라우저에서는 프로필을 요청하지 않고 앱 로그인 안내를 표시한다.
2. 로그아웃 또는 계정 전환 후 이전 계정의 프로필이나 늦게 도착한 응답이 표시되지 않는다.
3. 오래된 정보가 있는 화면에 복귀하면 프로필을 갱신한다. 방금 확인한 정보는 기존 정책대로 유지한다.
4. 개발용 시연은 개발 환경에서만 허용하고 운영 화면에 가상 회원을 표시하지 않는다.

### 경계 사례

- 지원하지 않는 회원 상태·직군, 필수 정보 누락, 잘못된 응답은 정상 프로필로 표시하지 않는다.
- 인증 만료는 기존 로그인 복구 흐름을 따른다. 데이터 충돌·서버 장애는 프로필 오류로 표시한다.
- 긴 이름과 작은 화면에서도 회원 상태·기수·직군과 재시도 기능을 확인할 수 있어야 한다.
- 프로필 이미지·출석 점수·면제권·메뉴의 정책은 이번 작업으로 변경하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: 이름의 표시 출처는 검증된 본인 프로필이어야 하며 로그인 세션 이름으로 대체하지 않는다.
- **FR-002**: 회원 상태·기수·직군을 표시하고 소속 정보가 없으면 해당 항목만 `—`로 표시한다.
- **FR-003**: 회원 상태·직군 표기는 기존 Android 앱과 일치시킨다. 세부 표는 [데이터 모델](data-model.md)에 둔다.
- **FR-004**: 최초 로딩·최초 실패·성공·미로그인 상태를 구분해 안내한다. 재조회 실패에는 마지막 성공 값을 유지한다.
- **FR-005**: 프로필과 출석 현황은 최초 로딩·실패·재시도 상태를 독립적으로 처리해야 한다.
- **FR-006**: 인증된 본인의 프로필만 표시하고 로그아웃·계정 전환 시 이전 프로필을 제거한다.
- **FR-007**: 화면 복귀 시 기존 갱신 정책을 적용하고 정상 조회 없이 가상 성공을 표시하지 않는다.
- **FR-008**: 키보드·터치로 재시도할 수 있고 보조 기술이 상태와 오류를 인식할 수 있어야 한다.
- **FR-009**: 개발 시연은 운영과 분리하며 기존 출석 조회·규칙 안내·내역 이동을 유지한다.

### 주요 개체

- **본인 프로필**: 현재 계정의 이름과 서버가 선택한 소속 정보. 회원 상태는 관리자 권한과 다르다.
- **소속 표시 정보**: 회원 상태·기수 표시 번호·선택적 직군. 소속 선택 책임은 서버에 있다.
- **조회 상태**: 최초 로딩·성공·오류와 재조회 여부. 마지막 성공 값은 같은 계정 안에서만 유지한다.

## 성공 기준

- **SC-001**: 정상·소속 없음·직군 없음 사례에서 네 표시 항목이 모두 기대값과 일치한다.
- **SC-002**: 로딩·최초 실패 중에도 출석 내역 이동과 출석 규칙 안내를 사용할 수 있다.
- **SC-003**: 최초 실패 후 재시도 성공 시 화면 전체를 다시 열지 않고 프로필이 표시된다.
- **SC-004**: 미로그인·로그아웃·계정 전환 사례에서 다른 계정의 프로필 표시가 한 번도 발생하지 않는다.
- **SC-005**: 키보드와 터치로 재시도할 수 있고 작은 화면에서도 핵심 프로필과 오류 안내를 확인할 수 있다.

## 가정과 범위

- 최신 서버의 본인 프로필 조회를 사용하며 인증 방식이나 소속 선택 정책을 새로 만들지 않는다.
- 이름을 로그인 세션에서 보완하지 않는 정책과 이슈 생성은 사용자가 명시적으로 선택·승인했다.
- 기존 기본 프로필 이미지와 Android의 표시 용어를 유지한다. 프로필 편집·사진·새 권한 표시는 제외한다.
- 공용 생성 코드 최신화와 필요한 소비 코드 호환성 수정은 포함하되 다른 기능을 새로 연결하지 않는다.
- 구현은 [계획](plan.md)의 네 리뷰 단계로 진행하며 각 단계 승인 후 다음 단계에 들어간다.
