# 기능 명세: 회원 웹의 오류 격리와 복구

**작업 브랜치**: `DongjaJ/sgbp0` — 이름 유지

**작성일**: 2026-11-25

**상태**: 공식 등록 — 구현 완료·최종 검토 대기

**요청**: 조회한 콘텐츠와 오류 화면의 중복 표시를 없애고, 일반 오류는 해당 영역에서 복구하며
인증 오류는 로그인으로 연결한다. 오류 안내의 디자인과 행동을 통일하고 단계별로 리뷰한다.

## 사용자 시나리오와 검증

### US1 — 실패한 영역만 복구하기 (P1)

회원은 조회가 실패한 영역에서 일관된 안내와 다시 시도를 보고 다른 정상 영역은 계속 사용한다.
기존 데이터 옆에 전체 오류 안내가 붙어 어떤 상태인지 알기 어려운 문제를 해결한다.

**독립 검증**: 일정·프로필의 조회 성공 후 재조회를 실패시키고 오류 표시와 재시도 결과를 확인한다.

1. 처음 조회가 실패하면 해당 영역은 오류 안내와 다시 시도를 표시한다.
2. 조회 성공 뒤 일반 재조회가 실패하면 실패한 영역의 기존 내용을 숨기고 오류 안내로 교체한다.
3. 재시도가 진행되면 해당 영역에 로딩 안내를 표시하고 성공 후 최신 내용을 표시한다.
4. 프로필만 실패하면 출석 현황·메뉴 등 독립된 정상 영역을 유지한다.
5. 다시 시도가 반복 실패해도 자동 반복 요청 없이 수동 재시도를 제공한다.
6. 정상 콘텐츠는 화면 복귀만으로 초기화하지 않는다. 기존 화면 복귀 조회 정책을 유지한다.

### US2 — 인증이 필요한 경우 로그인으로 이동하기 (P1)

회원은 유효한 인증을 확인할 수 없는 업무 요청에서 일반 오류 화면에 갇히지 않고 로그인으로 이동한다.

**독립 검증**: 조회·제출 인증 실패와 동시 실패가 기본 로그인으로 수렴하는지 확인한다.

1. 조회의 기존 인증 갱신이 성공하면 현재 화면을 유지한다.
2. 갱신 후에도 인증 오류가 남거나 업무 제출에서 인증 오류가 발생하면 기본 로그인 화면으로 이동한다.
3. 이동 이유를 위한 추가 안내·팝업은 표시하지 않는다. 로그인 자체의 실패 안내는 유지한다.
4. 로그인 이동 중과 이동 후 뒤로가기에서도 보호 콘텐츠를 표시하지 않는다.
5. 동시에 여러 인증 오류가 발생해도 중복 이동이나 로그인·회원 화면 왕복이 발생하지 않는다.
6. 일반 권한 부족·네트워크·서버 오류는 로그인으로 이동시키지 않는다.

### US3 — 추가 목록 조회 실패에서 이어보기 (P2)

회원은 다음 항목을 가져오지 못해도 이미 본 목록을 유지하고 같은 추가 조회를 다시 시도한다.

**독립 검증**: 공지·알림·출석 목록의 첫 조회, 전체 갱신, 다음 페이지 실패를 각각 재현한다.

1. 일반적인 추가 페이지 실패는 기존 목록과 하단의 작은 재시도 안내를 표시한다.
2. 추가 페이지 재시도는 항목을 중복 추가하거나 동시에 같은 요청을 반복하지 않는다.
3. 추가 페이지의 인증 오류는 US2와 동일하게 로그인으로 이동한다.
4. 일반 재조회 실패는 추가 페이지 실패의 예외를 적용하지 않고 US1처럼 실패 영역을 교체한다.

### US4 — 앱 전체 장애에서 탈출하기 (P2)

회원은 화면의 일반 복구가 불가능해 내비게이션까지 사라지면 새로고침이나 홈 이동을 선택한다.

**독립 검증**: 앱 최상위 렌더링 실패를 테스트 대역으로 발생시켜 두 액션을 확인한다.

1. 최종 오류 안내에는 새로고침과 홈으로 이동을 제공한다.
2. 일반 탭·상세·카드 오류에는 다시 시도만 제공하고 기존 내비게이션은 유지한다.

### 예외와 수명

- 일반 조회 오류로 폼이 교체되면 경계 내부 입력은 초기화한다. 별도 초안 저장·복원은 추가하지 않는다.
- 오류 fallback은 화면 복귀만으로 reset하거나 재조회하지 않는다. 사용자가 다시 시도하거나 대상 reset key가 바뀔 때만 복구한다.
- 일반 제출 실패에서는 입력을 유지한다. 인증 이동·계정 변경 때는 기존 보호 화면·초안 정리 정책을 따른다.
- 제출 성공과 후속 조회 실패를 분리한다. 성공한 제출을 실패로 바꾸거나 자동 재제출하지 않는다.
- 미지원 앱·OS 권한 거부·입력 검증·빈 결과·404의 기존 전용 안내는 무조건 일반 오류로 바꾸지 않는다.
- 최초 세션 복원 자체의 연결 실패 안내는 유지한다. 업무 요청에서 확정된 재인증 요구와 구분한다.

## 요구사항

### 기능 요구사항

- **FR-001**: 초기·일반 재조회 실패는 실패 영역의 콘텐츠와 교체되어야 한다. (US1)
- **FR-002**: 다른 정상 영역, 헤더, 뒤로가기, 하단 내비게이션은 유지해야 한다. (US1)
- **FR-003**: 페이지형·영역형 오류는 동일한 문구 원칙과 재시도 행동을 제공해야 한다. (US1)
- **FR-004**: 재시도 중에는 로딩 상태를 표시하고 성공·실패로 수렴해야 한다. (US1)
- **FR-005**: 해결되지 않은 업무 인증 오류는 보호 콘텐츠를 숨긴 뒤 기본 로그인으로 이동해야 한다. (US2)
- **FR-006**: 로그인 이동은 별도 안내 없이 수행하며 자동 제출·로그인 왕복을 만들지 않아야 한다. (US2)
- **FR-008**: 일반 추가 조회 실패는 목록을 유지하고 추가 조회 재시도를 제공해야 한다. (US3)
- **FR-009**: 최종 앱 오류만 새로고침·홈 이동을 함께 제공해야 한다. (US4)
- **FR-010**: 일반 제출 실패의 입력과 제출 성공 결과를 유지하고 조회 복구와 구분해야 한다. (US1·US2)
- **FR-011**: 키보드·스크린 리더·터치에서 오류 안내와 액션에 접근할 수 있어야 한다. (US1·US4)
- **FR-012**: 각 단계의 변경·검증 결과를 리뷰한 뒤 다음 단계로 진행해야 한다. (전체)

### 핵심 상태

- **실패 영역**: 같은 조회 결과로 표시하는 콘텐츠의 단위. 독립된 정상 형제 영역과 구분한다.
- **재인증 필요**: 업무 인증 실패로 보호 내용을 사용할 수 없는 상태. 기기에서 실제 로그아웃했다는 뜻은 아니다.
- **추가 조회 실패**: 이미 표시한 목록 이후의 항목만 가져오지 못한 상태.

## 성공 기준

- **SC-001**: 대표 초기·재조회 실패 시나리오에서 실패 영역의 기존 콘텐츠와 전체 오류 안내 동시 표시가 0회다.
- **SC-002**: 인증 실패 시나리오 모두 기본 로그인으로 수렴하며 중복 이동·보호 콘텐츠 재노출·자동 재제출이 0회다.
- **SC-003**: 추가 조회 실패 시 기존 항목은 유지되고 재시도 성공 뒤 중복 항목이 0개다.
- **SC-004**: 일반 오류·앱 전체 오류에서 약속한 액션을 키보드와 터치로 실행할 수 있다.
- **SC-005**: 모든 단계는 검증 성공·실패·미실행과 리뷰 결과를 구분해 기록한다.

## 확정한 전제와 범위

- 대상은 회원 웹과 이를 표시하는 브라우저·WebView다. 관리자·네이티브 구현·서버 계약은 범위 밖이다.
- 디자인은 [Hand off 공지 오류](https://www.figma.com/design/LUFGoDnVmwJT43QhecBI8x/YAPP-?node-id=222-40786)를 기준으로 한다.
  원본에 없는 다시 시도는 사용자와 합의한 보완이다. 큰 그림은 페이지형에만 제공한다.
- 일반 오류의 홈 이동은 제외한다. 오류 팝업·신규 애니메이션·초안 영구 보관·새 로깅 서비스는 추가하지 않는다.
- 화면 정책 변경은 합의된 범위에 한정하며 새 제품 판단이 필요하면 사용자에게 먼저 확인한다.
