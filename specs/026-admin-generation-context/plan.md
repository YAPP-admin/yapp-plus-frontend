# 구현 계획: 관리자 기수 선택과 세션 연결

**브랜치**: `DongjaJ/api-v3` | **작성일**: 2026-11-19 | **명세**: [spec.md](spec.md)
**상태**: 5단계 통합 검증·운영 문서 갱신 완료.

## 요약

최신 OpenAPI로 공용 생성물을 갱신하고 관리자 기수 목록·현재 선택을 Context로 제공한다.
기존 세션 CRUD의 환경 변수 ID 주입을 선택 기수 ID로 바꾼다. 이후 기수 전환 UI와 화면 수명을
연결한다. 회원 앱은 생성 계약 변경에 필요한 호환 수정만 수행한다.

## 기술 맥락

- Node 24.20.0·pnpm 12.3.4, TypeScript·React 19·TanStack Router/Query·Zod를 유지한다.
- SEED·기존 UI·overlay-kit·vanilla-extract를 사용한다. 새 의존성은 없다.
- 대상은 관리자 브라우저 UI다. SSR에서는 기수 API를 요청하지 않는다.
- 서버 목록·요청 상태는 Suspense Query, 사용자 선택 ID는 Context 내부 상태가 소유한다.
- 토큰은 브라우저에서만 읽는다. SSR은 관리자 작업 영역의 준비 fallback을 렌더링하고, 클라이언트가
  토큰 없음을 확인하면 Provider를 만들지 않은 채 `/login`으로 이동한다.
- Vitest·Testing Library·MSW와 브라우저 확인으로 검증한다. 새 성능 목표·자동 재시도는 만들지 않는다.

## 문서와 코드 구조

이 디렉터리에 명세·계획·조사·데이터 모델·계약·검증 절차·작업 목록·체크리스트·검증 기록을 둔다.

- `packages/api`: 생성물과 기존 소비자 호환, 기수 응답 fixture.
- `apps/admin/src/features/admin-generation`: Provider·Context·조회 검증·상태와 공개 `index.ts`.
- `apps/admin/src/app/ui`: 관리자 기수 초기화의 Suspense·오류 경계, 사이드바 선택 UI와
  기수별 모달 수명 조합.
- `apps/admin/src/routes`: 관리자 레이아웃, 로그인 성공 초기화, 세션 ID 주입.
- `apps/admin/src/features/login`: 저장 토큰 삭제의 공개 함수와 401 인증 실패의 캐시 폐기 경계.
- `apps/admin/src/pages/sessions`: 유효한 기수 ID를 받아 기존 CRUD와 필터 동작을 유지한다.

다른 feature 내부를 직접 import하지 않는다. 기수 feature가 login feature에 의존하지 않도록
인증 가능 여부는 상위 레이아웃에서 전달한다. 자세한 경계는 [계약](contracts/generation-context.md)에 둔다.

## 구현 단계와 리뷰

| 단계 | 작업                                   | 제출할 검증·리뷰                                      |
| ---- | -------------------------------------- | ----------------------------------------------------- |
| 1    | 이슈 초안·Spec Kit 문서                | 문서 일관성·링크·작업 형식·check, 제품 코드 변경 없음 |
| 2    | API 재생성·소비자 호환·기수 fixture    | 생성 계약 diff·관련 테스트·check/build                |
| 3    | US1 자동 선택·상태 안내·세션 CRUD 연결 | 로그인·초기화·미확정 요청 차단·CRUD 기수 경로         |
| 4    | US2 선택 UI·기수별 화면 수명           | 전환·화면 이동·늦은 응답·접근성·Storybook             |
| 5    | 통합 검증·운영 문서                    | 전체 check/build·브라우저·실서버 확인 범위            |

각 단계 결과를 제출하고 리뷰·다음 단계 진행 확인을 받는다. 650줄부터 분리를 검토하고 생성물·
문서·테스트를 포함한 실제 base 대비 변경량을 800줄 미만으로 유지한다. 단일 재생성만으로
초과하면 실제 수치와 원인을 보고하며 임의로 파일을 제외하거나 부분 생성물을 제출하지 않는다.
commit·push·PR 생성은 단계 진행 승인에 포함하지 않는다.

401 처리 순서는 저장 토큰 삭제, 진행 중 관리자 Query 취소·제거, `/login` 이동이다. 로그인 성공도
동일하게 이전 관리자 Query를 취소·제거한 뒤 대시보드로 이동한다. 토큰·요청 URL·응답 본문은
오류 화면이나 로그에 표시하지 않는다.

## 검증과 복구

[quickstart.md](quickstart.md)의 자동 검증과 브라우저·실서버 검증을 구분한다.
이번 단계는 문서만 변경하므로 build·expo:doctor는 대상이 아니다. 제품 코드 단계는 check/build를
실행하고 새 실행과 Turbo 캐시 재사용을 기록한다.

서버 마이그레이션은 없다. 문제 발생 시 이전 검증 버전을 배포하고 기존 기수 환경 설정을
복원한다. 프론트 복구로 이미 생성·수정·삭제한 서버 데이터를 되돌릴 수는 없다.
실서버 쓰기 검증은 테스트 기수·대상·정리 범위가 승인된 경우에만 수행한다.
