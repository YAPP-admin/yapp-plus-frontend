# 실행과 검증 절차

2026-11-24 사용자 리뷰 기준이다. 초기 계획의 선택 즉시 업로드·사진 존재 기반 제출 차단은
최종 버튼 업로드·본인 출석 상태 기반 분기로 대체했다. 상세 결정은 validation.md를 따른다.

## 준비

저장소 루트에서 mise의 Node 24.20.0·pnpm 12.3.4를 사용한다.
기준 원본은 .context/api-027-openapi.json이며 SHA-256은 research.md와 비교한다.
원본이 없으면 같은 URL에서 다시 받아 차이를 검토한다. 다른 원본을 같은 스냅샷으로 표시하지 않는다.
아래 생성 명령은 0단계에서 실행하지 않는다. 1A~1D의 해당 생성 설정을 적용한 뒤 실행한다.

    OPENAPI_INPUT="$PWD/.context/api-027-openapi.json" mise exec -- pnpm --filter @yapp-plus/api generate

## 단계별 자동 검증

각 단계는 plan.md의 리뷰 단위이며 실패를 소유하는 계층에서 검증한다.

| 단계  | 시나리오와 기대 결과                                                                                |
| ----- | --------------------------------------------------------------------------------------------------- |
| 1A~1D | 이름 변경 전후 HTTP 경로·Query key·MSW 의미 유지, 새 필수 필드 반영, 마지막 전체 재생성 일치        |
| 2     | 생성 Query 옵션 직접 소비, 실제 팀원·본인·직군 null 표시 확인                                       |
| 3     | 최초 조회 지연·재조회·OS 복귀에도 선택한 도구 1회, 취소 뒤 화면 유지, 직접 진입 가드                |
| 4     | 선택한 File·미리보기 URL의 Context 보관, 완료·이탈 시 폐기, 선택 단계 업로드 없음                   |
| 5     | 최종 버튼에서 presign·PUT·접수, 중복 제출 차단, 결과 불명 시 홈 복귀 안내                           |
| 6     | 유형별 출석 경로, TEAM 코드·위치 요청 0회, AVAILABLE은 사진 조회 없이 안내 진입                     |
| 6     | PENDING_APPROVAL만 사진 조회, 사진 없음·첫 조회 실패에도 검토 중 유지, 재조회 실패는 기존 화면 유지 |
| 6     | fresh 캐시에서도 홈·앱 복귀 조회, CHECKED_IN→AVAILABLE 서버 정정 반영, polling 없음                 |
| 7     | 모킹 모드 실서버 쓰기 0회, production 운영 진입·직접 완료 URL·정적 모드 차단                        |

추가 실패 검증: 선택 취소·권한 거부, 이전 사진 있음→새 조회 실패, 업로드 중 이탈,
늦은 결과·계정 변경, 중복 클릭, 최종 접수 결과 불명,
접수 성공 후 재조회 실패, 최종 버튼 전 사진 업로드가 발생하지 않는지 확인한다.
사진 준비·폼·전송·탐색에서 같은 실패 조합을 반복하지 않는다.

    mise exec -- node --run check
    mise exec -- node --run build

관련 테스트는 pnpm --filter @yapp-plus/web exec vitest run <해당 테스트 경로>로 선택한다.
관리자 소비자 변경은 관리자 인접 테스트도 실행한다. 새로 실행한 task와 Turbo cache hit를 구분한다.
네이티브 설정·의존성을 실제 변경할 때만 mise exec -- node --run expo:doctor를 추가한다.
0단계는 문서·링크·작업 형식과 check만 검증하고 build·사진 기능 테스트는 구현 후 수행한다.

## 브라우저와 iPhone

개발 브라우저는 VITE_API_MOCKING=true에서 응답 fixture·미리보기·오류 UI만 확인한다.
앱에서 실제 검증할 때는 모킹을 끄고, 지원하는 기존 iOS 빌드에서 로그인한다.
에이전트가 검증 목적으로 실제 사진 제출·삭제를 자동 실행하지 않는다.

사용자가 지정한 테스트 세션에서 다음을 직접 확인한다.

1. 정규 세션은 코드·위치 출석, TEAM은 사진 인증으로 진입하는지 확인한다.
2. 실제 팀·본인·팀원과 직군 표시를 확인한다.
3. 앨범·카메라의 일회성 실행, 취소·재선택·권한 거부를 확인한다.
4. 사진 선택 후에는 미리보기만 표시하고 최종 제출 버튼에서 업로드를 시작하는지 확인한다.
5. 참석자를 선택해 접수하고 완료 화면의 제출 시간·명단·심사 대기를 확인한다.
6. 운영진 처리 후 홈·앱 복귀로 상태가 바뀌는지 확인한다.
7. 본인의 출석 상태별 버튼·사진 상세 표시, 터치·VoiceOver 조작을 확인한다.

팀원 조회 실패는 현재 안내 문구만 제공하며 재시도 버튼은 없다. 제출 결과 불명에서는
재제출을 막고 홈 복귀를 제공한다. 홈 출석 상태는 본인 기준, 사진 상세는 팀 기준이다.

테스트 계정·세션은 사용자 검증 시 지정한다. 실제 결과 전에는 수동 검증을 미완료로 남긴다.
사진 원문·서명 URL·인증정보·개인정보 대신 시나리오·결과·기기 환경만 validation.md에 기록한다.

운영 진입 차단 복구와 SDK·소비자 동반 복구를 분리해 확인한다.
