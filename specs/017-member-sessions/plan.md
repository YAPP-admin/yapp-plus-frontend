**브랜치**: `DongjaJ/nsu85` · **작성일**: 2026-11-05 · **상태**: 범위 축소 리뷰 대기

## 구현 범위 조정 — 2026-11-06

사용자 리뷰에 따라 이 작업은 홈·일정 조회와 화면 상태에 집중한다.
인증 provider·mutation·Stackflow 전환 구조는 기존 구현을 사용한다.
인증 전환, 늦은 인증 응답 차단, 화면 수명과 앱 복귀 세션 복구는 인증 작업 #329와의 연동 대상으로 분리한다.
로그아웃·탈퇴·계정 변경 시 queryClient.clear()로 전체 query·mutation 캐시를 지우는 요구는 유지한다.
이 요구는 아직 구현 완료가 아니며 인증 작업의 확정된 전환 지점에 연결하고 통합 검증해야 한다.
같은 로그인 세션의 토큰 갱신에서는 데이터를 유지한다. 출시 전 계정 격리 검증은 필수다.
이 절이 아래의 이전 인증 구현 제안보다 우선하며, 전환 세대·상태 소유 방식은 여기서 새로 설계하지 않는다.

## 홈 바텀시트 탐색 — 2026-11-06

사용자 리뷰에 따라 출석 코드·출결 보고·팀 인증 안내를 Stackflow Activity로 등록한다.
시트를 열 때 push, 닫기·뒤로가기는 pop, 완료 후 다음 화면은 replace를 사용한다.
입력 값은 시트 내부 state로 유지하며 URL params에 넣지 않는다.
직접 진입의 부모는 홈이고, 모의 출석 동작은 DEV+MSW에서만 제공한다.
overlay-kit과 홈의 overlay 정리 Effect는 제거한다. 기존 WebView 뒤로가기 계약은 변경하지 않는다.
실패 시 이번 시트 탐색 변경만 되돌려 복구한다.

## 요약

기존 홈·일정에 생성 SDK 조회를 연결한다. 인증 결과는 공통 경계에서 반영하고, 사용자 또는 로그인
세션 변경 시 전체 query·mutation 캐시를 지운다. 같은 로그인 세션의 토큰 갱신은 데이터를 유지한다.
401은 기존 native 브리지로 갱신하고 동일 로그인 세션에 한해 한 번 재요청한다.

## 기술 맥락

- 실행: TypeScript·React·Vite·Stackflow, 기존 TanStack Query·Zod·MSW·Vitest·Testing Library.
- 도구: Node.js 24.20.0, pnpm 12.3.4. 스타일: 기존 SEED·vanilla-extract.
- 저장: 웹 메모리 캐시만 사용한다. refresh token 저장·회전은 기존 native 소유다.
- 대상: 회원 WebView와 브라우저 MSW 검증. 관리자·SSR·새 브리지·새 패키지는 제외한다.
- 성능: Provider의 기존 30초 stale 정책을 공유한다. 일정 종료 표시는 조회 시점에만 계산하며 타이머를 두지 않는다.

## 구성과 인터페이스

- `features/auth`: 기존 세션 상태와 native 갱신 브리지를 소비한다. 인증 상태 관리는 재설계하지 않는다.
- 인증 전환·화면 수명·앱 복귀 복구는 인증 작업과의 연동 대상으로 둔다.
- `pages/home`, `pages/schedule`: 생성 query 옵션 직접 사용·Zod 확장·화면 상태. 다른 page 내부를 import하지 않는다.
- `shared/lib`: 두 페이지가 실제 공유하는 한국 날짜·시간 처리만 둔다. 도메인 조회는 옮기지 않는다.
- 웹 MSW는 생성 faker·핸들러를 재사용하고 날짜·시간 관계만 보정한다. 기존 공용 핸들러보다 먼저 등록하며 생성 파일은 수정하지 않는다.
- Provider는 nativeAuthClientOptions로 만든 apiOptions를 제공한다. 생성 queryOptions + useSuspenseQuery를 사용하며 401 복구는 HTTP client의 afterResponse 훅에서 처리한다. 별도 인증 조회 래퍼는 없다.
- 화면의 query는 자체 응답 검증과 도메인 변환을 담당한다. 상태·오류 계약은 [계약](contracts/session-query.md)을 따른다.

## 실패와 복구

- 403·최종 401·잘못된 응답은 빈 결과가 아니다. 재로그인 또는 수동 재시도를 제공한다.
- 전체 캐시 초기화는 서버 mutation을 취소하지 않는다. 이전 전환 세대의 콜백과 화면 이동을 무효화한다.
- 갱신 실패 시 같은 계정의 기존 화면 내용은 유지할 수 있지만 계정 전환 후 내용은 유지하지 않는다.
- 복귀 중 세션 확인과 업무 조회는 동시에 실행할 수 있다. 세션 확인 실패가 확정되면 기존 인증 경계의 복구 안내를 표시하며, 실패만으로 업무 cache를 제거하지 않는다.
- 코드·데이터 마이그레이션이 없다. 문제 발생 시 웹 변경을 되돌려 이전 검증 커밋으로 복구한다.
- 실제 WebView·서버 검증이 불가능하면 미실행으로 남기며 MSW 통과를 실제 연동 성공으로 보고하지 않는다.

## main 병합 후 인증 연동 — 2026-11-06

origin/main bba7ca3b의 인증·Stackflow 2 변경을 병합한다. 인증 operation·계정 경계는
main 구현을 그대로 사용한다. HTTP 401 복구도 readAuthSession의 세대·tokenVersion 검사를
거쳐 유효한 동일 세션 토큰과 확정 로그아웃을 native 세션 cache에 반영한다.
다른 계정의 갱신 결과와 일시 오류는 재요청·세션 덮어쓰기에 사용하지 않는다.
홈·일정 생성 query를 실제 인증 mutation과 함께 실행해 계정 격리와 갱신을 검증한다.
일반 앱 복귀는 아래 동시 재조회 정책으로 검증하며, BFCache 이전 화면 비노출은 보장하지 않는다.
실패 시 병합 이력은 보존하고 이번 HTTP 연동 변경만 되돌려 복구한다.

## 복귀 재조회 단순화 — 2026-11-06

사용자 리뷰에 따라 홈·일정·세션 조회의 동시 실행을 허용한다. native의 single-flight와
sessionId/tokenVersion 검사로 토큰 갱신 중복을 처리한다. 수동 복귀 Effect·조회 취소·
Suspense 대기는 추가하지 않는다. 홈·일정은 앱 QueryClient의 기본 mount/focus/reconnect
재조회를 사용하며 stale일 때만 실행한다. 홈의 주 경계 예외는 유지한다.
정상 native 세션은 focus 시 always로 재확인하고, 복구 가능한 오류는 기존 5초 stale 간격을
사용한다. 인증 진행·가입 대기·미지원 상태는 focus 강제 재조회에서 제외한다.
BFCache 이전 화면 비노출과 선행 세션 확인은 이 방식의 보장 범위가 아니다.
