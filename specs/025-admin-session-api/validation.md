## 4단계 — 공통 폼 준비

- 입력 모델: 기존 메모리 저장용 `CreateSessionInput` 의존을 제거하고 정규 장소 유무가 유형으로
  결정되는 `SessionInput`을 폼 계약으로 사용한다. 팀 세션은 장소 속성 자체를 제출하지 않으며
  API 변환 단계에서 다섯 장소 필드가 `null`이 된다.
- 시간: 폼에는 시·분만 표시한다. 수정 세션의 시·분이 바뀌지 않으면 조회의 초·소수부 원본을
  보존하고, 생성 또는 바뀐 시간은 `HH:mm:00`으로 만든 뒤 최종 시작·종료 순서를 검증한다.
- 장소: 정규 세션만 주소 검색·상세주소·지도를 표시한다. 도로명주소와 상세주소는 각각 255자,
  위도·경도 `0`은 유효하다. 정규→팀→정규 왕복 중 정규 장소 초안은 폼 수명 동안 유지한다.
- 폼 연결: 주소·좌표까지 TanStack Form 값으로 옮기고 Zod Standard Schema를 `onDynamic`에 직접
  연결했다. 수동 필드 오류 변환 함수는 제거했으며 제출 경계에서 같은 스키마의 transform 결과를
  사용한다. 범용 fieldset·legend도 제거하고 각 필드의 기존 label을 유지했다.
- 좌표 조회: 주소 선택·재시도 이벤트에서 `useMutation().mutate()`로 직접 실행하고 호출별 성공
  콜백에서 폼 좌표를 갱신한다. `useEffect`와 `queryClient.fetchQuery()`는 사용하지 않으며 연속 선택과
  폼 종료 뒤의 늦은 응답은 Mutation observer의 호출별 콜백 수명으로 격리한다.
- 구성: `session-form.tsx`에는 TanStack Form 상태·검증·제출 조정만 남겼다. 다이얼로그 셸은
  `session-form-dialog.tsx`, 이름·유형·주소·상세주소·좌표 화면은 `session-form-fields.tsx`의 제어형
  컴포넌트로 분리하고 본문은 children으로 조합한다.
- 화면·접근성: 팀 장소 안내 입력을 제거하고 이름을 필수로 표시했다. 오류는 최초 렌더가 아닌
  blur·제출 뒤에 표시하는 기존 동적 검증 흐름을 유지한다. 상세주소에는 `maxlength=255`와
  연결된 오류 문구를 제공한다.
- 정리: 아직 화면에 연결되지 않은 기존 모의 생성·수정 래퍼 `session-dialogs.tsx`를 제거했다.

- 테스트: 정규 필수 장소, 팀 무입력, 유형 왕복, 주소별 255자, 좌표 0, 저장 좌표 복원, 같은 분의
  초 단위 시간 보존, 변경 시간의 00초, 주소 조회 경합·장애·닫힌 폼의 늦은 응답을 검증했다.

## 5단계 — 생성 API 연결

- 생성 요청: 생성 `create2Mutation()` 옵션을 검사·재구성하는 래퍼 없이 `useMutation`에 그대로
  사용하고, 제출 이벤트에서 앱 입력을 `CreateSessionRequest` 전체 본문으로 변환한다.
  `retry`·`networkMode`를 별도로 지정하지 않아 Mutation 기본값과 `online` 모드를 유지한다.
- 목록 갱신: HTTP 성공 뒤 진행 중인 전체 목록을 먼저 취소하고 무효화한다. 취소 완료까지만 저장
  콜백과 순서를 맞추고 재조회 Promise는 기다리지 않아 저장 성공과 목록 갱신 실패를 분리했다.
- 화면: 설정된 기수가 있을 때 세션 추가 버튼과 실제 폼을 연다. `mutate` 호출별 콜백에서만 창을
  닫고 전체 필터로 전환하며 완료 스낵바를 표시한다. 실패하면 유형별 안내만 표시하고 초안을 유지한다.
  Mutation 대기 상태를 공통 폼에 주입해 입력·닫기·중복 제출을 함께 막는다.
- 오류·수명: 400·401·404·409와 날짜 충돌을 서버 원문 없이 안내한다. 알 수 없는 결과는 목록을
  확인한 뒤 재시도하도록 안내한다. 페이지 이동으로 Mutation observer가 제거돼도 hook 성공 콜백의
  캐시 무효화는 실행되지만 이전 화면의 필터 변경·스낵바 콜백은 실행되지 않는다.
- 테스트: 전체 생성 본문·201 ID·400/401/404/409 단일 요청, 오프라인 보류 후 1회 실행, 이전 목록
  지연 경합, 성공 후 재조회 실패, 날짜 충돌 초안 유지, 중복 제출, 페이지 이동 뒤 완료를 검증했다.
  관련 2개 파일 14개 테스트와 라우터 103개 테스트가 통과했다.
- 전체 검증: 첫 어드민 전체 실행에서 새 버튼이 키보드 탭 순서에 추가되어 기존 고정 순서 테스트
  1건이 실패했다. 버튼 포커스를 명시적으로 확인하도록 수정한 뒤 `node --run check`가 통과했고
  어드민 75개 파일·671개 테스트가 새로 실행됐다. admin lint·typecheck·test는 새 실행, 나머지
  패키지 작업은 Turbo 캐시 재사용이다.
- 빌드: `node --run build` 통과. admin은 새 실행, web·storybook은 Turbo 캐시를 재사용했다.
  기존 500 kB 초과 chunk 경고 외 새 빌드 오류는 없다.
- 화면·접근성: MSW 합성 데이터로 추가 버튼의 키보드 포커스, 다이얼로그 제출 잠금, 오류 alert,

  커밋과 6단계 진행을 승인했다. 커밋 `8b58197a`로 완료했다.

## 6단계 — 수정 API 연결

- 수정 요청: 생성 `update1Mutation()` 옵션을 그대로 사용해 기수·세션 ID와 생성과 동일한 전체
  본문을 PUT으로 보낸다. 성공 뒤 진행 중인 전체 목록을 취소하고 무효화하되 재조회 완료를 수정
  성공 판정과 묶지 않는다.
- 입력 복원: 조회 ViewModel의 주소·좌표·초 단위 시간을 수정 폼 입력으로 보존한다. API의 선택
  상세주소 `null`만 폼의 빈 문자열로 변환하며, 저장 좌표는 외부 좌표 API로 다시 조회하지 않는다.
- 화면: 카드의 SEED 메뉴에 수정 액션을 복구하고 키보드로 메뉴와 수정 폼에 진입할 수 있게 했다.
  성공하면 현재 필터를 유지하고, 유형 변경으로 카드가 사라질 때 전체 목록 안내를 표시한다.
- 리뷰 반영: 메뉴 트리거는 세션 `관리`, 수정 폼 진입 항목은 Figma·기존 명세에 맞춰 `정보`로
  표현한다. `삭제`와 AlertDialog는 7단계에서 같은 메뉴에 추가한다. 수정 Mutation은 목록 데이터가
  표시된 뒤에만 실행할 수 있으므로 명시적 `cancelQueries`를 제거하고 `invalidateQueries`의 기존
  활성 refetch 취소·재조회 동작을 사용한다. 초기 목록 중에도 가능한 생성 Mutation의 취소는 유지한다.
  리뷰 반영 후 대상 2개 파일 22개 테스트, admin lint·typecheck, 전체 check·build가 다시 통과했다.
- 오류·수명: 날짜 충돌·출석 연결 수정 제한·대상 없음과 알 수 없는 결과를 서버 원문 없이 구분한다.
  실패 시 폼 초안을 유지하고, 페이지 이동 뒤 지연 성공은 캐시만 갱신하며 이전 알림을 띄우지 않는다.
- 대상 테스트: 모델·API·카드·페이지 4개 파일 28개 테스트를 새로 실행해 통과했다. 수정 경로·전체
  본문·204·404·두 409 코드·단일 요청, 장소·시간 복원, 필터 유지, 재조회 실패와 페이지 수명을 검증했다.
- 수정 중 발견: 204 런타임 결과가 생성 타입의 `void`와 달리 `null`이라 내부 파서 반환값 단언을
  제거하고 성공 여부를 검증했다. MSW 경로 매개변수는 `String`으로 정규화했고, 상세주소 `null`은
  폼 경계에서 빈 문자열로 변환했다. 첫 검증 명령은 admin 경로에서 루트 `format` 스크립트를
  호출해 즉시 종료됐고, 루트 포맷과 대상 테스트를 각각 다시 실행했다. admin lint·typecheck와
  대상 테스트가 다시 통과했다.
- 전체 검증: `node --run check` 통과. format과 admin lint·typecheck·75개 파일 680개 테스트는 새
  실행이고, 나머지 패키지 작업은 Turbo 캐시를 재사용했다. `node --run build`도 통과했으며 admin은
  새 실행, web·storybook은 캐시 재사용이다. 기존 500 kB 초과 chunk 경고 외 새 오류는 없다.
- 화면·접근성: 합성 MSW 데이터로 메뉴의 Enter 진입·초기 menuitem 포커스, 수정 다이얼로그,
  제출 잠금, 오류 alert, 성공 status와 현재 필터 유지를 DOM에서 확인했다. 실제 브라우저 캡처와
  실서버 수정은 실제 기수 ID 확보 뒤 후속으로 남긴다.
- 변경량: 6단계는 HEAD 대비 13개 파일 +512/-39줄로 650줄 미만이다. 최신 origin/main 대비 누적은
  53개 파일 +3,035/-1,240줄이므로 PR 생성 전 독립적으로 검토 가능한 단계별 분리가 필요하다.
- 사용자 리뷰: Mutation 갱신 범위와 Figma 메뉴 구조를 반영한 뒤 사용자가 6단계 커밋과 7단계
  진행을 승인했다.
