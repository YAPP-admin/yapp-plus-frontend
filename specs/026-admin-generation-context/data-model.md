# 데이터 모델과 수명

## 서버 데이터

`AdminGenerationListResponse`와 `AdminGenerationListItemResponse`를 생성 계약 그대로 사용한다.

| 필드             | 의미                                                    |
| ---------------- | ------------------------------------------------------- |
| generations      | 정렬된 전체 관리 가능 기수. 서버 계약상 하나 이상이다.  |
| generationId     | 다른 관리자 API의 경로 ID. 표시 번호와 혼동하지 않는다. |
| generationNumber | 기수 번호. 기본 선택 정렬 기준이다.                     |
| generationName   | 선택 UI와 현재 기수에 표시할 서버 이름이다.             |

생성 스키마로 응답을 검증하고 안전하지 않은 숫자 ID는 오류로 처리한다. 원본 배열을 변경하지
않고 서버 순서를 유지한다. 미선택 sentinel로 0이나 빈 문자열을 API에 전달하지 않는다.

## 클라이언트 상태

- Suspense Query: 목록·오류·최초 로딩·재조회 상태를 소유한다.
- Context 내부: 사용자가 선택한 `generationId | null`만 저장한다.
- 현재 기수: 저장한 ID가 목록에 있으면 그 항목, 없으면 첫 항목이다.
- 유효한 재조회에서 선택이 사라지면 선택 ID도 새 기본값으로 정규화해 나중에 과거 선택이 부활하지 않게 한다.
  현재 모든 관리자 계정이 모든 기수에 접근하므로 이는 권한 상태를 위한 흐름이 아닌 방어적 처리다.
- 미로그인 상태에서는 Provider를 만들지 않는다. 최초 로딩·실패는 현재 기수를 소비자에게 제공하지
  않고 관리자 작업 영역 경계가 처리한다. 기존 data가 있는 재조회 실패는 Query 기본 정책에 따라
  현재 선택을 유지한다. 401은 저장된 access token을 삭제한 뒤 즉시 로그인 화면으로 이동한다.
- 새로고침·로그인 화면 왕복으로 Provider 수명이 끝나면 선택은 폐기한다.

## 세션 연결

표시 기수와 경로 ID는 동일 Context 결과에서 가져온다. 각 Mutation은 제출 시점의 기수에
속하고 이후 기수 전환이 진행 중 요청의 경로를 바꾸지 않는다. 무효화도 원래 기수 key에 한정한다.
세션 필터는 URL이 소유하며 기수 선택으로 초기화하지 않는다.
