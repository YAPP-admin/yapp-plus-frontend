# 검증 가이드

## 준비

루트에서 mise의 Node.js 24.20.0·pnpm 12.3.4를 사용한다. 새 패키지를 설치하지 않는다.
코드가 구현된 단계에 맞는 테스트를 실행하며 이 문서만으로 구현 완료를 의미하지 않는다.

```sh
mise exec -- node --run check
mise exec -- node --run build
VITE_API_MOCKING=true mise exec -- node --run dev:web
```

문서만 변경한 1단계는 check를 실행하고 build·expo:doctor는 대상 변경이 없어 실행하지 않는다.
기능 코드 단계는 check/build, 모바일 설정·의존성을 실제 변경한 경우에만 expo:doctor를 추가한다.
오류·지연·401 fixture는 테스트의 MSW override를 사용하며 실서비스 자격을 소스·로그에 저장하지 않는다.

인증 전환·늦은 결과·복귀 확인은 인증 작업과의 통합 검증 항목이다. 이 작업에서 별도 인증 구조를 구현하지 않는다.

## 자동 검증 시나리오

| 경계      | 입력/행동                                        | 기대 결과                                                   |
| --------- | ------------------------------------------------ | ----------------------------------------------------------- |
| 인증 전환 | 임의 query와 mutation을 만든 뒤 A→B, A→새 A 세션 | 업무 query·mutation 제거, 인증 제어 cache 유지, 화면 초기화 |
| 인증 실패 | 취소·로그아웃 실패·확인 불가                     | 성공 전환·업무 cache 제거 없음                              |
| 늦은 결과 | A query·mutation pending → B → A 완료            | 캐시·토스트·탐색 변화 없음                                  |
| 토큰 갱신 | 같은 userId/sessionId의 새 tokenVersion          | 다른 query·mutation 유지, 인증만 갱신                       |
| 401       | 첫 401 → native SIGNED_IN → 성공                 | 요청 버전 전달, 새 token으로 원래 GET 1회 재요청            |
| 갱신 경계 | 동시/늦은 401, 갱신 중 계정 전환·취소            | 버전 역행·다른 계정 재전송 없음                             |
| 실패 상한 | 403·두 번째 401·브리지 오류                      | 추가 갱신 없음, 빈 결과로 변환하지 않음                     |
| 변환      | null 장소, 분/초, 잘못된 날짜·ID·응답            | 확정 표기 또는 오류; number 무검증 변환 없음                |
| 일정      | 서버 비정렬 목록·빈 목록·오류                    | 순서 유지, 빈 결과와 오류 구분                              |
| 홈        | session null·이번 주 세션                        | 독립 카드, 전체 일정 추가 요청 없음                         |
| 시간      | 기기 시간대 변경, 한국 자정·종료·주 경계         | 동일한 한국 시간 결과, 복귀 시 재계산                       |
| 개발 모드 | 실서비스·DEV+MSW·비목업 브라우저                 | 모의 성공 격리, 비목업 브라우저 API 요청 없음               |
| 재조회    | 성공 뒤 오류 → 재시도 성공                       | 기존 내용과 오류 안내, 복구 뒤 안내 제거                    |
| 복귀      | focus/online 연속 발생                           | 진행 중 세션 확인 공유, stale 조회 동시 실행 허용           |

복귀 시 세션 확인과 업무 조회를 직렬화하지 않는다. 인증 결과가 확정되면 계정 경계가 이전
계정의 업무 cache와 진행 요청을 정리한다. BFCache 복원 직후 이전 화면이 한 번도 노출되지
않는 보장은 별도 미완료이며, 위 자동 테스트의 통과로 대체하지 않는다.

## 화면 검증

1. MSW 브라우저에서 /와 /schedule의 정상·빈 결과·오류 화면을 각각 확인한다.
2. 홈 바로가기·하단 탭·직접 진입·브라우저 뒤로가기에서 URL과 화면이 일치하는지 확인한다.
3. 320px·390px 너비에서 가로 스크롤, 긴 세션명, 안전 영역과 라이트/다크를 확인한다.
4. Tab/Enter로 재시도와 이동을 수행하고 상태·오류·disabled 이유를 스크린 리더로 확인한다.
5. 터치 입력과 탭 복귀를 확인한다. 공용 UI를 변경한 경우 해당 Storybook 사례도 갱신한다.
6. 화면 근거는 `.context/member-sessions-evidence/`에 저장하고 validation에 경로·환경을 기록한다.

## 실제 WebView 검증

로그인 가능한 development build, 실제 API 접근 가능한 웹 origin, 합성 테스트 계정이 필요하다.
일반 브라우저 MSW는 native·CORS·실제 서버 데이터 검증의 대체물이 아니다.

1. 로그인 → 홈 → 일정 → 앱 백그라운드/복귀에서 두 조회를 확인한다.
2. 테스트 환경에서 만료된 access token으로 조회하고 native 갱신 후 복구를 확인한다. 토큰 값을 증거에 남기지 않는다.
3. 로그아웃 → 다른 테스트 계정 로그인 후 이전 데이터·입력·뒤로가기 화면이 없는지 확인한다.
4. 네트워크 차단 → 조회 실패 → 네트워크 복구 → 재시도를 확인한다.
5. 실제 기기의 복귀 이벤트, 안전 영역·VoiceOver/TalkBack·터치를 확인한다. 지원 앱이 없는 환경은 미실행으로 기록한다.

## 보고와 롤백

각 단계의 실행 명령·종료 코드·신규 실행·Turbo 캐시 재사용·실패·미실행을 validation에 기록한다.
PR 변경량은 실제 base 대비 추가·삭제 전체 합계이며 생성 파일·테스트·문서를 제외하지 않는다.
실환경 검증이 남으면 완료로 보고하지 않는다. 배포 문제는 승인된 절차로 웹 변경을 되돌리고 서버 데이터는 변경하지 않는다.

## 개발용 일정 화면 미리보기

DEV + VITE_API_MOCKING=true에서 URL을 직접 열거나 새로고침한다. 시나리오는 MSW 시작 시 읽으며 실서비스에는 적용하지 않는다.

- `/schedule`: 정상 목록.
- `/schedule?scheduleState=loading`: 조회를 5초 지연한 뒤 정상 목록.
- `/schedule?scheduleState=error`: 첫 조회 실패. 다시 시도를 누르면 정상 목록으로 복구.
- `/schedule?scheduleState=empty`: 빈 목록.
