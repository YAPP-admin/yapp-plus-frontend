# 화면과 후속 API 연결 계약

## 환경과 탐색

`/members/teams` 공급부는 개발·운영에서 같은 고정 snapshot을 전달한다. 환경 분기·시간/난수 기반 공급은 없다.
페이지는 fixture를 직접 import하지 않고 snapshot과 URL 필터·이동 callback을 받는다.
메뉴·기수 셸은 기존 구현을 유지한다. 팀 매핑 본문만 별도 데이터이며 기존 회원 공급은 변경하지 않는다.

| URL     | 계약                                                                  |
| ------- | --------------------------------------------------------------------- |
| filter  | all/complete/needs-check/unassigned, 기본 all, 잘못된 값 all          |
| preview | before/draft/confirmed, 기본 before, 모든 환경 허용, 잘못된 값 before |
| 탐색    | 기본값 생략, 알 수 없는 키 제거, 필터 변경은 history 추가·스크롤 유지 |
| 복원    | 뒤로가기/앞으로가기에서 필터·preview 복원; 초안 있으면 먼저 확인      |

패널 ID·검색어·체크·초안은 URL에 넣지 않는다. before에서는 빈 화면이 우선이며 팀 필터는 표시하지 않는다.
confirmed라도 미배정 회원이 있으면 미배정 필터와 팀 상세 조회를 제공한다.
확정 조회에서는 회원 추가·이동·제외 및 미배정 체크·대상 선택을 비활성화한다. 새 팀 만들기는 표시하지 않는다.

## 입력·검색·표시

- 팀명은 trim 후 필수, 서비스명은 선택이다. 최소 1명 이외의 길이·인원 상한을 추측하지 않는다.
- 검색은 trim·대소문자 정규화한 이름 또는 직군 표시명 부분 일치다. design은 Design/디자인, server는 Server/서버를 지원한다.
- 빈 검색은 후보를 입력 순서대로 표시한다. 선택·기존 소속 회원의 중복 추가는 막고, 다른 팀 소속은 팀명과 이동 예정 표시를 제공한다.
- 팀 생성과 패널 추가의 검색 결과는 ID로 구분한다. 현재 패널 기존 회원은 추가 결과에서 제외하고 예정 취소로 복원한다.
- 선택 후 검색어를 비우고 입력 포커스를 유지한다. 방향키·Enter·Escape 및 한글 조합 중 오선택 방지를 확인한다.
- 팀 카드 전체에 버튼을 중첩하지 않는다. 상세 열기와 메뉴 조작의 클릭·키보드 경계를 나눈다.
- 패널의 추가·이동·제외는 별도 예정 영역에 표시한다. 기존 직군 배지·팀원·통계는 원본을 유지한다.
- 미배정 체크 해제는 예정 취소가 아니다. 일괄 대상은 체크된 회원 전원의 예정을 최신 선택으로 덮어쓴다.

## 초안 종료와 포커스

생성 폼 입력(검색 제외) 또는 예정이 dirty다. 검색·체크만 있으면 바로 닫거나 이동한다.
닫기·취소·Escape·배경 클릭·다른 팀·filter/preview·페이지 이동·편집 종료에 같은 확인을 적용한다.
계속 편집은 목적 이동을 취소하고 입력·포커스를 보존한다. 변경 버리기는 해당 작업 초안을 비우고 요청한 동작을 한 번 실행한다.
확인창의 Escape/닫기도 계속 편집으로 취급하며 확인창 배경 클릭으로 폐기하지 않는다.
새로고침·탭 닫기는 enableBeforeUnload를 사용하며 브라우저 문구를 임의로 지정하지 않는다.
pathname key만으로 처리하지 않는다. 쿼리 변경·뒤로가기 차단은 Router와, 패널 닫기는 로컬 종료 요청과 연결한다.
초안의 단일 소유자는 현재 작업이다. 미배정 예정 중 새 생성 폼을 여는 경우도 기존 작업 종료 확인을 먼저 받는다.
작업이 없는 단순 모달·패널은 Escape로 닫고 트리거에 포커스를 돌린다. 트리거가 사라진 탐색은 새 화면 제목으로 복귀한다.

## 확정 화면과 비활성 작업

배정 중 ‘팀 확정’은 원본 요약 모달만 연다. 최종 확정은 비활성이다.
확정 요약은 읽기 전용이므로 열고 닫아도 현재 작업의 예정을 유지한다. 요약에는 예정을 포함하지 않는다.
확정됨의 수정하기는 화면의 편집 모드만 켠다. 상태 배지·확정 이력은 유지하며 편집 중임을 별도로 표시한다.
편집 모드에는 팀원 변경만 있고 생성·팀 정보 수정·삭제의 실행은 없다. 편집 종료는 초안 폐기 확인 후 조회로 복귀한다.
만들기·반영·삭제·확정·정보 수정은 준비 중임을 설명하고 disabled로 제공한다. Enter submit도 차단한다.
실제 성공 알림은 발생시키지 않는다. Figma의 생성·확정 토스트는 고정된 시각 테스트 사례에서만 검토한다.

## 후속 API 요구

현재 생성 계약은 CRUD·팀원 교체·후보 조회를 제공하지만 이 문서는 요청 DTO나 HTTP 경로를 신설하지 않는다.
운영 기수·대상 후보 자격·확정 상태/이력·재수정·앱 반영 시점·팀장·과거 기수와 최소 인원 서버 검증이 필요하다.
후속 단계에서 OpenAPI 원본을 확인하고 SDK/Query·expectedVersion·expectedCurrentTeamId·충돌 처리를 연결한다.
동시 변경 실패 시 최신 상태 재조회와 초안 재검토, 정보/팀원 별도 저장의 부분 실패 복구를 그때 설계한다.
