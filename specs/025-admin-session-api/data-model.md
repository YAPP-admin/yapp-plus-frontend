# 세션 화면 데이터 모델

이 문서는 생성 DTO를 복제하는 별도 서버 명세가 아니다. 앱 경계의 검증·변환과 상태 수명을 정한다.

## 조회 모델

| 값          | 원본·규칙                                                              |
| ----------- | ---------------------------------------------------------------------- |
| 기수 ID     | `VITE_ADMIN_GENERATION_ID` 또는 테스트 주입값                          |
| 세션 ID     | 생성 SDK 응답의 `sessionId`, SDK 요청에서 같은 값 사용                 |
| 유형        | `REGULAR` → `offline`, `TEAM` → `team`                                 |
| 이름·일정   | 원본 보존, 표시 날짜·시분은 별도로 파생                                |
| 정규 장소   | 주소·상세주소·위도·경도와 기존 `location`                              |
| 팀 장소     | 편집 입력 없음, 화면 표시만 `팀별 자율 장소`                           |
| 집계        | presentCount → present, absentCount → absent, undecidedCount → pending |
| 미제공 집계 | late·reported는 0, 백엔드 보완 주석. 실제 집계 완료를 의미하지 않음    |
| 출석 상태   | `NOT_STARTED` 또는 `STARTED`, 삭제 UI 판단에 보존                      |
| 목록 개수   | totalCount·allCount·regularCount·teamCount 보존, 전체 요청 기준 검증   |

기수 ID와 세션 ID는 확인된 API 계약과 설정을 그대로 사용한다. 외부 DTO는 생성 타입을 재사용하고
화면 모델에 필요한 차이만 정의한다.

## 입력 모델과 장소

- 이름은 trim 후 필수. 날짜는 유효한 날짜, 시간 입력은 시·분이며 최종 제출 시각의 종료가 같은 날 시작보다 늦어야 한다.
- 정규: 선택한 도로명주소와 유효한 위도·경도 필수, 상세주소 선택. 각 주소 최대 255자.
- 위도 -90~~90·경도 -180~~180의 유한 숫자만 허용한다. 0은 정상 좌표다.
- 정규 `location`은 도로명주소와 trim한 상세주소를 공백으로 합친다. 이는 프론트의 표시 변환 선택이다.
- 팀은 location·roadAddress·detailAddress·latitude·longitude를 모두 null로 보낸다.
- 상세주소 공백은 null로 직렬화한다. 팀 안내·미등록 문구 같은 표시 fallback을 저장값으로 보내지 않는다.
- 정규→팀→정규의 미저장 초안은 폼 수명에서 유지한다. 닫으면 폐기하고 현재 유형 값만 제출한다.
- 수정 전 유효 좌표를 그대로 복원한다. 새 주소 선택 때만 이전 상세주소·좌표를 초기화한다.

## 날짜·시간

날짜·시간은 한국 지역 일정이며 UTC 변환을 추가하지 않는다. 조회의 HH:mm·HH:mm:ss 및 유효한
초 소수부는 원본을 보존하고 UI에는 HH:mm을 표시한다. 변경하지 않은 시간은 원본을 제출하고,
사용자가 바꾼 시간은 HH:mm:ss의 초 00으로 보낸다. 읽기 검증과 분 단위 폼 검증을 구분한다.
생성은 분 단위 입력, 수정은 미변경 원본과 변경 입력을 합친 최종 제출 시각으로 순서를 검증한다.
예를 들어 기존 14:00:10~14:00:30을 시간 변경 없이 저장하면 같은 분으로 표시되어도 유효하다.
서버의 좌표 소수점 7자리 반올림 결과는 후속 재조회로 확인하며 프론트가 서버 결과를 추정하지 않는다.

## 상태 소유권

- Query: 서버 원본·목록·재조회 오류. 검색 필터는 URL. 파생 필터·정렬을 별도 state에 복제하지 않는다.
- Form·모달: 입력·장소 초안·제출 검증·해당 화면의 요청 수명.
- Mutation: 요청·서버 성공/실패. 성공 이후 목록 오류는 저장 실패로 전파하지 않는다.
- 네트워크 실패로 성공 여부가 불명확하면 안내와 목록 확인을 제공한다. 자동 재전송하지 않는다.
- 삭제 성공 시 진행 중 목록을 취소한 뒤 해당 ID가 캐시에 있을 때만 한 번 제거한다.
  totalCount·allCount와 해당 유형 count를 함께 갱신하고 서버 재조회로 확인한다. 404·409에는 적용하지 않는다.
- Query key는 생성 `find1QueryKey`의 기수·전체 유형을 사용해 모의 `['admin', 'sessions']`와 분리한다.
- 생성·수정의 성공 엔티티를 임의로 만들어 캐시에 넣지 않는다. 재조회 실패 시 기존 목록은 이전 결과임을 알린다.
