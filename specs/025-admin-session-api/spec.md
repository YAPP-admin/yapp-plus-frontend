# 기능 명세: 어드민 세션 API 연결

**브랜치**: `DongjaJ/session-management-api-plan`
**작성일**: 2026-11-17
**상태**: 1단계 문서 작성 — 사용자 리뷰 대기, 제품 구현 전
**이슈**: [#462](https://github.com/YAPP-admin/yapp-plus-frontend/issues/462)
**입력**: 세션 목록·생성·수정·삭제를 단계별로 연결하고, 단계마다 검증 결과를 리뷰한다.

## 사용자 시나리오와 검증

### US1 — 기수 세션 조회 (P1)

운영진이 지정한 기수의 일정과 집계를 확인한다. 이후 관리 행동의 출발점이므로 우선한다.
독립 검증: 정상·빈 목록·조회 실패를 공급해 필터와 상태 안내를 확인한다.

1. 기수가 설정되면 세션명·유형·날짜·시간·장소·집계가 최신 일정순으로 보인다.
2. 전체·오프라인·팀 세션 필터와 결과 개수가 일치하고, 뒤로·앞으로 가기로 조건이 복원된다.
3. 처음 조회 중에는 빈 목록으로 오인시키지 않는다. 전체 없음과 필터 결과 없음을 구분한다.
4. 조회 실패에는 재시도를 제공한다. 기수 설정이 없으면 안내만 표시하고 조회·변경하지 않는다.
5. 출석·결석·미처리는 제공된 수치, 지각·출결 보고는 이번 범위에서 0으로 표시한다.

### US2 — 세션 생성 (P1)

운영진이 새 일정을 등록한다. 목록 다음의 핵심 작업이며 유형별 장소 입력을 검증한다.
독립 검증: 정규·팀 세션을 각각 작성하고 성공·입력 오류·중복 날짜를 확인한다.

1. 정규 세션은 주소와 유효한 좌표가 필수이고 상세주소는 선택이다.
2. 팀 세션은 장소를 입력하지 않는다. 목록에는 `팀별 자율 장소`를 표시한다.
3. 이름·날짜·시작·종료 시간을 검증한다. 종료는 같은 날짜의 시작보다 늦어야 한다.
4. 같은 폼에서 유형을 왕복하면 정규 장소 초안을 복원하되 숨겨진 장소값을 저장하지 않는다.
5. 제출 중 중복 제출·입력 변경·닫기를 막는다. 취소하면 초안을 폐기한다.
6. 생성 성공 후 창을 닫고 전체 필터로 전환하며 완료를 알린다. 저장 실패 시 초안을 유지한다.

### US3 — 세션 수정 (P2)

운영진이 저장된 세션을 수정한다. 생성 이후 운영 과정에 필요하다.
독립 검증: 기존 세션을 열어 장소 복원, 유형 변경과 저장 제한을 확인한다.

1. 저장값으로 폼을 열고 유효한 저장 좌표를 자동 재조회해 덮어쓰지 않는다.
2. 지도 장애라도 유효한 저장 주소·좌표가 있으면 수정할 수 있다.
3. 성공하면 현재 필터를 유지한다. 유형 변경으로 카드가 사라지면 전체 목록에서 확인하도록 안내한다.
4. 날짜 중복·수정 제한·대상 없음에는 원인에 맞는 안내를 제공하고 입력을 유지한다.
5. 취소·닫기는 미저장 변경을 버린다. 다시 열면 마지막으로 확인한 저장값을 표시한다.

### US4 — 세션 삭제 (P2)

운영진이 출석 시작 전 불필요한 세션을 삭제한다. 서버의 삭제 제한을 지켜야 한다.
독립 검증: 시작 전·시작 후 세션과 확인 도중 상태가 바뀐 세션을 각각 처리한다.

1. 카드 메뉴에서 삭제할 수 있다. 출석 시작 상태이면 비활성화하고 이유를 표시한다.
2. 확인 창에 세션명을 표시하고 취소에 초기 포커스를 둔다. 취소하면 요청하지 않는다.
3. 삭제 중 중복 요청·닫기를 막고 성공 후 현재 필터·목록 개수·빈 상태를 갱신한다.
4. 출석이 뒤늦게 시작되어 삭제가 거절되면 항목을 유지하고 최신 상태를 확인한다.
5. 대상이 이미 없으면 찾을 수 없음을 알리고 목록을 갱신한다. 이번 요청의 성공으로 표현하지 않는다.
6. 취소 시 실행 버튼으로, 삭제 성공 시 실행 버튼이 사라지면 목록 제목으로 포커스를 옮긴다.

### 경계 조건

- 생성·수정·삭제 성공 뒤 목록 갱신이 실패해도 변경 성공을 실패로 바꾸지 않는다. 목록만 재시도한다.
- 오래된 조회 응답이 변경 이후의 목록을 덮어쓰지 않는다. 성공 전 항목을 미리 추가·수정·삭제하지 않는다.
- 저장 응답 유실로 결과가 불명확하면 목록 확인을 먼저 안내하며 자동으로 다시 저장하지 않는다.
- 요청 중 페이지를 이동하면 이전 화면의 완료 처리가 새 화면을 탐색하거나 알림을 띄우지 않는다.
- 인증 실패에는 로그인 필요 안내와 로그인 진입을 제공한다. 기존 인증·권한 체계를 확대하지 않는다.
- 잘못된 응답을 빈 목록·예시 데이터로 숨기지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: US1의 조회·필터·정렬·개수·상태 안내를 제공한다.
- **FR-002**: US2의 유형별 입력·검증·생성·취소를 제공한다.
- **FR-003**: US3의 값 복원·수정 제한을 처리한다.
- **FR-004**: US4의 삭제 진입·확인·제한·결과·포커스를 제공한다.
- **FR-005**: 변경 결과와 목록 갱신 결과를 구분하고 위 경계 조건을 지킨다.
- **FR-006**: 세션 관리의 실제 데이터와 출석 관리의 예시 데이터가 혼용되지 않는다.
- **FR-007**: 키보드·스크린 리더·터치로 주요 작업과 오류·진행 상태를 확인할 수 있다.

### 주요 개념

- **운영 기수**: 이번 세션 관리의 대상이다. 표시 번호와 내부 식별자는 서로 다르다.
- **정규 세션**: 현재 화면의 오프라인 세션이다. 주소와 출석 기준 좌표를 가진다.
- **팀 세션**: 운영진이 장소를 입력하지 않는 세션이다.
- **출석 시작 상태**: 집계 숫자와 별개로 삭제 가능 여부를 판단하는 상태다.

## 성공 기준

- **SC-001**: 조회·생성·수정·삭제 네 흐름의 정상·실패 수용 시나리오가 모두 검증된다.
- **SC-002**: 중복 클릭·늦은 조회·재조회 실패 사례에서 의도하지 않은 중복 변경이 0건이다.
- **SC-003**: 정규·팀 세션의 장소 규칙을 지키며 생성·수정할 수 있다.
- **SC-004**: 출석 시작 후 삭제는 실행할 수 없고, 확인 후 상태 변화도 사용자에게 설명된다.
- **SC-005**: 실제 환경에서 확인하지 않은 결과를 완료로 보고하지 않고 후속 조건을 명시한다.

## 가정과 범위

- 대상은 기존 관리자 인증을 사용하는 운영진이다. 기수 선택·출석부·출석 코드·마감은 제외한다.
- 기수는 임시 고정으로 주입한다. 실제 식별자 확보 전 모의 응답을 통한 연결 검증까지 완료한다.
- 실서버 확인은 후속이다. 기존 데이터의 일괄 보정·삭제 복구 기능은 추가하지 않는다.
- [기존 세션 명세](../008-admin-sessions/spec.md)의 모의 저장·초기화 정책과
  [장소 정책](../010-session-location/location-policy.md)의 팀 안내 입력은 이번 세션 화면에서 대체한다.
- 이번 문서는 사용자와 확정한 후속 요구다. 이전 문서의 과거 구현·검증 기록을 소급 수정하지 않는다.
