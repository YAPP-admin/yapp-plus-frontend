## 5-3 화면·접근성

Chrome 데스크톱에서 기본 화면, 391×844 및 320×480 CSS px 화면을 확인했다.
브라우저 배율 때문에 viewport 설정값과 CSS px가 달라 `innerWidth/innerHeight`로 실제 크기를 확인했다.

- 키보드 Enter로 카드 메뉴·수정 폼·날짜 선택창·주소 결과에 접근했다.
- 검색 Enter가 폼을 저장하지 않으며, Escape는 최상위 선택창만 닫고 부모 값은 유지했다.
- 391px에서 주소 줄바꿈, 지도·읽기 전용 좌표, 본문 스크롤과 저장·취소 버튼 접근을 확인했다.
- 320×480에서 날짜 선택창의 마지막 날짜에 접근하고 취소할 수 있었다.
- 페이지 너비는 각각 viewport와 같았고 선택창의 가로 넘침은 없었다.
- 접근성 트리에서 입력 이름·선택 상태·대화상자 제목을 확인했다. 이는 음성 스크린 리더 검증을 대신하지 않는다.
- 이미 열린 지도를 데스크톱에서 좁게 리사이즈하면 마커가 화면 밖으로 벗어날 수 있었다.
  좁은 화면에서 폼을 다시 열면 중심·마커가 정상 표시됐다. 회전·실시간 리사이즈 대응은 별도 개선 후보다.
- 실제 VoiceOver/NVDA 음성 출력, 터치 기기 마커 드래그와 모바일 Safe Area는 미검증이다.
- 공용 UI 패키지는 변경하지 않았으며 이번 검증을 위해 Storybook 사례를 추가하지 않았다.

화면: `.context/session-final-narrow.png`, `.context/session-final-picker-small.png`.
T019는 실기기·음성 검증이 남아 있어 부분 완료로 유지한다.

## 5-4 빌드·SSR·복구

- `mise exec -- node --run check`: 통과. admin 테스트 471개 포함, 이번 실행은 Turbo 캐시 재사용.
- `mise exec -- node --run build`: 통과. admin 빌드를 실제 실행했다.
- 배포용 산출물을 `http://127.0.0.1:3004`에서 실행했다. 원격 Vercel 배포는 수행하지 않았다.
- 배포용 브라우저에서 예시 2개 목록, SEED DatePicker·TimePicker를 이용한 팀 세션 생성,
  3개 목록 반영, 빈 안내의 대체 문구, 집계 0을 확인했다.
- 동일 시작·종료 시간의 저장 차단과 오류 표시, 종료 시간을 변경한 후 저장 성공을 확인했다.
  TimePicker는 휠 이동이 끝난 선택값을 확인한 뒤 확정했다.
- 새로고침하면 생성한 예시 항목이 사라지고 기존 2개로 초기화됐다.
- SSR `/sessions`는 HTTP 200과 로딩 안내를 반환했고, 예시 카드와 Kakao SDK 스크립트는 포함하지 않았다.
- SSR·window 없음에서 메모리 서비스 접근을 막는 계약은 기존 자동 테스트로 확인했다.
- 이번 배포용 빌드에는 실제 주소·지도 키를 주입하지 않았다. 키 누락 안내를 확인했으며
  배포용 오프라인 API 연결은 이번 개발 서버 검증과 구분한다.

화면: `.context/session-final-production.png`.
복구는 브라우저 새로고침으로 예시 데이터를 초기화한다. 코드 복구는 기능 변경을 되돌리는 방식이며
영구 데이터 이관·백엔드 계약 변경은 없다. 키 문제는 해당 서비스 설정을 수정한 뒤 재검증한다.
키 만료일·전체 허용 도메인 같은 외부 콘솔 메타데이터는 기존 준비 단계의 미확인 항목으로 남긴다.
