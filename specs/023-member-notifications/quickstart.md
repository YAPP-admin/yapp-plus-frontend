# 검증 실행 안내

## 선행 조건

1. 각 단계 리뷰와 이슈 생성 절차를 완료한다. #412는 완료되었으며 재실행하지 않는다.
2. mise의 Node.js 24.20.0·pnpm 12.3.4와 기존 workspace 의존성을 사용한다.
3. 푸시 실기기는 서버와 같은 Firebase 환경의 org.yapp.yappplus 설정·APNs 연결·새 runtime 빌드가 필요하다.
4. 계정·token·기기 식별자를 로그나 캡처에 남기지 않는다. 아래 시나리오는 아직 실행 완료가 아니다.

## 자동 검증

저장소 루트에서 단계별 관련 테스트를 먼저 실행하고 리뷰 단위의 기본 게이트를 실행한다.

```sh
mise exec -- node --run check
mise exec -- node --run build
mise exec -- node --run expo:doctor
```

문서만 변경한 1단계는 check를 실행한다. build는 배포 앱/빌드 변경, expo:doctor는 모바일 설정/의존성
변경부터 필수다. iOS native build는 기존 apps/mobile/README.md의 절차를 따른다.
각 결과에 실행 시각·새 실행/캐시·실패/미실행을 기록하고 같은 테스트를 불필요하게 강제 재실행하지 않는다.

## 출시·복구 확인

검증된 main SHA와 native build/runtime을 기록한다. 승인된 시험 발송은 실제 회원 대상 발송과
구분한다. 푸시 미검증이면 모의 테스트 통과로 대체하지 않는다. 웹 이전 배포·동일 runtime JS·
네이티브 수정 빌드를 구분해 복구하고, 서버 등록 해제/발송 중단 필요도 별도로 확인한다.

## TestFlight 실행 기록

2026-11-16 사용자 결정: 실제 푸시 검증은 나중에 TestFlight에서 진행한다.
현재 자동 검증 통과는 아래 실행 결과의 대체가 아니다. 빌드·배포·시험 발송은 아직 수행하지 않았다.

| 준비 항목 | 기록할 값                                  | 현재 상태                           |
| --------- | ------------------------------------------ | ----------------------------------- |
| 네이티브  | 검증 SHA·앱 버전·빌드 번호·runtime         | TestFlight 검증 빌드 미지정         |
| 웹        | MOBILE_WEB_URL·배포 SHA                    | 7-C 배포 확인 전                    |
| 환경      | 서버 환경·Firebase 프로젝트 일치·APNs 연결 | 실기기 확인 전                      |
| 기기      | 모델·iOS 버전                              | 실행 시 기록, 식별자·계정 정보 제외 |
| 발송      | 테스트 계정 범위·일시·공지/일반 유형       | 미발송                              |

1. TestFlight의 실제 설치 버전과 웹 배포 SHA를 확인하고 로그인한다.
2. 알림을 ON으로 바꾸고 권한을 허용한다. 설정 재진입 후 ON 유지와 서버 등록 성공을 확인한다.
3. 앱에서 알림함을 연 채 승인된 일반 알림을 발송한다. 배너가 표시되고 목록이 갱신되며,
   수신만으로 다른 화면으로 이동하지 않는지 확인한다.
4. 알림함을 떠난 상태에서 새 알림을 수신하고 복귀한다. 최신 목록이 조회되는지 확인한다.
5. 백그라운드·종료 상태에서 각각 POST와 일반 푸시를 눌러 공지 상세·알림함으로 이동하는지
   확인한다. 뒤로가기·동일 대상 반복 탭·연속 탭·삭제된 공지의 기존 오류 안내도 확인한다.
6. 알림 OFF와 화면 재진입 유지·서버 등록 해제를 확인한다. OFF 전 발송·OS에 남은 알림과
   해제 완료 후 새 발송을 구분한다. 알림함 내역은 OFF로 삭제되지 않는다.
7. OS 권한 차단 후 앱 복귀·설정 안내와 권한 재허용 후 동기화를 확인한다.
8. 로그아웃·계정 전환 후 이전 세션의 탭 대기가 재생되지 않는지 확인한다.
9. VoiceOver·터치·작은 화면·safe-area·알림함 스크롤과 뒤로가기를 확인한다.

각 항목은 실행 일시·통과/실패/미실행·민감 정보 없는 관찰 결과를 validation.md에 남긴다.
재현이 어려운 경합은 자동 테스트 결과와 실기기 관찰을 구분한다. 내부 revision·ack를
확인하려고 토큰이나 전체 푸시 본문을 출력하지 않는다. 목록 변화·목적 화면·중복 이동 여부를
우선 관찰한다. 모두 확인한 뒤에만 T035/T041/T042의 완료 여부를 다시 판단한다.
