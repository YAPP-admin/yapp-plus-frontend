# 기능 명세: 관리자 기수 선택과 세션 연결

**브랜치**: `DongjaJ/api-v3` | **작성일**: 2026-11-19
**상태**: 1단계 문서 작성 완료 — 2단계 API 최신화 진행 중
**이슈**: [#480](https://github.com/YAPP-admin/yapp-plus-frontend/issues/480)
**입력**: 로그인 후 최신 기수를 설정하고 기수 전환과 세션 관리를 연결한다.

## 사용자 시나리오와 검증

### US1 — 최신 기수에서 세션 관리 시작 (P1)

운영진은 별도 기수 설정 없이 로그인 후 최신 기수의 세션을 관리한다.
우선 이유: 이후 모든 기수별 관리 작업의 기준이다.
독립 검증: 서로 다른 두 기수와 세션을 공급하고 최초 선택·조회·생성·수정·삭제 대상을 확인한다.

1. 로그인에 성공하면 기수 목록을 조회하고 첫 번째 기수를 선택한다.
2. 최신은 기수 번호 내림차순, 동률이면 기수 ID 내림차순의 첫 기수다. 미래 기수도 포함한다.
3. 화면의 기수 이름과 세션 목록·생성·수정·삭제 대상 기수가 일치한다.
4. 새로고침·재로그인하면 최신 기수로 시작하고 이전 계정의 결과를 노출하지 않는다.
5. 미로그인 상태 또는 기수 목록 조회의 401 응답에서는 저장된 access token을 삭제하고 기수·세션을
   요청하지 않은 채 즉시 로그인 화면으로 이동한다.
6. 최초 로딩에는 관리자 작업 영역 전체의 준비 상태를 표시한다.
7. 기수 조회의 일반 실패는 관리자 작업 영역 전체에 재시도를 제공한다.

### US2 — 다른 기수로 전환 (P2)

운영진은 데스크톱 사이드바 또는 모바일 탐색 패널에서 관리할 기수를 바꾼다.
우선 이유: 기본 기수의 정상 연결 이후 과거·미래 기수를 같은 방식으로 관리한다.
독립 검증: 두 기수를 왕복하고 다른 메뉴로 이동한 뒤 돌아와 선택과 세션 대상을 확인한다.

1. 조회 순서대로 기수 이름을 표시하고 현재 선택을 식별할 수 있다.
2. 전환 시 세션 목록·생성·수정·삭제가 새 기수를 사용한다.
3. 화면 이동에는 선택과 기존 세션 유형 필터를 유지한다.
4. 전환 시 이전 기수의 세션 모달·미저장 초안·오류·알림을 폐기한다.
5. 이전 기수 요청이 늦게 완료되어도 현재 기수의 목록·탐색·알림을 변경하지 않는다.
6. 키보드·스크린 리더·터치로 선택하고 현재 기수를 확인할 수 있다.

### 경계 조건

- 조회 중을 빈 목록으로 표현하거나 임의 기수 ID로 대신 요청하지 않는다.
- 기수 목록은 서버 계약상 항상 하나 이상이다. 프론트는 별도 빈 목록 UI나 길이 검증을 추가하지 않는다.
- 잘못된 응답은 오류로 처리하며 예시 기수로 숨기지 않는다.
- 유효한 기존 목록의 재조회 실패는 Query의 기본 Suspense 오류 정책을 따른다. 기존 데이터가 있으면
  선택값과 작업 영역을 유지하며, 초기 조회 실패는 오류 경계가 처리한다.
- 유효한 재조회 결과에 선택 기수가 없으면 첫 기수를 선택한다. 이 경우는 모든 관리자 계정이
  모든 기수에 접근할 수 있다는 현재 권한 모델에서 발생하지 않는 방어적 처리다.
- 세션 변경 성공과 이후 목록 갱신 실패는 기존 정책대로 별도 결과로 처리한다.
- 재로그인 이전의 늦은 요청 결과가 새 로그인 상태에 표시되지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: US1의 로그인 이후 자동 선택·세션 관리·초기화 흐름을 제공한다.
- **FR-002**: US1의 로딩·오류·인증 안내를 관리자 작업 영역 경계에서 제공한다.
- **FR-003**: US2의 기수 선택·화면 이동 중 유지·기수별 작업 분리를 제공한다.
- **FR-004**: 경계 조건의 늦은 응답·초안 폐기·재조회 복구를 보장한다.
- **FR-005**: 기수 선택 UI의 접근성을 검증한다.

### 주요 개념

- **관리 가능 기수**: 운영진이 조회 가능한 과거·현재·미래 기수. ID·번호·표시 이름을 가진다.
- **선택 기수**: 현재 관리자 화면에서 작업 대상으로 사용하는 하나의 기수다.
- **기수 세션**: 선택 기수에 속한 일정이며 기존 생성·수정·삭제 정책을 유지한다.

## 성공 기준

- **SC-001**: 로그인·새로고침·재로그인의 대표 사례 모두 최신 기수에서 시작한다.
- **SC-002**: 두 기수의 조회·생성·수정·삭제 시나리오에서 다른 기수에 반영되는 요청이 0건이다.
- **SC-003**: 로딩·오류·미로그인 상태에서 기수 미확정 세션 요청이 0건이다.
- **SC-004**: 기수 전환·화면 이동·지연 완료 후 선택과 표시 결과가 일치한다.
- **SC-005**: 키보드·스크린 리더·터치로 기수 전환을 완료할 수 있다.

## 가정과 범위

- 대상은 관리자 세션 목록·생성·수정·삭제다. 회원 앱과 출석부·출석 코드·마감은 제외한다.
- 기수 선택은 화면 이동 동안만 유지한다. 새로고침·재로그인에는 최신 기수로 초기화한다.
- 기수 선택은 다른 관리자 페이지의 미연결 데이터를 실제 데이터로 바꾸지 않는다.
- 기존 인증 방식을 유지하며 새 로그아웃·토큰 갱신 정책을 추가하지 않는다. 기수 목록의 401은
  유효하지 않은 access token을 삭제하는 로그인 진입 조건으로 취급한다.
- 모든 관리자 계정은 반환된 모든 기수에 접근할 수 있다. 선택 기수의 권한별 제거·대체 UI는
  제공하지 않는다.
- API 제공 순서와 표시 이름을 사용한다. 날짜나 활동 여부로 최신 기수를 재정의하지 않는다.
- [기존 세션 명세](../025-admin-session-api/spec.md)의 임시 기수 설정을 대체하는 후속 요구다.
  과거 검증 기록은 소급 수정하지 않는다.
