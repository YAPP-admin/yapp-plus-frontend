# 회원 화면·후속 연결 계약

## 화면 경계

개발 페이지 공급부가 합성 fixture를 props로 전달한다. 제품 UI가 fixture·모의 저장소를 직접 조회하지 않는다.
로딩·실패·재시도 상태는 props 기반 UI와 테스트로 검증하고 가짜 네트워크 요청을 추가하지 않는다.
SSR 첫 화면과 프로덕션에는 준비 중 안내를 표시한다. 개발 클라이언트 준비 후에만 fixture를 동적 로딩한다.
미정인 SDK 타입·경로·클라이언트 wrapper를 이번 변경에 추가하지 않는다.

## URL과 탐색

| 항목             | 계약                                                                |
| ---------------- | ------------------------------------------------------------------- |
| 경로             | /members, /members?tab=pending, /members/import 유지                |
| tab              | all/pending, 기본 all                                               |
| q                | 문자열, 기본 빈 문자열. 제출 시 trim 후 이름 부분 검색              |
| part             | all/pm/design/android/ios/web/server, 기본 all                      |
| team             | 팀 식별자 문자열, 미선택은 생략. 없는 팀·매핑 전 조건은 전체로 정리 |
| 과거 role/status | 제거하고 무시. 앱이 새로 만드는 URL에서는 제외                      |
| 검색             | Enter 제출 때 replace, 입력 중 URL 유지. 한글 IME 조합 중 제출 방지 |
| 선택형 조건      | 다른 조건을 유지하며 history 추가·스크롤 유지. URL 기본값 생략      |
| 탭 이동          | 사이드바 회원 목록/가입 신청으로 tab 변경. 다른 회원 조건은 보존    |
| 업로드           | 진입·명시적 목록 복귀는 조건 초기화. 뒤로가기는 이전 조건 복원      |

상단 탭은 제거한다. 업로드에서도 회원 관리가 현재 메뉴이며 목록·신청의 동시 활성 표시는 피한다.
모바일 메뉴는 이동 시 닫힌다. 다른 메뉴 진입에는 회원 검색 조건을 전달하지 않는다.
가입 대기 수는 0이며 이번에는 생성된 findPending을 호출하지 않는다.

## 목록·수정

목록은 전체 결과 스크롤이다. 매핑 전 안내에는 아직 없는 팀 매핑 경로로 이동하는 버튼이 없다.
점수·팀 미제공은 —, 비활동은 읽을 수 있는 상태 문구로 구분한다. 팀 필터에 별도 배정 UI는 없다.
수정은 기존 overlay.open·SEED·AdminOverlayProvider를 사용하고 폼이 초안을 소유한다.
pathname 변경뿐 아니라 tab/q/part/team 변경에도 해당 모달을 닫는다. Query는 이번에 연결하지 않는다.
저장·비활동은 disabled이며 옆에 기능 준비 중 설명을 표시한다. form submit도 차단한다.
사용자가 편집한 초안으로 목록·변경 이력을 갱신하거나 성공 알림을 표시하지 않는다.

## 파일 미리보기

선택과 드롭은 같은 검증 경로를 사용한다. 실제 검증 결과를 표시하며 고정 결과로 대체하지 않는다.
다운로드 양식은 파서와 같은 열 정의로 만들고 전화번호 열을 문자열로 취급한다.
약 9행 높이의 스크롤 영역에 모든 행을 표시한다. 중복 라디오는 행별 이름으로 연결한다.
오류 행에 원본 번호와 이유를 표시하고 반영 예정 수와 정상·오류·중복 합계를 구분한다.
건너뛰기가 기본이며 반영 버튼은 예정 수와 무관하게 disabled다. 실제 반영·완료 이동은 없다.
업로드 화면에 예시 명단 기준 검토이며 실제 반영 전 다시 확인해야 한다는 안내를 표시한다.

## 필요한 후속 API 정보

| 능력           | 화면에 필요한 계약                                                     |
| -------------- | ---------------------------------------------------------------------- |
| 회원 조회      | 회원/활동 식별자, 기수 이력·직군·권한·활동 상태·가입일, 출석 요약      |
| 팀 조회        | 기수별 매핑 상태·팀·소속·팀장, 목록과 식별자 일관성                    |
| 수정·비활동    | 대상 활동, 변경 가능 필드, 기수 정정 제한, 권한·충돌 오류              |
| 변경 이력      | 작업자·시각·항목·이전/새 값과 조회 범위                                |
| 명단 검증·반영 | 중복 기준, 덮어쓰기 허용 필드, 최신 상태 재검증, 부분 반영·재시도 정책 |

위 표는 요구 정보이며 HTTP 경로·요청/응답 DTO가 아니다. 백엔드 확인 후 OpenAPI를 생성 원본으로 사용한다.
현재 status:string·PLAYER/OB만으로 운영진 권한이나 기수 비활동 의미를 추측하지 않는다.
생성 SDK/Query와 기존 Faker/MSW를 재사용하고 필요한 경우 MSW 내부에서만 최소 변경 상태를 유지한다.
