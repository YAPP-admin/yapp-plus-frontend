# 관리자 라우팅 PR 6 검증

- 확인일: 2026-10-11. 관련 이슈: [#55](https://github.com/YAPP-admin/yapp-plus-frontend/issues/55).
- 기준 커밋: PR 5 `8e48bc4`. 브랜치: `DongjaJ/admin-notices-routing`.
- 범위: `/notices` 최소 화면, 공지 목록 메뉴와 종류 필터.
- 실제 공지 데이터·API·인증·상세·작성·수정은 포함하지 않는다.

## URL과 탐색

- `category`는 `all | session | submission | operation`이며 전체·세션·제출·운영으로 표시한다.
- 누락·잘못된 쿼리는 `all`로 처리하고 앱이 생성하는 URL에서 기본값은 생략한다.
- 필터 변경은 history에 추가하고 스크롤을 유지한다. 뒤로가기·앞으로가기는 URL의 종류를 복원한다.
- 다른 메뉴로 이동할 때 공지 쿼리를 전달하지 않고 공지 메뉴 재진입은 기본 상태를 사용한다.
- 종류 스키마와 화면은 notices 슬라이스에 두고 route에서 Zod 검증·탐색을 연결한다.
- effect·라우터 이벤트 구독·새 의존성은 추가하지 않았다. 생성 라우트는 Vite로 갱신했다.

## 검증 결과

- `mise exec -- node --run check`: 포맷·lint·타입 검사·전체 테스트 통과.
- `mise exec -- node --run build`: 전체 빌드 통과.
- 관리자 테스트 9개 파일, 129개 통과. PR 5 대비 26개 추가.
- 허용값·누락·잘못된 외부 입력, 직접 접근, 현재 메뉴 표시, history 복원·기본값 생략,
  메뉴 이동 시 쿼리 초기화, 키보드 진입, 알 수 없는 하위 경로의 404를 검증했다.
- 메뉴 추가에 맞춰 기존 세션·출석·업로드 화면의 키보드 탐색 테스트를 갱신했다.
- 프로덕션 서버의 기본·제출·잘못된 쿼리 `/notices`는 HTTP 200과 예상 필터·문서 제목을 반환했다.
- `/notices/missing`은 HTTP 404를 반환했다.
- Chrome에서 필터 변경·새로고침·뒤로가기·앞으로가기·메뉴 이동을 확인했다.
- 375px·1280px에서 가로 넘침이 없으며 필터 높이 44px, 글자 16px, 포커스 테두리 2px를 확인했다.
