# 기능 명세: 회원 공지 조회·읽음 연동

**브랜치**: `DongjaJ/member-notices-home` | **작성일**: 2026-11-07 | **상태**: 구현·자동 검증 완료, 실서버 상세·읽음 검증은 테스트 공지 필요
**입력**: 안드로이드 구현과 최신 서버 명세를 참고해 회원 공지 목록·홈·상세·읽음 저장을 단계별로 연결한다.

## 사용자 시나리오와 검증

### US1 — 게시판에서 공지 찾기 (P1)

회원이 열람 가능한 공지를 종류별로 찾고 이전 목록으로 돌아온다. 상세 열람의 진입점이므로 우선 구현한다.
독립 검증: 종류가 다른 3페이지의 공지로 필터·추가 조회·상세 왕복을 확인한다.

1. 로그인 회원이 게시판에 들어가면 열람 가능한 공지를 서버 순서로 20개씩 본다.
2. 전체·세션·과제·기타를 선택하면 해당 종류를 첫 페이지부터 조회하고 스크롤이 위로 이동한다.
3. 목록 끝에서 다음 페이지를 추가한다. 같은 공지를 반복 표시하거나 같은 페이지를 무한 요청하지 않는다.
4. 추가 조회만 실패하면 기존 목록과 재시도를 보여준다. 빈 결과와 실패를 구분한다.
5. 필터 URL 직접 진입·새로고침에서 선택을 복원하고 상세 왕복 시 필터와 스크롤 위치를 유지한다.

### US2 — 홈에서 이번 주 공지 확인하기 (P2)

회원이 홈에서 이번 주 공지를 빠르게 확인한다. 전체 목록 기반을 재사용하되 다른 홈 기능과 실패를 분리한다.
독립 검증: 이번 주·지난주 공지가 섞인 첫 페이지로 주간 범위·최대 개수·빈 결과를 확인한다.

1. 전체 공지 첫 페이지에서 서울 기준 일요일부터 토요일까지 작성된 공지를 최대 3개 보여준다.
2. 공지를 누르면 해당 상세로 이동한다. 공지가 없으면 빈 안내를 보여준다.
3. 공지 실패가 세션·출석을 막지 않는다. 주가 바뀐 뒤 복귀하면 현재 주 기준으로 다시 조회한다.

### US3 — 공지 본문과 제출 안내 읽기 (P1)

회원이 서식 본문·제출 안내·첨부를 확인한다. 목록 없이 상세 직접 진입으로도 검증할 수 있다.
독립 검증: 세션·과제·기타 상세와 접근 불가·이미지 오류를 각각 준비한다.

1. 제목·종류·작성일·본문을 표시하고 과제에만 제출 기한·대상·방법을 보여준다.
2. 제목·문단·강조·목록·인용·링크·코드 서식을 읽을 수 있다. 본문의 실행 코드와 위험한 링크는 실행하지 않는다.
3. 첨부 이미지는 지정된 순서로 표시하며 읽기 주소 만료 시 재시도로 다시 조회할 수 있다.
4. 없는 공지·열람 불가 공지는 접근 불가 안내, 일시적 실패는 재시도 안내를 보여준다.
5. 상세를 열기만 해서는 읽음 상태가 바뀌지 않는다.

### US4 — 공지를 읽었다고 확인하기 (P1)

회원의 명시적인 확인을 서버에 저장한다. US3 완료 후 같은 상세의 읽음 상태만으로 독립 검증한다.

1. 미확인 상태에서 버튼을 누르면 저장하며 진행 중 중복 요청을 막는다. 확인 취소는 제공하지 않는다.
2. 저장 성공 후 확인 완료를 표시하고 서버에서 확인 인원을 다시 받는다. 인원을 임의로 증가시키지 않는다.
3. 저장 실패는 다시 저장할 수 있다. 저장은 성공하고 인원 갱신만 실패하면 확인 완료를 유지하고 조회만 재시도한다.
4. 이미 읽은 공지와 재진입한 상세는 서버 상태를 사용한다. 다른 회원에게 이전 요청 결과가 반영되지 않는다.

### 경계 조건

- 카테고리 빠른 전환, 빈 중간 페이지, 중복 공지, 반복·무효 커서, 화면 숨김과 복귀.
- 주간 경계·서울 자정·해외 기기 시간대, D-day 전날·당일·지난 날짜.
- 잘못된 상세 ID, 권한 상실 뒤 재조회, 연결 끊김, 본문·이미지 주소 오류.
- 읽음 응답 유실 후 재시도, 저장 중 화면 이탈·공지 변경·로그아웃·다른 계정 로그인.

## 요구사항

### 기능 요구사항

- **FR-001**: 로그인 회원에게 현재 열람 가능한 공지만 표시하고 미로그인 상태를 조회 실패와 구분한다.
- **FR-002**: 유형별 조회·20개 커서 추가 조회·중복 제거·반복 방지·재시도를 제공한다.
- **FR-003**: 카테고리를 URL로 복원하고 상세 왕복의 카테고리·스크롤을 보존한다.
- **FR-004**: 홈은 첫 페이지에서 서울 기준 이번 주 공지를 최대 3개 보여주며 독립적으로 실패를 처리한다.
- **FR-005**: 상세는 실제 본문·과제·첨부·읽음 상태·인원을 표시하고 조회만으로 읽음을 저장하지 않는다.
- **FR-006**: 날짜는 서울 기준이다. D-day는 양수에 D-N, 0에 D-day, 음수에 D+N이다. 날짜뿐인 기한에 시간을 보충하지 않는다.
- **FR-007**: 기본 본문 서식을 지원하고 실행 가능한 본문·허용하지 않은 URL을 차단한다. 이미지 실패는 복구 가능하게 표시한다.
- **FR-008**: 확인은 취소 없는 명시적 저장이며 중복·지연 응답·저장 후 조회 실패를 구분한다.
- **FR-009**: 조회·읽음 결과를 해당 계정과 화면에만 반영하며 오프라인에서 읽음 저장을 예약하지 않는다.
- **FR-010**: 고정 예시를 제품에서 제거하고 로딩·빈 결과·접근 불가·일시 실패를 구분한다. 키보드·스크린 리더·터치로 주요 흐름을 제공한다.

### 주요 개체

- 공지 요약과 목록: 식별자·종류·제목·작성일·마감까지 남은 일수, 전체 개수·정렬된 요약·다음 조회 위치.
- 공지 상세: 서식 본문·선택적 과제 안내·첨부·읽음 상태·인원.
- 과제 안내와 첨부: 제출 날짜·대상·링크, 이미지 이름·순서·읽기 주소·만료 시각.

## 성공 기준

- **SC-001**: 준비한 3페이지에서 필터별 결과를 누락·중복 없이 탐색하고 상세 왕복 후 기존 위치에서 계속 읽을 수 있다.
- **SC-002**: 주 경계·해외 시간대 사례 모두 동일한 서울 주간 범위와 최대 3개 표시를 만족한다.
- **SC-003**: 세 종류의 상세·제출 안내·첨부를 확인하고 오류별로 맞는 복구 행동을 선택할 수 있다.
- **SC-004**: 상세 열람만으로 확인 수가 바뀌지 않고 연속 클릭·응답 유실에도 한 회원의 확인이 중복 집계되지 않는다.
- **SC-005**: 계정 전환·뒤로가기·새로고침·터치·키보드·스크린 리더 시나리오 결과와 미실행 항목을 구분해 제출한다.

## 가정과 제외 범위

- [제품 맥락](../../docs/mission.md)과 사용자 선택에 따라 회원 목록·홈·상세·읽음만 다룬다. 관리자 CRUD·알림·푸시·질문은 제외한다.
- Android의 홈 첫 페이지·주간 기준을 따른다. 전체 페이지를 모아 주간 공지를 재구성하지 않는다.
- 기존 디자인을 유지한다. 표·체크리스트·수식·구문 강조·본문 편집·읽음 취소는 추가하지 않는다.
- 기존 인증을 재사용한다. 개발 모의 환경은 별도이며 일반 브라우저의 실회원 인증은 추가하지 않는다.
- 각 단계 종료 후 사용자 리뷰와 다음 단계 진행 확인을 받는다. 문서 요청은 외부 이슈 생성·Git 작업 승인이 아니다.
