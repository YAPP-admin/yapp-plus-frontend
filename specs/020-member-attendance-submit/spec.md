# 기능 명세: 회원 코드 출석과 사전 출결 보고

**브랜치**: `DongjaJ/wh3c0` | **작성일**: 2026-11-08 | **갱신일**: 2026-11-17
**상태**: 코드 출석 구현 유지 · 사전 보고 1단계 문서 리뷰 대기 · [#385](https://github.com/YAPP-admin/yapp-plus-frontend/issues/385)
**입력**: 기존 코드 출석 작업을 보존하고, 사용자 인터뷰에서 확정한 회원 웹 사전 보고 정책을 연결한다.

## 사용자 시나리오와 검증

### US1 — 세션 출석하기 (P1)

회원은 출석 가능 상태인 세션에 4자리 코드를 제출하고 실제 검증 결과를 확인한다.
핵심 사용 목적이므로 먼저 구현한다. 독립 검증은 홈에서 코드 입력·성공·오류·복귀까지다.

1. 출석 대상과 가능 여부에 맞는 버튼·안내를 표시한다. 불가능한 상태에서는 제출할 수 없다.
2. 숫자 4자리를 입력하거나 붙여넣고 제출한다. 앞자리 0을 포함한 코드를 입력할 수 있다.
3. 서버가 출석을 확인한 경우에만 완료 화면을 표시하고 홈으로 돌아와 해당 세션의 완료 상태를 본다.
4. 잘못된 코드나 일시적 실패는 완료로 바뀌지 않으며 입력을 수정하거나 다시 시도할 수 있다.

### US2 — 사전 출결 보고하기 (P2)

회원은 지각·조퇴·결석을 선택하고 필수 사유를 제출한다.
독립 검증은 코드 출석과 별개로 세 종류 보고의 성공·실패·마감을 각각 확인하는 것이다.

1. 유형은 미선택으로 시작한다. 유형을 선택한 뒤 한 줄 사유와 글자 수를 표시한다. 사유는 최대 30자이며 빈 값·공백만 있는 값은 제출할 수 없다.
2. 세 유형 모두 한국 시간 기준 이번 주 세션 시작 전까지 제출한다. 시작 정각부터 해당 세션 보고를 막고 운영진 문의를 안내한다.
3. 토요일 세션 시작 후에는 보고가 닫혀 있으며, 일요일 00:00부터 새 주간 세션을 조회한다. 세션이 없으면 제출하지 않는다.
4. 사유 단계의 뒤로가기는 유형 선택으로 돌아가며 입력을 유지한다. 첫 단계에서 뒤로가거나 시트를 닫으면 초안을 버리고, 다시 열면 처음부터 작성한다.
5. 서버가 제출을 확인하면 시트를 닫고 홈에 '출결 보고를 완료했어요'를 표시한다. 보고만으로 출석 완료·점수·횟수를 바꾸지 않는다.
6. 자격 없음·대상 없음·보고 불가·대상 변경은 구분해 안내한다. 대상 변경·충돌 응답 후에는 최신 내용을 확인하고 수동으로 다시 제출한다.
7. 응답을 받지 못하면 이미 접수됐을 수 있음을 안내한다. 같은 유형을 다시 제출하면 최신 보고로 반영됨을 알리고 수동 재제출을 허용한다.

### 보고 규정 안내

사전 보고는 출석 현황을 미리 파악하고 무단 지각·조퇴·결석을 방지하기 위한 절차다.
지각·조퇴는 세션 시작 전까지, 결석은 특별한 사유가 없는 한 세션 시작 이틀 전까지 보고하도록 안내한다.
결석의 이틀 전 기준으로 웹 제출을 따로 막지는 않는다. 보고 접수와 감점 인정은 별도이며,
기존 서버의 결석 사전 보고 인정 기준인 시작 48시간 전은 변경하지 않는다.
특별한 사유는 운영진에게 별도 문의하도록 안내하고 앱 내 예외 신청·심사는 추가하지 않는다.

### 경계 조건

- 연속 클릭, 붙여넣기·백스페이스, 30자 경계와 이모지, 통신 단절·응답 유실.
- 출석 가능 상태 변경, 주간 경계, 직접 URL 진입, 입력 중 뒤로가기, 숨겨진 화면으로 늦게 도착한 결과.
- 인증 만료, 로그아웃·다른 계정 로그인, 제출 성공 뒤 조회 갱신 실패.

## 요구사항

- **FR-001**: 실제 로그인한 회원이 출석·보고를 제출한다. 일반 브라우저에서 실제 인증을 새로 제공하지 않는다.
- **FR-002**: 코드 출석 가능 여부는 서버가 정하며, 클라이언트가 출석 시간·점수를 계산하지 않는다. 보고의 웹 마감은 US2의 시작 전 제한을 적용한다.
- **FR-003**: 코드 네 자리와 보고 유형·필수 사유를 검증하고, 유효한 서버 성공 확인 전 완료를 표시하지 않는다.
- **FR-004**: 제출 중 중복과 시트 닫기를 막고 진행 상태를 안내한다. 연결 복귀나 인증 복구만으로 제출을 자동 재실행하지 않는다.
- **FR-005**: 완료 상태는 제출한 계정에 한정하고 오류·입력·화면 이동은 현재 화면에 한정한다. 입력값을 URL·영구 저장소·로그에 남기지 않는다.
- **FR-006**: 홈의 출석 완료 표시는 현재 앱 화면 수명의 확인 결과이며 재시작 후 영구 복원을 보장하지 않는다.
- **FR-007**: 웹의 보고 마감과 별개로 최종 접수·대상 선택·출석 결과·점수는 서버 결과를 따른다. 보고 수정·취소·이력 UI를 추가하지 않는다.
- **FR-008**: 키보드·스크린 리더·터치로 입력·오류 수정·완료·복귀가 가능해야 한다.
- **FR-009**: 보고 진입을 코드 출석 가능 상태나 출석 완료 여부에 묶지 않는다. 유효한 주간 세션 정보가 없거나 시작 시각에 도달하면 보고 제출을 막는다.
- **FR-010**: 일반 제출에 별도 세션 재확인 단계를 요구하지 않는다. 작성 중 마감되면 제출을 막고, 주간 변경이 일어나도 초안을 자동 제출하지 않는다.

### 주요 개체

- 출석 대상: 세션 식별자, 일정, 출석 가능 상태.
- 출석 확인: 해당 계정과 세션에 대한 성공 확인 및 확인 시각.
- 출결 보고: 지각·조퇴·결석 유형, 회원 웹에서 필수인 사유, 서버가 선택한 세션과 제출 시각.

## 성공 기준

- **SC-001**: 가능한 상태에서만 코드 제출에 진입하고 정상·잘못된 코드·서버 실패 사례가 모두 기대 결과와 일치한다.
- **SC-002**: 세 보고 유형 모두 빈 사유·공백·길이 초과를 막고, 정상·서버 실패·접수 불확실 상태를 구분한다.
- **SC-003**: 연속 클릭·통신 복귀에 의한 의도치 않은 중복 제출과 다른 계정에 반영되는 늦은 결과가 없다.
- **SC-004**: 두 사용자 흐름의 자동 검증·접근성 확인·실기기 확인 결과와 미실행 항목을 별도로 기록한다.
- **SC-005**: 세션 시작 직전에는 제출할 수 있고 정각·직후에는 막힌다. 결석 이틀 전 이후에도 시작 전이면 제출 가능하며, 다음 주 보고는 일요일부터 열린다.
- **SC-006**: 사유 단계에서 뒤로가면 입력이 유지되고 시트를 닫았다 다시 열면 초기화된다. 성공 뒤 홈 조회 실패가 접수 성공을 취소하지 않는다.

## 가정과 제외 범위

- 최초 코드 출석 비교 기준은 Android `2b837e3c`다. 11월 8일 한국 시간의 팀 사진 UI 두 커밋은 제외했다. 이번 사전 보고는 11월 17일 인터뷰와 최신 Hand off를 기준으로 하며 Android와 정책이 같다고 주장하지 않는다.
- 기존 화면·인증을 재사용한다. 공지 작업 세션, 팀 사진·푸시·알림·프로필·관리자 기능은 제외한다.
- 출석 완료의 수명은 Android와 같이 비영구 상태다. 새 조회 계약을 만들지 않는다.
- 사용자가 기존 #385와 이 명세의 후속 작업으로 진행하도록 승인했다. 사전 보고는 문서 → 제출·마감 처리 → 화면·탐색 → 통합 검증의 네 단계로 리뷰하며 아직 제품 코드는 구현하지 않았다.
- 백엔드와 다른 앱은 변경하지 않는다. 웹의 기기 시각·조회 결과와 서버 처리 사이의 일정 변경을 원자적으로 보장하지 않는다.
- 구현 완료 기준은 자동 테스트와 브라우저 검증이다. 실서버·실기기는 별도 확인 항목이며 과거 검증을 이번 실행으로 보고하지 않는다.
