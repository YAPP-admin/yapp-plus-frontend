# 어드민 출석 백엔드 계약 초안

**상태**: 프런트엔드 검토용 초안. 백엔드 담당자와 합의하거나 배포 서버를 검증한 문서가 아니다.
**확인 기준**: 2026-10-29 로컬 생성 코드 및 백엔드 dev `b52fce938e1679287160b1c2ba5eebb601b89c99`.

## 확인된 API

아래 상대 경로의 기준은 `/api/admin/generations/{generationId}/sessions/{sessionId}`다.

| 메서드·경로                                       | 로컬 생성 코드            | 확인한 의미                                    |
| ------------------------------------------------- | ------------------------- | ---------------------------------------------- |
| GET `/attendance`                                 | `list1`, items/nextCursor | 회원별 현재 출결·최신 보고 유형/사유·명찰·점수 |
| PATCH `/attendance/{membershipId}`                | `override`                | 개별 출결 정정                                 |
| PATCH `/attendance/{membershipId}/badge`          | `badge`, enabled          | 명찰 검증 여부 변경                            |
| POST `/attendance/close`                          | `close`                   | 최종 출석 마감; 미정→결석, 점수 계산           |
| POST `/attendance/close/cancel`                   | `cancel`                  | 마감 취소; 아래 의미 차이 참조                 |
| GET `/team-attendance-photos`                     | 없음, dev 구현 확인       | 제출 사진 목록                                 |
| POST `/team-attendance-photos/{photoId}/decision` | 없음, dev 구현 확인       | APPROVED/REJECTED, 선택적 reason 최대 500자    |

출석 코드 조회·발급·재발급 SDK는 `get`/`start`/`reissue`다. 출석 생성 API로 취급하지 않는다.
생성 SDK의 타입·함수명은 경계 구현 참고이며 ViewModel에서 import하지 않는다.

## 응답과 입력의 차이

| 항목                            | 현재 근거                                                                      | 필요한 처리·협의                                                          |
| ------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 세션 생성과 출석 생성           | 사용자 전제; 목록은 명단 기준, 마감 시 기록 보장 로직 확인                     | 실제 물리 기록 생성 시점과 무관하게 생성 후 전체 대상 명단 조회 보장 필요 |
| 보고 유형·사유                  | latestReportType/latestReportReason 있음                                       | 보고 시각·적격성·전체 이력은 별도 응답 필요                               |
| 지각·조퇴 구간과 일반/무단      | UI 입력과 일치하는 명시적 입력 필드 없음                                       | 운영진 직접 지정의 의미 및 감점 우선순위 합의 필요                        |
| 실제 시각                       | 로컬 수정 입력에 checkedInAt 없음, 조회 응답에 earlyLeaveAt 없음; dev에는 있음 | OpenAPI 원본 갱신 후 재생성; 임의 시각을 만들지 않음                      |
| 마감 여부·취소 가능 여부        | 출석 목록은 items/nextCursor만 제공                                            | 조회 가능한 상태·취소 제약·권위 있는 요약 계약 필요                       |
| 마감 오류                       | 로컬 CloseErrors에 409 없음                                                    | dev의 TEAM_ATTENDANCE_PENDING을 명세와 생성 코드에 반영 필요              |
| 관리자 보고/변경 이력·누적 점수 | 현재 관리자 생성 코드에서 충분한 계약 없음                                     | 회원용 history/scores/me를 관리자 전체 조회에 재사용하지 않음             |
| 공결·복합 상태                  | 백엔드 점수 규칙에 존재                                                        | 편집은 후속 범위. 일반 결석으로 강제 매핑하지 않음                        |

현재 백엔드 결석 보고 기준은 시작 48시간 전이며, 지각·조퇴는 실제 체크인·퇴장 시각과 보고 시각을 비교한다.
사용자 정책의 ‘2일 전’ 및 사전 보고 기준과 같다고 단정하지 않는다. 모의 적격성은 명시적 필드로 제공한다.
실제 연결 전에는 경계 시각·시간대·운영진 정정 우선순위를 함께 확정한다.

## 출석 마감과 마감 취소

- 화면의 ‘출석 마감’이 POST `/attendance/close`에 대응한다. 별도 ‘저장’ 또는 2차 최종 마감을 만들지 않는다.
- 마감은 필터와 무관하게 전체 대상에게 적용한다. 미정은 결석으로 전환하고 점수를 확정한다.
- 백엔드는 제출 사진 PENDING 존재 시 409 `TEAM_ATTENDANCE_PENDING`을 반환한다.
- 명찰 변경은 검증자·시각만 바꾸며 출결·점수를 바꾸지 않는다. 프런트도 동일하게 분리한다.
- 백엔드는 마감 후에도 일부 출결 정정과 명찰 변경을 허용한다. 화면의 마감 후 잠금은 프런트 정책이다.

| 항목           | 모의 구현 기준                    | 확인한 dev 동작                           | 합의 필요                                      |
| -------------- | --------------------------------- | ----------------------------------------- | ---------------------------------------------- |
| 취소 후 결과   | 출결·점수 유지, 편집 잠금 해제    | 마감 자동 결석→미정, 계산 점수 초기화     | 결과 보존 여부                                 |
| 취소 가능 시각 | 모의 세션의 canCancelClose로 표현 | 세션 종료 전만 해제                       | UI 표시와 서버 제약                            |
| 취소 응답      | 갱신된 phase 확인                 | 취소 불가/이미 취소도 void 성공 응답 가능 | 성공 응답만으로 해제 단정 금지, 상태 조회 필요 |

모의 정책은 서버 지원 사실이 아니다. 실제 연결 전에 표의 차이를 사용자·백엔드와 결정한다.

## 검수 대기 사진: 백엔드 공유 제안

### 상태와 데이터

- 팀 전체 명단과 제출 사진 목록을 결합하여 notSubmitted와 pending을 구분한다.
- dev의 제출 목록은 photoId, teamId/teamName, uploaderId/uploaderName, submittedAt, status, readUrl, members를 제공한다.
- members는 membershipId, userName, selected, provisionalStatus, priorReports를 제공한다.
- priorReports는 유형·보고 여부·사유이며 제출 시각은 없다. 점수 적격성의 근거로 충분하지 않다.
- readUrl은 단기 서명 URL(현재 5분)이며 보관 기간 경과 등으로 null일 수 있다.
- URL null·만료·다운로드 오류는 사진 접근 불가이며 미제출이 아니다. 재조회로 URL 갱신을 시도한다.

### 제안하는 처리 순서

1. 판단 초안을 photoId별로 유지하고, 승인·반려 결정과 선택적 사유를 기록한다.
2. ‘출석 마감’에서 판단을 반영한 뒤 명시적 개인 수정을 반영한다. 팀 승인으로 개인 결정을 잃지 않게 한다.
3. 서버가 검수 대기를 검사한 후 전체 미정을 결석으로 바꾸고 마감한다.
4. 대기가 남으면 409 `TEAM_ATTENDANCE_PENDING`으로 마감을 실패 처리한다.
5. 프런트는 최신 사진 목록을 읽고 대기 항목을 안내한다. 이미 반영된 판단은 유지하고 나머지 검수를 이어간다.
6. 미제출 팀은 검수 대기가 아니다. 해당 회원의 미정만 일반 마감 규칙에 따라 결석으로 전환한다.

### 백엔드와 확정할 항목

- 제출 상태 전이와 마감 검사를 같은 일관성 경계에서 보장할지, 마감 후 업로드/판단을 어떻게 제한할지.
- 재제출 사진 식별자·이전 판단 처리, 낡은 photoId에 대한 오류와 동시 수정 충돌 응답.
- 승인 시 selected 회원에 적용할 상태, 이미 명시적으로 정정한 회원의 보호 및 우선순위.
- 반려 후 개인 출결을 무엇으로 유지/변경할지. 모의 초안은 반려만으로 명시적 개인 출결을 덮어쓰지 않는다.
- 마감·판단 재시도의 멱등성, 응답 유실 시 확인할 조회 상태 또는 버전.
- 전체 팀 명단·검수 대기 수·마감 여부를 일관되게 읽는 방법과 권한 범위.

위 항목은 제안/협의 대상이다. 실제 API의 원자성이나 충돌 처리를 구현 사실로 주장하지 않는다.
모의 서비스에는 신규 제출 경합, URL 만료, 판단 부분 실패, 이미 마감된 세션을 검증 시나리오로 둔다.

## API 갱신과 실제 연결의 완료 조건

OpenAPI 원본 갱신 → 생성 명령 실행 → 생성 결과 검토 → adapter 검증·매핑 테스트 순서로 진행한다.
생성 코드는 직접 편집하지 않는다. 현재 부족한 필드를 프런트 DTO 타입 단언으로 보충하지 않는다.
실제 연동 시 이 문서의 협의 항목, 오류 코드, 마감 후 조회 상태를 확정하고 복구 절차를 다시 검토한다.

## 점수 계산의 소유권

실제 감점과 누적 점수의 계산 주체는 서버다. 출석 응답의 scoreDelta를 그대로 표시하고 클라이언트에서 재계산하지 않는다.
관리자 누적 점수는 별도 응답 계약을 협의하며, 현재 계약 누락을 클라이언트 합산으로 대체하지 않는다.
프런트의 계산 함수는 `model/mocks`에서만 사용한다. 모의 점수의 source는 mock, 서버 점수는 server로 구분한다.
