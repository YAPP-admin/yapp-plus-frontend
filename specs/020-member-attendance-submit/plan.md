## 요약

기존 홈·Stackflow 시트·네이티브 인증과 생성 API를 재사용한다. 두 기능을 각각 구현·검증·리뷰한다.
사용자가 승인한 초안을 이 디렉터리로 옮겼다. 코드 출석과 사전 보고를 각각 리뷰한다.

## 기술 맥락

- 대상: `apps/web`의 iOS WebView, 개발 MSW 브라우저. TypeScript·React·TanStack Query·SEED·Stackflow·Vitest를 유지한다.
- 생성 클라이언트의 `verify`, `submit1`, 생성 스키마와 `useNativeAuthSession().apiOptions`를 사용한다. 서버·브리지 계약은 수정하지 않는다. mutation key는 생성 설정의 `mutationKeys: true`로 생성한다.
- 저장: 서버만 영구 저장한다. 출석 완료 표시는 계정·세션별 메모리 상태로 관리한다. 새로운 의존성은 없다.
- 제출은 사용자 동작에서 한 번 실행한다. mutation 재시도·오프라인 대기 재생을 끄고 요청 중 버튼을 잠근다.

## 구조와 동작

- 홈 전용 입력·요청·응답 검증은 `apps/web/src/pages/home/model`과 `ui`에 둔다. 다른 페이지 슬라이스를 직접 import하지 않는다.
- `CurrentWeekCard`의 서버 `attendanceStatus`로 버튼·안내를 구분한다. `AVAILABLE`만 진입 가능하다. 존재하는 현재 주 query를 재사용한다.
- `home-sheets.tsx`의 출석·보고 Activity만 운영 인증 화면으로 연결한다. 팀 사진 개발 가드는 유지한다.
- 코드 시트가 열릴 때 현재 주의 실제 세션 ID를 고정한다. 제출 직전 현재 대상·가능 상태와 비교하고 달라졌으면 재조회 안내 후 제출을 막는다. URL에 코드·토큰·사유를 추가하지 않는다.
- 입력 네 자리를 문자열로 검증한 뒤 숫자로 변환한다. `0000`을 임의로 거절하지 않는다. 성공은 `verified=true`와 유효한 시각을 확인해야 한다.
- 생성된 `verifyMutation`의 성공 상태에서 제출한 세션 ID를 읽고 현재 주·내 출석 조회를 갱신한다. 점수나 횟수를 임의로 더하지 않는다. 조회 실패로 제출 성공을 취소하지 않는다.
- 보고는 세 유형·선택적 사유를 전송한다. 사유의 UTF-16 길이를 30 이내로 제한하고 surrogate pair를 중간에 자르지 않는다. 서버가 보고 대상 세션을 선택한다.
- 401은 기존 GET 조회 복구 경로로 현재 주 정보를 다시 확인하도록 안내한다. POST를 자동 재전송하거나 공용 인증 client의 GET 전용 정책을 변경하지 않는다. 복구 후 사용자가 다시 제출한다.
- 성공 결과는 `useMutationState`로 계정별로 구독하고 앱 수명 동안 보존한다. 계정 변경 뒤 늦은 응답은 버리고, 화면 이탈 뒤 같은 계정의 성공은 보존하되 강제로 이동시키지 않는다.
- 오류 문구는 확인된 오류 코드에 대응한다. 알 수 없는 응답·네트워크 실패는 결과 확인 불가로 안내하고 성공으로 간주하지 않는다.

## 단계와 복구

1. 준비: 이슈 생성·이 초안 리뷰 후 명세·계획·작업 목록을 정식 위치에 반영한다.
2. 코드 출석: API 연동·상태 표시·입력·완료·회귀 검증 후 리뷰받는다. 보고 버튼은 기존 상태다.
3. 사전 보고: 유형·사유·오류·완료·회귀 검증 후 리뷰받는다.
4. 각 구현 단계에 `check`와 `build`, UI 검증을 수행한다. 실서버 테스트는 허용된 테스트 계정·세션이 있을 때만 수행하고 운영 출석을 시험 변경하지 않는다.

실패 시 해당 단계의 프런트 연결을 되돌리고 기존 준비 중 상태로 복구한다. DB migration은 없으며 이미 접수된 출석·보고를 롤백 목적으로 삭제하지 않는다.

## 승인된 구조 수정과 보류한 제안

- 시트의 인증 경계 안에서 생성 `find3Options`와 `useSuspenseQuery`를 사용한다. 최초 로딩·실패는 Suspense·ErrorBoundary로 분리한다.
- TanStack Form의 `code` 필드가 네 칸 입력과 제출 후 수정 검증을 관리한다. 별도 코드 값·입력 오류 state는 제거한다.
- 생성 `verifyMutationKey`를 요청 식별 기준으로 사용하고 계정 범위를 덧붙인다. 기존 키를 생성 파일에 직접 추가하지 않는다.
- 홈의 완료 표시와 완료 Activity의 접근 차단 정책, 제출 중 닫기 차단·`useIsMutating` 제거, 서버 오류별 복구 UI는 제안 단계다. 이번 구조 수정에서는 기존 동작을 유지하며 해당 정책을 임의로 적용하지 않는다.
