# 검증 실행 안내

## 선행 조건

1. 각 단계 리뷰와 이슈 생성 절차를 완료한다. #412는 완료되었으며 재실행하지 않는다.
2. mise의 Node.js 24.20.0·pnpm 12.3.4와 기존 workspace 의존성을 사용한다.
3. 푸시 실기기는 서버와 같은 Firebase 환경의 org.yapp.yappplus 설정·APNs 연결·새 runtime 빌드가 필요하다.
4. 계정·token·기기 식별자를 로그나 캡처에 남기지 않는다. 아래 시나리오는 아직 실행 완료가 아니다.

## 자동 검증

저장소 루트에서 단계별 관련 테스트를 먼저 실행하고 리뷰 단위의 기본 게이트를 실행한다.

```sh
mise exec -- node --run check
mise exec -- node --run build
mise exec -- node --run expo:doctor
```

문서만 변경한 1단계는 check를 실행한다. build는 배포 앱/빌드 변경, expo:doctor는 모바일 설정/의존성
변경부터 필수다. iOS native build는 기존 apps/mobile/README.md의 절차를 따른다.
각 결과에 실행 시각·새 실행/캐시·실패/미실행을 기록하고 같은 테스트를 불필요하게 강제 재실행하지 않는다.

## 출시·복구 확인

검증된 main SHA와 native build/runtime을 기록한다. 승인된 시험 발송은 실제 회원 대상 발송과
구분한다. 푸시 미검증이면 모의 테스트 통과로 대체하지 않는다. 웹 이전 배포·동일 runtime JS·
네이티브 수정 빌드를 구분해 복구하고, 서버 등록 해제/발송 중단 필요도 별도로 확인한다.
