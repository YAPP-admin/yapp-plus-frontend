# 기능 명세: 회원 홈 출석 상태와 팀 사진 출석 연결

작성일: 2026-11-20 · 상태: 1단계 리뷰 대기 · 브랜치: `DongjaJ/wojt9`
이슈: [#501](https://github.com/YAPP-admin/yapp-plus-frontend/issues/501)

## 목적과 범위

회원이 홈에서 서버가 판정한 자신의 출석 상태를 확인하고 정규 세션은 코드로, 팀 세션은
사진으로 출석한다. [제품 맥락](../../docs/mission.md)과 기존 위치 출석·팀 사진 제출을 따른다.
이번 제출물은 명세·계획·작업 목록이다. 단계별 사용자 리뷰와 다음 단계 확인 후에만 구현한다.

## 사용자 시나리오와 검증

### US1 — 홈에서 최신 출석 상태 확인 (P1)

회원은 이번 주 세션의 유형과 출석 상태에 맞는 안내를 본다.
독립 검증: 주간 API 응답을 바꾸어 모든 상태의 문구·비활성화·진입 경로를 확인한다.

1. 세션이 없으면 기존 빈 화면을 표시하며 출석 진입은 없다.
2. 세션이 있고 장소가 `null`이면 임시로 팀 세션, 그 외에는 정규 세션으로 판별한다.
3. `CHECKED_IN`은 세션 종료 이후에도 서버가 반환하는 동안 유지한다.
4. `PENDING_APPROVAL`은 출석 확인 중으로 표시하고 다시 제출하는 진입을 막는다.
5. 홈·앱 복귀 시 캐시가 신선해도 재조회한다. 실패하면 이전 데이터와 재시도 안내를 유지하고 출석 진입은 막는다.

### US2 — 정규 세션 코드 출석 (P1)

회원은 정규 세션의 `AVAILABLE`에서 기존 코드·위치 검증을 거쳐 출석한다.
독립 검증: 코드 성공부터 완료 화면·홈 복귀까지 실제 서버 상태 변화와 지연을 모의한다.

1. 코드 출석 성공 즉시 기존 완료 화면으로 이동한다. 홈 재조회 완료를 기다리지 않는다.
2. 이후 홈 상태는 주간 API를 따른다. 이전 세션의 로컬 성공 기록으로 현재 응답을 덮어쓰지 않는다.
3. 같은 요청의 중복 전송 방지와 완료 화면 직접 진입 방어는 유지한다.

### US3 — 팀 사진 제출과 확인 대기 (P2, 운영 연결 선행 조건 있음)

회원은 자신이 속한 팀·팀원을 확인하고 사진을 제출한 뒤 운영진 확인을 기다린다.
독립 검증: 회원용 조회 계약이 준비된 후 실제 형태의 대상 데이터로 선택·취소·업로드·제출·홈 복귀를 확인한다.

1. 운영 연결 전 팀 `AVAILABLE`은 비활성화하고 “팀 출석 기능을 준비 중이에요”를 안내한다.
2. 운영 연결 후 홈에서 안내를 열고 선택한 버튼에 따라 카메라·사진 보관함을 바로 연다.
3. 최초 사진 선택 취소는 안내로 돌아간다. 사진 교체 취소·실패는 기존 사진과 팀원 선택을 보존한다.
4. 본인은 기본 선택되고 해제할 수 없다. 선택한 팀원의 출석만 운영진 확인 대상임을 안내한다.
5. 제출 성공은 접수 완료다. `CHECKED_IN`으로 간주하지 않고 홈 재조회 결과를 표시한다.
6. 서버가 다시 `AVAILABLE`을 반환하면 일반 제출 흐름을 이용할 수 있다. 반려 사유는 추측하지 않는다.

## 기능 요구사항

- **FR-001**: 세션 존재 확인 후 `location === null`만 팀 판별에 사용한다. 빈 문자열은 정규다. 판별은 한 곳에 두고 임시 사유·제거 조건을 한국어로 기록한다.
- **FR-002**: 홈 상태 문구·버튼은 [상태 계약](contracts/attendance-flow.md)을 따른다. 시간·역할·로컬 성공 이력으로 서버 상태를 재계산하지 않는다.
- **FR-003**: `CHECKED_IN`은 본인의 체크인 기록을 의미한다. 최종 출결 점수나 모든 팀원의 출석 확정으로 해석하지 않는다.
- **FR-004**: `PENDING_APPROVAL`은 본인의 출석 인증 확인 중 상태다. 팀의 제출 여부만으로 모든 구성원에게 전파하지 않는다.
- **FR-005**: 최초 조회·재조회·오프라인 대기·조회 실패 중에는 신규 출석 진입을 막고 복구 수단을 제공한다.
- **FR-006**: 홈 재진입과 앱 포그라운드 복귀 시 캐시 나이와 무관하게 재조회한다. 홈에 계속 머무는 동안 주기 조회하지 않는다.
- **FR-007**: 정규 출석의 코드·위치·중복 요청 방어를 유지하고, 완료 화면은 현재 제출 성공 결과로 연다.
- **FR-008**: 팀 운영 연결은 회원 권한의 세션별 팀·팀원 조회 계약 확인 후 시작한다. 관리자 API나 개발용 고정 대상은 운영에서 사용하지 않는다.
- **FR-009**: 팀 사진 선택부터 접수 완료까지 한 흐름에서 메모리 상태를 유지한다. 나가면 임시 사진 URL·요청·접수 정보를 정리한다.
- **FR-010**: 기존 JPEG 품질 0.9·긴 변 2560·최대 10MiB 및 네이티브 사진 브리지 정책을 유지한다. 웹에서 재압축하지 않는다.
- **FR-011**: 팀 제출 전 사진 미리보기와 참석 팀원 선택은 제공한다. 최초 선택 취소·교체 취소는 US3의 보존 정책을 따른다.
- **FR-012**: 팀 제출 성공 후 주간 데이터를 무효화한다. 최종 제출 결과가 불확실한 오류는 자동 재전송하지 않고 홈에서 상태를 확인하도록 안내한다.
- **FR-013**: `current-week`에 종료 시간이 없으면 “출석 가능한 시간 안에 올려주세요”를 표시한다. 고정 14~18시나 추가 목록 조회로 대체하지 않는다.
- **FR-014**: 향후 `type`·`endTime`은 OpenAPI 갱신·클라이언트 재생성 후 도입한다. 실제 계약과 배포 순서를 확인하고 임시 판별을 제거한다.
- **FR-015**: 상태·오류 안내는 스크린 리더에 전달하고 비활성화 이유를 텍스트로 제공한다. 바텀시트의 키보드·포커스·터치 동작을 검증한다.

## 제외 사항

제출 후 사진 다시 보기·썸네일 카드, 승인 완료 바텀시트, FCM·알림함 변경, 반려 상세·전용 재제출 화면,
결석 신고, 캘린더 배지, 홈 전체 재설계는 제외한다. 제출 전 사진 미리보기는 포함한다.

## 주요 데이터

주간 세션과 서버 출석 상태, 임시 세션 유형, 회원용 제출 대상, 사진·참석자 임시 상태, 제출 접수 결과를
구분한다. 필드·검증·수명은 [데이터 모델](data-model.md)을 따른다.

## 성공 기준

- **SC-001**: 세션 없음 및 두 유형의 다섯 출석 상태에 대한 테스트에서 문구·버튼 정책이 모두 일치한다.
- **SC-002**: 정규 출석 성공 후 재조회가 지연·실패해도 완료 화면을 표시하고, 홈에서는 서버 상태만 사용한다.
- **SC-003**: 신선한 캐시 상태의 홈·앱 복귀에서도 재조회하며, 화면에 머무를 때 폴링 요청은 없다.
- **SC-004**: 팀 운영 연결 후 최초 취소·교체 취소·성공·불확실한 제출 오류에서 사진 수명과 중복 전송 정책이 지켜진다.
- **SC-005**: 단계별 관련 테스트와 기본 품질 게이트 결과를 기록하고, 앱 변경 단계에는 빌드·접근성·실기기 확인 결과를 제출한다.

## 확정 사항과 외부 선행 조건

대화에서 장소 기반 임시 판별, 홈·정규 우선, 사진 조회·승인 알림 제외를 확정했다.
회원용 조회 API의 경로·응답·권한은 아직 제공되지 않았다. 이는 3단계 진입 조건이며 임의 계약으로 구현하지 않는다.
`type`·`endTime` 추가 전에도 2단계는 임시 판별·일반 시간 안내로 진행할 수 있다.
