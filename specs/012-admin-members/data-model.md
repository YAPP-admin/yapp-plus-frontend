# 화면 데이터 모델

실제 API DTO나 저장 계약이 아닌 이번 화면의 입력 모델이다. 아래 항목만 현재 소비 범위에 맞게 타입화한다.
도메인 저장소·CRUD 서비스·영속 상태는 만들지 않는다. 객체·배열은 readonly 입력으로 취급한다.

## 화면 입력

| 모델           | 필요한 정보·규칙                                                            |
| -------------- | --------------------------------------------------------------------------- |
| 회원           | 식별자, 이름, 정규화된 전화번호, 기수별 활동. 이름은 공통 정보              |
| 기수별 활동    | 식별자, 기수, 직군, 권한, active/inactive, 가입일. 한 회원·기수 조합은 하나 |
| 팀 표시        | 팀 식별자·표시명·팀장 여부 또는 null. 기수의 매핑 전후 상태는 별도 입력     |
| 출석 요약      | 점수 또는 null, 출석 기록 존재 여부. 0점 여부로 연결 유무를 추정하지 않음   |
| 기존 변경 이력 | 시각·합성 작업자·변경 항목·이전/새 값. 읽기 전용으로 최신순 표시            |
| 기수 목록      | 현재 33기와 fixture의 지원 기수. 선택만 제공하고 생성·전환은 제외           |

직군 내부 값은 pm/design/android/ios/web/server, 표시는 PM/Design/Android/iOS/Web/Server다.
권한 내부 값은 admin/active-member/regular-member, 표시는 운영진/활동회원/정회원이다.
이는 현재 화면 용어이며 OpenAPI PLAYER/OB 매핑을 의미하지 않는다.
새 기수 활동의 초기 권한·출석 생성 등 저장 정책을 이 모델에서 구현하지 않는다.

## 파생 값과 초안

- 현재 기수 활동 하나가 목록 행 하나가 된다. 과거 기수는 같은 회원의 다른 활동에서 파생한다.
- 정렬은 이름 오름차순, 동명이인은 식별자순이다. 이름 검색은 trim 후 부분 일치다.
- 직군·팀·이름 교집합에서 목록 총원을 계산한다. 팀별 인원은 현재 기수 전체 활동 기준이다.
- 수정 초안은 이름·선택 활동의 기수·직군·권한만 가진다. 변경 이력·원본 활동을 수정하지 않는다.
- 기수 정정은 팀 연결·출석 기록·동일 회원의 대상 기수 활동이 있으면 막는다.
- 고정 fixture 공급에는 로딩·오류 상태가 없다. 실제 API 연결 시 Query 조회 상태를 사용하며 화면 상태 사례는 별도 테스트 입력으로 검증한다.

## 파일과 검증 결과

- 파일은 한 개이며 크기는 10 × 1024 × 1024 bytes 이하로 제한한다. 첫 시트를 사용한다.
- 헤더는 이름/전화번호/기수/직군/권한 순서의 다섯 열이다. 첫 행에서 이름·순서를 검증한다.
- 필드 양끝 공백을 제거하고 완전히 빈 행은 제외한다. 원본 행 번호는 헤더를 포함한 1부터의 번호다.
- 전화번호는 010-숫자4자리-숫자4자리 또는 010으로 시작하는 숫자11자리만 허용한다.
- 비교 값은 숫자 문자열, 표시 값은 하이픈 형식이다. 숫자로 바뀌어 0이 사라진 입력은 오류다.
- 이름은 공백이 아니어야 하고 기수는 양의 정수이며 직군·권한은 화면의 허용값이어야 한다.
- 각 행은 원본 번호·표시 값·검증 성공 데이터 또는 오류·중복 대상 활동 식별자를 가진다.
- 검증 오류 행은 내부 중복 집합에 넣지 않는다. 유효한 전화번호·기수의 두 번째 이후 행은 오류다.
- 내부 중복을 제외한 유효 행만 기존 명단과 비교한다. 신규 회원·새 기수 활동은 정상, 기존 활동은 중복이다.
- 정상/오류/중복은 배타적이며 합계가 비어 있지 않은 전체 데이터 행 수와 같다.
- 반영 예정 수는 정상 행 수 + 덮어쓰기로 선택한 중복 행 수다. 건너뛰기·오류는 제외한다.
- 원본 파일·검증 결과·중복 선택은 업로드 페이지 로컬 상태이며 로그·URL·영속 저장에 넣지 않는다.

## 상태 전이

파일 없음 → 읽는 중 → 미리보기 또는 파일 오류. 교체·다시 올리기는 이전 결과·선택을 폐기한다.
읽기 식별자나 cleanup으로 교체·이탈 후 오래된 결과를 무시한다. 저장/반영 완료 상태는 없다.
수정 모달은 열기 → 초안 변경 → 닫기/취소이며 제출로 원본이 바뀌는 전이는 없다.
