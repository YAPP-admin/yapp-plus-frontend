# 세션 유형별 장소 입력·표시 정책

**단계**: 1-2 — 승인 (사용자의 다음 단계 진행 지시)
**이슈**: [#88](https://github.com/YAPP-admin/yapp-plus-frontend/issues/88)
**기준**: [기존 세션 명세](../008-admin-sessions/spec.md), 사용자와 합의한 장소 입력 범위

이 문서는 생성·수정 폼의 장소 입력과 목록 표시 정책을 정리한다. 구현 완료를 의미하지 않는다.
오류·비동기 상태는 1-3, Spec Kit 전체 명세·계획과 라이브러리 선택 근거는 1-4에서 작성한다.
기존 명세의 FR-006과 D6 중 장소 정책을 아래 내용으로 대체하며, 나머지 세션명·일정·집계 정책은 유지한다.

## 유형별 입력

| 항목       | 오프라인                                    | 팀 세션          |
| ---------- | ------------------------------------------- | ---------------- |
| 도로명주소 | 검색 결과에서 선택, 필수                    | 입력·검색 없음   |
| 상세주소   | 선택 입력: 장소명·층·호수 등                | 입력 없음        |
| 기준 좌표  | 선택 주소에서 조회한 좌표를 확인·조정, 필수 | 입력·지도 없음   |
| 장소 안내  | 별도 입력 없음                              | 선택 자유 텍스트 |

- 세션명, 날짜, 시작·종료 시간, 유형은 기존 명세를 따른다. `전체`는 목록 필터일 뿐 저장 가능한 유형이 아니다.
- 장소명 전용 필드는 만들지 않는다. 예를 들어 도로명주소를 선택한 뒤 상세주소에 `교육장 3층 세미나실`을 적는다.
- 상세주소와 장소 안내는 앞뒤 공백을 제거한다. 공백만 입력하면 미입력으로 처리한다.
- 근거 없는 글자 수 제한이나 과거 일정 금지는 추가하지 않는다.

## 오프라인: 주소와 좌표의 관계

1. 검색어를 입력하고 결과에서 도로명주소를 선택한다. 검색어 자체를 저장할 주소로 취급하지 않는다.
2. 선택한 결과에 대응하는 좌표를 조회·변환해 초기 기준 좌표로 사용한다.
3. 지도 클릭이나 마커 드래그로 기준 위치를 조정할 수 있다. 키보드로 조정할 수 있는 좌표 입력도 제공한다.
4. 주소와 유효한 최종 좌표가 모두 있어야 저장할 수 있다. 상세주소는 비어 있어도 된다.

- 좌표는 위도·경도를 구분한다. 유한한 숫자이고 위도는 -90~~90, 경도는 -180~~180 범위여야 한다. `0`을 미입력으로 판단하지 않는다.
- 지도 이동·확대·축소만으로 선택 좌표를 바꾸지 않는다. 조정 후에는 최종 좌표 하나를 지도·폼·저장이 함께 사용한다.
- 좌표를 조정해도 선택한 도로명주소·상세주소는 바뀌지 않는다. 역지오코딩이나 주소 자동 치환은 하지 않는다.
- 다른 주소를 선택하면 기존 상세주소·좌표를 초기화하고 새 주소의 좌표를 조회한다. 이전 주소의 좌표를 새 주소와 함께 저장하지 않는다.
- 검색어를 편집하는 것과 새 주소를 선택하는 것을 구분한다. 검색어만 바꿔도 이미 선택한 주소를 덮어쓰지는 않는다.
- 주소가 선택되지 않은 상태에서는 좌표만 입력해서 저장할 수 없다. 지도 장애·좌표 조회 실패 시의 입력과 저장 허용 조건은 1-3에서 명세화한다.

## 팀 세션: 선택 안내 문구

- 장소 안내만 입력하며 주소 검색·좌표 조회·지도를 제공하지 않는다.
- `팀별로 정한 장소에서 진행`처럼 자유롭게 안내할 수 있다. 안내 문구가 없어도 저장할 수 있다.
- 안내를 비워 저장한 경우 목록에는 `팀별 자율 장소`를 표시한다. 이는 표시용 대체 문구이며 입력한 값으로 저장하지 않는다.
- 수정 폼에서도 미입력 안내는 빈 입력으로 복원한다. 대체 문구를 자동 입력하지 않는다.

## 목록 표시와 수정 복원

| 저장 상태                           | 목록 장소 표시                  | 수정 폼                                   |
| ----------------------------------- | ------------------------------- | ----------------------------------------- |
| 오프라인: 주소만 있고 상세주소 없음 | 도로명주소                      | 주소·저장된 최종 좌표 복원, 상세주소 비움 |
| 오프라인: 상세주소 있음             | 도로명주소 다음에 상세주소 표시 | 주소·상세주소·저장된 최종 좌표 복원       |
| 팀: 안내 있음                       | 공백 정리한 안내 문구           | 저장한 안내 복원                          |
| 팀: 안내 없음                       | `팀별 자율 장소`                | 안내 입력 비움                            |

- 목록 카드에 위도·경도 숫자나 지도를 추가하지 않는다. 긴 장소 정보는 좁은 화면에서도 확인할 수 있어야 한다.
- 수정 폼은 저장된 조정 좌표를 그대로 복원한다. 열 때 주소를 재검색하거나 좌표를 재조회해 덮어쓰지 않는다.
- 저장한 도로명주소와 상세주소는 분리해 유지한다. 표시를 위해 합친 문자열로 원본 정보를 대체하지 않는다.
- 오프라인의 주소 없는 저장값을 팀 대체 문구로 숨기지 않는다. 기존 모의 데이터의 구조 전환은 3-1에서 처리한다.
- 실제 백엔드 저장 계약은 변경하지 않는다. 이번 정책은 관리자 기능과 DEV 메모리 저장에 적용한다.

## 유형 변경 정책

1-2 리뷰 후 사용자의 다음 단계 진행 지시로 아래 정책을 확정했다.

- 같은 폼을 연 동안에는 유형별 미저장 입력을 임시로 보존한다. 오프라인 → 팀 → 오프라인으로 돌아오면 입력한 주소·상세주소·조정 좌표를 복원한다.
- 저장할 때는 현재 선택한 유형의 장소 정보만 포함한다. 숨겨진 다른 유형의 값을 저장하거나 검증하지 않는다.
- 유형 변경으로 다른 유형의 장소 입력을 자동 변환하지 않는다. 오프라인 주소를 팀 안내로 복사하지 않는다.
- 취소·닫기·Esc는 기존 D5대로 임시 입력을 모두 버린다. 다시 열면 마지막 저장된 유형과 값만 복원한다.
- 예를 들어 오프라인을 팀으로 바꿔 저장한 뒤 다시 수정하면 팀 안내만 복원하며, 이전 오프라인 주소를 되살리지 않는다.

| LP-11 | 유형 왕복 전환 후 저장·닫기·재진입 | 승인된 유형 변경 정책에 따라 임시 입력과 저장값 구분  |
