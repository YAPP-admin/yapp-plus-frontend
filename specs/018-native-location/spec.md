# 기능 명세: 출석용 앱 위치 수집과 웹 공유

**브랜치**: `DongjaJ/native-location-runtime` · **작성일**: 2026-11-07 · **상태**: 2-2 네이티브 구현 리뷰 대기

**입력**: 출석에 사용할 현재 위치를 iOS 앱에서 필요할 때 한 번 수집해 웹에 전달한다.
사용자는 위치 기반까지만 구현하고, 정확도와 함께 전달하며, 앱 설정 열기를 포함하도록 결정했다.
작업 이슈: [#353](https://github.com/YAPP-admin/yapp-plus-frontend/issues/353). 사용자 승인으로 생성했으며 문서 커밋과 다음 단계 진행을 승인받았다.

## 사용자 시나리오와 검증

### US1 — 필요한 순간 현재 위치를 전달한다 (P1)

회원은 출석에 필요한 위치를 명시적으로 요청한 순간에만 앱과 웹 사이에서 공유한다.
이번 단계의 독립 검증은 개발 전용 도구에서 한 번 요청해 성공 결과를 받는 것이다.

1. 권한이 없는 상태에서 위치를 요청하면 사용 중 권한을 요청한다. 앱 시작·페이지 진입만으로는 요청하지 않는다.
2. 허용하면 현재 위치·오차·측정 시각·정밀 권한 수준을 전달하고 수집을 끝낸다.
3. 대략적 위치만 허용해도 정확도 정보를 함께 전달한다. 이 결과만으로 출석 성공을 표시하지 않는다.
4. 연속으로 요청해도 동시에 두 번 수집하지 않으며, 완료 후 다시 요청하면 새 측정을 시작한다.

### US2 — 권한과 위치 오류에서 복구한다 (P1)

회원은 위치를 얻지 못한 이유를 구분하고 필요할 때 앱 설정을 직접 열 수 있다.
독립 검증은 권한을 거부한 뒤 상태 조회·설정 열기·재요청을 수행하는 것이다.

1. 상태 조회는 권한 팝업 없이 권한·재요청 가능 여부·정밀 수준·위치 서비스 상태를 반환한다.
2. 권한 거부, 위치 서비스 꺼짐, 시간 초과, 취득 실패를 서로 다른 결과로 전달한다.
3. 설정 열기를 선택했을 때만 앱 설정으로 이동한다. 앱 복귀만으로 다시 측정하지 않는다.
4. 설정 변경 후 사용자가 다시 요청하면 변경된 권한을 읽어 측정한다.

### US3 — 지원 환경과 요청 수명을 지킨다 (P2)

회원은 지원 환경에서 위치를 요청하고 중단된 요청의 결과를 받지 않는다.
독립 검증은 미지원 환경과 화면 이탈·앱 전환·지연 응답을 재현하는 것이다.

1. 일반 브라우저에서는 위치 호출을 막고 앱 이용을 안내한다. 웹 위치 권한을 대신 요청하지 않는다.
2. 시작 시 active가 아니거나 권한 확인 후·위치 반환 시 background이면 실패한다. 권한 팝업의 일시적 inactive는 허용한다. 백그라운드 전환 즉시 취소는 하지 않는다. 화면 이탈 후 도착한 결과는 화면에 반영하지 않는다.
3. 측정 제한 시간이 지나면 실패로 종료하고, 늦게 도착한 위치는 반영하지 않는다. OS 측정 자체는 취소하지 않는다.
4. 개발 도구는 프로덕션에서 접근할 수 없으며, 실서비스 출석 버튼은 기존 비활성 상태를 유지한다.

### 경계 사례

- 최초 거부·재요청 불가·일회 허용·정밀 권한 변경·기기 위치 서비스 꺼짐.
- 잘못된 좌표·알 수 없는 오차·수신 시점 기준 5초를 초과한 위치·중복 호출·시간 초과 뒤 늦은 응답.
- 권한 선택 대기는 유지하며 측정 전과 결과 반환 시 앱 활성 상태를 확인한다.
- 설정 열기 실패·연결되지 않은 앱·화면 이탈 뒤 지연 응답.

### 주요 개체

- 위치 측정값: 위도·경도, 오차, 측정 시각과 정밀 권한 수준을 가진 일회성 결과.
- 권한 상태: 허용 여부, 다시 요청할 수 있는지와 기기의 위치 서비스 상태.
- 요청 결과: 성공 측정값 또는 복구 방법을 구분할 수 있는 실패 이유.

## 성공 기준

- SC-01: iOS 실기기에서 US1~US3의 해당 수용 시나리오를 모두 통과한다.
- SC-02: 권한 승인 뒤 측정은 15초 이내에 성공 또는 시간 초과로 종료한다. 권한 선택 대기는 제외한다.
- SC-03: 종료된 요청의 늦은 결과 반영·응답 대기 중 중복 호출·위치 원문 로그 사례가 검증에서 0건이다.
- SC-04: 일반 브라우저에서 위치 권한 요청, 프로덕션에서 개발 도구 노출·모의 출석 성공이 0건이다.

## 전제와 제외 범위

- 구현 범위 정정: 이 저장소의 Expo 셸은 iOS용이다. 별도 Android 네이티브 앱은 수정·빌드하지 않으며 Android 정밀 권한 매핑·테스트도 이 구현에서 제외한다.

- 출석 허용 반경은 사용자 합의에 따라 행사 기준 위치로부터 **100m를 예정 기준**으로 둔다. 실제 출석 판정은 후속 API 연결에서 구현한다.
- 위치 오차는 출석 거리 기준과 별개다. 측정 오차를 100m에 더해 허용 반경을 넓히지 않는다.
- 오차가 크거나 알 수 없을 때의 재측정 기준과 출석 처리 정책은 후속 API 작업에서 확정한다. 이번 브리지는 오차 값으로 성공 응답을 차단하거나 출석 여부를 결정하지 않는다.
- [제품 맥락](../../docs/mission.md)과 사용자 합의를 근거로 한다. 외부 기능명세서는 접근하지 못했으며 출석 정책을 추정하지 않는다.
- 출석 API 제출·거리 판정 구현·허용 오차 및 재측정 기준 확정·부정 출석 탐지·지속 추적·지도·일반 브라우저 위치 수집은 제외한다.
- 기존 로그인·외부 탐색 정책을 재설계하지 않는다. 위치 RPC 자체에 신규 로그인 조건을 추가하지 않는다.
- 기존 앱의 허용된 서비스 웹에서 호출하며, 일반 브라우저의 UA만으로 네이티브 지원을 판단하지 않는다.
- 자동 테스트와 실기기 검증은 구현 단계에서 수행하고 미실행 항목은 완료로 표시하지 않는다.
