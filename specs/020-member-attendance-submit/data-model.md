# 데이터와 상태

- 출석 대상: 현재 주 응답의 sessionId, 날짜·시작 시각, attendanceStatus. 서버 상태를 그대로 사용한다.
- 코드 입력: 메모리 문자열 4자리 ASCII 숫자. 서버 요청에서는 정수로 변환한다.
- 출석 응답: verified가 true이고 checkedInAt이 유효한 시각일 때 성공이다.
- 출석 완료 표시: 성공 mutation의 대상 ID를 사용한다. 계정 변경 시 공용 인증 계층이 캐시를 정리하고 화면을 다시 만든다. 출석 전용 계정 키는 추가하지 않으며 앱 재시작 후 복원하지 않는다.
- 보고 입력: types 배열과 공통 reason. LATE·EARLY_LEAVE는 함께 선택할 수 있고 ABSENT는 단독이다. 중복 유형·빈 배열을 거절한다. 사유는 공백만 불가, Unicode 코드포인트 2~30자이며 원문을 전송한다. 카운터도 같은 기준이고 초과 입력은 자르지 않는다.
- 보고 조회: 생성 SDK의 CurrentWeekAttendanceReportResponse를 검증한다. reportId가 null이면 신규, 있으면 수정이다. 전체 types와 reason을 초기값으로 쓰고 reason이 null이면 빈 문자열로 표시한다. 구형 단일 type을 복수 선택의 기준으로 사용하지 않는다.
- 보고 저장 응답: 생성 SDK 타입을 사용한다. 현재 화면은 저장 응답 본문을 표시하거나 submittedAt을 사용하지 않으므로 별도 앱 측 저장 응답 검증을 추가하지 않는다.
- 코드 출석 상태: 입력 → 제출 중 → 서버 확인 후 완료 또는 수정 가능한 오류. 화면 이탈 뒤 같은 계정의 출석 성공은 기존 mutation에 보존한다.
- 보고 대상: 기존 주간 응답의 세션 ID·이름·날짜·시작 시각. 출석 가능 상태는 보고 진입 조건으로 사용하지 않는다. ID는 화면의 예상 대상이며 POST body에는 넣지 않는다.
- 보고 시간 상태: 조회 중/실패/대상 없음 → 시작 전 제출 가능 → 시작 정각부터 마감. 토요일에는 다음 주를 미리 선택하지 않고 한국 시간 일요일 00:00에 주간 조회를 갱신한다. 제출 직전 GET은 없다.
- 보고 화면 상태: 세션·보고 조회 → 유형 선택 → 사유 입력 → 생성/수정 중 → 성공 또는 오류/접수 불확실. 조회 실패는 빈 폼으로 대체하지 않는다. Form이 입력·검증, mutation이 비동기 상태, Stackflow step이 단계를 소유한다.
- 입력 수명: 단계 이동·작성 중 재조회는 유형·사유를 유지한다. 닫기는 초안을 버리고 재진입은 저장된 보고로 초기화한다. 제거되거나 숨겨진 화면에 늦은 응답의 탐색·완료 알림을 적용하지 않는다. 보고의 영구 완료 캐시·전역 store는 추가하지 않는다.
- 접수 결과: 성공 후 보고·주간 조회 실패가 접수를 취소하지 않으며 보고가 실제 출석·점수·횟수를 덮어쓰지 않는다. 수정은 조회한 reportId의 보고를 전체 교체한다. 최종 제출 시각과 감점 판정은 서버가 소유한다.
- 요청이 처리되었는지 알 수 없는 네트워크 오류는 성공도 실패 확정도 아니다. 자동 재제출을 하지 않고 사용자에게 결과 확인 불가와 수동 재시도를 안내한다.
