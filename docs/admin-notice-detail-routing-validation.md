# 관리자 라우팅 PR 7 검증

- 확인일: 2026-10-12. 관련 이슈: [#56](https://github.com/YAPP-admin/yapp-plus-frontend/issues/56).
- 기준 커밋: PR 6 `c978587`. 브랜치: `DongjaJ/admin-notice-detail-routing`.
- 범위: `/notices/:noticeId`, 읽음·질문 탭, 목록 복귀 링크.
- 공지 데이터·존재 여부 조회·API·인증·질문 답변·작성·수정은 포함하지 않는다.

## URL과 탐색

- `tab`은 `readers | questions`이며 누락·잘못된 값은 `readers`로 처리한다.
- 앱이 생성하는 URL은 기본 탭을 생략한다. 탭 변경은 ID를 유지하며 history에 추가하고 스크롤을 유지한다.
- 상세는 공통 관리자 셸 아래 별도 화면이다. `notices_` 파일 경로로 목록 필터 중첩을 피한다.
- 상세에서도 공지 목록 메뉴가 현재 영역으로 표시된다.
- 명시적인 목록 복귀는 필터 없는 `/notices`로 이동하고 뒤로가기는 이전 목록 필터를 복원한다.
- 실제 목록 행 링크는 데이터 화면 구현 시 연결하며 이번에는 typed 탐색 테스트로 진입을 검증한다.
- 임의의 ID도 라우팅 안내 화면을 표시한다. 존재 여부에 따른 404는 API 연결 시 구현한다.
- `new` 정적 경로는 PR 8에서 구현한다. 현재 `/notices/new`도 동적 ID로 처리된다.
- effect·이벤트 구독·새 의존성은 추가하지 않았다. 라우트 트리는 Vite로 생성했다.
