# 웹 SEED 일관성·접근성 개선 검증

이 문서는 [이슈 #366](https://github.com/YAPP-admin/yapp-plus-frontend/issues/366)의
구현 범위와 검증 결과를 기록합니다. 새 API·의존성·공용 타입·제품 정책 변경은 없습니다.

## 반영 범위

- 설정 Switch와 출석 규칙 Dialog에 접근성 이름을 연결했습니다.
- 게시판 탭의 키보드 이동과 팀원 선택의 포커스 표시를 개선했습니다.
- 가입 서버 필드 오류를 TextField에 연결했습니다.
- 홈 초기 로딩은 Skeleton, 앱 초기 로딩은 접근성 이름이 있는 진행 표시로 정리했습니다.
- 홈·공지·일정의 상태 라벨을 Badge로, 로그인 오류 CTA를 ActionButton으로 전환했습니다.
- 설정·공지·일정·알림·팀 인증·홈·시연 시트의 반복 배치를 SEED 레이아웃으로 정리했습니다.
- PageShell의 구조, 의미 있는 HTML 태그, 최대 너비, safe-area와 스크롤 소유권을 유지했습니다.
  모든 CSS flex/grid를 교체한 것은 아닙니다. 달력·입력·이미지 정렬과 시안 보존 스타일은 남겼습니다.

## 버튼 상태

기본 화면의 배경색은 유지하고 활성 버튼의 고정 배경 선언이 SEED 상태를 막는 문제를 수정했습니다.

| 대상                       | 기본 배경 | pressed 배경 | 투명도 |
| -------------------------- | --------- | ------------ | ------ |
| 홈 팀 인증                 | `#2A3038` | `#555D6D`    | 1      |
| 로그인 제보·시트 확인·촬영 | `#FF6600` | `#E14D00`    | 1      |
| 로그인 닫기·앨범 선택      | `#F3F4F5` | `#EEEFF1`    | 1      |

비활성 버튼의 시안 색상, 글꼴·크기·모서리 및 말풍선 스타일은 일괄 제거하지 않았습니다.
로그인 제보 링크의 의미·주소·target·rel과 Dialog 닫기 동작을 유지했습니다.

## 화면·동작 검증

단계별 변경 전후를 같은 시간과 faker seed의 MSW/시연 데이터로 비교했습니다.
아래 단계별 비교 횟수는 서로 다른 기준 커밋의 결과이므로 하나의 전체 화면 검사로 합산하지 않습니다.

| 비교 단위                | 화면 너비     | 결과                                        |
| ------------------------ | ------------- | ------------------------------------------- |
| Badge                    | 320·390px     | 14쌍 RGB 픽셀 차이 0, 스타일 68개 항목 동일 |
| 홈 외곽 배치             | 320·390·768px | 30쌍 RGB 픽셀 차이 0                        |
| 시연 시트                | 320·390·768px | 24쌍 RGB 픽셀 차이 0, 버튼 상태 10건 동일   |
| 최신 main 위 rebase 전후 | 320·390px     | 핵심 화면 16쌍 RGB 픽셀 차이 0              |

로그인 기본 390px 화면은 일러스트 경계에서 34픽셀, 최대 RGB 채널 차이 9가 있었습니다.
팀 업로드 선택 화면은 카드의 둥근 경계에서 8픽셀, 최대 차이 1이 기록됐습니다.
해당 컴포넌트의 배치·색상 스타일은 같았지만 렌더러 내부 원인은 확정하지 않았습니다.
전체 누적 화면이 픽셀 단위로 완전히 같다고 판정하지 않습니다.

키보드 Tab·Enter·Space, 코드 입력의 자동 포커스·Backspace 이동, 라디오 방향키 선택,
오류·완료 전환과 터치 에뮬레이션 탐색을 확인했습니다. 낮은 화면의 하단 버튼 접근과
가로 overflow도 확인했습니다. 터치 미디어에서 강제한 `:active` 검사는 실제 터치 누름 유지
검증과 구분합니다.

## 자동 검증과 제출 이력

검증 기준은 main `32f4c3d0` 위로 SEED 커밋 10개를 적용한 최상단 `4ba682ab`입니다.

- `mise exec -- pnpm install --frozen-lockfile` 통과, manifest·lockfile 변경 없음.
- `mise exec -- node --run check` 통과. 웹 lint·typecheck·293개 테스트는 새 실행했습니다.
  다른 lint·typecheck 각 6개와 test 4개는 Turbo 캐시를 재사용했습니다.
- `mise exec -- node --run build` 통과. 웹은 새 실행, 다른 2개는 캐시 재사용입니다.
  기존 500kB 청크 크기 경고는 남아 있습니다.
- main의 모바일 설정·의존성 반영 후 `mise exec -- node --run expo:doctor` 20/20 통과.
- rebase의 커밋 10개 모두 range-diff에서 동일했고, 최종 파일 1,047개가 사전 패치 적용 결과와
  바이트 단위로 같았습니다. main의 위치 기능 등 별도 변경을 보존했습니다.
- 중간 브랜치 각각의 check·build는 별도로 실행하지 않았습니다.
