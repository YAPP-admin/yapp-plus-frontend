# 관리자 내부 UI·조회 계약

## 공개 진입점과 조회

`apps/admin/src/features/notice-management/index.ts`는 필요한 타입·Query 훅·UI만 노출한다.
모의 저장소는 공개하지 않는다. 본문은 Tiptap JSONContent 계약을 사용한다. 네트워크 API 계약을 새로 만들지 않는다.

- listNoticeMembers(): 읽음 대상 계산에 사용할 합성 회원 전체 명단을 반환한다. 명단 Query 키는 ['admin', 'notice-members']다.
- listNotices(): 전체 공지 반환. 종류 필터와 전체/필터 개수는 같은 조회 결과에서 계산한다.
- getNotice(id): 공지 또는 null 반환. null은 찾을 수 없음, 예외는 조회 오류다.
- createNotice(input), updateNotice(id, input): noticeInputSchema로 정규화한 NoticeContent를 받고 검증된 저장 결과 반환. deleteNotice(id): 삭제 성공 반환.
- 모든 호출은 비동기이며 개발 브라우저 외에는 실행을 차단한다. Query enabled도 DEV와 hydration을 함께 검사한다.
- 키는 ['admin', 'notices'], 상세는 그 뒤 id로 구분한다. 읽음은 상세에서 파생한다.
- 변경 성공 후 목록·해당 상세를 갱신한다. 삭제 시 상세 캐시도 제거한다. 실패 시 낙관적 변경은 하지 않는다.
- 오류는 validation/not-found/unavailable/unknown으로 구분한다. 테스트에서 저장소 실패를 주입하며 운영용 실패 토글은 만들지 않는다.

## 편집기·폼·첨부

- NoticeEditor: initialValue(선택적 JSONContent), onChange(JSONContent), 레이블·오류 연결 id를 받는다.
- 지원 서식은 명세의 문단·줄바꿈·H1~H6·굵게·링크·목록·인라인 코드·코드 블록·인용문·구분선·기울임·취소선·밑줄으로 제한한다.
- 초기값이 없으면 빈 문단에서 시작하고 Placeholder로 “공지 내용을 입력하세요”를 표시한다. 안내는 본문에 저장하지 않는다.
- 초기값은 마운트 시에만 읽는다. 다른 공지 전환·명시적 초기화는 부모의 key 변경으로 새 편집기를 생성한다.
- 툴바는 Figma 675:10640에 맞춰 제목(H1~H6)·굵게·링크·글머리 목록·인라인 코드만 제공한다. 번호 목록·코드 블록·실행 취소 버튼은 제공하지 않으며 기존 JSON 지원과 키보드 실행 취소는 유지한다.
- 툴바는 선택 상태·접근 가능한 이름·키보드 조작을 제공한다. 링크 입력은 Tiptap 기본 처리를 사용하며 별도 URL 검사 정책을 추가하지 않는다.
- 작성·수정용 편집기는 항상 편집 가능하다. 상세 본문은 상세 단계에서 별도로 같은 지원 스키마로 렌더링한다. JSON 원문을 HTML로 직접 주입하지 않는다.
- NoticeForm: 초기 저장값, 저장 콜백, 취소 콜백, 저장 중/실패 상태를 받는다. TanStack Form이 입력·검증을 담당한다.
- 초기값 복원은 공지 id 단위로 수행하고 백그라운드 재조회로 편집 중 값을 덮어쓰지 않는다.
- AttachmentInput: 기존+신규 목록과 변경 콜백을 받는다. 파일 오류는 항목별로 연결하고 같은 파일 재선택도 가능하게 한다.
- dirty는 정규화된 저장값과 초안을 비교한다. 편집기 초기화는 변경으로 세지 않고 첨부 추가·제거도 포함한다.
- 저장 성공을 반영한 뒤 이탈 차단을 해제한다. 진행 중 버튼을 비활성화하고 중복 요청도 막는다.

## 탐색·접근성

- 기존 /notices, /notices/new, /notices/$noticeId, /notices/$noticeId/edit를 유지한다.
- category=all|session|submission|operation, tab=readers|questions는 기본값 생략·잘못된 값 기본 복원을 유지한다.
- 필터 이동은 history push·resetScroll:false다. 뒤로가기는 기존 필터/탭을 복원한다.
- 생성·수정 성공은 해당 상세 readers로 이동한다. 명시적 목록 복귀는 all, 수정 취소는 readers다.
- 목록에서 삭제 후 현재 필터를 유지한다. 질문 탭은 준비 중이며 질문·알림 실행 버튼을 추가하지 않는다.
- 미저장 앱 이동·뒤로가기는 Router blocker로 확인하고 새로고침·닫기는 beforeunload를 사용한다.
- 확인 창은 제목·설명·취소·확정을 제공하고 포커스를 가둔다. 닫은 뒤 실행점 또는 남은 목록 제목으로 복귀한다.
- 모의 조회가 비활성화된 SSR·프로덕션은 준비 중 안내를 렌더링한다. 로딩·오류·빈 결과와 구분한다.

## 읽음 현황 테이블 정렬

- 기본 데이터는 `getNoticeReaders`의 읽음 우선·확인 시각 내림차순·미열람 이름순·동률 ID순을 사용한다.
- 7단계에서 TanStack Table로 이름·기수·직군·읽음 여부·확인 시각 헤더 정렬을 제공한다. 전체 대상 행을 대상으로 클라이언트에서 수행하며 서버 요청을 추가하지 않는다.
- 정렬 상태는 테이블 내부 상태로 관리한다. 단일 컬럼의 오름차순·내림차순·정렬 해제를 제공하며, 해제 시 원래 기본 순서로 복원한다.
- 이름은 한국어 이름순, 기수는 숫자순, 직군은 표시 문자열순, 읽음 여부는 상태값, 확인 시각은 실제 시각값으로 비교한다. 미열람 확인 시각은 방향과 무관하게 마지막에 두며 동률은 기본 행 순서를 유지한다.
- 헤더에는 키보드로 조작 가능한 버튼과 정렬 방향 표시를 두고 `aria-sort`로 현재 방향을 전달한다. 정렬은 대상·읽음 집계나 원본 기록을 변경하지 않는다.
