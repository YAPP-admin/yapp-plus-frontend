# 구현 계획: 관리자 공지 관리

**브랜치**: `DongjaJ/term-specification-review` | **작성일**: 2026-10-19
**명세**: [spec.md](spec.md) | **상태**: 2단계 리뷰 완료 · 3단계 사용자 리뷰 대기

## 요약과 기술 맥락

관리자 내부에서 개발용 공지 CRUD·대상·읽음을 구현한다. Tiptap은 서식 편집을 담당하고
Markdown만 저장한다. 이미지 첨부는 별도 상태로 관리한다. 실제 API와 회원 앱은 변경하지 않는다.

- TypeScript 6·React 19, TanStack Start/Router/Query/Form, Zod 4, SEED·vanilla-extract를 유지한다.
- Node.js·pnpm은 mise와 저장소 고정 버전을 사용한다. 테스트는 기존 Vitest·Testing Library를 쓴다.
- 데이터는 개발 브라우저 탭의 모듈 메모리에 보관한다. SSR·프로덕션·영속 저장에는 사용하지 않는다.
- 대상 플랫폼은 관리자 웹의 데스크톱·375px이다. 목록·읽음 표는 전체 결과를 스크롤한다.
- 새 성능 SLA나 가상화는 도입하지 않는다. 모의 회원 전체에서 중복 대상 계산 없이 집계를 공유한다.
- Tiptap 후보는 core/react/pm/starter-kit/markdown 3.32.0 동일 버전이며 설치·호환 검증은 3단계다.

## 지침 점검

헌법 파일은 미작성 템플릿이므로 [AGENTS.md](../../AGENTS.md)와 사용자 확정 사항을 적용했다.
설계 전후 모두 앱 경계, 공개 진입점, 생성 파일 수정 금지, catalog, 단계별 리뷰 원칙을 확인했다.
새 공용 패키지·API 계약·배포 정책은 추가하지 않는다. 용어 명세서 원문 확인은 사용자 지시로 보류한다.
이슈 연결·commit·push·PR은 아직 수행하지 않았으며 해당 작업 시 기존 승인 규칙을 따른다.

## 구조와 책임

- `apps/admin/src/features/notice-management/model/`: 스키마, 대상·읽음·마감 계산, 모의 저장소와 Query.
- `apps/admin/src/features/notice-management/ui/`: 편집기, 공통 폼·첨부·이탈 확인. 외부는 `index.ts`로 접근한다.
- `apps/admin/src/pages/notices/`: URL 필터와 목록 조합.
- `apps/admin/src/pages/notice-detail/`: 상세·전체 읽음 표와 준비 중 질문 탭.
- `apps/admin/src/pages/notice-editor/`: 작성·수정 데이터 로딩과 성공 후 이동.
- 테스트는 대상 파일 옆에 둔다. 앱 내부 UI의 Storybook은 admin 내부 설정을 사용해 앱 간 import를 피한다.
- 공용 `packages/ui`는 실제 공용 변경이 필요할 때만 수정한다. `routeTree.gen.ts`는 직접 수정하지 않는다.

설계 근거는 [research.md](research.md), 데이터는 [data-model.md](data-model.md),
UI·Query 경계는 [계약](contracts/notice-management.md), 실행 검증은 [quickstart.md](quickstart.md)에 둔다.

## PR·리뷰 경계

각 행은 별도 리뷰 단위이며 선행 행의 사용자 리뷰·다음 진행 확인 후 시작한다.
예상치는 테스트·스타일·문서·lockfile을 포함한 추가+삭제 줄 수이며 실제 diff를 보장하지 않는다.
650줄부터 분리를 검토하고 800줄 이상은 제출하지 않는다. PR은 실제 base 대비 계산한다.
선행 PR이 미병합이면 승인받은 의존 PR의 브랜치를 base로 사용하거나 병합을 기다린다.
같은 PR 안의 커밋 분할만으로 제한을 충족했다고 간주하지 않는다.

## 검증과 진행 조건

각 리뷰에 변경 파일, 실제 base 대비 추가·삭제, 실행/실패/미실행 검증, UI 화면 근거를 제출한다.
문서 단계는 구조·링크·명세 대응을 검증하고, 구현 단계는 [작업 목록](tasks.md)의 회귀를 추가한다.
기본 게이트는 `mise exec -- node --run check`, 앱·빌드 변경은 `mise exec -- node --run build`다.
Markdown 왕복·한글 조합 또는 프로덕션 모의 차단이 실패하면 후속 화면 연결보다 먼저 수정한다.
복구는 해당 독립 변경을 되돌리는 방식이며 저장 데이터 마이그레이션이나 서버 복구는 필요 없다.
