# 계약: 코드 출석 전 위치 확인

## 기존 공개 계약 재사용

- 조회: `GET /api/sessions/current-week`의 sessionId·latitude·longitude·attendanceStatus.
- 제출: `POST /api/attendance-verifications`의 `{ sessionId, code }`. 새 필드는 추가하지 않는다.
- 위치: `@yapp-plus/app-bridge/web`의 requestCurrentLocation·openAppSettings·getAppBridge.
- 신규 공개 API·타입은 없다. 홈 내부 판정 타입은 공용 패키지로 내보내지 않는다.
- 코드의 앞자리 0 입력과 기존 숫자 변환을 유지한다. 위치 조건 통과만으로 onComplete를 실행하지 않는다.

## 제출 순서와 차단

1. 실제 native 로그인·유효한 코드·AVAILABLE·미완료·조회 성공·온라인 여부를 확인한다.
2. nullable 세션 좌표를 검사한다. 없거나 잘못됐으면 위치 요청과 코드 전송을 모두 생략한다.
3. 공개 bridge의 requestCurrentLocation 메서드 지원을 확인하고 단발 위치를 요청한다.
4. 정확한 위치 권한 → 오차 50m 이하 → 거리 100m 이하 순서로 검사한다.
5. 활성 시도·화면·계정·세션 ID·좌표·출석 상태·조회 성공·온라인 여부를 재확인한 뒤 SDK로 제출한다.
6. 기존 서버 응답 검증·성공 context·관련 조회 무효화를 유지한다. 전송 전 위치 실패·시도 무효화는 서버 성공 캐시에 남기지 않는다.

제출마다 세션 GET을 강제로 추가하지 않는다. 현재 Query 변경은 감지하되 서버의 동시 장소 변경을 원자적으로 보장하지 않는다.
기존 static content 차단을 유지한다. DEV+MSW에서도 운영 코드에 합성 위치 우회 분기를 추가하지 않고 테스트에서 브리지를 대체한다.

## 화면 실패와 행동

| 사유                        | 안내                                                                          | 행동                                      |
| --------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------- |
| 범위 밖                     | 세션 장소에서 100m 이내로 이동해 주세요.                                      | 확인으로 새 위치 검사                     |
| 오차 초과·미확인            | 현재 위치를 정확하게 확인하지 못했어요. 다시 시도해 주세요.                   | 확인으로 새 위치 검사                     |
| approximate·unknown         | 정확한 위치 권한을 허용해 주세요.                                             | 앱 설정 열기, 이후 수동 확인              |
| PERMISSION_DENIED           | 위치 권한을 허용해 주세요.                                                    | canAskAgain이면 확인, 아니면 앱 설정 열기 |
| SERVICES_DISABLED           | 기기 위치 서비스를 켜 주세요.                                                 | 기기 설정 안내, 이후 수동 확인            |

| 취득·계산·통신 실패         | 위치를 확인하지 못했어요. 앱 연결과 설정을 확인해 주세요.                     | 확인                                      |
| 브라우저·연결 미준비·미지원 | 위치 확인이 가능한 YAPP+ 앱에서 다시 시도해 주세요.                           | 앱 이용·업데이트 안내                     |
| 세션 좌표 없음·오류         | 세션 장소 정보를 확인하지 못했어요. 다시 확인하거나 운영진에게 문의해 주세요. | 세션 다시 확인                            |
| 대상 변경·조회 실패         | 세션 정보가 바뀌었거나 확인되지 않았어요. 다시 확인해 주세요.                 | 세션 다시 확인                            |
| 설정 실행 실패              | 앱 설정을 열지 못했어요. 기기 설정에서 위치 권한을 확인해 주세요.             | 설정 수동 안내                            |

모든 위치 실패는 제출을 차단하고 코드를 유지한다. 반복 실패 시 운영진 문의를 안내하되 자동 우회하지 않는다.
위치 오류는 폼 코드 오류와 구분하고 진행 상태는 위치 확인/출석 처리로 낭독한다.
기존 서버 코드 오류·인증 복구 정책은 유지하고 위치 raw 오류나 좌표를 문구에 보간하지 않는다.

## Android 공통 수용 사례

| 입력                              | 양쪽에서 기대하는 판정         |
| --------------------------------- | ------------------------------ |
| precise, 오차 10m, 거리 80m       | 제출 허용                      |
| precise, 오차 50m, 판정 거리 100m | 경계 포함, 허용                |
| precise, 오차 50.01m 또는 null    | 차단                           |
| precise, 거리 100.01m             | 차단, 반올림으로 허용하지 않음 |
| approximate·unknown, 가까운 좌표  | 차단                           |
| 좌표 없음·취득 실패·서비스 꺼짐   | 차단                           |
| 대기 중 이탈·계정 변경·대상 변경  | 코드 전송 없음                 |

거리·오차 정책 단위 테스트는 위 값을 직접 주입한다. 계산 통합은 합성 좌표로 별도 검증한다.
Android는 기존 distanceBetween의 반올림 전 값을 사용한다. 동일 WGS84여도 결과의 비트 단위 일치를 요구하지 않는다.
인위적으로 다른 판정 허용치를 추가하지 않고 경계 차이가 관찰되면 원인·실측 값을 비교한다.

## 완료 조회 후속 확인

현재 current-week는 체크인 완료 여부를 제공하지 않고 제출 응답에만 checkedInAt이 있다.
앱 재시작 후 완료 복원은 제외한다. 별도 API·필드가 확인되면 완료 의미·null 의미·재조회 정책부터 합의한다.
