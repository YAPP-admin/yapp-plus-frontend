# 분석 데이터 모델

## 행동과 식별

이벤트는 이름·허용 속성·SDK 식별/시각으로 구성하며 [이벤트 계약](contracts/events.md)이 기준이다. 별도 DB·조회 API·전송 큐는 만들지 않는다.
API 응답·폼 전체를 펼치지 않는다. ID는 문자열, 횟수·기간은 유한한 숫자, 여부는 boolean이며 모르는 값은 키를 생략한다.

| 사실                                   | 식별·기록                                                              |
| -------------------------------------- | ---------------------------------------------------------------------- |
| 신규 소셜 인증, 등록 토큰만 있음       | 익명 login_completed, is_new_user=true                                 |
| 대기·반려·승인 회원 ID 확보            | userId 문자열로 identify 후 직접 인증 이벤트                           |
| 신규 가입 신청 성공으로 ID 확보        | identify 후 signup_requested                                           |
| 같은 회원 토큰·세션 갱신               | 식별 유지, 직접 인증 이벤트 없음                                       |
| 로그아웃·탈퇴 성공 또는 다른 회원 전환 | 필요한 완료 기록 후 reset, 새 회원 identify; 로그아웃 클릭은 확인 시점 |

웹과 native의 userId는 같지만 SDK 세션을 공유하지 않는다. 토큰·sessionId를 식별자로 쓰지 않으며 native는 웹 행동을 복제하지 않는다.

## 활성 구간·알림·오류

화면 활성은 Activity·선택 탭·전면 상태를 합성한다. 홈은 데이터가 준비된 활성 구간당 1회이며 재조회로 추가하지 않는다.
공지 읽기는 같은 상세 화면의 전면 구간 밀리초를 초로 변환한다. 새 상세 진입은 새 구간이며 본문 끝은 고정 버튼이 아닌 실제 sentinel로 판단한다.
notification_id는 서버 항목, eventId는 native 프로세스의 임시 요청 번호, channel은 in_app/push다. 같은 요청의 처리 확인 재시도는 기록을 추가하지 않는다. 실제 재클릭은 별도 기록이며 전역 exactly-once는 보장하지 않는다.
오류는 코드 위치·앱 버전·build·runtime·OTA update ID·배포 SHA와 연결한다. 번들·맵·dSYM은 같은 빌드에서 얻고 비밀·폼 값·개인 파일 주소는 첨부하지 않는다.
