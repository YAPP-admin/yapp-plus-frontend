# 실행·검증 가이드

## 사전 조건

저장소 고정 mise Node.js 24.20.0·pnpm 12.3.4와 설치된 의존성을 사용한다.
개발 실행은 기존 Doppler yapp-plus-admin/dev 접근이 필요하다. 비밀 값은 출력·복사하지 않는다.
회원 fixture 화면은 실제 API나 VITE_API_MOCKING 활성화를 요구하지 않는다. 기존 모킹 설정은 변경하지 않는다.

```sh
mise exec -- node --run dev:admin
mise exec -- pnpm --filter @yapp-plus/admin test
mise exec -- node --run check
mise exec -- node --run build
```

첫 명령은 로컬 개발 서버 실행이다. 나머지는 구현 단계의 검증이며 1단계 문서 작성에서 서버 실행은 필요 없다.

## 단계별 검증

| 단계     | 실행·확인                              | 기대 결과                                    |
| -------- | -------------------------------------- | -------------------------------------------- |
| 1        | 문서 링크·작업 ID·FR 대응·포맷·check   | 미해결 표식 없음, 다음 단계 미착수           |
| 2a/2b    | 모델·변환·고정 fixture 테스트          | 읽기 전용 입력, 페이지별 필요한 props        |
| 3        | 실제 route tree 테스트·모바일 메뉴     | 직접 진입·탭·현재 위치·뒤로가기·0건          |
| 4a/4b/4c | 목록·검색·팀 UI 테스트와 브라우저      | URL·총원·팀 인원 일치, 매핑 전후 구분        |
| 5a/5b    | 폼·모달 테스트와 키보드                | 초기값·제한·취소·포커스 복귀, 저장 요청 없음 |
| 6a/6b    | 실제 XLSX·XLS·CSV parser 테스트        | 형식·첫 시트·행 번호·전화번호·중복 판정 일치 |
| 7a/7b    | 업로드 UI·파일 교체·미리보기           | 집계·예정 수·전체 행 접근, 반영 없음         |
| 8        | 전체 흐름·화면 비교·접근성·check/build | 포함 화면·환경 경계 검증과 미실행 기록       |

## 수동 인수 시나리오

1. /members에서 이름·직군·팀을 조합하고 뒤로가기·새로고침해 조건과 총원을 확인한다.
2. 가입 신청의 0건 빈 화면과 업로드 진입·복귀, 모바일 메뉴 현재 항목을 확인한다.
3. 수정 모달에서 기수 정정 제한·기존 이력·취소 후 초기값을 확인한다. 저장·비활동은 비활성이어야 한다.
4. 합성 명단 양식을 내려받아 세 파일 형식으로 읽는다. 첫 시트·전화번호 앞자리·오류 행 번호를 확인한다.
5. 정상·오류·중복 혼합 파일에서 마지막 중복 행까지 조작하고 예정 수를 확인한다. 실제 반영은 없어야 한다.
6. 읽는 중 파일 교체·페이지 이탈, 다시 올리기로 오래된 결과와 선택이 남지 않는지 확인한다.
7. 375px/데스크톱, Tab·Enter·Escape, 스크린 리더 레이블·오류 안내와 터치 조작을 확인한다.
8. 프로덕션 빌드에서 합성 명단 노출·모의 저장 요청이 없음을 확인한다.

모델 규칙은 가까운 테스트에서 검증하고 페이지마다 같은 조합을 반복하지 않는다.
공통 UI를 바꾸면 해당 테스트·Storybook 사례를 갱신한다. 화면 전용 UI를 위해 다른 앱 내부를 import하지 않는다.
스크린샷은 합성 데이터로 .context/에 저장한다. 결과에 새 실행·Turbo 캐시·실패·미실행을 구분한다.
