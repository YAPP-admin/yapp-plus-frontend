# 검증 절차

## 준비

저장소 고정 mise 도구와 설치된 의존성을 사용한다. 실제 서버 출석은 승인된 테스트 계정·세션에서만 확인한다.

## 자동 검증

1. 인접 Vitest 테스트에서 기존 MSW 응답을 재정의해 출석/보고 성공·실패와 지연 응답을 검증한다.
2. `mise exec -- node --run check`를 실행한다.
3. `mise exec -- node --run build`를 실행한다.
4. `git diff --check`와 실제 PR base 대비 numstat을 확인한다. 새 실행과 Turbo 캐시 사용을 구분한다.

## 사용자 흐름

- 출석: 불가/오픈 전/가능 상태, 네 자리 붙여넣기·앞자리 0, 잘못된 코드, 정상 검증, 완료 후 홈 표시.
- 보고: 세 유형, 빈 사유·30자·31자·이모지 경계, 대상 없음·변경·충돌·자격 없음.
- 공통: 중복 클릭, 오프라인 제출·복귀, 성공 응답 유실, 인증 만료 후 복구와 수동 제출, 제출 중 화면 이탈·계정 변경.
- 키보드 포커스·오류 안내·터치 키패드·VoiceOver·safe-area를 확인하고 실제 수행하지 못한 항목을 기록한다.

화면 녹화·스크린샷에는 실회원 이름·코드·사유·토큰을 노출하지 않는다. 자동 검증 성공을 실서버 출석 검증으로 보고하지 않는다.
