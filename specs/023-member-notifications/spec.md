# 기능 명세: 회원 알림함과 iOS 푸시

**실제 브랜치**: `DongjaJ/android` · **작성일**: 2026-11-10
**상태**: 1단계 문서 작성 완료 · **이슈**: [#417](https://github.com/YAPP-admin/yapp-plus-frontend/issues/417)
**입력**: Android 구현을 참고해 회원 알림 전체를 단계별로 구현한다.

## 사용자 시나리오와 검증

### US1 — 받은 알림 확인 (P1)

회원은 푸시 허용 여부와 무관하게 받은 알림의 내용·날짜를 확인하고 공지로 이동한다.
알림함만 연결해도 가치를 제공하므로 첫 구현 단위로 둔다.
독립 검증: 알림 목록을 조회해 다음 페이지·새로고침·공지 상세 왕복을 확인한다.

1. 받은 알림이 있으면 최신순 내용·한국 날짜를 표시하고 다음 목록을 불러올 수 있다.
2. 받은 알림이 없으면 빈 목록 안내를 표시한다. 조회 실패를 빈 목록으로 표시하지 않는다.
3. 공지 알림을 선택하면 상세로 이동하고 돌아오면 목록·스크롤을 유지한다. 일반 알림은 이동하지 않는다.
4. 갱신·추가 조회가 실패해도 기존 목록을 유지하고 다시 시도할 수 있다.
5. 계정이 바뀌면 이전 계정의 목록과 늦게 도착한 결과를 표시하지 않는다.

### US2 — 현재 기기의 수신 선택 (P1)

회원은 현재 설치의 알림 수신을 켜고 끈다. 다른 기기와 알림함 조회에는 영향을 주지 않는다.
독립 검증: 설정 변경·재시작·재로그인 후 선택 보존과 서버 등록 상태를 확인한다.

1. 처음 사용하는 설치의 기본 선택은 ON이며 최초 인증 완료 후 미결정 권한을 요청한다.
2. 기존 로그인 사용자는 기능 도입 후 첫 세션 복원에서 권한을 확인한다. 저장된 OFF는 자동 요청하지 않는다.
3. 변경 처리와 저장이 성공한 뒤에만 선택을 확정한다. 실패하면 이전 선택과 재시도를 유지한다.
4. 시스템 권한과 앱의 저장된 선택을 구분한다. 권한이 거부되면 사용자가 시스템 설정을 열 수 있다.
5. 선택은 앱 재시작·로그아웃·재로그인 후에도 보존한다. 재설치 후 보존은 보장하지 않는다.
6. 저장값 손상은 OFF로 복구하며 조회 실패는 자동 등록을 막고 재시도를 제공한다.
7. 브라우저·구버전 앱은 지원하지 않는 설정을 비활성화하고 안내한다.

### US3 — 로그아웃 시 기기 연결 종료 (P1)

회원은 서버의 세션·기기 해제가 성공한 뒤 로그아웃한다.
이는 새로 발견한 장애가 아니라 사용자가 선택한 기존 로그아웃 정책 변경이다.
독립 검증: 서버 성공·실패를 각각 재현해 로그인 상태와 기기 등록 정리를 확인한다.

1. 서버 해제가 실패하면 로그인 상태를 유지하고 설정 화면에서 다시 시도한다.
2. 성공하면 로컬 세션을 지우고 이전 세션의 기기 등록 작업·대기 탐색을 폐기한다.
3. 서버 성공 뒤 로컬 삭제 실패는 삭제를 다시 시도하며 이전 세션을 복원하지 않는다.
4. 설치별 수신 선택은 유지한다. 탈퇴 성공과 계정 변경도 이전 작업을 폐기한다.

### US4 — 푸시에서 관련 화면 열기 (P2)

회원은 앱 실행·백그라운드·종료 상태에서 받은 알림을 눌러 관련 화면을 연다.
독립 검증: 세 앱 상태에서 공지·일반 푸시를 각각 탭해 한 번만 이동하는지 확인한다.

1. 공지는 기존 상세, 일반 알림은 알림함으로 이동한다. 수신만으로 화면을 강제 전환하지 않는다.
2. 화면과 인증 준비가 늦어도 탭을 보관했다가 한 번 처리한다. 같은 이벤트가 중복 이동을 만들지 않는다.
3. 잘못된 대상은 알림함으로 이동하고 외부 임의 주소를 실행하지 않는다.
4. 복원 가능한 세션이 없으면 로그인 흐름으로 이동한다. 이전 계정의 목적지를 새 계정에 넘기지 않는다.
5. 실행 중 푸시는 시스템 배너·알림 센터에 표시하고 앱 목록을 갱신한다.

### 경계 조건

- 중복 알림·반복 페이지·만료된 페이지 위치는 무한 요청 없이 복구한다.
- 삭제되거나 권한을 잃은 공지는 기존 상세 오류 안내를 사용한다. 알림은 목록에 남을 수 있다.
- OFF 또는 로그아웃 처리 전에 전송된 푸시는 지연 도착할 수 있다. 즉시 완전 차단을 보장하지 않는다.
- 서버 응답 유실 뒤 세션 만료가 확인되면 기존 인증 정리 절차를 적용한다.

## 요구사항

- **FR-001**: 받은 알림의 내용·날짜·최신순 목록과 새로고침·더 불러오기·재시도를 제공한다. (US1)
- **FR-002**: 공지 상세 연결과 비로그인 안내를 기존 회원 탐색 정책에 맞춰 제공한다. (US1)
- **FR-003**: 조회 실패와 빈 결과를 구분하고 계정 간 알림을 격리한다. (US1)
- **FR-004**: 기기별 선택·시스템 권한을 구분하고 성공 후에만 선택을 확정한다. (US2)
- **FR-005**: 재시작·재로그인·권한 변경 후 저장된 선택에 맞춰 수신 상태를 동기화한다. (US2)
- **FR-006**: 실패·손상·구버전에서 허위 성공과 자동 권한 반복 요청을 막는다. (US2)
- **FR-007**: 서버 해제 성공 후 로그아웃하고 종료된 세션의 작업을 다시 적용하지 않는다. (US3)
- **FR-008**: 푸시 탭의 목적지를 검증하고 인증·화면 준비 후 중복 없이 이동한다. (US4)
- **FR-009**: 앱 상태별 수신·탭과 접근성, 실패·계정 경합을 가까운 계층의 회귀 테스트로 검증한다. (전체)

### 주요 개체

알림 항목은 내용·날짜·출처·선택적 공지 대상을 갖는다. 기기 선택은 설치 수명이며 계정 수명과
분리된다. 기기 등록은 인증 세션에 귀속된다. 대기 탐색은 탭한 알림과 현재 세션에 연결된다.

## 성공 기준

- **SC-001**: 목록·빈 결과·조회 실패·추가 조회·공지 왕복 시나리오가 모두 통과한다.
- **SC-002**: ON/OFF·권한 거부·재시작·재로그인에서 저장된 선택과 확인된 수신 상태가 일치한다.
- **SC-003**: 서버 로그아웃 실패는 로그인 상태를 유지하고 성공 후 이전 세션 작업이 반영되지 않는다.
- **SC-004**: 세 앱 상태 × 두 알림 종류의 실제 기기 탭 검증에서 이동이 각각 한 번만 일어난다.
- **SC-005**: 키보드·터치·스크린 리더로 목록 이동·설정·실패 재시도를 조작할 수 있다.
