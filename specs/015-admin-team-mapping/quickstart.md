# 검증 실행과 리뷰 안내

## 환경과 명령

저장소 루트에서 실행한다. Node.js 24.20.0·pnpm 12.3.4를 사용한다.

```sh
mise exec -- node --run check
mise exec -- node --run build
```

check는 각 단계의 기본 게이트다. 앱/빌드 변경에는 build도 실행한다. 1단계는 문서만 변경하므로 build 대상이 아니다.
모바일 변경은 없어 expo:doctor 대상이 아니다. 필요한 경우 `mise exec -- pnpm --filter @yapp-plus/admin test`로 근접 테스트를 먼저 실행한다.
실제 실행·Turbo 캐시·실패·미실행은 validation.md에 구분한다. 코드 구현 전의 문서 점검을 제품 테스트 통과로 보고하지 않는다.

## 화면 확인

```sh
mise exec -- pnpm --filter @yapp-plus/admin dev
mise exec -- pnpm --filter @yapp-plus/admin start
```

첫 명령은 개발, 두 번째는 build 완료 후 운영 산출물이다. 앱 README의 기존 환경 설정을 따르며 새 모킹 플래그는 요구하지 않는다.
로그에 나온 서버 주소에서 아래 경로를 확인한다. 4단계 전에는 해당 경로가 없으며 문서 작성 시 실행했다고 기록하지 않는다.

- `/members/teams`: 빌딩 전, 생성 진입점.
- `/members/teams?preview=draft`: 배정 중, 8팀·42명 배정·10명 미배정.
- `/members/teams?preview=draft&filter=needs-check`: PM/Design 경고 필터.
- `/members/teams?preview=draft&filter=unassigned`: 개별·일괄 대상 선택.
- `/members/teams?preview=confirmed`: 확정 이력·조회·팀원 전용 편집.

## 단계별 검증 배치

| 단계 | 가까운 계층의 확인                             | 사용자 리뷰 근거                        |
| ---- | ---------------------------------------------- | --------------------------------------- |
| 1    | 명세 링크·요구/작업 대응·체크리스트·check      | 문서와 이슈 초안                        |
| 2    | 구성/집계/검색/필수값/중복/최소 인원 순수 함수 | 규칙별 테스트 결과                      |
| 3    | 참조 무결성·고정 인원·동명이인·상태 공급       | 합성 입력 요약                          |
| 4    | 경로·활성 메뉴·모바일 이동·운영 공급           | 빈 화면·생성 진입 의도, 실제 폼은 6단계 |
| 5    | 필터·URL 복원·빈 결과·메뉴 이벤트              | 카드·경고 화면, 실제 패널은 8단계       |
| 6    | 필수 입력·초안 원복·Enter 차단                 | 생성 빈 폼과 오류                       |
| 7    | 한글/키보드 검색·중복·최소 인원                | 검색 결과·선택 완료                     |
| 8    | 추가/이동/제외 예정·취소·원본 유지             | 패널·메뉴·예정 영역                     |
| 9    | 개별→일괄→개별·체크 해제·팀 없음               | 미배정 다중 선택                        |
| 10   | 모든 이탈 경로·계속/버리기·원래 상태 복귀      | 확인창·포커스 복귀                      |
| 11   | 원본 요약·확정 유지·편집 종료                  | 확정 모달·확정됨·편집                   |
| 12   | 개발/운영·375px·접근성·기존 탐색 회귀          | research.md의 12개 화면별 비교          |

10단계의 복귀는 원래 화면·입력·포커스 보존을 의미한다. 규칙 실패를 모든 UI 테스트에서 반복하지 않는다.

## 최종 인수

1. 생성 입력·패널 예정·미배정 예정을 바꿔도 원본 목록/통계는 유지되고 실제 API 요청이 없어야 한다.
2. 새로고침은 fixture로 돌아간다. 개발·운영에서 같은 URL의 입력과 조작이 같아야 한다.
3. last-member 사례와 여러 예정 합산을 확인한다. 모두 취소는 가능해야 한다.
4. 키보드·스크린 리더·터치·375px을 확인한다. 공용 UI 수정 시 관련 Storybook도 갱신한다.
5. Figma 12개별 데스크톱 비교와 의도된 차이(셸·필수 팀원·비활성·예정 영역)를 기록한다.
6. 스크린샷은 .context/ 아래에 저장하고 validation.md에는 경로와 재현 절차를 남긴다. 실패·미실행을 완료로 표시하지 않는다.
