# 기능 명세: 관리자 로그인 화면과 모의 동작

**브랜치**: `DongjaJ/admin`
**작성일**: 2026-10-06
**상태**: 확정
**이슈**: [#34](https://github.com/YAPP-admin/yapp-plus-frontend/issues/34)

## 사용자 시나리오와 검증

### US1 — 로그인 화면 접근 (P1)

운영 측에서 계정을 발급받은 관리자가 아이디와 비밀번호를 입력한다.
독립 검증: `/login`을 직접 열고 데스크톱·좁은 화면에서 입력한다.

1. 로그인 화면에는 관리자 내비게이션 없이 로고와 두 입력, 로그인 버튼이 표시된다.
2. 좁은 화면에서는 세로로 배치되고 입력과 버튼에 모두 접근할 수 있다.
3. 비밀번호는 마스킹되고 키보드와 자동완성으로 입력할 수 있다.

### US2 — 검증과 모의 로그인 (P1)

개발자가 실제 인증 없이 로그인 성공·실패와 재시도를 검증한다.
독립 검증: 개발용 공개 계정과 틀린 입력을 각각 제출한다.

1. 빈 입력을 제출하면 필드 오류가 표시되고 첫 오류 필드로 포커스가 이동한다.
2. 최초 제출 전에는 오류를 표시하지 않고 제출 이후 수정 시 재검증한다.
3. 제출 중에는 중복 요청을 막고 로딩을 표시한다.
4. 실패 시 입력을 유지하고 오류를 표시하며 수정하면 인증 오류를 해제한다.
5. 성공 시 기존 대시보드 `/`로 이동한다.

### 경계 조건

- 아이디 앞뒤 공백은 제거하지만 비밀번호는 그대로 전달한다.
- 서비스 오류와 예외 발생 후에도 다시 입력·제출할 수 있다.
- 프로덕션 빌드에서는 모의 인증이 동작하지 않는다.

## 요구사항

- **FR-001**: `/login`은 Figma 기본·실패 상태와 반응형 배치를 제공한다.
- **FR-002**: 아이디·비밀번호 필수 입력만 검증하며 가입용 형식 규칙을 추가하지 않는다.
- **FR-003**: Enter와 클릭 제출, 오류 알림, 명확한 키보드 포커스를 제공한다.
- **FR-004**: 인증 실패 문구는 “아이디 혹은 비밀번호가 일치하지 않아요.”로 표시한다.
- **FR-005**: 프로덕션에서는 제출을 비활성화하고 “로그인 기능을 준비 중입니다.”를 표시한다.
- **FR-006**: 계정 입력·모의 결과를 저장하거나 로그에 기록하지 않는다.

## 성공 기준

- **SC-001**: 1440×1080, 768px, 375px 화면에서 기본·오류 상태와 넘침을 확인한다.
- **SC-002**: 필수 입력·중복 제출·실패 재시도·성공 이동 시나리오가 자동 테스트를 통과한다.
- **SC-003**: 프로덕션 빌드에 공개 테스트 계정과 모의 판정 코드가 포함되지 않는다.

## 가정과 범위

- 계정 발급은 운영 측에서 수행한다. 회원가입·계정 관리 화면은 없다.
- 실제 API·세션·접근 제어·로그아웃은 후속 범위이며 대시보드는 직접 접근 가능하다.
- Pretendard를 유지한다. 개발 서버에서만 모의 동작을 사용하며 Vercel Preview도 비활성화한다.
