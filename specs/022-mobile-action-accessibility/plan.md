# 구현 계획: 회원 앱 하단 버튼 접근성

**실제 브랜치**: `DongjaJ/plan-proceed` | **작성일**: 2026-11-10 | **명세**: [spec.md](spec.md)
**기준**: `origin/main` / `7bd77d09035d8c1a317469bc4d03caedb25955f1` | **이슈**: #411

## 요약

앱 콘텐츠의 실제 가용 높이를 기준으로 헤더·스크롤 본문·하단 액션을 합성한다.
가입 단계는 탐색 이력과 연결하고 가시 영역 변화에 맞춰 버튼을 배치한다.
기존 프레임을 확장하되 웹 내부에서만 사용하며 새 의존성·API·브리지 변경은 없다.

## 기술 맥락

- TypeScript 6.0.3, React 19.2.8, SEED React 3.1.0, Stackflow React 2.1.4, vanilla-extract.
- Node.js 24.20.0 / pnpm 12.3.4를 mise와 lockfile 기준으로 사용한다.
- 기존 TanStack Form·Query·Vitest·Testing Library를 사용하며 영속 저장은 추가하지 않는다.
- 대상은 모바일 WebView와 일반 브라우저. iOS 설치 앱 우선, Android 회귀 검증.
- 비활성 화면의 listener·observer는 중단하고 기존 탭 DOM·스크롤 상태를 유지한다.

## 헌법 점검

기준 commit에서 루트·웹 AGENTS, 제품 맥락, 프론트엔드·웹 가이드와 탐색 계약을 확인했다.

| 원칙           | 설계 판정과 근거                                                       |
| -------------- | ---------------------------------------------------------------------- |
| 제품·최소 범위 | 적용: 승인된 UI 결함만 수정하며 미연결 기능은 후속 기록                |
| 경계·생성 코드 | 적용: 웹 내부 프레임·Activity만 변경, 공용 계약과 생성 코드는 유지     |
| 도구·의존성    | 적용: 고정 버전·기존 라이브러리 사용, 추가 의존성 없음                 |
| 검증           | 적용: 가까운 회귀 테스트와 화면 측정 구분, 실제 iOS 결과는 현재 미확인 |
| 검토·복구      | 적용: 단계별 리뷰·800줄 미만 PR, 인증 정책·데이터 마이그레이션 없음    |

설계 후 재점검에서도 원칙 예외가 없다. 구현 후 실제 diff와 검증 결과로 다시 판정한다.

## 구조와 내부 인터페이스

- `apps/web/src/app/layouts`: 기존 PageShell·AuthLayout·TabsLayout을 조합한다.
- `apps/web/src/shared/ui`: 페이지에서도 쓰는 도메인 비의존 본문·액션 프레임을 둔다.
- `apps/web/stackflow/src`: Activity 높이·활성 scroll root 연결과 Signup 단계 계약을 소유한다.
- 페이지 전용 상태·스타일·테스트는 해당 `src/pages/<화면>`에 둔다. 페이지가 app 레이어를 새로 import하지 않는다.
- 헤더·본문·액션의 배치 계약은 [contracts/screen-layout.md](contracts/screen-layout.md), 상태 수명은 [data-model.md](data-model.md)에 둔다.
- Signup params에는 선택적인 `step: 'name' | 'phone'`만 추가하고 입력값은 폼에 유지한다.
- 사용자 정의 back 동작은 가입 Activity에서 AuthLayout에 전달한다. 일반 BackButton의 전역 동작은 변경하지 않는다.

## 구현 순서와 리뷰 단위

1. **명세·재현 기준**: 설계 산출물, 화면별 수정 전 측정·캡처, 미연결 기능 기록을 제출한다. 제품 코드는 변경하지 않는다.
2. **US1 / 높이·safe-area**: 기존 프레임과 설정·가입에 최소 적용한다. 실제 본문에 상태바 observer를 연결하고 탭의 34px 중복 여백을 제거한다.
3. **US2 / 가입**: 활성 화면의 VisualViewport 처리, step 탐색, 값·오류 보존, 로딩·중복 제출 회귀를 구현한다.
4. **US3 / 관련 화면**: 로그인·완료·팀 인증·오류에 적용하고 공지·탭·무한 목록·스낵바 위치를 회귀 확인한다.
5. **US4 / QA**: 팝업·터치·오류·테마 결함을 수정하고 실제 iOS·Android 검증을 완료한다.

각 단위의 수정·테스트·문서를 함께 리뷰한다. 확인 없이 다음 단계 구현을 시작하지 않는다.
650줄부터 PR 분리를 검토하고 800줄 이상이면 독립적인 목적의 PR로 분리한다.
현재 1단계 문서와 후속 제품 변경은 별도 검토 단위로 유지하며 Git 외부 작업은 승인 범위를 따른다.

## 검증·호환성·복구

- [quickstart.md](quickstart.md)의 동일 조건으로 전후 비교한다. DOM 단위 테스트는 물리적 키보드·WebView 검증을 대신하지 않는다.
- 화면 변경 후 `mise exec -- node --run check`와 `mise exec -- node --run build`를 실행하고 캐시 사용을 분리한다.
- 공유 UI 동작 변경은 해당 Storybook 사례와 키보드·스크린 리더·터치 확인을 포함한다.
- 모바일 설정·의존성이 변경될 때만 `expo:doctor`를 추가한다. 현재 계획에는 해당 변경이 없다.
- `/signup` 직접 진입·새로고침의 초기화, Android back, 탭 복원과 safe-area 준비 지연을 회귀 확인한다.
- 회귀 발생 시 해당 단계 변경을 되돌리는 수정 PR로 복구한다. 배포·인증 데이터·서버 변경은 수행하지 않는다.
