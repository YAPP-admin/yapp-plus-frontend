# 0단계 검증 기록

작성일: 2026-10-29 · [이슈 #180](https://github.com/YAPP-admin/yapp-plus-frontend/issues/180)

## 범위

명세·독립 모델 설계·계약 초안과 검증 가이드만 작성했다. 제품 코드와 생성 코드는 수정하지 않았다.
Git 브랜치는 `tallinn/xoaj3`를 유지한다. Spec Kit 기능 선택 파일은 새 문서 디렉터리를 가리킨다.
Spec Kit 확장 hook 설정이 없어 전후 hook 실행은 해당하지 않는다.

## 검증

- `mise exec -- node --run check`: 통과. 포맷 검사는 실행했고 lint 7개·typecheck 7개·test 4개 작업은 Turbo 캐시를 재사용했다.
- 새 문서의 로컬 링크: 24개 대상 존재 확인. 외부 링크의 배포 환경 접근 권한까지 검증하지 않았다.
- 생성 SDK와 고정 SHA의 백엔드 소스를 읽기 전용으로 대조했다. 실제 HTTP 변경 요청은 하지 않았다.
- 기존 tracked 변경은 없고 새 문서 8개만 추가했다. Spec Kit의 `feature.json`은 저장소 ignore 대상 로컬 선택 상태다.
- PR 크기는 650줄 분리 검토 기준 미만이다. commit·push·PR 생성은 수행하지 않았다.

## 미검증과 리뷰 대상

UI 변경이 없어 스크린샷·브라우저 동작·접근성 검증은 이번 단계에 해당하지 않는다.
문서 변경이므로 앱 build와 expo:doctor는 실행 대상이 아니다.
실제 서버 호출·배포 버전 일치 여부·백엔드 담당자의 계약 동의는 검증하지 않았다.

사용자 리뷰에서는 독립 모델의 필드, 마감 취소의 모의 정책과 서버 차이,
검수 대기 차단 및 판단 순서, 단계별 범위를 확인한다.
0단계 리뷰와 다음 단계 진행 확인 전에는 제품 구현을 시작하지 않는다.

## 1단계 분할: 1-1 세션 모델 추출

0단계와 함께 800줄 미만을 유지하도록 1단계를 나눴다. 이번 범위는 세션 모델과 공개 진입점이다.
`features/session-management/model/session.ts`로 기존 모델을 그대로 옮기고 소비자는 공개 `index.ts`를 사용한다.
폼·위치 검색·서비스·Query·모의 저장소와 기존 테스트 위치는 유지한다. API 타입 의존성은 추가하지 않았다.
서비스·Query·모의 저장소 추출은 문서 PR 분리 및 사용자 리뷰 이후의 1-2단계로 남긴다.
화면·데이터 동작 변경은 없으므로 새 스크린샷과 Storybook 사례는 추가하지 않는다.

검증 결과: `mise exec -- node --run check`와 `mise exec -- node --run build` 통과.
어드민 lint·typecheck·테스트는 재실행했으며 기존 39개 파일의 478개 테스트가 통과했다.
첫 검사에서 공개 export 누락을 발견해 수정한 뒤 다시 통과했다. 이동 모델은 원본과 byte 단위로 동일하다.
브라우저 수동 검증은 실행하지 않았고 기존 폼·목록·CRUD 자동 테스트로 회귀를 확인했다.

## 1-2단계: 세션 서비스·Query·모의 저장소 추출

문서 기준 브랜치 `attendance-design`을 `412f542`에 생성했다. 현재 브랜치 `tallinn/xoaj3`는 유지한다.
문서 PR의 base는 main, 1단계 코드 PR의 base는 attendance-design으로 분리한다. 실제 push·PR 생성은 하지 않았다.
서비스는 `features/session-management/service/index.ts`, Query와 저장소는 같은 feature의 model로 옮겼다.
페이지는 공개 진입점을 사용하고 feature 내부는 상대 경로로 참조한다. 폼·장소 검색·필터는 기존 페이지에 남겼다.
테스트용 `testing/index.ts`로 fixture 저장소를 노출하고 서비스의 저장소 동적 import를 유지했다.
기존 서비스 테스트를 보강해 서비스·화면 공개 진입점 사이의 생성·수정·삭제 결과 공유를 검증했다.

`mise exec -- node --run check` 통과: 어드민 lint·typecheck·39개 테스트 파일(478개 테스트)을 재실행했다.
`mise exec -- node --run build` 통과. 첫 lint의 중복 import를 합친 후 전체 check를 다시 통과했다.
화면·정책 변경이 없어 새 스크린샷·Storybook 사례는 없으며 브라우저 수동 검증은 실행하지 않았다.
1단계 추출을 완료했으며 2단계 모델·점수 규칙 구현은 리뷰와 진행 확인 전까지 시작하지 않는다.

## 2-1단계: 독립 출결 모델과 감점 규칙

1-2단계를 `38712aa`로 커밋한 뒤 출결·보고·명찰 스키마와 `calculateAttendanceDelta`를 추가했다.
생성 API 타입을 import하지 않으며 출결의 일반/무단 구분과 시간 구간으로 감점을 계산한다.
미정·미지원·근거 누락은 null로 유지하고 공결을 일반 결석으로 바꾸지 않는다.
감점 조합, 잘못된 출결 조합, 보고 유형·시각 및 출결·명찰 분리를 8개 테스트로 검증한다.
팀 사진·회원 집계·입력·초안 모델은 2-2단계에 남겨 두었고 화면 연결과 마감 실행은 구현하지 않았다.
화면 변경이 없어 스크린샷·Storybook 갱신은 없고 브라우저 수동 검증은 실행하지 않았다.

`mise exec -- node --run check`와 `mise exec -- node --run build` 통과. 어드민 테스트 486개를 재실행했다.

## 2-2단계: 나머지 조회 모델·입력·초안

`attendance-core`를 `e073c39`에 생성했고 작업 브랜치는 그대로 유지했다. 이번 변경의 PR base는 attendance-core다.
세션·회원·이력·팀 사진·검수·코드·누적 점수 ViewModel을 추가했다. 생성 API 타입과의 결합은 없다.
편집 입력의 출결별 필수 필드, 사진 사유 길이, 초안 키와 ID, 마감 대상 세션의 일치를 검증한다.
누적 점수는 미확정 기여를 보존하고 40점 경계·100점 기본값·입력 내역의 독립성을 검증한다.
화면 연결·마감 실행·모의 서비스는 이번 범위가 아니다. 스크린샷과 브라우저 수동 검증은 없다.

`mise exec -- node --run check`와 `mise exec -- node --run build` 통과. 어드민 테스트 17개를 추가해 총 503개가 통과했다.
초기 lint의 타입 선언·테스트 단언·레코드 순회 타입 지적을 수정한 뒤 전체 검사를 다시 통과했다.
로컬 문서 링크와 diff 공백 검사도 통과했다. API 응답 변환과 외부 입력 검증은 실제 연동 단계에 남아 있다.
2단계 모델 구현은 완료했으며 3단계 모의 서비스는 리뷰와 진행 확인 전까지 시작하지 않는다.

### 2단계 리뷰 반영: 점수 계산 경계

사용자 리뷰에 따라 실제 감점·누적 점수는 서버가 제공하고 프런트는 재계산하지 않도록 역할을 정리했다.
계산 함수는 `model/mocks`로 옮기고 Mock 접두 표현으로 이름을 구분했으며 일반 공개 export를 제거했다.
관리자 누적 점수 API 미비는 백엔드 계약으로 해결하며 클라이언트 합산으로 대체하지 않는다.
초안 순회는 forEach, 모의 합산은 reduce로 변경한 리뷰 내용도 유지한다.
`mise exec -- node --run check`와 `mise exec -- node --run build` 통과. 어드민 테스트 503개 통과.
화면 변경은 없고 실제 API 연동 및 브라우저 수동 검증은 실행하지 않았다.

### 리뷰 반영: mock 생성 테스트 제외

사용자 요청에 따라 mock 감점·누적 합산 테스트 9개를 제거하고 출결 모델·입력·초안 검증은 유지했다.
향후 mock 데이터 생성 자체는 테스트 대상에서 제외하며 실제 사용자 흐름 검증은 유지한다.
`mise exec -- node --run check` 통과, 어드민 테스트 494개 통과. 테스트·문서만 수정해 build는 재실행하지 않았다.

## 3-1단계: 세션 생성과 출석 조회 연결

2단계 리뷰 반영을 `7f07d81`로 커밋했다. 이번 단계는 기존 attendance-core base 위에서 이어간다.
`createSessionStore`가 세션과 출석 명단을 함께 소유한다. 신규 세션은 가상 회원 40명의 미정 출석을 즉시 준비한다.
기존 예시는 세션 집계에 맞는 가상 명단을 생성하며 실제 회원 정보·API 타입을 사용하지 않는다.
`getSessionAttendance`를 서비스 공개 진입점에 추가했다. 서버 실행을 차단하고 반환 데이터는 복사한다.
세션 변경은 출석 조회 메타데이터에 반영하며 삭제 시 명단도 삭제한다. 출석 코드 발급과는 독립적이다.
mock 생성 자체의 테스트는 추가하지 않았다. 기존 서비스 테스트로 생성→출석 조회→세션 수정→삭제와 실행 경계를 검증한다.
신규 화면은 없으며 세션 생성 후 기존 카드의 미정 집계가 0명에서 모의 회원 수로 바뀐다. 브라우저 수동 검증·스크린샷은 없다.
출결 수정·변경 이력·실패 재현은 3-2단계로 남겨 두었다.

`mise exec -- node --run check`와 `mise exec -- node --run build` 통과. 어드민 테스트 494개 통과.
초기 lint의 중첩 삼항식을 상태별 배열 생성으로 바꾸고, 기존 UI 테스트의 미정 0명 기대값을 자동 생성된 40명으로 갱신했다.
세션 생성 후 카드의 미처리 40명 표시를 기존 사용자 흐름 테스트에서 확인했다.
650줄 분리 검토 기준을 넘었으므로 다음 변경 전 PR 기준을 추가 분리한다. 현재 변경은 800줄 미만으로 유지한다.
