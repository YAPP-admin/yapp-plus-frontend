# 실행·검증 가이드

## 현재 상태

1-4는 문서 작성 단계다. 아래 장소 기능 실행 절차는 구현 후 사용할 가이드이며 지금 동작한다고 의미하지 않는다.
현재까지 설치된 것은 기존 lockfile의 의존성뿐이다. 실제 키 발급·지도/좌표 라이브러리 추가는 후속 단계다.

## 환경 준비

저장소 루트에서 실행한다.

```sh
mise exec -- node --version
mise exec -- pnpm --version
mise exec -- pnpm install --frozen-lockfile
mise exec -- node --run check
```

Node.js 24.20.0·pnpm 12.3.4인지 확인한다. 로컬 셸에 mise가 활성화되어 있으면 `mise exec --`는 생략 가능하다.

## 2단계 키 준비 순서

1. 2-1: 기존 조직 소유 앱·승인키·담당자·허용 도메인을 확인한다. 키 자체를 보고서에 적지 않는다.
2. 2-2: [주소 API 신청](https://business.juso.go.kr/jst/jstAddressApiApplicationWrite?uniqKey=cntcInfoApi)에서 개발용 키 신청 조건·유효기간을 확인한다. 90일을 초기 계획으로 잡되 발급 화면의 실제 옵션을 따른다.
3. 2-3: [좌표 API 신청](https://business.juso.go.kr/jst/jstAddressApiApplicationWrite?uniqKey=cntcInfoCoordApi)에서 운영용 신청·본인 확인·사용 목적을 준비한다. 주소 키와 별개이며 발급 시간을 보장하지 않는다.
4. 2-4: 카카오 앱의 Maps 사용 설정과 JavaScript 키·웹 도메인 `http://localhost:3001`을 확인한다. 유료 결제나 앱 소유권 변경은 별도 승인 없이 하지 않는다.
5. 2-5: `apps/admin/.env.local`에 계약 문서의 세 변수를 설정하고 `.env.example`에는 빈 값만 기록한다. 주소→좌표의 실제 호출·JSONP 형식·현재 오류 응답과 카카오 도메인 허용을 확인한다.

각 번호는 별도 리뷰 단계다. 신청 과정에서 본인 확인이 필요하면 사용자가 직접 수행한다.

## 구현 후 실행

```sh
mise exec -- pnpm --filter @yapp-plus/admin dev
```

개발 화면에서 주소 검색·페이지 이동·좌표 조회·마커 조정 후 생성한다. 화면 이동 후 값 유지와 새로고침 초기화를 확인한다.
수정 시 조정 좌표가 복원되는지, 팀 안내를 비워도 저장되는지 확인한다.
LP-01~~11, ST-01~~15를 순서대로 검증하고 실제 키 테스트와 모의 테스트 결과를 분리 기록한다.
실제 키·네트워크가 없으면 외부 연동 검증은 미완료로 남긴다.

## 자동·수동 검증

```sh
mise exec -- node --run check
mise exec -- node --run build
```

키보드·스크린 리더·터치, 좁은 화면과 짧은 화면 높이를 확인한다. 실패·재시도와 SDK 로딩 실패도 포함한다.
스크린샷은 `.context/`에 저장하고 값·URL에 키가 노출되지 않았는지 확인한다.
프로덕션·SSR에서는 모의 편집과 외부 장소 SDK 초기화가 실행되지 않는지 검증한다.

## 복구

DEV 데이터는 새로고침으로 초기화한다. 기능 코드 변경을 되돌리면 이전 구조로 돌아가며 영구 데이터 이관은 없다.
발급 키에 문제가 있으면 해당 기능 오류로 안내하고 실제 키 재설정 후 재검증한다. 인증·배포 정책을 바꿔 우회하지 않는다.

### 기존 카카오 앱 설정

1. 카카오디벨로퍼스에서 기존 앱을 선택한다.
2. `카카오맵 > 사용 설정`에서 상태를 `ON`으로 설정하고 앱 정보의 `카카오맵 무료 쿼터` 뱃지를 확인한다. 유료 설정이 필요하다고 나오면 임의로 결제 설정하지 않고 확인한다.
3. `앱 설정 > 앱 > 플랫폼 키`에서 사용할 JavaScript 키를 선택한다.
4. 해당 키의 `JavaScript SDK 도메인`에 아래 여섯 주소를 각각 추가한다. 기존 사용 중인 주소는 제거하지 않는다.

```text
http://localhost:3000
http://localhost:3001
http://localhost:3002
http://localhost:3003
http://localhost:3004
https://yapp-plus-admin.vercel.app
```

5. JavaScript 키를 보관한다. REST API 키나 Admin 키를 지도 Web SDK에 사용하지 않는다.
6. 활성화 여부·무료 쿼터 적용 여부·도메인 저장 완료를 확인한다. 키 값은 보고에 포함하지 않는다.

근거: [카카오 지도 Web 가이드](https://apis.map.kakao.com/web/guide/),
[카카오맵 사용 방법](https://developers.kakao.com/docs/ko/kakaomap/common).

## Doppler 개발 환경 연결 (2-5 진행 중)

공통 경로 `/Users/dongja/conductor/workspaces/yapp-plus-frontend`에는 CLI 인증만 유지한다.
이전 `yapp-plus-frontend/dev` 프로젝트 기본값은 제거했다. `libreville`의 이전 기본값도 제거되어 있다.
인증 토큰과 키 값은 저장소에 기록하지 않는다.

루트 `package.json`의 `dev:admin`은 `yapp-plus-admin` 프로젝트와 `dev` config를 명시한다.
따라서 다른 앱의 Doppler 프로젝트 기본값에 영향을 받지 않고 관리자 설정을 주입한다.
Doppler CLI 설치와 해당 프로젝트에 접근 가능한 로그인이 필요하다.

```sh
mise exec -- node --run dev:admin
```

mise가 셸에 활성화되어 있으면 `node --run dev:admin`으로 실행한다.
새 워크스페이스도 위 공통 경로 아래에 있으면 인증을 상속한다. 다른 경로의 clone이나 팀원 PC에서는 로그인해야 한다.
다른 워크스페이스에 별도 토큰 설정이 있으면 해당 인증이 우선하며 이번 작업에서 다른 워크스페이스 설정은 바꾸지 않았다.

프로세스에 주소 검색 키·카카오 JavaScript 키가 존재함을 값 출력 없이 확인했다.
좌표 키는 아직 없으며 승인 대기다. 이 확인은 키의 유효성이나 실제 API 성공 검증은 아니다.
환경 변수 관리 방식은 앞선 `.env.local` 직접 입력 안내 대신 Doppler 주입을 사용한다.
변수 변경 후에는 개발 서버를 다시 실행한다. 회원용 앱 스크립트와 Vercel 동기화·배포 설정은 이번 연결에서 변경하지 않았다.
