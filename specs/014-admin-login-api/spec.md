# 기능 명세: 관리자 로그인 API와 세션 연동

**브랜치**: `DongjaJ/login-api`

**작성일**: 2026-10-31

**상태**: 초안

**이슈**: [#241](https://github.com/YAPP-admin/yapp-plus-frontend/issues/241)

**요청**: 기존 관리자 로그인 화면을 실제 인증 서비스와 연결하고, 발급된 세션을 브라우저를
다시 열어도 유지해 후속 관리자 요청에 사용한다.

## 사용자 시나리오와 검증

### US1 — 발급 계정으로 관리자 로그인 (P1)

운영진은 발급받은 아이디와 비밀번호를 입력해 실제 인증을 완료하고 관리자 대시보드로 이동한다.
개발 전용 판정이나 실행 환경에 따라 로그인 가능 여부가 달라지지 않아야 한다.

**우선순위 근거**: 실제 인증이 되지 않으면 관리자 기능을 안전하게 서버와 연결할 수 없다.

**독립 검증**: 로그인 화면에서 성공·자격 증명 실패·서비스 실패를 각각 발생시켜 이동과 오류 안내,
재시도를 확인한다.

1. **Given** 유효한 발급 계정을 입력한 상태에서 **When** 로그인을 제출하면 **Then** 인증 세션을
   확보하고 관리자 대시보드로 이동한다.
2. **Given** 아이디 또는 비밀번호가 올바르지 않은 상태에서 **When** 로그인을 제출하면 **Then**
   자격 증명 오류를 안내하고 입력을 유지해 다시 시도할 수 있다.
3. **Given** 인증 서비스를 이용할 수 없거나 응답이 계약과 다른 상태에서 **When** 로그인을
   제출하면 **Then** 서비스 오류를 안내하고 인증 성공으로 처리하지 않는다.
4. **Given** 로그인을 제출 중인 상태에서 **When** 다시 제출을 시도하면 **Then** 요청을 중복으로
   만들지 않는다.

---

### US2 — 브라우저 재시작 후 관리자 세션 사용 (P2)

운영진은 로그인한 브라우저를 닫았다가 다시 열어도 이미 확보한 세션으로 Staff 전용 요청을 보낼 수
있다. 관리자 세션이 회원 인증이나 서버 렌더링으로 잘못 전달되어서는 안 된다.

**우선순위 근거**: 로그인 성공 뒤 후속 관리자 기능이 인증되지 않으면 실제 API 연동의 사용자 가치가
완성되지 않는다.

**독립 검증**: 로그인 성공 뒤 브라우저를 다시 시작한 상황을 재현하고 Staff 전용 요청과 다른 인증
종류의 요청에서 세션 전달 여부를 확인한다.

1. **Given** 로그인에 성공한 상태에서 **When** 브라우저를 다시 열고 Staff 전용 요청을 보내면
   **Then** 저장된 관리자 세션을 인증에 사용한다.
2. **Given** 관리자 세션이 저장된 상태에서 **When** 다른 사용자 인증 종류의 요청을 보내면
   **Then** 관리자 세션을 전달하지 않는다.
3. **Given** 브라우저 저장소를 읽거나 쓸 수 없는 상태에서 **When** 세션을 사용하거나 저장하면
   **Then** 비밀 값을 노출하지 않고 인증되지 않은 상태 또는 로그인 실패로 처리한다.

---

### US3 — 떠난 로그인 화면의 늦은 성공 격리 (P3)

운영진이 로그인 요청을 보낸 뒤 다른 화면으로 이동하면, 늦게 도착한 성공 응답이 사용자의 현재
화면을 다시 대시보드로 바꾸지 않는다.

**우선순위 근거**: 실제 네트워크 요청은 지연될 수 있으므로 기존 개발용 판정보다 화면 수명 경계를
명확히 해야 한다.

**독립 검증**: 로그인 요청을 지연한 뒤 화면을 떠나 성공 응답을 완료하고 현재 위치가 유지되는지
확인한다.

1. **Given** 로그인 요청이 진행 중인 상태에서 **When** 로그인 화면을 떠난 뒤 요청이 성공하면
   **Then** 인증 결과는 저장하되 떠난 화면의 이동 동작은 실행하지 않는다.
2. **Given** 로그인 화면이 유지된 상태에서 **When** 요청이 성공하면 **Then** 정상적으로
   대시보드로 이동한다.

### 경계 상황

- 성공 응답에 필수 정보가 없거나 형식이 잘못되면 세션을 저장하지 않고 서비스 오류로 처리한다.
- 새 로그인이 실패하면 기존에 정상적으로 저장된 세션을 임의로 삭제하거나 교체하지 않는다.
- 빈 세션 값은 인증 정보로 사용하지 않는다.
- 세션 저장은 성공했지만 로그인 화면이 사라졌다면 세션과 화면 이동을 분리해 처리한다.
- 저장된 세션이 만료되거나 서버에서 폐기된 경우 이번 기능은 자동으로 갱신하거나 이동하지 않는다.

## 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 관리자 로그인 제출을 실제 Staff 인증 서비스로 전달해야 한다.
- **FR-002**: 시스템은 아이디의 앞뒤 공백만 제거하고 비밀번호는 입력 원문을 전달해야 한다.
- **FR-003**: 시스템은 성공·자격 증명 실패·서비스 실패를 구분하고 기존 로그인 화면의 안내와
  재시도 동작을 유지해야 한다.
- **FR-004**: 시스템은 인증 성공 응답을 신뢰 경계에서 검증하고 유효한 access token만 관리자
  세션으로 저장해야 한다.
- **FR-005**: 시스템은 관리자 세션을 브라우저 재시작 후에도 유지해야 한다.
- **FR-006**: 시스템은 저장된 관리자 세션을 Staff 인증이 필요한 요청에만 전달해야 한다.
- **FR-007**: 시스템은 브라우저가 아닌 실행 환경과 다른 사용자 인증 종류에 관리자 세션을
  전달하지 않아야 한다.
- **FR-008**: 시스템은 저장소 접근·쓰기 실패를 로그인 성공으로 처리하지 않아야 한다.
- **FR-009**: 시스템은 새 로그인이 완전히 성공한 뒤에만 기존 세션을 교체해야 한다.
- **FR-010**: 시스템은 로그인 화면이 사라진 뒤 도착한 성공 응답으로 이전 화면의 이동 동작을
  실행하지 않아야 한다.
- **FR-011**: 시스템은 개발 모킹을 명시적으로 켠 경우에도 실서버와 같은 로그인 호출 경로를
  사용해야 한다.
- **FR-012**: 시스템은 실제 자격 증명·발급 token·인증 header를 소스, 테스트 데이터, 문서,
  로그와 검증 이미지에 기록하지 않아야 한다.

### 주요 엔터티

- **로그인 입력**: 운영진이 제출하는 아이디와 비밀번호. 요청 중에만 사용하며 영구 저장하지 않는다.
- **관리자 인증 응답**: Staff 요약과 access token을 포함하는 인증 결과. 계약 검증 뒤 token만 세션에
  사용한다.
- **관리자 세션**: 브라우저에 유지되는 Staff 전용 access token. 다른 사용자 인증 종류와 분리한다.
- **로그인 화면 수명**: 성공 응답이 현재 로그인 화면의 이동 동작을 실행할 수 있는 범위다.

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 유효한 로그인 시나리오의 100%에서 한 번의 제출로 대시보드에 도달한다.
- **SC-002**: 자격 증명 실패·서비스 실패·잘못된 성공 응답·저장 실패 검증의 100%에서 대시보드로
  이동하지 않고 다시 제출할 수 있다.
- **SC-003**: 브라우저 재시작 시나리오의 100%에서 저장된 관리자 세션이 Staff 전용 요청에만
  사용된다.
- **SC-004**: 로그인 화면을 떠난 뒤 성공하는 모든 회귀 시나리오에서 예상하지 않은 화면 이동이
  0회다.
- **SC-005**: 개발 모킹·개발 실서버·프로덕션 빌드의 세 환경에서 같은 로그인 사용자 흐름을
  확인할 수 있다.
- **SC-006**: 저장소와 검증 산출물에서 실제 자격 증명·발급 token·인증 header 검출 건수가 0건이다.

## 전제와 제외 범위

- 기존 OpenAPI Staff 로그인 계약과 생성 클라이언트를 단일 진실 공급원으로 사용한다.
- Staff 로그인 응답에는 access token만 있고 refresh token과 만료 시간 정보는 없다.
- access token 자동 갱신, 만료·401 전역 처리와 로그인 이동은 후속 범위다.
- 관리자 경로 접근 가드, 로그아웃 UI와 사용자별 Query 캐시 정리는 후속 범위다.
- 로그인 화면 디자인, 관리자 셸, 회원 인증 계약과 서버 API 명세는 변경하지 않는다.
- 기존 `specs/007-admin-login`은 모의 로그인 구현 당시 기록으로 유지하고 이 명세가 실제 인증 전환을
  추가한다.
