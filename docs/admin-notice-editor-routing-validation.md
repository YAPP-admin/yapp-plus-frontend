# 관리자 라우팅 PR 8 검증

- 확인일: 2026-10-12. 관련 이슈: [#57](https://github.com/YAPP-admin/yapp-plus-frontend/issues/57).
- 기준 커밋: PR 7 `e3a2229`. 브랜치: `DongjaJ/admin-notice-editor-routing`.
- 범위: `/notices/new`, `/notices/:noticeId/edit`, 작성·수정 진입과 복귀 링크.
- 편집기·첨부·미리보기·저장·API·인증·공지 존재 여부 조회는 포함하지 않는다.

## 경로와 탐색

- 목록에서 작성, 상세에서 해당 공지 ID의 수정 화면으로 이동하며 이전 쿼리는 전달하지 않는다.
- 작성·수정 화면은 공통 셸 아래 독립 화면이다. 목록 필터·상세 탭을 중첩하지 않는다.
- 작성 복귀는 기본 목록, 수정 복귀는 해당 공지의 기본 읽음 탭으로 이동한다.
- 뒤로가기·앞으로가기는 이전 목록 필터와 상세 탭을 복원한다.
- `new`는 정적 작성 경로로 예약하며 동적 공지 ID보다 우선한다.
- 작성·수정에서도 공지 메뉴가 현재 영역으로 표시된다.
- 준비 중 안내와 링크만 제공하며 effect·이벤트 구독·새 의존성은 추가하지 않았다.
- 라우트 트리는 Vite로 생성했다.

## 검증 결과

- `mise exec -- node --run check`: 포맷·lint·타입 검사·전체 테스트 통과.
- `mise exec -- node --run build`: 전체 빌드 통과.
- 관리자 테스트 10개 파일, 156개 통과. PR 7 대비 8개 추가.
- 직접 접근·독립 화면·정적 경로 우선, 이동 시 쿼리 제거·history 복원·기본 화면 복귀,
  키보드 진입·복귀, 알 수 없는 하위 경로 404를 검증했다.
- 기존 공지 메뉴 키보드 테스트는 새 작성 링크를 포함하도록 갱신했다.
- 프로덕션 작성·수정 URL은 HTTP 200과 예상 문서 제목을 반환했다.
- `/notices/new/missing`, `/notices/notice-123/edit/missing`은 HTTP 404를 반환했다.
- Chrome에서 작성·수정 진입·새로고침·뒤로가기 상태 복원과 수정 화면 키보드 복귀를 확인했다.
- 수정 화면 375px, 작성 화면 1280px에서 가로 넘침이 없으며 복귀 링크 높이 44px·포커스 테두리 2px를 확인했다.
