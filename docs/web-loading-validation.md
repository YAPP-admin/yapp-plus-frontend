# 회원 웹 조회 로딩 점검

1단계 관련 이슈: [#652](https://github.com/YAPP-admin/yapp-plus-frontend/issues/652). 1단계는 마이페이지의 조회·이미지 로딩을 변경했다.
2단계는 사용자 지시에 따라 새 이슈 없이 홈·기존 목록 로딩을 보완했다.
안드로이드 비교 기준은 `develop@8cbf4b8`이며, 웹의 표현은 [SEED Loading](https://seed-design.io/patterns/loading)을 따른다.

## 확정한 정책

- 콘텐츠가 없는 최초 조회는 Suspense fallback으로 스켈레톤을 표시한다. 별도 지연·최소 표시 타이머 없이 React의 전환 동작을 따른다.
- 수동 재시도는 기존 LocalErrorBoundary의 Query 오류 초기화에 맡긴다. 데이터가 없으면 Suspense 스켈레톤을 표시하고, 캐시가 있으면 이전 콘텐츠를 보여주며 재조회한다. 별도의 재시도 UI 상태를 관리하지 않는다.
- 일반 백그라운드 재조회는 기존 콘텐츠를 유지한다. 실패·인증 위임은 기존 오류 경계 정책을 따른다.
- 추가 페이지·제출·인증의 진행 표시는 유지한다. 조건부 보조 조회는 결과가 있을 때만 표시한다.
- 이미지 다운로드 중에는 SEED Avatar fallback으로 즉시 스켈레톤을 표시한다.

## 1단계 검증 기준

- 조회·이미지 스켈레톤을 별도 타이머 없이 표시하는지 검증한다. React 내부의 전환 시간은 테스트하지 않는다.
- 프로필·점수의 독립 조회, 일반 재조회 유지와 실패 뒤 복구는 마이페이지 테스트에서 검증한다.
- 이미지 load·error·주소 변경은 이미지 컴포넌트 테스트에서 검증한다.
- 브라우저 화면과 실제 WebView 검증을 구분하며, 미실행 항목을 완료로 표시하지 않는다.

## 1단계 확인 결과

- 이미지 2건, 마이페이지 21건이 통과했다. 초기 오류와 캐시가 있는 오류의 수동 재시도를 각각 검증했다.
- Chromium의 390×844 모바일 화면에서 조회 대기·완료·이미지 다운로드 대기·이미지 실패를 확인했다. 프로필 공간은 66px이고 가로 넘침이 없었다.
- 이미지 다운로드 중에도 프로필 텍스트를 표시하고, 실패 시 SEED 사람 placeholder로 전환했다. 다크 모드에서도 확인했다.
- 로딩 중 출석 규칙 버튼과 메뉴가 유지됐다. reduced motion에서는 스켈레톤의 shimmer를 제거했다.
- 실제 Android/iOS WebView와 VoiceOver/TalkBack 검증은 아직 수행하지 않았다.

## 2단계 적용 및 확인 결과

- 홈 이번 주 공지의 텍스트 로딩을 배지·제목이 있는 카드 스켈레톤으로 교체했다.
- 홈 세션·팀 사진, 일정·공지 목록·알림·출석 내역의 조회 로딩은 이름이 있는 section과 aria-busy로 표현하고 장식 윤곽은 접근성 트리에서 숨겼다.
- 홈·공지 목록·알림·출석 내역과 마이페이지가 같은 모션 감소 CSS를 사용한다. 일정의 기존 정적 스켈레톤은 유지했다.
- 데이터가 없을 때의 Suspense와 캐시가 있을 때의 기존 콘텐츠 표시, 추가 페이지 진행·오류 처리와 조건부 보조 조회는 유지했다.
- node --run check 통과: 웹 린트·타입 검사·85개 파일 751개 테스트는 새로 실행했다. 다른 패키지의 린트·타입 검사 6개씩, 테스트 4개는 Turbo 캐시를 재사용했다.
- node --run build 통과: 웹 빌드는 새로 실행하고 관리자·Storybook 빌드는 캐시를 재사용했다.
- Chromium 390×844에서 공지 대기 중 정상 세션·바로가기, 가로 넘침 없음, 가짜 공지 링크 없음, 다크 모드와 모션 감소, 키보드 진입 및 로딩 완료 후 터치 탐색을 확인했다.
- 실제 Android/iOS WebView와 VoiceOver/TalkBack은 미검증이다. 뒤풀이·알림 설정·공지 상세 Structured Activity·출석 시트는 후속 단계다.

## 3단계 적용 및 확인 결과

- 사용자 승인에 따라 새 이슈 없이 `DongjaJ/webview-loading-stage3`에서 작업했다. 검토 기준은 선행 브랜치 `DongjaJ/webview-v2`다.
- 뒤풀이 목록·상세의 스켈레톤을 분리했다. 상세 헤더·뒤로가기는 조회 경계 밖에 두어 로딩·오류·잘못된 ID에서도 유지한다.
- 알림 최초 조회는 52×28 컨트롤 공간에 스켈레톤을 표시한다. 캐시가 있는 재조회·저장 중에는 스위치를 유지하고 미지원·권한 관련 실패는 기존 상태로 수렴한다.
- Query·API·브리지의 조회·저장 계약은 변경하지 않았다. 반복 윤곽은 Array.from과 공통 모션 감소 CSS를 사용한다.
- 뒤풀이 지연 목록·상세·잘못된 ID와 설정 최초 대기·캐시 재조회·미지원·권한 오류 테스트를 확인했다.
- Chromium 390×844에서 뒤풀이와 설정의 로딩·완료·오류 화면을 확인했다. 설정은 화면 검증용 브리지 응답을 사용했으며 실제 네이티브 브리지 검증은 아니다.
- 직접 진입한 뒤풀이 상세의 뒤로가기는 커뮤니티 화면으로 복귀했다. 브라우저의 복귀 URL은 `/schedule/?initialTab=community`로 관찰됐으며 이 단계에서는 기존 탐색 경로 계약을 변경하지 않았다.
- 실제 Android/iOS WebView와 VoiceOver/TalkBack은 미검증이다. 공지 상세 Structured Activity와 출석 시트는 아직 후속 단계다.

- 3단계 최종 check·build 통과: 웹 린트·타입 검사·756개 테스트와 웹 빌드는 새로 실행했다. 다른 패키지는 Turbo 캐시를 재사용했다.

## 4단계 적용 및 확인 결과

- 새 이슈 없이 같은 후속 브랜치에서 공지 상세만 Structured Activity로 전환했다. 설치된 Stackflow 버전은 유지했다.
- Activity가 레이아웃·Suspense·오류 경계를 소유하고, 페이지 공개 로더로 상세 본문을 별도 청크로 불러온다. 페이지 내부의 중복 경계를 제거했다.
- Query 오류 재설정과 401의 상위 인증 경계 위임은 LocalErrorBoundary를 통해 유지한다. 읽음 저장·분류명·URL 매개변수 계약은 변경하지 않았다.
- 상세 조회 중 제목·메타 정보·본문 스켈레톤을 표시한다. 로딩·오류·잘못된 ID에서도 기본 헤더와 뒤로가기를 제공한다.
- 첨부 이미지는 SEED ImageFrame의 로딩 상태와 CSS 클래스로 스켈레톤·실패 안내를 구분한다. 기존 4:5 비율·서버 순서·대체 텍스트와 URL 변경 시 초기화를 유지한다.
- Chromium 390×844에서 데이터 지연·이미지 지연·성공·실패·오류 재시도와 키보드 뒤로가기 진입·터치 복귀를 확인했다. 이미지 프레임은 308×385px이며 가로 넘침이 없었다.
- 청크를 지연한 목록 → 상세 탐색은 기존 목록에서 기다린 뒤 상세로 전환했다. 데이터 지연 스켈레톤과 구분했으며, 다크 모드·모션 감소 시 shimmer 제거도 확인했다.
- 상세 직접 진입 후 뒤로가기는 게시판 화면을 복원했다. URL은 기존 탭 복원 방식에 따라 `/schedule/?initialTab=notices`로 관찰됐으며 이 단계에서 탐색 계약을 바꾸지 않았다.
- 실제 Android/iOS WebView와 VoiceOver/TalkBack은 미검증이다. 출석 코드·보고 시트와 팀원 선택은 5단계 리뷰 대상으로 남아 있다.
- 4단계 최종 check·build 통과: 웹 린트·타입 검사·85개 파일 760개 테스트와 웹 빌드를 새로 실행했다. 다른 패키지의 린트·타입 검사 6개씩, 테스트 4개와 관리자·Storybook 빌드 2개는 Turbo 캐시를 재사용했다. 기존 500kB 초과 청크 경고는 남아 있다.
