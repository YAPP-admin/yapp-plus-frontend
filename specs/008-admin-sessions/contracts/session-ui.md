# 세션 UI와 URL 계약

## 라우트와 공개 진입점

- 기존 `/sessions`를 유지한다. 검색값은 `type=offline|team`이며 전체는 생략한다.
- `type` 누락·잘못된 값과 예전 `part`만 있는 URL은 전체로 해석한다.
- `type`과 `part`가 함께 있으면 유효한 type만 사용한다. 필터 탐색 시 type만 기록한다.
- 초기 방문 시 강제 redirect를 추가하지 않는다. 필터 변경은 history에 기록하고 스크롤을 리셋하지 않는다.
- 페이지는 type과 필터 변경 콜백을 받는다. 내부 데이터 함수는 라우트에서 직접 호출하지 않는다.
- 카드 본문은 `/attendance/$sessionId`로 이동한다. 출석 화면 내용은 이번 작업에서 변경하지 않는다.

## 상호작용

- 생성 버튼은 목록과 전체 빈 상태에서 제공한다. 필터 빈 상태에서는 전체 보기와 기존 생성 버튼을 이용한다.
- 메뉴에는 연결이 완료된 작업만 노출한다. 수정·삭제 기능은 각각 구현 단계에서 활성화한다.
- 모달 열기는 해당 트리거를 기억한다. 생성은 명시적인 label이 있는 필드와 저장·취소 버튼을 제공한다.
- Enter는 폼을 제출한다. 첫 제출 전 오류를 노출하지 않고 이후 입력 변경 시 재검증한다.
- 생성·수정·삭제 실패는 모달 안에서 안내한다. 성공은 화면의 live region으로 알린다.
- 삭제 확인 문구는 세션명을 표시하고 관련 출석 기록도 삭제된다는 정책을 안내하되 실제 연동은 후속 범위다.
- 이미 사라진 id에 대한 작업은 성공을 가장하지 않고 오류와 목록 새로고침 경로를 제공한다.
- 프로덕션에서는 준비 중 안내만 제공하고 모의 데이터·편집 버튼을 노출하지 않는다.

## 수정 폼

- 메뉴 이름은 `세션 정보`를 유지하고 폼 제목은 `세션 수정`, 제출 버튼은 `저장`으로 표시한다.
- 열 때 마지막 저장값으로 초기화하고 편집 중인 값은 목록 캐시와 분리한다. 다른 세션을 열면 이전 편집값을 재사용하지 않는다.
- 생성과 같은 검증·제출 중 잠금·실패 입력 보존을 적용한다. 취소 시 저장하지 않고 별도 폐기 확인창 없이 닫는다.
- 수정 성공 시 현재 필터를 유지한다. 유형·날짜 변경을 필터와 정렬에 반영하고 id·출석 집계는 보존한다.
- 수정 대상이 사라졌다면 오류를 안내하고 목록을 새로고침할 수 있게 한다. 임의로 생성하지 않는다.
- 저장에 성공한 뒤 실행한 카드가 필터에서 사라졌다면 남은 카드 또는 목록 제목으로 포커스를 이동한다.
- 수정 시 알림 발송이나 출석 재계산을 수행하지 않는다.

## 테스트 경계

페이지 테스트는 service 모듈을 대체하여 지연·실패·빈 결과를 재현한다.
서비스 자체 테스트는 독립 저장소로 생성·조회·수정·삭제·복사본 분리를 검증한다.
UI에서 새로운 테스트 전용 URL, debug 전역 변수 또는 mock 제어 패널은 제공하지 않는다.
