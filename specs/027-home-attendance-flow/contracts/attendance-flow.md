# 홈·출석 흐름 계약

## 홈 상태 표

세션이 없으면 출석 진입을 만들지 않는다. 세션이 있을 때만 `location === null`을 팀으로 판별한다.
아래 버튼은 최초 조회·재조회·paused·오류 중에는 모두 비활성화한다. 오류 시 이전 카드와 재시도 안내를 함께 표시한다.

| 서버 상태          | 표시 문구                                 | 정규 행동 | 팀 행동                |
| ------------------ | ----------------------------------------- | --------- | ---------------------- |
| `AVAILABLE`        | 정규: 출석하기 / 팀: 인증 사진 업로드하기 | 코드 화면 | 운영 준비 후 안내 화면 |
| `NOT_OPEN`         | 아직 출석할 수 없어요                     | 비활성화  | 비활성화               |
| `NOT_ELIGIBLE`     | 출석 대상이 아니에요                      | 비활성화  | 비활성화               |
| `PENDING_APPROVAL` | 출석 확인 중이에요                        | 비활성화  | 비활성화               |
| `CHECKED_IN`       | 출석했어요!                               | 비활성화  | 비활성화               |

팀 운영 준비 전 `AVAILABLE`의 버튼은 비활성화하고 “팀 출석 기능을 준비 중이에요”를 추가한다.
시간이 지나도 상태를 로컬에서 변경하지 않는다. 체크인 기록은 종료 후에도 서버 응답에 따라 유지한다.

## 현재 제공된 API와 경계

- `GET /api/sessions/current-week`: 본인 주간 세션·출석 상태 조회. 기존 생성 클라이언트와 Query key를 유지한다.
- `POST /api/sessions/{sessionId}/team-attendance-photos/presign`: 기존 사진 업로드 준비 계약.
- 서명된 저장소 URL 업로드: 기존 signed headers만 사용하며 앱 인증 헤더를 덧붙이지 않는다.
- `POST /api/sessions/{sessionId}/team-attendance-photos`: 사진·참석자 제출. 기존 성공 응답을 검증해 접수 결과로 사용한다.
- 관리자 팀 사진 조회의 `readUrl`은 회원용 조회 계약이 아니다. 이번 범위에서 사진 다시 보기용으로 사용하지 않는다.

## 회원용 대상 조회 계약 확인표 — 3단계 진입 조건

HTTP 경로·응답 필드는 현재 미확정이다. 아래 조건을 실제 OpenAPI와 응답으로 확인하고 문서를 갱신한다.

- [ ] 회원 토큰으로 현재 세션의 본인 팀과 참석 가능한 팀원을 조회할 수 있는 경로·권한.
- [ ] 본인의 현재 기수 멤버십 ID와 팀원별 멤버십 ID를 구분해 받을 수 있음.
- [ ] 팀 이름·팀원 이름·직군 표시의 출처 및 null/누락 처리 정책.
- [ ] 본인이 목록에 정확히 한 번 포함되고 중복·다른 세션/계정 데이터는 거절할 수 있음.
- [ ] 팀 없음·권한 없음·소속 변경·조회 실패 시 진입 차단 및 사용자 안내 정책.
- [ ] 제출 API에 전달하는 참석자 ID와 조회 계약 ID의 의미가 같음.

질문은 실제 누락·불일치 항목별로 사용자에게 확인한다. API 경로, 관리자 권한 대체, 임의 멤버십 ID를 만들어 진행하지 않는다.

## 백엔드 요청 초안 — 발송 상태와 구분

`current-week.session`에 `type: REGULAR | TEAM`과 종료 시간 `endTime` 제공을 요청한다.
`type`은 사용자에게 요청 완료 사실을 전달받았으며 응답 반영은 아직 확인하지 못했다.
`endTime`의 형식·nullable 여부·시간대, 기존 `date`·`startTime`과의 관계도 함께 확인해야 한다.
회원용 대상 조회는 위 확인표를 만족하는 계약이 필요하다. 이 문서 작성만으로 외부 요청을 발송하지 않는다.

필드 도착 후 원본 OpenAPI를 갱신하고 생성 클라이언트를 재생성한다. 실제 응답 배포를 확인한 뒤
장소 판별을 `type`으로 교체한다. 종료 시간이 없을 때는 “출석 가능한 시간 안에 올려주세요”를 유지한다.
종료 시간은 안내용이며 출석 허용 여부는 계속 `attendanceStatus`를 따른다.

## 내비게이션·수명·조회

- 홈 재진입·앱 포그라운드 복귀는 캐시 나이와 무관하게 주간 재조회한다. 계속 머무는 동안 폴링하지 않는다.
- 정규 제출 성공은 기존 완료 화면을 즉시 연다. 과거 성공 기록과 현재 제출 중복 방지는 분리한다.
- 팀 안내·업로드·완료는 한 흐름 안에서 사진을 소유한다. 기존 `/team-attendance/guide`, `/team-attendance/upload`, `/team-attendance/complete` URL을 보존한다.
- 업로드는 유효한 대상·사진 없이, 완료는 접수 결과 없이 진행할 수 없다. 기존 직접 진입 방어를 유지한다.
- 초기 선택 취소는 안내로, 사진 교체 취소·실패는 기존 사진·참석자로 복귀한다.
- 안내 문구는 “선택한 참석 팀원의 출석을 운영진이 확인해요”로 정리한다. 팀 전체 일괄 반영으로 안내하지 않는다.
- 제출 성공은 주간 Query 무효화로 연결한다. 접수 결과는 영구 보관하지 않고 승인 팝업도 띄우지 않는다.
- 최종 제출 응답이 유실되면 자동 재전송하지 않는다. 홈 상태 확인을 안내하고 서버 결과를 기다린다.

## 실패 시 복구

조회 실패는 재시도할 수 있지만 이전 `AVAILABLE`만으로 새 제출을 시작하지 않는다.
팀 연결 배포에 문제가 있으면 홈의 팀 진입을 준비 중으로 되돌린다. 이미 접수된 데이터에는 손대지 않는다.
계약 변경과 소비 코드는 함께 되돌릴 수 있게 변경 단위를 유지한다.
