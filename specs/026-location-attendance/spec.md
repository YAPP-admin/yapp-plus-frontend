# 기능 명세: 위치 조건을 만족한 회원만 코드 출석 제출

**브랜치**: `DongjaJ/akax9-stage3` · **작성일**: 2026-11-18 · **상태**: 5단계 통합 검증 진행 중
**입력**: 세션 장소에서 100m 밖이거나 위치를 확인할 수 없으면 제출을 차단한다.
정확한 위치 권한과 측정 오차 50m 이하를 요구하며 이번 출시 적용 범위는 iOS다.
작업 기준은 [GitHub #478](https://github.com/YAPP-admin/yapp-plus-frontend/issues/478)이며,
Android 적용은 이번 기능의 출시 범위에 포함하지 않는다.

## 사용자 시나리오와 검증

### US1 — 현장에서 위치 확인 후 출석한다 (P1)

회원이 출석 가능한 세션에서 코드 네 자리를 입력하고 확인을 누르면 현재 위치를 확인한 뒤 제출한다.
핵심 출석 흐름이므로 최우선이다. 독립 검증은 동일 세션의 거리·오차를 바꿔 제출 여부를 관찰한다.

1. 화면 진입·코드 입력만으로 위치 권한을 요청하거나 위치를 측정하지 않는다.
2. 정확한 위치 권한, 알려진 측정 오차 50m 이하, 세션까지 거리 100m 이하를 모두 만족하면 제출한다.
3. 거리 100m 초과, 오차 50m 초과·미확인, 정밀 권한 부족이면 제출하지 않는다.
4. 세션 좌표가 없거나 잘못됐으면 제출하지 않고 세션 재확인·운영진 문의를 안내한다.
5. 위치 확인 성공만으로 출석 완료를 표시하지 않으며 서버가 성공을 확인해야 완료한다.

### US2 — 위치 확인 실패에서 복구한다 (P2)

회원이 실패 원인에 맞게 설정 변경·이동·재시도를 할 수 있어야 현장 출석을 마칠 수 있다.
독립 검증은 실패를 주입하고 안내된 행동 뒤 사용자의 재제출로 복구하는 것이다.

1. 권한 거부·정확한 위치 미허용·서비스 꺼짐·시간 초과·취득 실패를 구분해 안내한다.
2. 권한 재요청이 불가능하거나 정밀 권한이 부족하면 앱 설정을 열 수 있다. 설정 실행 실패도 안내한다.
3. 실패해도 코드를 유지한다. 설정 복귀·통신 복구만으로 재측정하거나 제출하지 않는다.
4. 재시도하면 새 위치를 확인한다. 반복 실패에도 코드만 제출하는 우회를 제공하지 않고 운영진 처리를 안내한다.
5. 사용자는 키보드·스크린 리더·터치로 입력, 진행 상태 확인, 오류 복구를 할 수 있다.

### US3 — 중단된 시도가 다른 계정에 반영되지 않는다 (P1)

대기 중 계정이 달라져도 의도하지 않은 출석 제출을 막는다.
독립 검증은 위치 응답을 지연시킨 상태에서 계정 변경과 중복 클릭을 재현하는 것이다.

1. 위치 확인부터 서버 처리까지 중복 제출·입력 변경·시트 닫기를 막는다.
2. 로그아웃·계정 변경 후 도착한 위치로는 제출하지 않는다.
3. 이미 서버에 보낸 요청을 취소됐다고 표시하지 않는다.
4. 일반 브라우저·위치 미지원 앱에서도 위치 검사를 건너뛰어 제출하지 않는다.

### 경계 사례

- 정확히 100m·50m, 0인 좌표·오차, 한쪽 좌표만 누락, 유한하지 않은 값, 계산 실패.
- 권한 선택 대기, 권한 팝업의 일시적 비활성, 앱 백그라운드, 시간 초과 뒤 늦은 응답.
- 측정 중 오프라인 전환, 서버의 세션 변경 거절, 서버 응답 유실.
- 앱 재시작 후 기존 성공 기억 소실. 이 작업에서 새로운 완료 조회 기능을 추정해 만들지 않는다.

## 요구사항

- **FR-001**: 유효한 코드 제출 의사 표시가 있을 때만 위치 확인을 시작한다. (US1)
- **FR-002**: 정확한 위치 권한·오차 50m 이하·거리 100m 이하를 모두 만족해야 제출한다. 오차를 허용 반경에 더하지 않는다. (US1)
- **FR-003**: 세션 위치나 사용자 위치를 확인할 수 없으면 제출을 차단한다. (US1·US2)
- **FR-004**: 실패 원인과 복구 행동을 안내하고 입력 코드를 유지한다. (US2)
- **FR-005**: 재시도는 사용자 동작으로만 시작하며 이전 위치를 재사용하지 않는다. (US2)
- **FR-006**: 중복·계정 변경으로 의도하지 않은 제출이 발생하지 않는다. (US3)
- **FR-007**: 사용자 위치는 이번 판정에만 사용하고 서버·로그·영구 저장소·공유 캐시에 남기지 않는다. (US1·US3)
- **FR-008**: 지원 환경과 기존 로그인·출석 가능 조건을 통과해야 하며 서버 성공으로만 완료를 표시한다. (US1·US3)
- **FR-009**: 설정 열기, 진행·오류 안내, 재시도를 키보드·스크린 리더·터치로 사용할 수 있다. (US2)
- **FR-010**: 이번 출시 적용·검증 범위는 iOS로 제한하고 Android 동작을 완료로 보고하지 않는다. (US1)

### 주요 개체

- 출석 대상: 세션 식별자, 장소 좌표, 서버가 정한 출석 가능 상태.
- 위치 표본: 사용자 좌표, 측정 오차, 측정 시각, 정밀 권한 수준. 일시적으로만 사용한다.
- 제출 시도: 계정·세션에 묶인 코드 확인 행동과 진행 단계, 복구 가능한 실패 사유.
- 출석 확인: 서버가 확인한 성공 결과. 위치 조건 통과와 구분한다.

## 성공 기준

- **SC-001**: 경계·오류 수용 사례에서 위치 조건 미충족 시 코드 전송이 0회, 충족 시 시도당 1회다.
- **SC-002**: 계정 변경 뒤 지연 위치로 새 제출이 발생하는 사례가 0건이다.
- **SC-003**: 각 복구 시나리오에서 코드가 유지되고 사용자 재시도 전 자동 전송이 0회다.
- **SC-004**: 위치 원문이 출석 HTTP 요청·캐시·로그·영구 저장소에 남는 사례가 0건이다.
- **SC-005**: 실기기에서 정상 출석과 오류 복구를 확인하고, 실제 장소의 반복 실패·접근성 미검증을 출시 검토에 남긴다.

## 전제와 제외 범위

- 근거는 이번 대화의 사용자 결정, [제품 맥락](../../docs/mission.md), [기존 위치 명세](../018-native-location/spec.md), [코드 출석 명세](../020-member-attendance-submit/spec.md)다.
- 이 저장소와 이번 출시에서는 iOS 회원 웹만 구현·검증한다. Android 저장소 수정·메시지 전송·출시 판단은 제외한다.
- 위치를 서버에 전송·저장하거나 서버에서 검증하는 변경, 부정 출석 탐지, 지도·층수·경로 거리, 지속 추적은 제외한다.
- 운영진 처리는 기존 출석 관리 절차를 안내한다. 앱에 예외 승인·우회 버튼을 만들지 않는다.
- 팀 사진 출석·사전 출결 보고·출석 시간 계산·점수 정책은 변경하지 않는다.
- 앱 재시작 후 완료 상태 복원은 별도 조회 계약 확인 항목이다. 기존 완료 표시 수명을 유지한다.
- 측정 오차는 추정값이며 실제 위치의 절대 보장이 아니다. 현장 실패를 이유로 기준을 임의 완화하지 않는다.
