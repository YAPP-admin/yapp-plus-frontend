# 검증 가이드

이 문서는 후속 구현의 검증 절차다. 현재 0단계에는 출석 화면 기능이 구현되지 않았으며
아래 시나리오의 통과를 주장하지 않는다. 현재 실행 결과는 [검증 기록](validation.md)을 참조한다.

## 환경과 명령

저장소의 mise·pnpm 고정 버전과 설치된 의존성을 사용한다.

```sh
mise exec -- node --run check
mise exec -- node --run build
mise exec -- pnpm --filter @yapp-plus/admin test
mise exec -- node --run dev:admin
```

`dev:admin`은 기존 Doppler 설정이 필요하다. 실서버에 출결 변경을 요청하지 않도록 모의 서비스 경계를 먼저 확인한다.
문서만 변경한 0단계에는 build와 화면 구동을 요구하지 않는다. 앱 변경 단계부터 build를 수행한다.

## 모의 데이터 준비

일반/팀 세션, 열린/마감 세션, 여러 파트와 페이지에 걸친 회원을 준비한다.
미정·출석·각 시간 구간의 지각/조퇴·일반/무단 결석, 명찰 확인 전후를 포함한다.
적격/부적격/근거 불명 보고, 미제출/대기/승인/반려 사진, 사진 접근 실패, 39/40점 회원을 준비한다.
자료는 가상 이름과 테스트 이미지로 구성하며 실제 회원 개인정보를 fixture에 넣지 않는다.

## 확인 시나리오

| 항목           | 조작과 기대 결과                                                    |
| -------------- | ------------------------------------------------------------------- |
| 세션 생성      | 코드를 발급하지 않고 새 세션 출석 명단 조회 가능                    |
| 보고 분리      | 지각 보고 회원을 출석으로 바꿔도 보고 이력 유지                     |
| 명찰 독립      | 확인/해제 전후 출결·감점 동일                                       |
| 구간 경계      | 1시간 이내 -4/-10, 1시간 초과 3시간 이내 -8/-14                     |
| 전체 마감      | 파트 필터·페이지 밖 미정도 결석; 적격 결석 보고 -12, 그 외 -20      |
| 개인 수정 보존 | 팀 승인 후 명시적 지각·결석 유지                                    |
| 부분 실패      | 판단/출결/명찰 일부 실패 시 마감하지 않고 실패 항목 재시도          |
| 마감 실패      | 변경 반영 성공 뒤 close 실패는 마감만 재시도                        |
| 응답 유실      | 조회로 실제 마감 상태 확인 후 재시도 판단                           |
| 마감 취소      | 모의 정책에서 결과·점수 보존, 편집 재개; 서버 차이는 계약 문서 확인 |
| 사진 상태      | URL 실패도 제출·대기 유지, 미제출과 구분                            |
| 동시 제출      | 마감 중 새 대기 발생 시 실패 및 최신 목록 재검수                    |
| 점수 경고      | 39점 경고, 40점 정상; 결석 횟수만으로 추가 경고하지 않음            |
| 초안 이탈      | 화면 이동 경고, 계속 편집 시 초안 유지, 버리기 시 폐기              |
| 코드           | 조회로 자동 발급하지 않음; 명시적 발급·재발급·실패 확인             |

## UI 단계의 확인 자료

키보드 표 탐색, 메뉴·Dialog 포커스 복귀, 스크린 리더 이름·오류 알림, 터치 조작을 확인한다.
화면 폭에 따른 표 가독성과 Dialog 동작을 확인하고 재사용 UI 변경에는 관련 Storybook 사례를 갱신한다.
단계별 화면 자료는 `.context/`에 저장하고 리뷰 보고에 첨부한다.
