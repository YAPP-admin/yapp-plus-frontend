# 기능 명세: 관리자 공지 관리와 모의 동작

**작업 브랜치**: `DongjaJ/term-specification-review`
**작성일**: 2026-10-19
**상태**: 1단계 리뷰 반영 완료 — 2단계 설계 진행
**입력**: 공지 목록·작성·수정·삭제·읽음 현황을 구현하고 단계마다 사용자 리뷰를 받는다.

## 사용자 시나리오와 검증

### US1 — 공지 목록과 종류 필터 (P1)

운영진이 전달한 공지와 확인 현황을 조회하고 종류별로 찾는다.
우선순위 근거: 작성·상세·수정·삭제로 진입하는 출발점이다.
독립 검증: 세 종류의 예시 공지가 있는 목록에서 필터·주소·브라우저 이력을 확인한다.

1. 전체·세션·제출·운영 중 하나를 선택하면 작성일 최신순의 1열 목록과 결과 개수를 표시한다.
2. 상단 게시 개수는 전체 공지 수이며 필터 아래 개수는 현재 결과 수다. 페이지 구분 없이 전체 결과를 스크롤한다.
3. 카드에 종류·제목·작성일·대상·읽음 수/대상 수·읽음 비율·미답변 질문 수를 표시한다.
4. 제출 공지는 한국 시간 기준 D-N·D-day·마감 배지를 표시한다. 같은 날에도 마감 시각에 도달하면 마감이다.
5. 제목을 누르면 해당 공지의 읽음 현황으로 이동하고 케밥 메뉴에서 수정·삭제에 진입한다.
6. 필터는 주소에 반영되고 직접 접근·새로고침·뒤로가기·앞으로가기로 복원된다. 누락되거나 잘못된 값은 전체로 처리한다.
7. 전체 공지 없음과 필터 결과 없음을 구분한다. 조회 중 상태와 조회 실패 안내·재시도를 제공한다.

### US2 — 일반·제출 공지 작성 (P1)

운영진이 대상을 지정하고 서식을 보면서 내용을 작성한다.
우선순위 근거: 공지를 전달하기 위한 핵심 관리 행동이다.
독립 검증: 일반 대상 네 가지와 제출 직군 조합으로 작성하고 저장 결과를 확인한다.

1. 새 작성 화면은 세션·전체 사용자로 시작하며 제목·본문·첨부는 비어 있다.
2. 세션·운영 공지의 대상은 전체 사용자·활동회원·정회원·수료회원 중 하나다. 정회원과 수료회원을 합치지 않는다.
3. 제출 공지는 활동회원 안에서 전체·PM·Design·Mobile·Web·Server·AI Native를 선택한다. 전체와 개별 직군은 배타적이고 개별 직군은 복수 선택할 수 있다.
4. 제출 종류로 전환하면 대상 기본값은 활동회원 전체이며 마감은 비어 있다. 대상은 하나 이상, 마감 날짜·시간은 필수이며 과거 마감도 허용한다.
5. 제출 방법은 선택이다. 이름 또는 URL을 입력하면 둘 다 필요하다. 사용자 결정에 따라 URL 형식·프로토콜은 별도로 검사하지 않는다.
6. 제목은 앞뒤 공백 제거 후 1~60자다. 본문은 공백·빈 문단만으로 저장할 수 없다. 본문 길이에 추가 제한은 두지 않는다.
7. 문단·줄바꿈·제목 H1~H6·굵게·링크·글머리/번호 목록·인라인 코드·코드 블록·인용문·구분선·기울임·취소선·밑줄을 편집 영역에서 서식으로 보여준다.
8. 툴바로 서식을 적용하고 선택 상태를 확인한다. 지원 문법의 입력 단축 동작, 한글 조합, 실행 취소·다시 실행을 제공한다.
9. 본문은 JSON으로 저장하고 다시 열어도 내용·서식·링크 의미를 유지한다. 본문 스키마 버전을 함께 저장한다. 글자 수는 편집 문서의 텍스트 기준이다.
10. 붙여넣기는 지원 서식만 유지한다. 이미지 붙여넣기·드롭으로 첨부 제한을 우회하거나 본문 안에 이미지를 삽입할 수 없다.
11. 종류 변경 후 저장할 때 해당 종류에 불필요한 입력은 제외한다. 일반 공지에 제출 마감·직군·제출 방법을 저장하지 않는다.
12. 저장 중 진행 상태를 표시하고 중복 제출을 막는다. 실패 시 입력을 유지하며 오류·재시도를 제공한다. 성공 시 새 공지를 목록에 반영하고 해당 공지의 읽음 현황으로 이동한다.

### US3 — 이미지 첨부와 수정 취소 (P1)

운영진이 본문 하단에 안내 이미지를 첨부하고 저장 전에 확인한다.
우선순위 근거: 요청한 작성·수정 화면의 필수 기능이며 잘못된 파일과 초과 선택을 막아야 한다.
독립 검증: 빈 폼과 기존 첨부가 있는 수정 폼에서 선택·제거·저장·취소한다.

1. JPG·PNG·WebP 이미지를 파일당 최대 10MB, 기존 첨부와 신규 첨부를 합쳐 최대 5개까지 허용한다.
2. 선택 순서로 본문과 분리된 하단 영역에 미리보기·파일명·제거 동작을 제공한다. 순서 변경은 제공하지 않는다.
3. 선택 묶음을 추가하면 5개를 초과하는 경우 해당 묶음 전체를 반영하지 않고 남은 개수를 안내한다.
4. 개수 제한 안에서 형식·크기·이미지 읽기 검증에 실패한 파일은 제외하고 파일별 오류를 표시한다. 정상 파일은 유지한다.
5. 5개가 되면 추가 버튼을 비활성화하고 제거하면 다시 활성화한다. 파일 선택을 취소하면 기존 선택은 바뀌지 않는다.
6. 수정 중 기존 이미지를 제거해도 저장 전에는 원본 첨부를 변경하지 않는다. 수정 취소 후 다시 열면 마지막 저장 상태를 복원한다.
7. 저장된 첨부는 화면 이동 후에도 유지된다. 저장 실패 시 선택한 첨부와 제거한 상태를 편집 화면에 보존한다.

### US4 — 읽음 현황과 대상 변경 (P1)

운영진이 공지 확인 여부와 아직 읽지 않은 회원을 파악한다.
우선순위 근거: 공지 전달 상태를 확인하는 핵심 관리 정보다.
독립 검증: 읽음·미열람이 섞인 공지와 대상 0명인 공지를 조회하고 노출 대상을 수정한다.

1. 상세에 종류·대상·작성일·제목, 수정 진입점, 읽음 수·미열람 수·읽음 비율을 표시한다.
2. 대상 회원 전원의 이름·기수·직군·읽음 여부·확인 시각을 스크롤로 확인한다. 8명으로 제한하지 않는다.
3. 기본 정렬은 읽은 회원의 확인 시각 내림차순, 그 뒤 미열람 회원의 이름순이며 동률은 회원 ID순이다. 이름·기수·직군·읽음 여부·확인 시각 헤더를 선택하면 해당 컬럼 기준으로 클라이언트 정렬한다. 정렬을 해제하면 기본 순서로 돌아간다. 미열람 확인 시각은 대시로 표시한다.
4. 새 공지의 대상은 모두 미열람이다. 대상 0명일 때 읽음 수·미열람 수·비율은 0이며 대상 없음 안내를 제공한다.
5. 대상 수정 시 계속 포함되는 회원의 읽음 기록을 유지하고 새 대상은 미열람으로 추가하며 제외 대상은 현재 집계에서 뺀다.
6. 제목·본문만 수정하면 읽음 기록을 초기화하지 않는다. 목록·상세의 대상 수와 읽음 집계는 동일해야 한다.
7. 없는 공지·삭제된 공지는 찾을 수 없음 안내와 목록 복귀를 제공한다. 조회 실패와 혼동하지 않는다.
8. 질문 수는 예시 값으로 표시하고 질문 탭은 준비 중 안내를 유지한다. 질문 답변·미열람자 알림 발송은 제공하지 않는다.

### US5 — 수정·삭제·미저장 이탈 (P2)

운영진이 기존 공지를 변경하거나 제거하고 실수로 입력을 잃지 않는다.
우선순위 근거: 목록·작성 기반 이후 필요한 관리 흐름이다.
독립 검증: 예시 공지를 수정·취소·삭제하고 요청 실패와 이탈 취소를 확인한다.

1. 수정 시 마지막 저장값과 첨부를 복원하고 작성과 같은 검증을 적용한다. 일반 대상과 제출 직군도 수정할 수 있다.
2. 수정 성공 시 같은 공지를 갱신하고 해당 공지의 읽음 현황으로 이동한다. 작성일은 유지한다.
3. 저장 실패 시 수정 입력을 유지한다. 저장 중 중복 제출을 막으며 자동으로 화면을 떠나지 않는다.
4. 미저장 변경이 있으면 취소·앱 내 이동·뒤로가기에서 이탈을 확인한다. 이탈 취소 시 입력을 유지하고 이탈 확정 시 마지막 저장 상태를 보존한다.
5. 새로고침·탭 닫기는 브라우저가 지원하는 기본 이탈 경고를 사용한다. 자동 저장·작성 중 입력의 영속 보관은 하지 않는다.
6. 삭제 시 공지 제목을 포함한 확인 창을 표시한다. 취소하면 그대로 유지하고 진행 중에는 중복 삭제를 막는다.
7. 삭제 성공 시 현재 필터를 유지하며 목록·개수를 갱신한다. 실패 시 항목을 유지하고 오류·재시도를 제공한다.
8. 마지막 항목 삭제 시 해당 조건의 빈 상태를 표시한다. 실행 버튼이 사라지면 남은 카드 또는 목록 제목으로 포커스를 이동한다.

### US6 — 개발용 검증과 접근성 (P1)

운영진 관점에서 데스크톱과 좁은 화면의 전체 관리 흐름을 검증한다.
우선순위 근거: 모든 관리 동작에 접근할 수 있어야 하며 모의 동작을 실제 운영으로 오해하지 않아야 한다.
독립 검증: 개발 환경의 화면 이동·새로고침과 프로덕션 안내, 375px·데스크톱 조작을 확인한다.

1. 실제 운영 데이터가 아닌 개발용 예시임을 안내한다. 같은 브라우저 탭에서 화면 이동 후 변경을 유지하고 새로고침하면 초기화한다.
2. 프로덕션에서는 공지 관리 준비 중 안내를 제공하며 모의 조회·생성·수정·삭제를 실행하지 않는다.
3. 기존 관리자 메뉴·현재 위치 표시·공지 경로를 유지한다. 좁은 화면에서 메뉴·툴바·폼·표·확인 창에 접근할 수 있다.
4. 키보드·스크린 리더·터치로 주요 기능을 이용한다. 입력 레이블·오류·진행 상태와 포커스가 명확해야 한다.
5. 확인 창은 포커스를 내부에 유지하고 닫을 때 실행한 컨트롤로 돌린다. 긴 제목·본문과 낮은 화면에서도 주요 버튼을 사용할 수 있다.

### 경계 조건

- 제목 60자/61자, 공백 제목, 빈 문단만 있는 본문, 불완전한 마감·제출 방법은 US2 기준으로 검증한다.
- 마감 전날·당일 마감 전·정확한 마감 시각·마감 후와 한국 시간 자정 경계를 구분한다.
- JPG·PNG·WebP 각각의 선택·미리보기·저장을 확인한다. 이미지 0·1·5개, 한 번에 6개, 기존 4개에서 2개 추가, 제거 후 재추가, 10MB 경계·잘못된 형식·읽기 실패를 검증한다.
- 제목·굵게·중첩 목록·링크·줄바꿈·코드를 조합한 본문을 저장 후 재편집해 내용과 서식 손실을 확인한다.
- 조회·생성·수정·삭제 각각의 실패와 재시도, 중복 요청, 필터의 마지막 항목 삭제, 없는 공지 직접 접근을 검증한다.
- 읽음 현황은 실제 회원 앱의 읽음 처리 구현이 아니다. 예시 기록만 사용하며 최초 확인 기록을 기준으로 표시한다.

## 요구사항

### 기능 요구사항

- **FR-001**: US1의 목록·필터·정렬·집계·마감 배지·탐색과 상태 안내를 제공한다.
- **FR-002**: US2의 일반 대상 네 가지와 제출 대상·마감·제출 방법 검증을 적용한다.
- **FR-003**: US2의 서식 편집·JSON 저장·내용 보존과 작성 성공·실패 처리를 제공한다.
- **FR-004**: US3의 이미지 형식·크기·개수 제한, 미리보기·제거와 취소 시 원본 보존을 적용한다.
- **FR-005**: US4의 전체 대상 회원 표·읽음 집계·대상 변경과 없는 공지 처리를 제공한다.
- **FR-006**: US5의 수정·삭제·중복 요청 방지·실패 복구·미저장 이탈 확인을 제공한다.
- **FR-007**: US6의 개발용 데이터 수명·프로덕션 비활성화·반응형·접근성 조건을 충족한다.
- **FR-008**: 기존 공지 주소와 탐색 규칙을 유지한다. 명시적 목록 복귀는 전체 필터, 수정 취소 후 상세 복귀는 기본 읽음 탭이며 브라우저 뒤로가기는 이전 필터·탭을 복원한다.

### 주요 개념

- **공지**: 식별 정보·종류·대상·제목·서식 있는 본문·작성일·첨부·읽음 기록·예시 미답변 질문 수를 가진다.
- **제출 정보**: 활동회원 내 대상 직군·한국 시간 마감·선택적인 제출 방법 이름과 링크다.
- **노출 대상**: 일반 공지는 네 가지 대상 중 하나, 제출 공지는 활동회원 내 선택한 직군이다.
- **대상 회원**: 예시 명단의 식별 정보·이름·기수·직군·회원 구분으로 공지 대상 여부를 결정한다.
- **읽음 기록**: 공지와 대상 회원의 확인 여부·최초 확인 시각이다. 읽지 않은 회원은 확인 시각이 없다.
- **첨부 이미지**: 본문 하단에 별도로 표시하는 이미지와 파일명이며 작성·수정 입력과 함께 저장한다.

## 성공 기준

- **SC-001**: US1의 네 필터·최신순·개수·주소 복원·빈 상태·조회 실패 시나리오를 모두 확인한다.
- **SC-002**: 일반 대상 네 가지 및 제출 직군별 작성·수정에서 대상과 필수 입력 규칙이 일치한다.
- **SC-003**: 지원 서식을 조합한 공지를 저장·재편집해 내용·서식·링크 의미를 보존하고 한글 입력·실행 취소가 동작한다.
- **SC-004**: US3의 첨부 경계 사례에서 5개·파일당 10MB 제한을 지키고 취소·실패로 원본 첨부가 변경되지 않는다.
- **SC-005**: US4의 대상 변경 전후 읽음 기록과 목록·상세 집계가 일치하며 대상 회원 전원을 확인할 수 있다.
- **SC-006**: US5의 저장·삭제 성공/실패, 중복 방지, 이탈 취소/확정과 포커스 복귀를 모두 확인한다.
- **SC-007**: 데스크톱·375px에서 키보드·스크린 리더·터치로 주요 흐름에 접근하고 모의 변경의 화면 이동 유지·새로고침 초기화·프로덕션 비활성화를 확인한다.

## 가정과 범위

### 확정한 범위와 기본값

- 관리자 공지 기능만 다룬다. 현재 기수의 예시 명단으로 검증하고 실제 회원·인증·권한·기수 전환 정책은 변경하지 않는다.
- 전체 사용자는 예시 명단 전체, 나머지 일반 대상은 해당 회원 구분과 일치하는 회원으로 계산한다. 운영진에게 별도로 노출 대상을 확대하지 않는다.
- 노출 대상에서 제외된 회원의 기록은 현재 대상 집계에 포함하지 않는다. 다시 대상이 되면 새 대상 규칙을 적용한다.
- 같은 마감 날짜의 남은 일수는 한국 시간 날짜 차이로 계산한다. 정확한 마감 시각부터 마감으로 취급한다.
- 파일 크기 검증의 10MB는 10 × 1024 × 1024바이트 이하로 적용한다. 첨부 총용량에는 별도 제한을 추가하지 않는다.
- 예시 공지는 실제 개인정보를 포함하지 않는다. 새 공지의 미답변 질문 수는 0이다.
- Figma는 정보 구조·배치의 기준이며 기존 관리자 화면과 시각적 일관성·사용성을 유지한다.
- 사용자 선택인 서식 편집 방식과 JSON 저장을 요구사항으로 확정한다. Tiptap 선택과 버전·연결 방식은 다음 설계 단계에서 기록한다.
- 실제 API·서버 이미지 업로드·회원 앱 읽음 처리·질문 답변·알림 발송·자동 알림·예약 게시·공지 고정·검색·페이지네이션은 제외한다.
- 편집기 원문 모드·별도 미리보기·표·협업, 본문 이미지 삽입과 첨부 순서 변경은 제외한다.

### 작업 경계

- 이 문서는 1단계 요구사항 명세다. 구현 계획·타입·함수·의존성 설치·화면 구현은 이번 단계에 포함하지 않는다.
- 0단계 공통 가이드 리뷰는 사용자의 다음 단계 진행 지시로 완료했다. 1단계는 사용자의 계획 진행 지시로 리뷰를 마쳤다.
- 후속 단계도 사용자 리뷰·수정 반영·다음 단계 진행 확인 후 시작한다. PR 변경량은 실제 base 대비 추가·삭제 합계 800줄 미만으로 유지한다.
- 이슈 연결과 commit·push·PR 생성은 아직 수행하지 않았다. 현재 브랜치 이름은 유지한다.
