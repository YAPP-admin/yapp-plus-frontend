## 작업 배경

회원 웹은 초기 조회 오류, 재조회 오류, 인증 실패를 화면마다 다르게 처리합니다. 기존 데이터와
오류 안내를 함께 표시하거나 재조회 오류를 무시하고, 하위 경계가 인증 오류까지 처리하는 경로가 있습니다.
실패 영역을 일관되게 교체하고 인증 오류를 로그인으로 연결하는 공통 구조가 필요합니다.

## 작업 내용

- [ ] 일반 조회 실패는 실패 영역만 공통 오류 UI로 교체하고 다른 정상 영역·내비게이션을 유지합니다.
- [ ] LocalErrorBoundary·AuthErrorBoundary·AppErrorBoundary로 일반 복구·로그인 이동·최종 복구를 구분합니다.
- [ ] 공통 ErrorState는 페이지형·영역형과 다시 시도를 제공하고, 최종 앱 오류만 홈 이동을 추가합니다.
- [ ] 다음 페이지의 일반 오류는 기존 목록을 유지하고 실패한 추가 조회를 다시 시도할 수 있게 합니다.
- [ ] 조회의 최종 인증 실패와 업무 Mutation 인증 오류는 추가 안내 없이 기본 로그인으로 연결합니다.
- [ ] 일반 Mutation 입력·롤백·성공 결과를 유지하고 자동 재제출하지 않습니다.
- [ ] 동시 실패·계정 전환·늦은 응답·화면 복귀와 접근성을 검증하고 단계별 리뷰를 진행합니다.

## 완료 조건

- [ ] 초기·재조회 실패에서 실패 영역의 이전 콘텐츠와 전체 오류 화면이 동시에 표시되지 않습니다.
- [ ] 인증 오류가 하위 오류 화면에 갇히지 않고 로그인 왕복·중복 이동·이전 계정 영향이 없습니다.
- [ ] 추가 조회 실패의 목록 보존과 재시도 성공, 일반 오류의 재시도, 최종 오류의 두 복구 액션을 검증합니다.
- [ ] 제출 성공 후 재조회 실패를 제출 실패로 바꾸지 않고, 인증 이동 뒤 요청을 자동 재전송하지 않습니다.
- [ ] 단계별 check·build와 브라우저/WebView 확인 결과에 신규 실행·캐시·미실행을 구분해 기록합니다.
