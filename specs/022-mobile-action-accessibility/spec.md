# 기능 명세: 회원 앱 하단 버튼 접근성

**작업 브랜치**: `DongjaJ/plan-proceed`
**작성일**: 2026-11-10
**상태**: 1단계 리뷰 초안 — 화면 기준 측정 미완료
**이슈**: [#411](https://github.com/YAPP-admin/yapp-plus-frontend/issues/411)
**입력**: 사용자가 첨부한 「YAPP+ 모바일 하단 버튼 접근성 개선 및 UI QA 계획」과 단계별 진행 승인.

## 사용자 시나리오와 검증

### US1 — 하단 버튼을 찾지 않고 조작 (P1)

회원은 기존 하단 배치에서 설정의 로그아웃과 가입의 다음 버튼을 바로 찾고 누른다.
핵심 조작이 화면 밖으로 밀리면 진행할 수 없으므로 최우선이다.
독립 검증은 기본 글자 크기·키보드 닫힘 상태에서 두 화면의 버튼 전체가 보이는지 확인한다.

1. 작은 화면에서 설정에 진입하면 스크롤 없이 로그아웃 버튼 전체가 안전 영역 안에 보인다.
2. 가입 이름·휴대폰 단계에 진입하면 다음 버튼 전체가 보이고 본문과 겹치지 않는다.
3. 큰 글자나 긴 본문에서는 내용을 스크롤해 마지막 항목까지 접근할 수 있다.

### US2 — 입력을 유지하며 가입 단계 이동 (P1)

회원은 키보드를 닫지 않고 다음 버튼을 누르고, 뒤로가기로 입력을 수정한다.
입력 유실과 조작 불가는 가입을 막으므로 최우선이다.
독립 검증은 이름 → 휴대폰 → 뒤로가기 → 이름 → 휴대폰의 값·포커스·버튼을 확인한다.

1. 키보드가 열려도 다음 버튼 전체를 누를 수 있고 입력 본문은 스크롤된다.
2. 휴대폰 단계 뒤로가기는 이름으로 돌아가며 두 필드의 입력값을 유지한다.
3. 이름 단계 뒤로가기는 기존 로그인 복귀 동작을 따른다.
4. 서버 이름 오류는 이름 입력을 표시하고 포커스하며, 휴대폰 값과 오류는 보존한다.
5. 제출 중 진행 상태가 보이고 터치·키보드 반복 제출은 요청을 중복 생성하지 않는다.
6. 직접 진입과 새로고침은 빈 이름 단계부터 시작한다.

### US3 — 다른 회원 화면의 내용과 조작에 접근 (P2)

회원은 로그인·완료·팀 인증·오류·탭·공지 화면에서도 내용과 버튼에 접근한다.
독립 검증은 각 화면의 마지막 내용·버튼과 탭 복귀 시 스크롤 위치를 확인한다.

1. 작은 화면에서 로그인·완료 화면의 그래픽과 여백이 줄어 버튼을 밀어내지 않는다.
2. 팀 사진 인증은 사진·팀원 목록을 스크롤하고 확인 버튼은 하단에 유지한다.
3. 공지 읽음 확인은 본문 끝에 유지하고 마지막 내용까지 가리지 않는다.
4. 탭 이동 후 이전 본문 위치가 유지되고 하단 탐색은 시스템 영역에 가리지 않는다.

### US4 — 팝업·오류·상태 안내를 읽고 조작 (P2)

회원은 좁은 화면·큰 글자에서도 팝업과 오류를 읽고 안전하게 취소·재시도한다.
독립 검증은 320px 폭 팝업, 입력 오류, 터치 영역, 테마별 가독성을 확인한다.

1. 로그인·설정·출석 규칙 팝업은 화면 안에 들어오고 긴 내용은 내부 스크롤로 읽는다.
2. 수정 대상의 작은 상호작용 영역은 최소 44×44px로 확보한다.
3. 오류는 해당 입력과 연결되고 요청 중·실패 상태와 가능한 재시도 행동이 구분된다.
4. 시스템 라이트·다크 환경에서 문구와 조작 요소를 읽을 수 있다.

### 경계 조건

- 홈 인디케이터 유무, 키보드 열림·입력 전환·닫힘, 앱 복귀와 화면 회전.
- 확대·패닝을 키보드로 오인하지 않으며 큰 글자에서 내용을 영구히 자르지 않는다.
- 뒤로가기 종류(화면 버튼·브라우저·Android 시스템)와 직접 진입·새로고침.
- 긴 오류·다중 필드 오류·빠른 반복 제출·화면 이탈 후 응답.

## 요구사항

### 기능 요구사항

- **FR-001**: 설정·가입의 하단 배치를 유지하고 기본 글자 크기에서 스크롤 없이 버튼 전체를 표시한다.
- **FR-002**: 헤더·본문·액션이 서로 덮지 않으며 긴 내용은 스크롤로 끝까지 접근 가능해야 한다.
- **FR-003**: 시스템 안전 여백은 중복하지 않고 버튼·탭을 보호한다.
- **FR-004**: 가입 키보드가 열리면 버튼을 그 위에 유지하고 닫히면 원래 위치로 복귀한다.
- **FR-005**: US2의 단계 이동·값 보존·오류 포커스·초기화·중복 제출 조건을 충족한다.
- **FR-006**: US3의 관련 화면, 공지 본문 끝 버튼, 탭 스크롤 복원을 유지한다.
- **FR-007**: US4의 팝업·터치·오류·로딩·가독성 조건을 충족한다.
- **FR-008**: 알림 설정 저장과 팀 사진 실제 제출의 미연결 상태를 근거·영향·필요한 계약과 함께 후속 기록한다.

### 주요 상태

가입 초안은 이름·휴대폰 값과 오류, 현재 단계, 제출 상태로 구성되며 가입 화면 수명에 한정한다.
새로운 회원 데이터나 영속 저장을 만들지 않는다.

## 성공 기준

- **SC-001**: 기본 글자 크기·키보드 닫힘의 설정·가입 화면에서 버튼을 찾기 위한 스크롤이 0회다.
- **SC-002**: 키보드가 열린 가입 화면에서도 다음 버튼 전체를 누를 수 있다.
- **SC-003**: 단계 왕복 시 입력값 유실이 없고 빠른 반복 제출에서 처리 요청이 중복되지 않는다.
- **SC-004**: 대상 화면에 영구히 잘린 내용·조작이 없고 공지 확인 버튼은 본문 뒤에 있다.
- **SC-005**: 좁은 폭 팝업에 좌우 잘림이 없으며 검증한 수정 대상의 터치 영역이 44×44px 이상이다.
- **SC-006**: 실제 iOS 설치 앱과 Android 회귀 결과를 남긴 뒤 최종 완료로 판정한다.

## 가정과 확정 범위

- 회원 앱 전체가 대상이며 채소ZIP·관리자·디자인 전면 개편·미연결 기능 개발은 제외한다.
- 기존 서버·인증·가입 검증 정책은 유지한다. 기존 로그아웃·탈퇴의 실제 실행 검증은 테스트 환경에서 한다.
- 1단계는 브라우저·시뮬레이터 기준이며 실제 iOS 검증은 사용자 승인으로 최종 단계까지 연기했다.
- 각 단계 리뷰와 다음 단계 진행 확인을 받는다. 첫 제출은 명세·수정 전 재현 근거이며 제품 변경을 포함하지 않는다.
- 실행 환경별 재현 결과와 미확인 항목은 [validation.md](validation.md)에 기록한다.
