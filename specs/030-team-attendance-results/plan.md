# 구현 계획: 팀 세션 출석 결과 안내

**브랜치**: `DongjaJ/t90s9` · **날짜**: 2026-11-26 · [명세](spec.md) · [이슈 #622](https://github.com/YAPP-admin/yapp-plus-frontend/issues/622)
**상태**: 1단계 문서 작성·검증 및 사용자 리뷰 완료. 2단계 진행을 승인받았다.

## 요약

기존 API로 세션 시작 이후 본인 팀 출석 결과를 조회하고 홈에 세 가지 BottomSheet를 표시한다.
실제 표시한 photoId와 본인 결과를 localStorage에 저장한다. 재제출 시 기록을 삭제하지 않으며
새 사진의 결과는 각 팀원이 다음 홈 진입에서 구분한다. 서버 확인 API·새 결과 ID는 추가하지 않는다.

## 기술 맥락

- TypeScript·React·Vite·Stackflow 회원 웹, 일반 브라우저와 iOS WebView를 대상으로 한다.
- 기존 TanStack Query·생성 SDK·Zod·SEED·vanilla-extract를 사용한다. 새 의존성은 없다.
- Node.js 24.20.0, pnpm 12.3.4를 사용한다. 루트 명령은 node --run으로 실행한다.
- 서버 상태는 Query, 표시 이력은 localStorage, 열린 시트·진입 수명은 홈 로컬 상태가 소유한다.
- Vitest·Testing Library·MSW로 가까운 계층에서 검증하고 화면·접근성은 실제 렌더링으로 확인한다.
- 홈 진입당 한 건을 찾으면 과거 페이지·사진 탐색을 중단한다. polling·전역 store는 추가하지 않는다.

## 프로젝트 구조와 계약

문서는 spec·plan·research·data-model·contracts·quickstart·tasks·validation으로 구분한다.
실제 구현 경로와 작업별 테스트는 [작업 목록](tasks.md)을 따른다.

- apps/web/src/pages/home/model: 결과 판정·조회 조합·표시 이력. 다른 페이지 모델을 직접 import하지 않는다.
- apps/web/src/pages/home/ui: 세 결과의 표시 전용 시트와 홈 연결. 기존 홈 상태·사진 안내를 재사용한다.
- apps/web/src/shared/ui: 기존 완료 일러스트와 스타일만 이동한다. 범용 모달 프레임워크는 만들지 않는다.
- apps/web/src/features/team-attendance: 접수 성공 시 기존 Query 무효화에 본인 출석 내역을 추가한다.

외부 API·브리지 공개 계약은 유지한다. 내부 결과와 저장 형식은 [데이터 모델](data-model.md),
조회·판정·CTA는 [계약](contracts/team-attendance-results.md)에 단일 기준으로 기록한다.

## 검증·복구

각 단계는 [검증 안내](quickstart.md)의 관련 항목을 실행하고 validation.md에 새 실행·Turbo 캐시·
실패·미실행을 구분한다. 기본 게이트는 node --run check이며 제품 화면 변경 이후 build도 실행한다.
재사용 일러스트 동작은 유지하고 UI 재현은 웹 개발용 fixture에 둔다. 앱 내부를 Storybook 앱에서
직접 import하지 않으며 packages/ui의 공개 동작을 변경하는 경우에만 공용 Storybook을 별도 갱신한다.
문제 발생 시 홈의 자동 결과 시트 연결을 되돌려 기존 사진 제출을 유지한다. 로컬 키는 이 기능만
사용하므로 다른 저장소를 지우지 않고 비활성 상태로 남길 수 있다. 배포는 이번 작업에 포함하지 않는다.
