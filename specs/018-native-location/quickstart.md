# 위치 브리지 검증 절차

이 문서는 후속 구현의 실행 가이드다. 네이티브 위치 RPC와 계약은 구현했다. 웹 호출 도우미·개발 검증 화면은 3단계에 남아 있다.
실행 결과는 [validation.md](validation.md)에 새 실행·캐시·미실행을 구분해 기록한다.

## 준비와 자동 검증

저장소 고정 도구 버전과 설치된 의존성을 사용한다. 필요하면 루트에서 `mise exec -- pnpm install --frozen-lockfile`로 설치한다.
2단계 의존성 추가는 모바일에서 Expo 설치 명령으로 호환 버전을 결정하고 lockfile을 갱신한다.
토큰·실제 좌표·개인 정보를 명령 출력이나 검증 기록에 남기지 않는다.

```sh
mise exec -- pnpm --filter @yapp-plus/app-bridge test
mise exec -- pnpm --filter @yapp-plus/mobile test
mise exec -- pnpm --filter @yapp-plus/web test
mise exec -- node --run check
mise exec -- node --run build
mise exec -- node --run expo:doctor
```

| 계층          | 확인할 프로젝트 동작                                                                   |
| ------------- | -------------------------------------------------------------------------------------- |
| 계약          | 범위 밖 좌표·NaN·무한수·잘못된 timestamp/정밀 수준 거부, accuracy null 허용            |
| 네이티브      | 허용·재요청 가능 거부·재요청 불가, fine/coarse·full/reduced 매핑, 서비스 꺼짐          |
| 네이티브 수명 | 단발 응답, 오래된 표본 거부, 15초 대기, BUSY, timeout 후 재시도와 늦은 결과 무시       |
| 설정          | 요청 성공·실패 구분, 복귀 자동 수집 없음, 다음 요청의 권한 재조회                      |
| 웹 도우미     | SSR·일반 브라우저·연결 지연/실패, 잘못된 응답, 정규화된 오류                           |
| 개발 화면     | 중복 클릭 방지, 화면 이탈·재진입 시 늦은 반영 없음, 원문 좌표 미노출, 키보드·상태 안내 |

타이머·권한·활성 상태·단발 API은 네이티브 어댑터 테스트에 주입한다. 브리지 라이브러리 자체 내부를 중복 테스트하지 않는다.
실제 좌표 대신 합성 표본으로 변환과 브리지 직렬화 결과를 검증한다.
accuracy가 10m·200m·null인 유효한 합성 응답이 모두 전달되는지 확인한다. 100m 출석 거리 기준으로 브리지 응답을 거부하거나 자동 재측정을 시작하지 않아야 한다.

## WebView와 실기기

1. 네이티브 모듈을 포함하는 새 development build를 iOS 기기에 설치한다. Expo Go나 기존 바이너리 통과로 대체하지 않는다.
2. `mise exec -- node --run dev:web`과 모바일 개발 서버를 실행한다. WebView가 로컬 웹을 열도록 기존 MOBILE_WEB_URL/Metro 호스트 규칙을 따른다.
3. WebView에서 `/dev/routes`의 위치 검증 도구를 연다. 진입만으로 권한 요청·위치 수집이 없어야 한다.
4. 권한 조회와 위치 요청을 각각 실행한다. 첫 승인 후 SUCCESS와 정밀 수준을 확인하고 좌표 원문은 캡처하지 않는다.
5. 권한 거부·재요청 불가·일회 허용·정밀 위치 해제·위치 서비스 꺼짐을 OS 설정에서 재현한다.
6. 설정 열기 후 복귀해도 수집이 시작되지 않는지 확인하고, 직접 재요청해 새 권한이 반영되는지 확인한다.
7. 측정 중 앱을 background로 전환한다. 비활성 상태에서 결과가 오면 실패하며, 응답 전 복귀하면 성공할 수 있음을 확인한다. OS 측정의 즉시 취소는 보장하지 않는다.
8. 개발 화면 이탈·연속 클릭·재진입을 확인한다. 네이티브 수집 종료 증거에는 상태·해제 여부만 기록한다.
9. 일반 브라우저에서는 위치 호출 차단·앱 이용 안내·위치 팝업 미표시를 확인한다.
10. 프로덕션 웹 빌드에서 개발 도구 접근이 차단되고 실서비스 출석이 비활성 상태인지 확인한다.

화면은 작은 화면·터치·키보드·스크린 리더에서 확인한다. 새 공용 UI 동작은 추가하지 않으므로 Storybook 새 사례는 필요하지 않다.
GPS 정상·오류 실기기 확인은 자동 테스트로 대체하지 않는다. 실기기 접근이 없으면 해당 결과를 미실행으로 기록한다. 별도 Android 앱은 이 저장소에서 빌드하지 않는다.

## 런타임·출시 확인

- Expo 설정에서 사용 중 위치 문구, background location·foreground service 비활성화와 새 앱 버전을 확인한다.
- 새 바이너리의 runtime이 1.0.1이고 기존 1.0.0과 분리되는지 확인한다. OTA로 네이티브 모듈을 추가하려 하지 않는다.
- 원격 EAS 배포·스토어 제출은 이 가이드 실행에 포함하지 않는다. 승인 후 검증된 main SHA와 연결해 진행한다.
- 문제 발생 시 웹 호출 비활성화와 새 런타임 안에서 위치 기능을 중단하는 수정으로 복구한다.
