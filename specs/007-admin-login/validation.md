# 관리자 로그인 검증 결과

## 자동 검증

- Node 24.20.0·pnpm 12.3.4에서 `node --run check`, `node --run build` 통과.
- admin 4개 파일의 테스트 12개 통과: 기존 대시보드, 로그인 화면, 폼 7개, 모의 판정 3개.
- 필수 입력·최초 제출 후 재검증·오류 포커스·Enter 제출·아이디 공백 제거를 검증했다.
- useMutation 요청 중 입력 잠금·중복 제출 차단·실패 입력 유지·수정 후 재시도·예외 복구를 검증했다.
- 사용 불가 환경에서 클릭·Enter·submit 이벤트로 로그인 함수가 실행되지 않음을 검증했다.
- 구현 전 폼 테스트의 실패를 확인하고 구현 후 통과했다.
- `git diff --check` 통과. 생성 라우트는 Vite를 실행해 갱신했다.

## 브라우저와 빌드 산출물

- Chrome에서 개발 서버 `/login` 접근을 확인했다. 접근 차단 설정은 변경하지 않았다.
- 1440×1080 기본·인증 실패 화면, 필수 입력 오류와 첫 입력 포커스를 확인했다.
- 공개 테스트 계정 제출 후 기존 `/` 대시보드로 이동하는 것을 확인했다.
- CSS 뷰포트 768px·375px에서 가로 넘침이 없고 입력·버튼이 표시됨을 확인했다.
- 스크린샷: `.context/admin-login-implemented.jpg`, `admin-login-error.jpg`, `admin-login-mobile.jpg`.
- 빌드된 서버의 `/login`에서 버튼 비활성화와 준비 중 안내를 확인했다.
- `.output` 전체에서 `admin-demo`, `demo-password`, `login.mock` 문자열이 검출되지 않았다.

## 검증 범위와 제한

- 브라우저의 배율·뷰포트 에뮬레이션에서 클릭 좌표와 키 입력이 일관되지 않아 좁은 화면의
  오류 제출·Tab 순서는 추가 수동 확인이 필요하다. 폼의 키보드·오류 동작은 자동 테스트로 검증했다.
- 실제 스크린 리더·터치 기기는 검증하지 않았다. 레이블, 오류 연결, alert와 포커스 처리를 구현했다.
- 실제 API·세션·접근 제어는 이번 범위가 아니다. `/` 직접 접근은 계속 가능하다.
- 모바일 파일과 공용 UI 동작은 변경하지 않아 expo:doctor와 Storybook 변경은 해당하지 않는다.

## 분리와 복구

- 1차 PR: 명세·라우팅·정적 로그인 화면. 해당 시점의 check/build를 통과했다.
- 2차 PR: 의존성·TanStack Form·TanStack Query mutation·모의 로그인·테스트·검증 문서. 첫 PR 브랜치를 base로 사용한다.
- 각 PR의 추가·삭제 합계는 문서·생성 파일을 포함해 800줄 미만으로 유지한다.
- 적용 취소 시 2차 동작·의존성 변경부터 1차 화면 변경 순서로 되돌린다. 데이터 복구는 필요 없다.
- 커밋·push·브랜치 생성은 승인 후 수행하며 실제 PR 링크는 전달 시 보고한다.
