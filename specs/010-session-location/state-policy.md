# 세션 장소 입력의 상태·오류 정책

**단계**: 1-3 — 승인 (사용자의 다음 단계 진행 지시)
**이슈**: [#88](https://github.com/YAPP-admin/yapp-plus-frontend/issues/88)
**선행 정책**: [유형별 입력·표시](location-policy.md), [기존 세션 명세](../008-admin-sessions/spec.md)

이 문서는 후속 구현의 동작 기준이다. 아래 상태와 검증 시나리오는 구현·검증 완료를 뜻하지 않는다.
이번 리뷰에서 새로 구체화한 조건은 좌표 조회 실패 시 수동 입력 제한, 요청 무효화,
지도 실패 시 저장 허용과 유형 복귀 시 조회 재시도 방식이다.

## 상태 분리와 저장 판단

주소 검색, 선택 주소의 좌표 조회, 지도 로딩, 세션 저장은 각각 상태를 가진다.
검색 결과가 없어도 이미 선택한 주소를 지우지 않고, 지도 실패를 좌표 조회 실패로 취급하지 않는다.

| 조건                                       | 오프라인 저장  | 팀 저장        |
| ------------------------------------------ | -------------- | -------------- |
| 공통 필수 입력 또는 일정 검증 실패         | 불가           | 불가           |
| 주소 미선택, 선택 주소의 좌표 조회 중·실패 | 불가           | 해당 없음      |
| 주소와 최종 좌표 유효, 검색 중·검색 실패   | 가능           | 해당 없음      |
| 주소와 최종 좌표 유효, 지도 로딩 중·실패   | 가능           | 해당 없음      |
| 좌표 수동 입력이 비었거나 유효하지 않음    | 불가           | 해당 없음      |
| 팀 안내 미입력                             | 해당 없음      | 가능           |
| 세션 저장 중                               | 중복 제출 불가 | 중복 제출 불가 |

수정 폼에서 복원한 유효 주소·좌표는 조회 완료된 값으로 취급하며 외부 조회 성공을 다시 요구하지 않는다.
새 주소의 좌표 조회가 실패하면 수동 좌표만으로 우회 저장하지 않는다. 좌표 입력은 조회 성공 또는
저장값 복원 이후의 조정 수단이다. 이렇게 하면 선택 주소와 연결된 초기 좌표 없이 저장되는 것을 막는다.

## 주소 검색

| 상태                | 표시와 행동                                 | 기존 선택값      |
| ------------------- | ------------------------------------------- | ---------------- |
| 초기                | 검색어 입력과 검색 버튼, 검색 전 안내       | 유지             |
| 검색어 비어 있음    | 검색어 입력 안내, 요청하지 않음             | 유지             |
| 조회 중             | 진행 안내, 이전 결과 선택·페이지 이동 차단  | 유지             |
| 결과 있음           | 도로명주소 목록, 현재 페이지·전체 결과 정보 | 선택 전까지 유지 |
| 결과 없음           | 검색 결과 없음과 검색어 변경 안내           | 유지             |
| 실패·시간 초과      | 검색 실패와 재시도                          | 유지             |
| 검색 조건 수정 필요 | 검색어 구체화 안내                          | 유지             |

- 명시적인 검색 버튼 또는 검색 입력의 Enter로 검색한다. Enter가 세션 저장까지 실행되지 않게 한다.
- 한 페이지에 10개를 조회한다. 새 검색어를 제출하면 1페이지부터 조회한다.
- 입력 중인 검색어와 마지막으로 제출한 검색어를 구분한다. 검색 결과와 페이지 이동은 제출한 검색어 기준이다.
- 다른 검색어를 제출하면 이전 요청을 무효화한다. 같은 요청의 중복 실행은 막고 자동 반복 재시도는 하지 않는다.
- 조회 중·실패한 페이지에 이전 페이지의 결과를 현재 결과처럼 표시하지 않는다. 선택 주소 요약은 별도로 유지한다.
- 재시도는 실패한 검색어·페이지를 사용한다. 새 검색어로 찾으려면 검색을 다시 실행한다.
- API 업무 오류와 응답 구조 오류도 실패로 처리한다. 결과가 너무 많아 검색어 수정이 필요한 경우에는 단순 재시도 대신 수정 안내를 제공한다.

## 주소 선택과 좌표 조회

| 상태·행동                                   | 처리                                                                         |
| ------------------------------------------- | ---------------------------------------------------------------------------- |
| 새 주소 선택                                | 선택 주소 갱신, 이전 상세주소·초기 좌표·최종 좌표 제거 후 좌표 조회          |
| 조회 중                                     | 선택 주소와 진행 상태 표시, 좌표 조정·저장 차단                              |
| 조회 성공                                   | 주소 식별 정보에 맞는 응답인지 확인 후 변환·검증, 초기 좌표와 최종 좌표 설정 |
| 조회 실패·시간 초과                         | 선택 주소와 입력한 상세주소 유지, 좌표 없음, 재시도·다른 주소 선택 제공      |
| 좌표 누락·잘못된 값·주소 불일치·모호한 결과 | 임의의 첫 결과를 사용하지 않고 조회 실패로 처리                              |
| 좌표 변환 실패                              | 유효 좌표로 취급하지 않으며 저장 차단, 재시도 안내                           |
| 같은 주소의 조회 재시도                     | 상세주소 유지, 현재 선택 주소만 다시 조회                                    |

현재 선택한 주소를 다시 클릭하는 것만으로 조정 좌표나 상세주소를 초기화하지 않는다.
조회가 실패한 같은 주소는 명시적인 재시도 버튼으로 다시 조회한다.
좌표 조회 중에도 상세주소 입력과 다른 주소 선택, 취소는 가능하다.

## 지도와 좌표 조정

- 지도는 좌표가 준비된 뒤 해당 위치와 마커를 표시한다. 임의의 기본 위치를 선택 좌표인 것처럼 보여주지 않는다.
- 지도 로딩 중에는 진행 상태를, 로딩 실패 시에는 오류와 다시 시도 동작을 제공한다.
- 지도 재시도는 표시 복구만 수행한다. 주소·상세주소·조정 좌표를 지우거나 좌표 API를 다시 호출하지 않는다.
- 지도 실패 시에도 유효한 주소·최종 좌표가 있으면 저장 가능하다. 수동 좌표 입력과 기존 선택값 확인을 유지한다.
- 지도 클릭·마커 드래그 완료·유효한 수동 좌표 적용은 동일한 최종 좌표를 갱신한다.
- 수동 입력 중 빈 값·잘못된 값은 오류로 표시하고 저장을 막는다. 마지막 유효 좌표로 조용히 저장하지 않는다.
- 초기 위치로 되돌리기는 현재 주소를 처음 조회한 좌표로 돌아간다. 수정 폼에서는 조회 없이 복원한 저장 좌표를 초기 위치로 삼는다.
- 지도 이동·확대·축소나 늦게 완료된 지도 로딩은 최종 좌표를 바꾸지 않는다.
- SDK가 오류를 알려주는 경우 이를 표시한다. SDK 로딩 성공만으로 지도 타일까지 정상 표시되었다고 판정하지 않으며 실제 화면 확인은 후속 검증에서 수행한다.

## 늦은 응답과 폼 수명

각 요청은 폼 인스턴스, 요청 순서, 검색 조건 또는 선택 주소와 연결한다.
콜백 시점에 연결이 여전히 유효한 요청만 화면에 반영한다. 네트워크 취소 여부에 의존하지 않는다.

| 상황                     | 무효화·보존 정책                                                  |
| ------------------------ | ----------------------------------------------------------------- |
| 검색 A 후 검색 B         | A 결과·오류가 B를 덮어쓰지 않음                                   |
| 주소 A 조회 중 B 선택    | A 좌표·오류 무시, B만 반영                                        |
| 타임아웃 후 응답 도착    | 실패한 요청의 늦은 응답 무시, 재시도 요청만 반영                  |
| 오프라인 → 팀            | 진행 중 장소 요청 무효화, 이미 입력한 오프라인 초안 보존          |
| 팀 → 오프라인            | 완료된 주소·좌표 초안 복원, 중단된 좌표 조회는 재시도 안내로 전환 |
| 취소·닫기·다른 세션 열기 | 기존 폼의 요청 무효화, 콜백이 새 폼이나 저장소를 변경하지 않음    |
| 저장 시작                | 진행 중 검색 요청 무효화, 제출 데이터 확정 후 입력 변경 차단      |

JSONP 요청은 타임아웃·정리 절차와 늦은 콜백 방어를 갖춘다. 시간 제한의 구체적인 값과
SDK 재시도의 구현 방법은 1-4에서 정하고, 3단계 구현 시 실제 동작을 검증한다.
유형 전환 후 복귀 시 자동 요청을 반복하지 않는다. 완료된 초안은 그대로 사용하고 중단된 조회만 사용자가 재시도한다.

## 세션 저장·취소

- 생성·수정은 같은 검증 규칙을 적용한다. 제출 시 검증 오류를 항목에 연결하고 첫 오류로 포커스를 이동한다.
- 검증 통과 후 저장 중에는 입력·유형 변경·검색·좌표 조정·중복 제출·취소·닫기·Esc를 막는다.
- 저장 실패 시 폼과 현재 입력을 유지하고 실패 안내와 재시도를 제공한다. 성공 안내나 목록 변경을 먼저 적용하지 않는다.
- 생성 성공 시 창을 닫고 전체 필터로 전환해 새 항목과 개수를 반영한다. 신규 출석 집계는 0이다.
- 수정 성공 시 식별자·출석 집계를 유지하고 현재 필터에서 정렬·개수를 갱신한다.
- 수정 대상이 없으면 오류로 처리한다. 생성으로 바꾸거나 다른 세션을 덮어쓰지 않는다.
- 저장 중이 아닐 때 취소·닫기·Esc는 입력과 요청을 폐기한다. 배경 클릭으로 닫지 않는 기존 D5는 유지한다.
- 모의 저장은 DEV 브라우저에서만 제공한다. 프로덕션·SSR에서 외부 장소 조회만으로 편집 기능을 활성화하지 않는다.

## 안내와 접근성

- 검색·좌표·지도·저장 오류는 각각 해당 영역에 표시한다. 외부 서비스의 원문 오류·키·요청 URL을 사용자 화면에 출력하지 않는다.
- 진행과 결과 개수는 보조 기술로 인지할 수 있게 알리고, 늦은 응답이 포커스를 임의로 이동하지 않게 한다.
- 재시도 버튼은 무엇을 다시 시도하는지 구분한다. 검색 재시도, 좌표 조회 재시도, 지도 다시 불러오기를 혼동하지 않게 한다.
- 지도 조작 외에 레이블이 있는 위도·경도 입력과 초기 위치 복귀로 키보드 조정 수단을 제공한다.
- 모달을 닫으면 실행한 컨트롤로 포커스를 돌린다. 수정 후 필터에서 카드가 사라졌으면 목록 제목으로 이동한다.
